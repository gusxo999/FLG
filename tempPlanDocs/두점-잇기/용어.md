# 두점-잇기 — 용어 결정 자료

> **언제 읽나:** 각 단계 착수 **직전**. §1(Step 1 의 말)은 2026-10-01 에 정했다. 사용자는 정의를 최대한 늦게 정한다(2026-09-30).
> **이 파일의 말은 전부 가칭이다.** 여기 적힌 것은 *"결정하려면 알아야 할 문맥"* 이지 결정이 아니다.
> 결정되면 합의한 말을 `docs/용어사전.md` 에 올리고 계획서를 그 말로 고친 뒤, 이 파일은 지운다.
>
> **3판에서 뺀 것** — 2판의 *범주*(계획 규칙 · 방출 규칙) · *규칙 아홉의 이름* · *다툼 · 규칙의 정의*. 규칙 층을 철회했으므로
> 정할 필요가 없어졌다(계획서 개정 기록).

**읽는 순서** — §1 Step 1 에 쓴 말(정했다) → §2 양보의 종류(진 쪽이 무엇을 내주나 — 아직) → §3 뒤 단계에 쓰는 말(아직).

## 2. 양보의 종류 — **진 쪽이 무엇을 내주나**

**양보는 총칭이다**(사용자 2026-09-30). 종류는 **진 쪽이 무엇을 내주나**로 가르면 겹치지 않는다. Step 1 은 **기존 이름**
(진출 변 뒤집기 · 지하 횡단 · 물러남 · 폴백)만 쓰므로 이 절의 결정은 Step 1 을 막지 않는다.

```
층        땅 위 → 땅속                        잠수 · 지하 횡단
순서      앞 자리 → 뒤(바깥) 자리              정렬(사용자 안)
변        이 변 → 저 변                        진출 변 뒤집기
모양      곧은 길 → 꺾인 길                    열 갈아타기
후보      앞 후보 → 다음 후보                  후보 강등 · 후보 제외
계획      도형 있음 → 도형 없음                물러남 · 폴백
결과      나감 → 안 나감                       skip
청구      가진 자리 → 남에게                   철회(오늘 없음)
```

**양보가 아닌 것 둘** — **강행**(졌는데 내줄 것이 없어 그대로 선다 · `ExitBlocked.kind: "forced"`) ·
**예약 무시**(이긴 쪽이 하는 일 — 남의 예약을 밟는다).

### 2.1 층을 내준다

#### 잠수 — *(기존 용어 · 정의를 고친다 — J-잠수기준)*

| | |
|---|---|
| **지금 정의** | 모듈 옆면의 벨트가 인서터가 없는 행에서 땅속으로 지나가 그 행의 지면을 남에게 내주는 것. *"비켜 주기"* 는 그중 먼저 앉은 줄이 들어가는 경우의 이름이었다 |
| **사용자 결정(2026-09-30)** | 비켜 주기 항목을 **없애고 잠수에 넣는다.** 잠수는 **경로 충돌**의 해소이고, *누가 먼저 왔나* 는 개념이 아니다. **누가 들어가나는 자유도** — 열 채널에서는 **엇갈린 상대가 많은 쪽**(계획서 Step 1 ③) |
| **어디서** | 모듈 옆면(`module/policy/link.diveRelief`) · gap 출구(`module/shape/body.gapExitDive`) · (지하 횡단과 묶으면) 열 채널 |
| **기록** | 계수기 `diveOwn` · `diveYield` · gap 출구 `잠수 a/b` (`flg.report()` 면깊이 줄) |
| **결정할 때 물을 것** | 정의 문장에 J-잠수기준 (가)의 문장(가능성 → 터널 적은 쪽 → 동률)을 넣나 · 열 채널의 지하 횡단까지 잠수라 부르나 |

#### 지하 횡단 — *(기존 용어)*

| | |
|---|---|
| **정의** | 열 채널에서 **아이템 납품**이 막힌 칸 밑을 지하벨트로 건넌다. 막힌 구간마다 점프 하나, 붙은 구간은 합친다 |
| **누가 · 언제** | 열 채널 · 계획. 땅 위를 내준 아이템 납품 — Step 1 뒤에는 *엇갈림으로 내줬거나 · 탐색에서 못 앉았거나* |
| **못 하는 것** | 반출(방출기가 땅 위로만 깐다 — 계획서 Step 5) · 유체 납품(결정 D2 — 지하파이프 페어링 — 계획서 Step 2 가 연다. 열리면 유체가 **먼저** 들어간다) |
| **코드 · 기록** | `channel/ledger/geometry.crossUnderground` · 계획 kind `undergroundCrossing` |
| **물을 것** | 잠수와 **같은 종류의 두 이름**인데 둘 다 둘까(영역이 달라 이름을 가른다) · 하나로 묶을까 |

### 2.2 순서를 내준다

#### 정렬 — *(사용자 안 · 가칭)*

| | |
|---|---|
| **정의(안)** | **순서만 묻는 장부**(트랙 번호 · 깊이 · 행 채널 트랙)에서 진 쪽이 **뒤(바깥) 자리**를 받는 것 — 자리를 잃지 않고 순서만 밀린다 |
| **왜 따로 서나** | 순번 · 트랙 번호 장부에서는 다툼의 답이 **순서**다 — *"서쪽이냐 동쪽이냐"* · *"얕으냐 깊으냐"*. 그 장부가 순서만 물으므로 순서를 지켜 좌표로 옮겨도 답이 안 바뀐다(pipeline-lifecycle §5) |
| **어디서** | 열 채널 트랙 배정(`assignSurface` — 폭이 는다) · 좌석 깊이(얕은 줄 · 깊은 줄) · 행 채널 전순서(`planRowChannel`) |
| **기록** | 없다 — 결과(트랙 · 깊이 번호)만 남는다 |
| **겹침** | 저장소의 *정렬* 은 대부분 **sort**(*"안정 정렬"* · *"정렬 두 번"* · *"재정렬"*)다 |
| **물을 것** | *sort* 와 같은 말을 쓸까 · 다른 말을 쓸까 · 이것을 **양보로 셀까**(진 쪽이 치르는 대가는 폭 · 길이뿐이다) |

> **이전 문장의 정정** — *"순번에서 내준 것은 방출에서도 그대로 성립한다"* 는 모듈 옆면의 **먼저 앉은 줄의 잠수**를 두고 한
> 말이었다. 그 줄은 순서를 안 바꾸고 **층**만 바꾼다 — 그래서 그 경우는 정렬이 아니라 **잠수**다.

### 2.3 변을 내준다

#### 진출 변 뒤집기 — *(기존 문구)*

| | |
|---|---|
| **정의** | 환승 반출(채널을 따라 N/S 바깥 변으로 나가는 반출)이 **진출 변을 N ↔ S 로 바꾼다.** 바꾼 변에서 새 엇갈림을 안 만들 때만 — Step 1 뒤에는 반출끼리도 본다 |
| **누가 · 언제** | 열 채널 · 계획 · 해소 사다리의 첫 칸 |
| **코드 · 기록** | `channel/policy.tryFlip` · 기록 없음 — `materializeChannelGeometry` 가 `exitEdge` 를 **덮어써** 뒤집혔는지 사후에 못 안다(채널-양보-명세 §3) |
| **겹침** | 용어사전 *같은 쪽 판정* 이 이 수를 *반출 재배정* 이라 부른다 |
| **물을 것** | *반출 재배정* 과 *진출 변 뒤집기* 중 하나로 |

### 2.4 모양을 내준다

#### 열 갈아타기 — *(기존 용어)*

| | |
|---|---|
| **정의** | 납품의 세로 주행이 한 트랙 전체에서 비어 있지 않을 때, 중간 행에서 **옆 트랙으로 한 번 꺾어** 빈 조각 둘을 이어 쓴다(dogleg) |
| **누가 · 언제** | 열 채널 · 계획 — **탐욕 배정에서만** 시도된다(백트래킹이 성공하면 안 나온다). 끝이 엇갈린 쌍은 이것으로도 못 푼다(§5-3) |
| **코드 · 기록** | `tryColumnSwitch` · 계획 kind `columnSwitch` · 테스트 코퍼스 실측 0건(채널-양보-명세 Step 0) |
| **물을 것** | 이름 그대로 둘까 |

### 2.5 후보를 내준다

#### 후보 강등 — *(기존 용어)*

| | |
|---|---|
| **정의** | 반출의 **직진 후보**가 먼저 확정된 직진의 선에 막혀 **건너뛰고 다음 후보로** 간다. 아직 확정 안 된 후보를 건너뛸 뿐이라 되돌림이 없다 |
| **누가 · 언제** | 외곽 · 계획 · 직진 × 직진(순서 P12) |
| **코드 · 기록** | `perimeter/policy.planPerimeterExits` · `PerimeterExitPlan.demotions = {상자, 버린 변, 승자, 칸}` |
| **겹침** | perimeter-export §3② · module-way-outs 가 *"강등은 양보가 아니다"* 라 적었다 — 양보를 총칭으로 쓰면 이 문장이 뒤집힌다 |
| **물을 것** | 그 두 문장을 고치는 데 동의하나 |

#### 후보 제외 — *(새로 지음)*

| | |
|---|---|
| **정의** | 반출의 한 방향이 **자격 판정에서 후보로 아예 안 선다.** 강등과 달리 순서와 무관하다 — 누가 먼저 골랐든 같다 |
| **누가 · 언제** | 외곽 · 계획 · 직진 × 행 채널 가로 트랙(관통) · Step 4 뒤에는 직진 × 모듈 옆 빈 자리의 가로선 |
| **코드 · 기록** | `perimeter/shape/qualify` 의 `no(방향, 사유)` — 사유는 **후보가 0 인 상자에만** 남는다(`ExitBlocked.why`) |
| **겹침** | 같은 `no()` 가 *모듈몸통* · *남의모듈* 로도 후보를 뺀다 — 그건 모듈과 부딪힌 것이라 **다툼이 아니라 사실**이다 |
| **물을 것** | 사실로 빠지는 것과 다툼에서 져서 빠지는 것에 같은 이름을 줄까 |

### 2.6 계획을 내준다

#### 물러남 — *(기존 문구)*

| | |
|---|---|
| **정의** | 환승 반출이 **채널 지상 배정을 포기한다.** 계획(트랙)이 없는 채로 남고, 방출에서 빈 트랙을 훑는다(`router` — 16칸까지). 폭은 유령 세로선으로 예약된다 |
| **누가 · 언제** | 열 채널 · 계획 · 해소 사다리에서 반출이 내준 쪽일 때 — 오늘은 유체와 엇갈렸을 때뿐, Step 1 뒤에는 반출끼리 엇갈려 뒤집기가 안 될 때도 |
| **코드 · 기록** | `yieldedExports` · 사유 `yielded-to-fluid` — `PackChannelGeometry` 에 **안 실린다**(채널-양보-명세 §3) |
| **물을 것** | *물러남* 과 *폴백* 을 가를까 — 둘 다 계획을 잃는다. 가르는 기준은 *"진 이유가 순위냐(물러남) · 자리가 없어서냐(폴백)"* |

#### 폴백 — *(기존 용어 · 용어사전 fallback(라우팅))*

| | |
|---|---|
| **정의** | 열 채널 장부가 그 경로에 **도형을 못 준다.** 납품은 방출에서 탐색(Dijkstra)으로, 반출은 빈 트랙 훑기로 간다 |
| **코드 · 기록** | 계획 kind `fallback` · 사유는 §1 |
| **물을 것** | *폴백* 을 그대로 쓸까 · 한국어 이름을 줄까 |

## 3. Step 3 · 4 에 쓰는 말 — 그 단계 착수 직전에

### 3.1 관통 — **뜻이 둘이다**

| | |
|---|---|
| **exit-ray §3 ③** | 세로 직진 반출이 행 채널(가로줄을 파는 통로)을 **세로로 지나는** 경우 — *"살 게 없다 → 비었나만 묻는다"*. 코드 사유 `행채널관통(d…)` |
| **용어사전** | *"벨트 한 줄이 부모 머신 여럿을 관통해 나눠 먹이기"* — 묶음 크기 `g = N`(한 줄이 기둥 전부를 먹인다) |
| **물을 것** | 둘 중 하나에 다른 이름을 줄까 · 한정어로 가를까(*영역 관통* · *기둥 관통* 같은) |

| **물을 것** | Step 4 가설이 맞으면 영역 이름으로 올릴 때 |

### 3.3 두 점 잇기 — 모델 이름
