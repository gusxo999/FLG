## J13 — 링크가 자리를 잃었을 때 **무엇을 내주나** (2026-09-02)

> **2026-09-03 — 새 계획으로 넘긴다.** 이 계획의 물음은 *나머지 줄*의 `g` 였고 그건 끝났다.
> 링크의 `g` 는 **간선**이라는 다른 축이고(양끝이 같은 `c` 를 봐야 한다), 아래 세 길이
> 각각 포트 폭증·채널 폭이라는 **다른 문제**를 연다. 조사와 실측은 여기 그대로 남긴다.

**무엇이 미결인가.** 링크 줄에 `g` 를 **받을 자리**는 생겼다(`edgeLinkGroups(…, bundle?)` ·
[EdgeBundle], `planner/link/edgeLinks.ts`). 그런데 **아무도 그 값을 주지 않는다.** 줄 사람
(깊이 예산 [planBundles])을 붙이려면 아래 셋 중 하나를 먼저 골라야 한다.

**먼저 확정된 기전 하나 — 부분 트렁크는 깊이를 안 돌려준다.**

```
g > 1   덮는 행 = [첫 머신 첫 행 … 끝 머신 끝 행]   →  토막이 몇이든 그 깊이는 그 줄 것
g = 1   덮는 행 = 그 머신의 자기 좌석 행뿐          →  여러 품목이 한 깊이를 나눠 쓴다
```

`depthBudget.ts` 의 부등식이 이미 그 말이다 — `(g>1 줄 수) + (g=1 이 있으면 면 수) ≤ Σ_f R_f`.
**그러므로 `1 < g < N` 은 깊이 압력에 대한 답이 아니다.** 부분 트렁크가 푸는 것은 **양**
(벨트 처리량·좌석)이고, 자리를 되찾는 것은 `g = 1` 뿐이다.

**포트가 무엇으로 폭증하나 — `c` 다** (2026-09-03 코드 확인, `linkPlanner.tryLinkFace`).

포트는 **토막마다** 난다. `c = ⌈N ÷ g⌉` 이므로 `g` 를 내리면 포트가 그만큼 는다 —
그리고 **양끝 모두**다(`c` 는 간선이 공유하는 낱말이라 자식에도 `c` 개, 부모에도 `c` 개).

```
g = N (관통)   c = 1     포트가 **기둥 끝**에 선다(`portEnd` N/S) — 좌석표 밖이라 남의 자리를 안 먹는다
g < N (토막)   c = N/g   `spansAllMachines` 가 거짓 → `portEnd = undefined` → **옆 포트**
                         옆 포트는 `(topT, d+1)` · `(topT, d+2)` — **바깥 깊이 둘을 판다**([portCells])
```

**그래서 `1 < g < N` 은 양쪽으로 손해다.** 토막이 몇이든 그 품목의 덮는 행 합집합은
그대로라 깊이는 안 돌아오는데(위 기전), 포트는 `c` 배로 늘고 그 포트가 **바깥 깊이까지**
먹는다. 자리를 살 수 없는 값을 치르는 셈이다.

**증상** (2026-09-02 브라우저 실측, `advanced-circuit`):

```
E 면 링크 입력 3줄 (copper-cable · kr-electronic-components · electronic-circuit)
면당 깊이 R = |reach 종류| = 2      ← 로드된 게임데이터에 reach 3 이 없다(인서터 7종 전수)
링크는 반대 면으로 못 가고 · gap 은 g=1 만 받는다   →  한 줄이 반드시 못 앉는다
처리량·머신 수와 무관하다(10/s 든 1/s 든 같다) — **구조적**이다
```

**길 셋**

| | 무엇을 내주나 | 값 | 위험 |
|---|---|---|---|
| **(가) 넘치는 링크를 `g = 1` 로** | 그 줄의 포트가 머신 수만큼 | 밸브가 이미 있다(`{side, g: 1}`) | 포트·납품 경로 폭증 → 채널 폭. 대조 실측: 외부 줄이 그렇게 떨어진 배치가 **포트 273 · 벨트 이용률 26%** |
| **(나) 링크 입력에 반대 면(W)을 연다** | 없음 — 깊이가 2 → 4 | 가장 싸다 | 오늘 금지 사유가 *"벨트가 채널 반대쪽에서 출발해 되돌아올 길이 없다"*(`planModulePorts`). 납품 경로 기하가 성립하는지 **미확인** |
| **(다) 오늘처럼 정직하게 실패** | 배치 자체 | 0 | 트리 안에서 만드는 재료가 3종 이상인 레시피가 `R = 2` 에서 **전부** 못 돈다 |

**따라오는 둘째 물음 — 예산을 링크에 대해선 면마다 셀 것인가.**
`planBundles` 는 모듈 전체(`Σ_f R_f`)로 센다. 근거는 *"선호 면이 차면 반대 면으로 넘어가기
때문"*(2026-09-01 electric-motor 실측). **그 전제가 링크에는 거짓이다** — 링크는 못 넘어간다.
(나)를 고르면 참이 되고, (가)를 고르면 **링크만 면 단위로** 세야 한다.

**착수 조건 — 입력의 성질**

```
한 모듈의 링크 입력 줄 수 > R    (= 트리 안에서 만드는 재료가 R 종을 넘는 레시피)
```

**채울 자리는 정해져 있다** — `modulePacking` 의 간선 루프. 자식·부모의 좌석표를 **둘 다**
보는 유일한 자리다(`seatLinkEdge` 를 부르는 그 줄).
