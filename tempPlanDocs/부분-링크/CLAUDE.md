# 부분-링크 — 공통 컨텍스트

**한 문장:** 간선 한 줄이 맡는 머신 수를 **양끝에서 함께** 정한다.

## 이름에 대하여

`부분-트렁크` 를 간선에 적용한 것이라 그 이름을 물려받았다. 다만 **간선은 끝이 둘**이라
낱말이 하나 더 붙는다:

```
g_from · g_to    끝마다 다르다 — 자식 32대 · 부모 64대면 한 줄이 맡는 수가 서로 다르다
c                **간선이 공유하는 낱말** — 토막 수.  c = ⌈N_자식 ÷ g_자식⌉ = ⌈N_부모 ÷ g_부모⌉
```

그래서 `EdgeBundle` 이 `(어느 끝, 그 끝의 g)` 쌍을 받는다 — 한쪽이 말하면 반대쪽은
**결과로** 정해진다.

## 하지 않는 것

```
나머지 줄의 `g`      이미 끝났다(`planBundles`). 여기서 안 건드린다
면·깊이 배정         `자리-배정` 의 몫
격자 클러스터        gap 을 벌리는 형태는 범위 밖
```

## 이미 확정된 기전 — **다시 논쟁하지 않는다**

```
부분 트렁크는 레인을 안 돌려준다
  g > 1   덮는 행 = [첫 머신 첫 행 … 끝 머신 끝 행]   → 토막이 몇이든 그 레인은 그 줄 것
  g = 1   덮는 행 = 그 머신의 자기 좌석 행뿐          → 여러 품목이 한 레인을 나눠 쓴다
```

**그러므로 `1 < g < N` 은 레인 압력에 대한 답이 아니다.** 부분 트렁크가 푸는 것은 **양**
(벨트 처리량·좌석)이고, 자리를 되찾는 것은 `g = 1` 뿐이다. → `judgements.md` **J13**
