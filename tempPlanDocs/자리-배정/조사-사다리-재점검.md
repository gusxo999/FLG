# 조사 · 사다리(구간막힘 해소) 재점검 — **켜도 안 달라진다** (2026-09-03)

> **묻는 것.** `AUTO_LAYOUT_LINK_LADDER`(못을 피해 링크를 토막내기)가 실제로 쓸모가 있나.
> 플래그 주석이 적어 둔 실험 그대로다 — *"꺼 둔 채로 순서 규칙을 넣고, 그래도 못 앉는 줄이
> 남는지를 본다."* 그 순서 규칙(간선 축 배정 · `Link.end` · 레인 예산)은 이미 들어갔다.

## 0. 결론

```
합성 스윕   사다리가 발동하는 형상이 **있다** — 108건 중 18건이 갈리고, 언제나 켠 쪽이 낫다
실물 실행   13번 돌렸는데 **한 번도 안 갈렸다** — `쪼갬 0`, ON/OFF 결과가 완전히 같다
```

**막히는 이유가 실물에선 다른 칸이다.** 사다리가 푸는 것은 1단(`구간막힘`) 하나인데,
실물에서 나온 사유는 `좌석부족` · `좌석막힘` · `포트막힘` 셋뿐이었다.

## 1. 못이 생기는 조건 — 코드에서 유도

`portCells` 한 줄이 전부다:

```
비관통 그룹(portEnd 없음)  →  포트가 (topT, d+1) · (topT, d+2)   ← **더 깊은 레인**에 박힌다 = 못
관통 그룹  (portEnd N/S)   →  포트가 (topT∓1, d) · (topT∓2, d)   ← 기둥 밖이라 표에서 잘린다
```

**그래서 못은 관통이 아니라 *쪼개진 줄*이 만든다.** 그리고 구간막힘이 되려면 넷이 동시에:

```
① 레인이 둘 이상        긴팔이 있어야 `d+1` 이 실제 레인이다
② 얕은 레인에 비관통 그룹  옆 포트가 깊은 레인에 못 2칸을 박는다
③ 깊은 레인에 걸치는 그룹  그 못 행을 가로지른다
④ 못이 **점**이라 사이가 빈다   `resolveSpanBlock` 이 자를 자리를 찾는다
```

④가 갈림길이다 — 막은 것이 남의 **벨트**(구간)면 조각을 내도 안 살아 `좌석막힘`이 되고,
남의 **포트 인서터**(점)여야 `구간막힘`이 된다.

## 2. 합성 스윕 — 발동한다

1차(3×3 · 링크 하나 · 느린 팔): 118건 실패가 **전부 `seat-budget`** 이었다 —
**좌석이 먼저 터져 레인 검사에 도달조차 안 했다.**

2차(좌석을 넉넉히: 큰 머신 + 빠른 팔 30/s + 느린 벨트 20/s):

```
레인 다툼 108건 중 **18건이 플래그로 갈린다** — 그리고 **언제나 켠 쪽이 낫다**

m3 k2 n2 r50   OFF{포트막힘4, 구간막힘후보2  못앉음 4}  →  ON{포트막힘2  못앉음 2}
m5 k3 n2 r50   OFF{포트막힘4, 구간막힘후보4  못앉음 6}  →  ON{포트막힘2  못앉음 2}
m7 k3 n2 r50   OFF{포트막힘4, 구간막힘후보4  못앉음 8}  →  ON{포트막힘2  못앉음 4}
```

18건의 공통 조건은 둘뿐이다:

```
자식 2개 이상   부모가 중간재를 2종 이상 받는다   → 링크 둘이 같은 면을 다툰다
rate > 벨트     줄이 쪼개진다                    → **비관통 그룹**이 생겨 못을 박는다
```

머신 크기(3·5·7)와 원료 수(0·2·4)는 **무관**했고, 머신 대수는 **2대**에서만 났다.

## 3. 실물 실행 — 한 번도 안 갈린다

`localhost:5173` · 게임데이터 = Krastorio+SE 모드팩(레시피 2647).
**주의: 이 데이터에 바닐라 `electronic-circuit` 은 없다** — 여기 것은 Krastorio 판
(`stone-tablet` + `copper-cable`)이다.

타깃 `electronic-circuit`, 외부공급 `stone`·`copper-ore`(→ 자식 둘), 벨트 `transport-belt`:

| 인서터 | perTarget | 깊은레인 | 사유 | ON↔OFF |
|---|---|---|---|---|
| inserter · long-handed | 20 | 0 | 좌석부족 6 | 같음 |
| fast · long-handed | 20 | 0 | 좌석부족 4 | 같음 |
| bulk · long-handed | 20 | 0 | **좌석막힘** 2 | 같음 |
| bulk · long-handed | 8 | 0 | **좌석막힘** 1 | 같음 |
| kr-superior · kr-superior-long | 12 | 7 | (실패 없음) | 같음 |
| 〃 | 16 / 24 / 30 / 40 | 8 / 10 / 12 / 16 | **포트막힘** 1 / 2 / 2 / 3 | 같음 |

**모든 실행에서 `쪼갬 0`.**

### 읽는 법 — 세 단계가 보인다

```
느린 팔        좌석부족   팔이 너무 많아 면에 안 들어간다.  레인은 구경도 못 한다
빠른 팔        좌석막힘   레인까지 갔는데 막은 것이 남의 **벨트**(구간)라 조각이 안 산다
빠른 긴팔      포트막힘   깊은 레인이 실제로 쓰이고, 막은 것이 **포트 칸**이다 ← 사다리 2단
```

**깊은 레인이 안 쓰이면 못이 아예 안 생긴다.** 그리고 바닐라 긴팔은 짧은 팔보다 **느려서**
`tryLinkFace` 의 후보 정렬(팔 적은 순)에서 언제나 진다 → 깊은레인 0. 깊은 레인이 쓰인 것은
**빠른 긴팔이 있는 모드팩**뿐이었고, 그때 나온 사유는 전부 `포트막힘` 이었다.

## 4. 그래서 판단

```
사다리 1단(구간막힘)   **이론상 옳고 합성으로 발동하지만, 실물에서 안 걸린다**
실물의 병목            좌석 → (빠른 팔) → 포트 칸.  구간막힘은 그 사이 어디에도 없다
```

**지우자는 말이 아니다** — 합성 18건이 *"이 형상이 오면 사다리가 답이다"* 를 보인다.
다만 **1순위가 아니다.** 지금 화면에 실제로 뜨는 실패는 `포트막힘`(2단)이고, 그건 사다리에
아직 없는 칸이다.

> **다음 물음은 하나다:** 포트막힘을 푸는 칸(2단)이 무엇인가. 못이 **포트 칸**이라는 것은
> 곧 *"남의 포트가 내 레인 한복판에 선다"* 이므로, 답의 후보는 **포트를 기둥 끝으로 미는
> 것**(= 그 줄을 관통으로 만들기)이거나 **깊이 방향 포트**(TR6)다. 둘 다 `g` 와 얽힌다.
