## 0. 그날 무엇이 실제로 통했나

**통한 것 하나:** 콘솔의 `[autoLayout debug] handleApplyCandidate` 덤프를 파싱해
**한 면의 단면표**를 찍은 것. 결함 두 개가 그 표 한 장에서 나왔다.

```
  y |     0     1     2     3     4     5     6
   5 |     .  Belt CHEST Inser  Belt Inser Assem
   6 |     .  Belt  Belt  Belt     . Inser Assem     ← d2(x4)에 구멍
   7 |     .     .     .  Belt     .     . Assem
```

**안 통한 것:** 스크린샷 눈대중. 같은 결함을 두 턴 동안 못 봤고, 캔버스 확대도 안 됐다.
메모리 `feedback_layout_check_by_dump` 가 이미 금지하던 방식이다.

> **그래서 요구의 축은 하나다 — 좌표를 사람이 읽을 모양으로 뽑는 일을 앱이 해야 한다.**
> 지금은 AI 가 100KB JSON 을 받아 파이썬으로 표를 만든다. 그 표가 결정적이라면 앱이 낸다.

## 1. 막힌 지점 — 원인 수준

### ① 조작이 3왕복 든다

`navigate → 6단계 클릭 → 생성 클릭 → 스크린샷으로 확인` 이 매번이다. 새로고침하면
위저드 단계가 되돌아가 **클릭이 엉뚱한 단계에 맞았다**(실제로 5단계 지하파이프 화면이 떴다).

```
필요:  flg.run()            현재 위저드 설정 그대로 생성까지 한 줄로
       flg.run({ target:'concrete', machines:8 })   설정을 바꿔 한 줄로
```

### ② 출력이 100KB라 읽기 도구가 잘린다

`handleApplyCandidate` 덤프는 **전체 트리의 모든 셀**이다. AI 의 콘솔 읽기가 잘려
파일로 떨군 뒤 파싱해야 했다. 필요한 건 대개 **모듈 하나의 한 면**이다.

```
필요:  flg.face('n0-concrete', 'W')     ← 단면표를 **문자열로** 낸다 (위 예시 모양)
       flg.face('n0-concrete', 'W', { depth: 6 })
```

깊이 열은 `d1..dN` 으로 라벨링하고 **상자·인서터·벨트·머신**을 구분해 찍는다.
좌표(x,y)와 모듈-로컬 depth 를 **둘 다** 보여야 한다 — 오늘 그 환산을 손으로 했다.

### ③ 진단 카운터가 흩어져 있다

한 번의 실행에서 봐야 하는 수가 최소 이만큼인데, 화면·콘솔·테스트에 흩어져 있다.

```
필요:  flg.report()
       ─ 납품:   planned / dijkstraFallback / reservationOverrun / failures
       ─ 반출:   relocated / skipped / skips[{chestId, reason}]
       ─ 모듈:   unroutedLines · supply.mode · 면별 레인 점유
       ─ 크기:   셀 수 · penalty · bbox
```

`planned = 0` 을 오늘 **우연히** 발견했다 — 콘솔 로그를 정규식으로 긁다가 나왔다.
카운터가 한 줄로 나왔으면 첫 턴에 봤을 것이다.

### ④ 기준선 비교가 `git stash` 다

*"이게 회귀인가 더 나은 배치의 부작용인가"* 를 판정하려고 **작업 트리를 stash 하고
새로고침해 다시 생성**했다. 위험하고(작업 유실 위험) 느리다.

```
필요:  flg.snapshot('before')      결과를 이름 붙여 저장
       flg.diff('before')          셀 수·penalty·카운터·포트 위치 차이만 출력
```

코드 두 버전을 비교하는 건 여전히 git 이 필요하다. 다만 **같은 코드에서 입력만 바꾼
비교**(지하벨트 유무, 머신 수, 레인 수)는 앱 안에서 끝나야 한다.

### ⑤ 규칙 검사를 AI 가 손으로 짠다

오늘 파이썬으로 *"벨트가 연속인가"* 를 검사했다. 그건 **앱이 아는 사실**이다.

```
필요:  flg.check()      위반만 출력.  통과하면 침묵
       R-연속    한 그룹의 벨트 셀이 행 방향으로 연속인가
       R-도달    모든 포트 벨트가 자기 포트 인서터에 인접한가
       R-겹침    유효 셀 겹침 0
       R-무우회  납품 벨트가 남의 포트 상자를 감싸는 ㄷ자를 만들지 않는가
```

이 넷은 **오늘 실제로 위반을 잡은 규칙들**이다(R-연속·R-도달이 결함 A, R-무우회가 결함 B).
지어낸 목록이 아니다.

## 2. 안 필요한 것 — 범위를 줄이기 위해

- **스크린샷·캔버스 확대** — 안 쓴다. 오늘 확대가 됐어도 결함을 못 봤을 것이다.
- **브라우저 드라이버 자동화** — `AI-콘솔조작` 계획서의 "하지 않는 것"과 같다.
  Chrome MCP 로 `navigate` + `read_console_messages` 면 충분하다. 명령을 **콘솔에 치는 것**은
  `javascript_tool` 로 AI 가 직접 할 수 있다.
- **블루프린트 문자열 왕복** — 게임에서 열어 보는 것은 사람의 판단이지 AI 의 디버깅 도구가 아니다.

## 3. 다음 작업에서 이 도구로 무엇을 할 것인가

주제: **`planned = 0` — 납품 경로가 예약을 한 번도 못 썼다.**

```
1. flg.run()  →  flg.report()           planned/fallback/overrun 을 먼저 본다
2. channelGeometry · reservePerimeterLanes 게이트가 켜져 있나
   → 위저드가 그 옵션을 안 넘기는 배선 문제인지부터 가른다
3. 켜져 있는데 0 이면 계획 단계가 어디서 포기하는지 (cut-different-side ·
   crossing-needs-underground) 를 사유별로 센다
4. flg.check() 로 고친 뒤 위반이 사라지는지 확인
```

**그 뒤에 남은 것:** `channelGeometryPlanner.test.ts` 의 *"예약을 켜도 skip 이 늘지 않는다"*
1건이 빨간 채로 있다(커밋 `518e487`). 계획 0 과 같은 뿌리로 보여 함께 푼다.
