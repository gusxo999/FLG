# 구간 사슬 — 트렁크 경로의 뼈대

> **작성일:** 2026-08-13 · **상태:** 설계 · **코드 0**
> **부모:** [트렁크벨트-경로모델](../트렁크벨트-경로모델.md) — 정의는 §1~§8, 결정은 §9(특히 D10)
> **이 문서가 첫 코드다.** [1-지하벨트](../1-지하벨트/) 는 여기 얹히는 **인자**이고,
> [2-격자배치](../2-격자배치/) 는 여기 **입력(머신 좌표)** 을 바꾸는 일이다.

## 0. 한 줄

> **줄 하나 = 트렁크 하나.** 그 트렁크는 **탭 주행(구성) + 연결 구간(탐색)** 의 사슬이고,
> 연결은 `containerRouting.dijkstraWithJumps` 를 그대로 부른다.

---

## 1. 자리 — 파이프라인의 어디에 들어가나

```
planModulePorts(좌표 없음)  ← 오늘 그대로. 다이렉트 기준 배정
layoutCluster(rowGaps)      ← 오늘 그대로. 머신 좌표가 여기서 난다
────────────────────────────────────────────────────────
planTrunks(machines, …)     ← **신설.** 좌표를 안다
────────────────────────────────────────────────────────
emit*(…)                    ← 트렁크 계획을 셀로
```

**폴더 판정**(`code-folders` 두 축):

| 축 | 판정 |
|---|---|
| 계층 | `PlacedCell` 을 **안 만든다** → `planner/` |
| 관심사 | 형제 모듈을 **모른다** → `module/` |

⟹ **`planner/module/planTrunks.ts`**

> **`linkPlanner` 와 나란히 있지만 계약이 다르다.** 그 파일 머리말은 *"좌표를 모른다"* 인데,
> 이쪽은 **좌표를 안다** — 머신이 놓인 뒤에 돌기 때문이다(부모 §7). 같은 폴더에 계약이
> 다른 두 파일이 있는 것이므로 **각자 머리말에 그 계약을 적는다.**

## 2. 자료형 — 트렁크 하나

```ts
/** 트렁크 하나 — 부모 §6 의 (경로 P, 좌석 S, 끝점) 을 좌표로 편 것. */
export interface TrunkPlan {
  item: string;
  role: "input" | "output";
  /** 이 트렁크가 맡은 머신 index → 팔 수. `size === 1` 이면 그게 다이렉트다(부모 §마). */
  arms: Map<number, number>;
  /** 벨트가 지날 타일 — **포트에서 먼 끝까지 순서대로.** 흐름 방향이 이 순서에서 나온다. */
  path: { x: number; y: number }[];
  /** `path[i] → path[i+1]` 이 지상인지 점프인지. 길이 = `path.length - 1`. */
  edges: RouteEdge[];
  /** 이 트렁크가 판 지하 쌍 — 다음 트렁크의 `isJumpAllowed` 입력이 된다. */
  corridors: UndergroundCorridor[];
  /** 좌석 — 머신마다 팔 수만큼. 각 좌석은 `path` 의 어떤 타일에 닿는다. */
  seats: { machine: number; cells: { x: number; y: number }[] }[];
  /** 포트가 설 자리 = `path` 의 한쪽 끝 바깥. */
  port: { x: number; y: number };
}
```

**`path` + `edges` 는 `DijkstraResult` 와 같은 모양이다** — 그래서 방출이
`emitPath.emitItemPath` 를 그대로 쓸 수 있다(§6).

## 3. 알고리즘 — 줄 하나를 트렁크로

```
① 머신 순서를 정한다                    기둥이면 위→아래 하나뿐
② 머신마다 탭 주행을 구성한다             좌석 k개 + 그에 닿는 벨트 타일 k개. **지상**
③ 포트 자리를 정한다                    경로의 한쪽 끝
④ 구간마다 dijkstraWithJumps 를 부른다   포트→M1 · M1끝→M2 · M2끝→M3 …
⑤ 이전 셀을 다음 호출의 blocked 에       자기 교차 원천 차단
⑥ 실패하면 거기서 끊고 쪼갠다            나머지는 새 트렁크 (부모 §마)
```

### ②가 왜 탐색이 아닌가 — **구성으로 나온다**

머신 `m` 이 면 `f` 에서 팔 `k` 개를 쓰면:

```
좌석 깊이 = 벨트깊이 − reach        (emitModule.tapSeatDepth 와 같은 식)
좌석 타일 = faceCell(m, f, 좌석깊이, t)   t = 연속 k 칸
벨트 타일 = faceCell(m, f, 벨트깊이, t)   같은 t
```

**고를 것은 `면 f` 와 `시작 행 t₀` 둘뿐이고, 나머지는 산술이다.**

### ⑤가 자기 교차를 어떻게 막나

`dijkstraWithJumps` 는 `blocked` 를 통과 못 한다. 그러니 **이미 놓인 자기 셀을 전부
`blocked` 에 넣으면** 다음 구간이 자기를 못 밟는다 — 벨트가 한 줄이라는 성질이 공짜로 나온다.

---

## 4. `dijkstraWithJumps` 에 무엇을 넘기나

| 인자 | 트렁크가 넘길 값 | 근거 |
|---|---|---|
| `starts` | 이전 탭 주행의 **끝 타일** | |
| `ends` | 다음 머신이 닿을 수 있는 **벨트 타일 전부** — 어디로 붙을지는 **탐색이 고른다** | 다중 싱크가 이미 있다 |
| `blocked` | 머신 + 오늘까지 놓인 셀 + **자기 앞 구간**(§3-⑤) | |
| `corridors` | 이 모듈에서 앞서 판 지하 쌍 | [1-지하벨트](../1-지하벨트/) 요구 2 |
| `blockGroup` | **벨트 프로토타입** | 요구 5 — 티어가 다르면 독립 |
| `maxJumpDistance` | 지하벨트 `max_underground_distance` | |
| `jumpCostModel` | **`'length'` 고정** | 부모 §9.2 — 막혔을 때만 지하 |
| `bounds` | 모듈 bbox + **넉넉한 마진** | 부모 §9.2 — 탐색 종료용이지 설계 의도가 아니다 |
| `turnPenalty` | **0**(자리만 만든다) | 부모 §9.4 — 최적화는 나중 |
| `beltFlow` | ⚠️ **미정** — §8 |

## 5. 단계 — 다섯

각 단계에 **전제 · 불변 · 관문**을 적는다(`tempPlanDocs/CLAUDE.md`).
**뒤 단계는 확정이 아니라 방향이고, 앞 단계를 끝낼 때 전제를 다시 확인한다.**

### S1 — 탭 주행 구성 (순수 함수) · **확정**

- **무엇:** `(머신, 면, 팔 수) → { 좌석 타일[], 벨트 타일[] }`
- **전제:** 좌석 깊이 = 벨트깊이 − reach (`emitModule.tapSeatDepth` 로 확인)
- **불변:** 이 함수는 **아무도 안 부른다** — 테스트만. 배치가 안 바뀐다
- **관문:** ②가 탐색이 아님을 코드로 못 박는다

### S2 — 구간 사슬 (순수 함수) · **확정**

- **무엇:** `planTrunks(...)` — ①③④⑤ 를 엮어 `TrunkPlan[]` 을 낸다
- **전제:** `dijkstraWithJumps` 가 다중 싱크를 받는다(확인함: `ends: DijkstraEndpoint[]`)
- **불변:** 여전히 **호출자 0** — 테스트만
- **관문:** *"N개 머신 곁을 지나는 한 줄"* 이 실제로 나오는가

### S3 — 쪼개기 · **확정**

- **무엇:** 구간 실패 → 거기서 끊고 나머지를 새 `TrunkPlan` 으로
- **전제:** 실패가 `null` 로 온다(`dijkstraWithJumps` 반환형이 `DijkstraResult | null`)
- **불변:** 호출자 0
- **관문:** 부모 §마 — **극한이 다이렉트**임을 테스트가 단언한다(`arms.size === 1`)

### S4 — 방출 · **방향**

- **무엇:** `TrunkPlan` → 셀. `emitItemPath` 재사용 + 좌석 인서터 + 포트 상자
- **미정:** 좌석 인서터의 방향·프로토타입을 무엇이 정하나 — 벨트 깊이와 짝이다
- **불변:** 여전히 호출자 0

### S5 — 배선 · **방향** — **여기서 배치가 바뀐다**

- **무엇:** `generateModule` 이 기계별 포트 경로 대신 `planTrunks` 를 탄다
- **합격선:** **부모 §0** — 같은 품목을 다 앉히면서(미배치 증가 0) **포트 수가 줄어야 한다**
- **신호:** 실경로 테스트(`moduleInspect`·`modulePacking.realTree`·`layoutIssue`·
  `layeredWizard.recipeOverrides`). **합성 픽스처는 신호가 아니다**(부모 §10, 함정 4)

---

## 6. 방출은 있는 것을 쓴다

```
TrunkPlan.path/edges  ─(모양이 같다)─▶  emitPath.emitItemPath(result, pair, options, out)
                                          → { placed, corridors }
```

`emitItemPath` 가 이미 **점프 간선 → 지하 입·출구 셀** 로 바꾸고 corridor 도 낸다
([1-지하벨트](../1-지하벨트/) §1). **좌석 인서터와 포트 상자만 따로 놓으면 된다.**

## 7. 하지 않는 것

| | 왜 |
|---|---|
| **머신 배치 변경** | 부모 §9-가 — 다이렉트 전용 배치를 그대로 쓴다. 격자는 [2-격자배치](../2-격자배치/) |
| **`containerRouting` 수정** | 재사용한다. 고쳐야 할 것이 나오면 그게 (B) 재검토 신호다(부모 §9.6) |
| **최적화** | `turnPenalty`·모듈 밖 가산은 **자리만** 만든다(부모 §9.4) |
| **내부 링크** | 외부 줄부터(부모 §8) |
| **유체** | 파이프는 성질이 다르다 |

## 8. 미정 — 착수하며 정할 것

| # | 무엇 | 왜 지금 못 정하나 |
|---|---|---|
| **가** | **탭 면(W/E)을 누가 고르나** | 오늘은 역할이 정한다(출력 W·입력 E). 트렁크가 여럿이면 다퉈야 하는데, 그 다툼의 모양은 S2 를 만들어 봐야 보인다 |
| **나** | **포트 자리** | 경로의 어느 끝인가, 그리고 모듈 경계의 어디인가. `lineEnds`(부모↔자식 포트 정렬)를 봐야 한다 |
| **다** | **`beltFlow` 를 넘기나** | *"흐름 방향으로 인접해 합류하는 배치를 거부"* 하는 인자다. 트렁크끼리 의도치 않게 합류하는 것을 막아 줄 수도 있고, 과하게 막을 수도 있다 |
| **라** | **`bounds` 마진의 초기값** | 부모 §9.3 의 손잡이. 값은 실측 후 |

**가·나는 S2 착수 전에 답이 나와야 한다.** 다·라는 S2 를 돌려 보고 정한다.
