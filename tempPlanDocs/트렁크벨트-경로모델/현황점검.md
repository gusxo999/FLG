> **작성일:** 2026-08-12 · **갱신:** 2026-08-13 · **상태:** §1~§4(코드의 사실)만 유효
> **이 문서는 오늘 코드의 사실만 담는다** — 무엇이 있고(§1·§2) 무엇이 안 되나(§3·§4).
> **목표와 단계는** [계획서](트렁크벨트-경로모델.md) 가 단일 출처다.

## 1. 구성 — 트렁크 벨트에 관여하는 코드 전부

```
판정   insertingPlanner              탭으로 합칠 수 있나 (tap | direct)
배정   planClusterPorts              면 · clusterBeltDepth · reach · 벨트 티어
준비   buildTrunkContext             ext · pipeJumpMode · maxDepthAtEnd(stagger)
방출   emitTapInserting              트렁크 벨트 + 탭 인서터 + 포트(기둥 끝)
유체   emitTrunkPipe                 트렁크 파이프 + 지하 점프  (나란한 유체판)
────────────────────────────────────────────────────────────────────
대안   allocateLinkFaces             면 · 좌석 순번            ← 병합 없음
       emitOutputLinks/InputLinks    머신마다 벨트 + 포트
```

**두 경로가 나란히 있고 `supply.mode` 가 통째로 가릅니다.** 그것이 아래 결함 대부분의 뿌리입니다.

## 2. 지금 할 수 있는 것 (정직한 회계)

| | 내용 |
|---|---|
| ✓ | 한 면에 트렁크 **2줄**(= 고른 인서터의 서로 다른 reach 개수) |
| ✓ | 전 머신을 한 벨트로 — `untapped` 가 구성상 발생 불가(직선이 모든 머신 행에 접함) |
| ✓ | 수요가 벨트 한 줄을 넘으면 **줄 수를 늘림**(`determineBeltCount`) + 벨트 티어 선택 |
| ✓ | 머신 한 대에 팔 여러 개(`Parallel Inserting`) · 팔을 배정들에 채워서 분할 |
| ✓ | 유체 트렁크 파이프 + `pipeJumpToClusterPipe` · 케이스 B |
| ✓ | 포트 끝 정렬(`lineEnds`) — 부모↔자식을 마주 보게 해 교차를 줄임 |
| ✓ | 같은 면 두 레인의 `stagger` — 바깥 레인이 안쪽 상자를 막는 사고 방지 |

**트렁크 자체는 동작합니다.** 문제는 *"되거나 안 되거나"* 라는 것입니다.

## 3. 지금 못 하는 것 — 다섯 갈래 19항목

### (A) 병합 — *합치는 능력 자체*

| # | 결함 | 근거 |
|---|---|---|
| **A1** | **부분 병합 불가** — 5대 중 3대만 트렁크가 안 된다 | `arms.size !== 1` 문지기 + `emitOutputLinks` 의 좌석 행 **연속성 가정** |
| **A2** | **폴백이 "안 합침"이 아니다** — 모듈 전체가 다른 모델로 갈아탄다 | `supply.mode` 가 배분기·방출기를 통째로 가른다. §2-② 안전망이 실제로는 없다 |
| **A3** | **병합 정도를 고를 수 없다** | 축 자체가 구조에 없다 |
| **A4** | **내부 링크는 병합 대상이 아니다** — `edgeLinkGroups` 가 1:1 로만 낸다 | v1 결정. 사유는 *"부모 머신 인접 요구"* — D1 이 그 제약을 다루므로 **더 이상 하드 블로커가 아니다** |
| **A5** | **채널을 건너는 벨트의 합류·분기가 없다** — 자식 3개가 한 부모를 먹이면 채널에 3줄 | `machine-link.md` 가 *"되살릴 때는 채널 층에서"* 로 미뤄 둔 것 |

### (B) 기하 — *트렁크의 모양*

| # | 결함 | 근거 |
|---|---|---|
| **B1** | **트렁크가 기둥 전체를 달린다** — 2대만 탭해도 5대를 다 지난다 | `lo = min(t0,…), hi = max(t1,…)` 가 span 이 아니라 **클러스터 extent** |
| **B2** | **방출기가 둘, 포트 기하가 다르다** — 깊이로 vs 길이로. 부분 병합은 어느 쪽도 안 맞는다 | 포트 3칸이 span 밖에 있어야 한다는 제약에서 **셋째 형태**가 유도된다 |
| **B3** | **면당 트렁크 상한 = reach 종류 수** — 트렁크가 그 면의 한 깊이를 **독점**한다 | 벨트가 연속이라 span 전체를 덮는다 → 다른 품목은 더 깊이 → 팔이 안 닿는다 |
| **B4** | **밀려난 줄이 gap 으로 → 모듈이 세로로 벌어진다** | B3 의 결과(`gapRowsFromPlans`) |
| **B5** | **형태가 ColumnCluster 고정** | `layoutCluster` 의 `dx: 0`, 그리고 **방출기가 그 전제에 의존**(`ext` 로 W/E 기하 계산) |
| **B6** | **유체 면은 reach≥2 전용** — 긴팔이 없으면 그 면 레인이 **0** | 케이스 B. 유체 레시피는 아이템 줄이 둘만 돼도 `lanes-exceed-capacity` |
| **B7** | **면이 마주 보면 좌석 장부가 못 막는다** | 기둥에서는 W/E 가 **절대 안 마주 본다**(세로로만 쌓이므로). 마주 보는 N/S 는 `gapRowsFromPlans` 가 다룬다. `dx` 를 풀면 머신 A의 E면과 B의 W면이 마주 보는데, `seatKey(머신, 면)` 장부는 **머신마다 독립**이라 두 머신이 같은 칸을 각자 배정한다. **G3 의 실질은 "gap 개념을 N/S 전용에서 4방향으로 일반화"하는 것** |

### (C) 계획·방출 경계 — *같은 사실을 두 곳이 센다*

> `module-planning.md` §5 "확정 시점" 절이 아홉 축을 세어 뒀다. **탭은 다섯만 답하고 넷을 방출기가 다시 유도한다.**

| # | 결함 | 대가 |
|---|---|---|
| **C1** | `emitTapInserting.slotOnFace` — 면 위 순번을 **방출 시점에 누적** | 같은 수를 두 곳이 센다. 그래서 `emitModule:523` 에 *"planner 용량과 어긋난 것(안전망)"* 이 있다 |
| **C2** | `buildTrunkContext.emitDepthOf` — 계획이 자기 깊이의 **최종값을 모른다** | `pipeJumpMode` 가 좌표 단계에 있다 |
| **C3** | `maxDepthAtEnd`(stagger) — 배정이 stagger 를 **예측 못 한다** | 같은 면·같은 끝을 전부 훑어야 나온다 |
| **C4** | `skipRows` — 유체 행 회피 산술이 `commitLinkFace` 와 **두 벌** | 한쪽만 바뀌면 조용히 어긋난다 |

### (D) 자원 — *숫자가 새는 곳*

| # | 결함 | 근거 |
|---|---|---|
| **D1** | **링크 벨트가 벨트 티어를 무시한다** — `input.beltEntityName` 고정 | `emitModule:244·414` 주석이 *"티어는 후속"*. `determineBeltCount` 가 고른 티어가 **기계별 포트 경로로 안 간다** |

## 4. 의존 관계 — 무엇이 무엇을 막고 있나

```
        E1 관측                 (독립. 언제든 가능)
          │
        A1 부분 병합 ◀── B1 span ◀── B2 포트 기하
          │                              ▲
          ├──▶ A2 진짜 폴백              │ (포트가 span 밖이어야 한다는 제약)
          ├──▶ A3 선택 가능 ◀── E2 관측 창
          └──▶ A4 내부 링크 병합 ──▶ A5 채널 합류·분기

        C1~C4 경계          (A1 을 하면 자연히 줄어든다 — 방출기가 하나가 되므로)
        D1 D2               (독립. 작고 값이 확실)
        B3 깊이 독점 ──▶ B4 gap ◀── B5 형태 고정
              ▲
              └── 근치는 B5 를 푸는 것뿐 (GridCluster · ParallelBelt)
```

**읽는 법 세 가지:**

1. **A1 이 허브다** — 부분 병합이 되면 A2·A3 가 따라오고, 방출기가 하나가 되며 C1~C4 가 줄어든다.
2. **B3·B4 는 A1 로 안 풀린다** — 완화만 된다(부분 병합이면 깊이를 덜 쓴다). 근치는 **B5(형태)** 다.
3. **D1·E1 은 아무것에도 안 걸려 있다** — 작고, 값이 확실하고, 지금 할 수 있다.

### 여기서 유도된 것 — 포트 기하는 **선택이 아니다**

```
① 포트 상자는 벨트 셀 위에 놓을 수 없다              (occupancy)
② 트렁크 벨트는 탭하는 머신들 사이가 연속이어야 한다   (#3 — 끊기면 물건이 못 감)
   ⇒ 포트는 트렁크 span **밖의 행**에 있어야 한다
③ span 밖 행에서는 깊이 방향이든 길이 방향이든 상관없다
   ⇒ `emitTapInserting` 이 "기둥 끝"으로 가는 것은 **span = 기둥 전체일 때의 특수해**(#6)
   ⇒ 부분 병합이면 "span 바로 다음 행"이 그 자리다
```

**결론이 하나뿐이라 고를 것이 없다.** 두 방출기(#5 깊이로 · #6 길이로)는 두 후보가 아니라 **각자 자기 상황의 특수해**이고, 부분 병합은 제3의 상황이다.
