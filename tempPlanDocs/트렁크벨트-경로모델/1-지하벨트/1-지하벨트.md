# 지하벨트 — 트렁크가 지하를 계획할 수 있게

> **작성일:** 2026-08-13 · **상태:** 조사 완료 · **착수 가능**(부모 §9 확정)
> **부모:** [트렁크벨트-경로모델](../트렁크벨트-경로모델.md) — 문제 정의는 §1~§8, **결정 다섯은 §9**

## 0. 조사 결과 한 줄

> **지하벨트의 기하·규칙·방향 제약은 **전부 이미 구현돼 있다.**
> 없는 것은 하나뿐 — **모듈 안쪽 트렁크 계획이 그것을 부를 자리.**

설계할 것이 거의 없고 **배선할 것**이 있다. 규모가 처음 예상보다 훨씬 작다.

---

## 1. 이미 있는 것 — 전수 (2026-08-13 코드 확인)

| 무엇 | 어디 | 내용 |
|---|---|---|
| **간섭 규칙** | `planner/containerRouting.isJumpAllowed` | 같은 `blockGroup` ∧ 같은 `axis` ∧ 같은 `line` → 구간이 **strict disjoint** 여야 한다. 축이나 line 이 다르면 **검사 자체를 건너뛴다** |
| **자료형** | `containerModel.UndergroundCorridor` | `{ axis, line, range, blockGroup, kind }`. `Area.undergroundCorridors` 에 누적된다 |
| **티어 독립** | 같은 자료형 주석 | 벨트는 **프로토타입이 곧 그룹** → 다른 티어는 완전 독립. (파이프는 반대 — 전부 한 그룹) |
| **입구 방향 제약** | `containerRouting` 의 `entrance-straight` | Dijkstra 상태가 `(x, y, **arr**)` — **도착 방향까지** 상태다. 점프는 도착 방향과 **같은 방향만** → **입구 칸에서 꺾는 경로가 생성되지 않는다** |
| **머신에 닿는 입·출구** | `startJump` / `endJump` | 표면 면이 **머신을 향하도록** 방향을 강제 |
| **방출** | `execution/emitPath.emitItemPath` | `edges[i]` 가 점프면 `cells[i]` = INPUT, `edges[i-1]` 이 점프면 OUTPUT. `direction` = 점프 진행 방향. corridor 도 함께 낸다 |
| **비용 모델** | `jumpCostModel: 'flat' \| 'length'` | `flat`=2(긴 직선이면 지상보다 싸다) · `length`=k+1(막혔을 때만 점프) |
| **유체판 선례** | `docs/auto-layout/channel/fluid-underground-crossing.md` | 같은 일을 유체로 하려던 **설계 계획서(미구현)**. 결론이 그대로 우리 것이다 — *"페어링 모델 설계가 아니다. **있는 규칙을 장부에서도 부르기**다"* |

## 2. 없는 것 — 하나

```
containerRouting (탐색기)   지하 = **후보**. 규칙·자료형·방향 제약이 전부 여기 있다
channelGeometryPlanner      지하 = **사후**. 지상 실패 후에만. 그리고 몸통을 지하로 숨기는 것은 금지
모듈 안쪽(트렁크)            **없음**
```

> 트렁크는 **모듈 안쪽에서** 자리를 잡는데, 그 층에는 지하를 계획할 수단이 없다.

`channelGeometryPlanner` 가 몸통 숨기기를 금지한 이유가 그 자리에 적혀 있다 —
*"트랙은 지상 전용이다. 몸통이 지하로 숨으면 **다른 경로가 그 위를 지나가도 되는지 알 수 없다**."*
**표현이 없어서 금지한 것**이지 기하가 금지한 것이 아니다.

---

## 3. 정정 — 지하가 트렁크에 사주는 것은 **교차뿐**이다

처음에 지하를 *"자유도를 크게 늘린다"* 로 적었는데 **틀렸다.**

> **지하 구간 위에서는 인서터가 머신을 못 먹인다.** 몸통은 땅속이고 인서터는 지상 엔티티만 집는다.

| | 지하가 해주나 |
|---|---|
| 트렁크가 **더 많은 머신**을 먹인다 | ❌ 탭하려면 그 구간은 반드시 지상 |
| 트렁크가 남을 **건넌다** / 남이 트렁크를 **건넌다** | ✅ |

**그래서 부모 §3 정리(밀착 기둥 → 통로 독점이 유일해)는 지하로 안 깨진다.**
지하가 바꾸는 것은 그 독점의 **배타성**뿐이다.

```
독점을 깨는 것          →  2-격자배치
독점을 남이 건너게 하는 것 →  여기(1-지하벨트)
```

**그래도 지하가 먼저인 이유:** 격자로 통로가 늘어도 트렁크끼리 교차는 **반드시** 생기고,
그때 지하가 없으면 다시 막힌다. **지하는 격자의 전제다.**

## 4. 지하가 경로 모델에 거는 요구 — 다섯

부모 §9-나가 **(A′) 구간 사슬**로 확정됐으므로(D10), 아래는 *"그 뼈대가 지켜야 할 것"* 이다.
**이 폴더는 독립 계획이 아니라 (A′)에 얹히는 인자 목록이다.**

| # | 요구 | 안 지키면 |
|---|---|---|
| **1** | 경로 상태에 **도착 방향**이 있어야 한다 | 입구 칸에서 꺾는 경로가 나온다(`entrance-straight` 가 막던 것) |
| **2** | `UndergroundCorridor` 목록을 들고 다니며 `isJumpAllowed` 를 부른다 | 같은 축·같은 티어 쌍이 서로 짝을 가로챈다 |
| **3** | 점프 **비용 모델**은 `'length'` — 막혔을 때만(부모 §9.2) | `flat` 이면 안 막혀도 지하로 가서 **한정 자원**(축·티어 배타권)을 헛되이 쓴다 |
| **4** | **탭 지점은 반드시 지상** — 지하 구간과 좌석이 겹치면 안 된다 | 그 머신이 조용히 굶는다 |
| **5** | `blockGroup` = 벨트 프로토타입 | 티어를 여럿 고르면 **지하 자유도가 그만큼 는다** — 골라 쓸 수 있어야 한다 |

**4번이 트렁크 고유다.** 납품 경로에는 없던 제약이다 — 납품은 끝점만 중요하고 중간은
아무래도 좋지만, **트렁크는 중간이 곧 일하는 자리**다.

## 5. 선택지 — 경로를 무엇이 찾나 (부모 §9-나)

| | 무엇 | 지하 요구 1~5 | 문제 |
|---|---|---|---|
| **(A)** | `containerRouting` **재사용** | 1·2·3 **공짜** | 그건 *"한 쌍의 끝점을 잇는"* 탐색기다. 트렁크는 **N개 머신 곁을 지나야** 해서 경유지 문제라 그대로는 안 맞는다 |
| **(B)** | 트렁크 전용 탐색기 + **규칙만 재사용**(`isJumpAllowed`) | 1·3·4 를 새로 써야 한다 | 방향 상태와 비용 모델을 **두 번째로** 쓰게 된다(R3 위험) |
| **(C)** | 채널 장부 방식 — 구간 서술 + 사후 점프 | 몸통 숨기기를 못 한다(§2) | 부모 §5 가 폐기한 **직선 전제**로 되돌아간다 |

**(A′)로 확정됐다**(부모 §9-나 · D10). 그러니 이 폴더가 할 일은 **(A′)의 연결 구간이
`containerRouting` 을 부를 때 위 요구 1~5 를 지키게 배선하는 것**뿐이다 —
1·2·3·5 는 그 함수 안에 이미 있고, **4(탭 지점은 지상)는 구간 사슬이 구조적으로 준다**
(탭 주행은 탐색이 아니라 구성이므로 — 부모 §6).

---

## 6. 착수 조건

**충족됐다** — 부모 §9 가 (A′)로 확정(2026-08-13).

남은 선행은 하나: **구간 사슬의 뼈대**(머신 순서 · 탭 주행 구성 · 구간 호출)가 있어야
그 안에 지하가 얹힌다. 지하는 **그 뼈대의 인자**이지 별도 단계가 아니다.

## 7. 검증 (착수 시)

```powershell
npx tsc -p tsconfig.app.json --noEmit   # 반드시 -p
npx vitest run                          # 기준선: 45파일 537테스트
```

**합격선은 부모 §0 이다** — 같은 품목을 다 앉히면서 포트 수가 줄어야 한다.
*"산출물이 안 바뀐다"* 는 합격선이 아니다(부모 §10).

## 8. 하지 않는 것

| | 왜 |
|---|---|
| **지하파이프** | 유체는 합류가 공짜라 성질이 다르다. `emitTrunkPipe` 는 안 건드린다 |
| **`containerRouting` 수정** | 거긴 이미 지하를 후보로 다룬다. 재사용하거나 규칙만 빌린다 |
| **채널 층(모듈 사이)** | `fluid-underground-crossing.md` 가 그쪽 계획이다. 여기서 만든 것이 그쪽에도 쓰이면 좋지만 그건 별건 |
