>

```
0-레인예약/    설계 중.  계획서 §14 가 기하를 확정했고 **미결 J1~J4 가 남아 있다**

2-격자배치/    미착수.     0 의 **입력**(머신 좌표)을 바꾼다 — 독점 자체를 깬다
```

**셋은 배타적이지 않고 의존이 있다:**

```
0 이 뼈대다.  1 은 0 의 세로 레인이 잠수하는 자리로 얹힌다(계획서 §14-4 — 방향이 뒤집혔다).
2 는 0 의 입력(머신 좌표)을 바꾼다 — 뼈대는 그대로지만 §14-1~3 은 다시 세워야 한다.
```

격자로 통로가 늘어도 트렁크끼리 교차는 반드시 생기므로 **지하가 격자의 전제**다.
(옛 (ㄴ) *"머신 간격"* 은 폐기 — 격자 구현 시 자연히 따라온다.)

## 하지 않는 것

- **부모 폴더에서의 코드 변경** — 착수는 세부 폴더(`1-지하벨트/`)에서 한다.
- **유체 트렁크 파이프** — 합류가 공짜라 병합 판정 자체가 없다. `emitTrunkPipe` 는 안 건드린다.
- **채널 층 재설계** — 모듈 안쪽만. 단 §7 에서 **경로 주체가 둘이 되지 않는지**는 확인한다.
- **내부 링크 구현** — 타입은 열어 두되(계획서 §8) 구현은 외부 줄부터.
- **`manualEdit/`** — 호출자 0, 타입검사·테스트 제외 구역.

## 함정 (밟기 쉬운 것)

**★★★ 깊이(`d2`·`d3`)는 축이 아니라 결과다**(계획서 §16, 2026-08-15 사용자).
축은 **`(인서터, 그 팔이 집는 타일)`** 이다 — `reach` 가 고정 거리라 인서터를 고르면 벨트 칸이
따라온다. 반대가 아니다. 깊이를 **입력**으로 두는 순간 `if (depth === 3)` 이 생기고 §0.1 을 깬다.
*"인서터를 제대로 배치할 수만 있으면 된다."*

**★★ 계획서의 R·D 를 코드 분기로 옮기지 않는다** (2026-08-15 사용자 — 계획서 §0.1).
**목적은 하나: 모든 머신이 100% 가동한다.** 트렁크·부분·다이렉트·fan-out·gap·N/S 는 전부
그 목적에서 **유도되는 형태**이고, R1~R14 는 그 유도를 검산하며 관측한 성질일 뿐이다.
`if (트렁크) … else if (fan-out) …` 이 생기면 그 순간 이 모델을 배신한 것이다.
★(구현의 *어떻게* 를 의도로 착각하지 않는다)를 **이 계획서 자신에게도 적용한다.**


**★ 기존 구현의 "어떻게"를 의도로 착각하지 않는다.** — 2026-08-13 롤백의 원인이다.
*"의도만 파악하라"* 는 지시를 받고 깊이 레인·면당 상한·stagger 를 적었는데, 그 셋은
**직선으로 하기로 했을 때 따라온 것**이지 트렁크의 의도가 아니었다. 의도는
*"다이렉트 벨트 여럿을 한 줄로 합친다"* 하나뿐이다.

1. **모델 없이 검증을 늘리지 않는다.** 잴 것이 남의 모델뿐이면 계측이 아무 말도 안 한다.
2. **"산출물이 안 바뀐다"를 합격선으로 쓰지 않는다** — 기준선(오늘의 트렁크)이 미완성이라
   그 비교는 아무것도 증명하지 않는다(2026-08-12 사용자 지시).
3. **테스트 통과 = 그 분기가 돌았다가 아니다.** 2026-08-02 에 448개가 전부 통과하는데 바꾼
   분기는 한 번도 안 지나는 상황이 실제로 있었다.
4. **픽스처는 실경로를 대표하지 않는다.** 합성 `NodeSpec` 은 `supplyCapacity` 를 안 채우는데
   실경로는 채운다 — 그 차이가 배치를 통째로 갈랐다. **실경로 테스트**
   (`moduleInspect`·`modulePacking.realTree`·`layoutIssue`·`layeredWizard.recipeOverrides`)가
   신호다.
5. **`npx tsc` 는 `-p tsconfig.app.json` 없이 쓰면 0개 검사하고 조용히 성공**한다.

## 이 주제에서 실제로 밟은 함정

**전부 "확인 대신 추론"이고, 추론의 재료가 문서·타입·오류 메시지였다.**

| 틀린 진술 | 실제 |
|---|---|
| *"`dx: 0` 때문에 기둥으로 선다"* | 값이 아니라 **방출기가 그 값에 의존**한다 |
| *"`arms.size !== 1` 한 줄이 병합을 막는다"* | 방출기는 다중 머신을 지원한다. **막는 건 벨트 루프의 연속성 가정** |
| *"내부 링크는 병합 대상이 아니다"* | 대상이 아닌 게 아니라 **합의할 주체가 둘**이다(계획서 §8) |
| *"포트 기하를 (가)/(나) 중 무엇으로?"* | 양자택일이 아니었다 — **둘 다 직선의 특수해** |
| *"기둥에서 트렁크를 온전하게"* | **목표가 아니라 형용사다.** 결함으로 환원되지 않으면 목표가 아니다 |
| *"필드가 있으니 값도 온다"* | `SupplyCapacity.beltCapacity` 를 실경로는 **일부러 안 채운다**. 그 필드만 보다가 병합이 실배치에서 0건이었는데 **테스트는 전부 초록**이었다 |
| *"원인은 포트가 서는 **자리**다"* | 오류 메시지만 보고 단정했다. 재 보니 **포트 개수**였다 — 10줄 프로브가 2분 만에 뒤집었다 |
| *"탭의 기하가 트렁크의 의도다"* | ★ 위. **롤백의 원인** |
| *"stagger 는 직선일 때 따라온 우연이다"* | **진출-교차 회계의 결과**다(계획서 R3). 형태가 바뀌어도 남는다. ★ 를 적용하다 **반대쪽으로 지나쳤다** — 옛 구현의 어떤 것은 진짜 필연이다 |
| *"트렁크는 레인(깊이)을 통째로 독점한다"* | **아니다 — 자원은 레인이 아니라 `레인 × 행`이고 트렁크는 그중 `구간`을 산다.** 사용자 실물 배치에서 레인 2개 위에 트렁크 4개가 앉아 있었다. 이 착각 하나가 §14 전체를 잘못 세우게 했다(2026-08-14) |
| *"stagger 는 모듈을 키운다(계단)"* | **머신 안 여유 행 `h − a` 가 흡수한다.** 쪼갠 구간 사이의 **구멍**이 진출 통로다 — 모듈이 안 커진다 |
| *"쪼개기가 통로를 만들어 주니 좋다"* | **거꾸로다.** 사용자: *"운반량이 허락했다면 합쳐도 좋다"*(R1). 통로는 **깊이 순서**(R2)가 만든다 |
| *"진출은 가로 벨트로 깐다"* | **포트 인서터가 흡수한다**(R6). 배치1(벨트 3칸) → 배치2(0~1칸)에서 모듈 폭 13→10 |
| *"구간 적은 줄을 얕은 레인에 둔다"*(옛 R2) | **폐기.** 진출 수단을 *지상 전달 타일 하나*로 가정해서 생긴 회피책이었다. R7 이 수단을 둘 주면 사라진다. 게다가 처리량 논리와 **정반대**다(§14-9) |
| *"실물 트리에서 몇 건인지 세고 정하자"* | **D3 을 스스로 어긴 것이다** — *"실측 기반 트리거를 쓰지 않는다. 규칙으로 자른다."* 분포는 무엇이 흔한지만 말하고, **모드팩이 바뀌면 분포도 바뀐다.** 트리거는 **입력의 성질**로 적는다(2026-08-14 사용자) |
| **★ 좌석 예산을 면마다 센다** | **모듈 전체 `2h` 다.** 선호 면이 차면 반대 면으로 분산한다(R5·R8). **2026-08-13 에 이미 한 번 틀렸고 2026-08-14 에 또 틀렸다** — 그때는 *"입력은 E를 선호하니 E에만 앉는다"* 로 세다가 4줄 레시피에서 포트가 8개가 됐다. **같은 자리를 두 번 밟았으니 세 번째를 조심한다** |
| *"포트 인서터를 긴 팔로 써서 레인을 건너뛴다"* | **절대 금지**(2026-08-14 사용자). 내가 만든 기하이고 `배치1`·`배치2` 에는 없다. 진출은 **지상 전달 타일**뿐이고(R6), 막히면 R7(잠수/끊기)로 푼다 |
| *"지하는 아껴야 할 한정 자원이다"* | **모듈 안쪽에서는 아니다**(§14-10). 레인은 그 트렁크가 이미 독점하므로 같은 `line` 위 corridor 는 다툴 상대가 없다. **§9.2 의 문장을 층을 확인 않고 옮겨 왔다** |
| *"건너는 쪽이 지하로 들어간다"* | **건너지는 쪽(세로 트렁크)이 들어간다.** `entrance-straight`(`containerRouting.ts:351`)가 코너 점프를 막는다 — 도착 방향과 같은 방향으로만 점프한다(계획서 §14-4) |
| *"`columnTapCapacity` 의 주석이 곧 이유다"* | **수는 맞고 이유가 좁다.** 좌석이 `d2` 인 `(s=2,r=2) → belt d4` 배열도 성립한다. `R` 은 유일하지만 **깊이 배열은 유일하지 않다**(judgements J1 부수 발견) |
