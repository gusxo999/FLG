# 트렁크 벨트 — 아직 안 고른 것

> **미결 3** (2026-08-17 갱신). 계획서 **§14** 가 현재 모델이고, 이 문서는 그 모델이
> **아직 답하지 못하는 자리**다.
>
> **트리거를 전부 다시 썼다.** 이전 판은 *"실물 트리에서 N건 이상 관측되면 착수"* 로 적혀
> 있었는데 그건 **D3(실측 기반 트리거를 쓰지 않는다 — 규칙으로 자른다)를 스스로 어긴 것**이다.
> 분포는 무엇이 흔한지를 말할 뿐 무엇이 옳은지를 말하지 않고, **모드팩이 바뀌면 분포도 바뀐다.**
> 트리거는 이제 전부 **입력의 성질**(어떤 값이 들어오면)로 적는다.

**공통 전제 (2026-08-15 기준, 부패하면 둘 다 무효):**

| 전제 | 확인 방법 |
|---|---|
| 클러스터는 **세로 기둥**이다 (`positions.push({ dx: 0, dy })`) | `module/clusterLayout.ts:59`. 격자([2-격자배치](2-격자배치/))가 들어오면 §14 를 다시 세워야 한다 |
| 좌석·벨트·전달 타일이 **같은 장부**를 쓴다(레인 = 자유 타일 한 줄) | D10 |
| 유체 파이프 자리는 **트렁크보다 먼저** 차감된다 | 모듈 안의 저자가 트렁크 하나뿐이라는 전제 |
| 포트의 **면**은 밖에서 주어진다 | R5 |
| 깊이 배정은 **처리 가능성으로만** 정한다 | R2. 옛 R2(구간 수 순서)는 §14-9 에서 폐기 |

## J1 — `L_f = |ℛ|` 을 일반 `ℛ` 에 대해 증명하지 않았다

**무엇이 미결인가.** §14-1 은 면당 동시 벨트 레인 수를 `R = |ℛ|` 로 놓는다.
`R = 1, 2, 3` 은 `(s, r)` 짝을 **손으로 열거**해 확인했지만 임의 `ℛ` 에 대한 증명이 없다.
느슨한 상한(`k ≤ 2R − 1`)만 나와 있어 `R=2` 에서 3 — 열거로 얻은 2 보다 헐겁다.

**착수 조건 — 입력의 성질**

```
서로 다른 reach 가 4종 이상인 인서터 집합이 입력으로 들어올 수 있게 되면 착수.
그전까지는 **열거표가 곧 증명**이다(1·2·3 을 다 셌다).
```

**코드 역참조 — 아직 안 달았다.** 달 자리는 `module/clusterLayout.ts:90`(`columnTapCapacity`).
부모 폴더 정책상 **코드 변경 0** 을 지키느라 보류했고, 착수하는 단계에서 단다.

> **부수 발견 (미결이 아니라 사실):** `columnTapCapacity` 의 **수는 맞고 주석의 이유는 좁다.**
> 주석은 *"좌석은 d1"* 을 전제하지만 `(s=2, r=2) → belt d4` 배열도 성립한다.
> 같은 `R` 을 **다른 깊이 집합**으로 살 수 있고, **유체 파이프가 `d2` 를 먹은 면**에서만
> 차이가 드러난다.

## J4 — 격자로 가는 경계 — **이 계획의 범위 밖** (2026-08-15 사용자)

`R = 1` 이거나 품목이 아주 많아 gap 을 여러 개 열어야 할 때, 기둥을 유지할지 격자로 갈지가
갈린다. **이 계획에서는 결정하지 않는다.** 기둥 + gap 두 축으로 감당되는 데까지 간다.

**착수 조건**

```
이 계획(0-레인예약)이 끝난 뒤, 기둥 + gap 으로 100% 가동을 못 만드는 입력이 나오면 착수.
그때 [2-격자배치](2-격자배치/) 로 옮긴다.
```

**전제:** 기둥 + gap 의 한계가 `레인 2R + Σ가로줄` · `좌석 2h + 2w` 라는 것. §14-5·§14-11.

## J7 — 사다리를 내려갈 때 **어느 줄의 `g` 를 먼저 낮추나**

**결정된 것 (2026-08-16 사용자):** `g_max` 는 처리량이, 실제 `g` 는 자리가 정한다(R1).
그 면의 **관통 후보 수 > 레인 수**면 초과분의 `g` 를 낮춰 구간으로 만든다.

**미결:** 초과분 중 어느 줄을 먼저 낮추나.

```
낮추는 비용은 어느 줄이든 **포트 +1** 로 같다(g=N → c=2).
그래서 지금 가르면 근거 없는 취향이 된다.  결정적 순서(등장 순)로 두고 미룬다.
```

**후보**

| | 기준 | 성질 |
|---|---|---|
| **가** | 등장 순(오늘) | 근거 없음. 다만 **결정적**이라 재현된다 |
| **나** | 낮췄을 때 **남에게 나는 행**이 많은 줄부터 | 기전에서 나온다 — 사다리의 목적이 자리를 만드는 것이므로 |
| **다** | `k` 가 큰 줄부터(여유가 많아 쪼개도 덜 아깝다) | `c` 는 어차피 2가 되므로 잘 안 갈린다 |

**착수 조건 — 입력의 성질**

```
한 면의 **관통 후보가 레인 수를 넘는** 입력이 나오면 착수.
바닐라 R=2 이므로 한 면에 g=N 인 줄이 셋 이상일 때다.
```

**J7 은 R1 의 사다리가 실제로 도는 순간에만 의미가 있다** — ②(레인 장부)가 먼저다.

## J8 — 유체 레시피 UI 비활성화 — **이 브랜치 밖** (2026-08-17 사용자)

**결정:** 지하 파이프를 안 고르면 유체 처리 레시피를 **선택하지 못하게 막는다**(UI 비활성화).
그러면 `no-underground` 는 도달 불가능해지고, 케이스 B 가 사라진 근거가 완성된다.

**미룬다.** UI 는 다른 계층이고 지금 하면 범위가 두 배가 된다.

```
planner 는 그 게이트를 **전제로 삼지 않는다** — `no-underground` 거절 사유를 코드에 남겼다.
UI 가 새는 날 조용히 깨지는 것보다 정직한 거절이 낫다.
```

착수 조건: 트렁크 벨트 경로 모델이 끝나고 초록이 된 뒤.
