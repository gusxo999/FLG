# 포트 표면 규약 — 상자를 블록 밖으로 밀어낸다

## 0. 한 줄 요약

**모듈은 불투명 블록인데 포트 상자가 속에 있다.** 상자를 면 **표면**(그 면에서 가장 깊은
점유 바로 바깥)으로 옮기고, 레인에서 거기까지의 진입로를 **모듈이 자기 셀로** 깐다.
그러면 채널 계획의 좌표계(`… -1 = 벽`)가 **그대로 충분해진다** — 벽이 곧 상자다.

---

## 1. 문제 — 계획이 끝나는 곳과 방출이 가는 곳이 다르다

```
계획   staircaseShape 의 진출 세그먼트 =  hseg(endY, **-1**, track)      "W 벽까지"
방출   buildPlannedChain              =  … push(e)                      "**상자까지**"
```

`-1` 은 채널 계획의 **가상 벽 마진 열**이다. 계획은 거기서 끝난다. 그런데 상자는 부모 모듈
면의 어느 깊이에 있고, 방출은 벽에서 상자까지 **모듈 면 안쪽을 몇 칸 더 간다.**

**그 구간을 아무도 예약하지 않는다.** 채널 장부는 자기 좌표계 밖이라 모르고, 모듈은 자기
셀이 아니라 모른다. 예약 철학(*"주체 하나가 자리를 먼저 잡고 뒤 단계는 탐색 없이 놓는다"*)에
정면으로 어긋나는 유일한 구간이다.

### 1.1 그래서 무슨 일이 나나 — 2026-08-17 실측

```
[deliveryRoute] planned chain blocked  n2-stone-brick→n0-concrete  — 모듈 몸통 (12,6)
```

체인이 부모 면을 통과하다 막힌다 → dijkstra 폴백 → 그 폴백이 남의 예약을 밟는다
(코드가 스스로 *"연쇄 가능"* 이라 경고하는 수단) → 반출 예약이 깨져 **완제품 상자가 갇힌다.**

`planned = 0`(계획대로 깐 납품 경로 0개)이 이 사슬의 첫 마디다.

### 1.2 왜 구조적인가 — 규약이 이미 적혀 있다

[`src/autoLayout/module/CLAUDE.md`](../../src/autoLayout/module/CLAUDE.md):

> 모듈은 자기 ring 위에 입·출력 포트를 갖는 **불투명 블록**이다.

불투명 블록이면 **포트는 표면에 있어야 한다.** 지금은 같은 면의 더 깊은 레인이 상자를 감싸
포트가 *속*에 있고, 그래서 바깥 주체가 블록을 통과해야 한다 — 불투명성이 깨진 것이다.

`ModulePort.moduleWayOuts` 의 주석도 같은 규약을 말한다(*"모듈이 **자기 자신에 대해** 답하므로
planner 는 모듈 내부를 들여다보지 않는다"*). 그 값이 지금 반쪽인 이유가 이것이다 — 상자가
몸통 속이면 *"몸통에 안 막히나"* 라는 질문 자체가 성립하지 않는다.

## 2. 이미 있는 것 — **무엇을 새로 만들 필요가 없나**

> 계획서는 *"무엇을 만든다"* 앞에 *"무엇이 이미 있나"* 를 센다. 2026-08-16 에 이 절이 없어
> 있는 기능을 다시 만들 뻔했다(`tempPlanDocs/트렁크벨트-경로모델/CLAUDE.md` 함정표 ★★★★).

| 있는 것 | 어디 | 그래서 |
|---|---|---|
| 면의 **가장 깊은 점유**를 아는 장부 | `LinkFaceContext.lanes` (`${면}\|${깊이}` → 행 범위들) | 표면 깊이를 **새로 계산할 필요가 없다** |
| 포트 끝까지 세는 함수 | `linkFaceDepths` = `laneDepth + 2` | 유체 파이프가 이미 이 수를 보고 물러난다 |
| 상자 자리를 정하는 **유일한 곳** | `makeLinkPortChest` (`trunkEnd + 2·pfv`) | 바꿀 자리가 한 곳이다 |
| 기둥 끝 포트 | `LinkFacePlan.portEnd` (2026-08-17) | 관통은 **이미 표면 밖**에 있다. 이 계획의 대상은 **구간의 옆 포트**뿐 |
| 진입로가 막혔는지 아는 검사 | `plannedChainClear` (막은 칸과 정체를 낸다) | 실패를 **정직하게** 낼 수단이 있다 |
| 규칙 검사기 | `flg.check()` — R-겹침·R-연속·R-도달·R-무우회 | 새 불변식을 **같은 자리에** 붙인다 |

**새로 만드는 것은 둘뿐이다: 표면 깊이를 읽어 상자를 밀어내는 것, 그 사이를 잇는 진입로.**

## 3. 무엇을 만드나

### 3.1 표면 깊이

```
surfaceDepth(면) = 그 면에서 가장 깊은 점유 + 1
```

`lanes` 장부가 `${면}|${깊이}` 를 키로 갖고 있으므로 **최댓값을 읽으면 끝**이다. 유체 면은
`ClusterPipe` 가 더 깊을 수 있으니 `linkFaceDepths` 와 같은 셈을 쓴다.

### 3.2 상자를 표면에

```
지금   d2 벨트 · d3 인서터 · **d4 상자**          그 뒤 d5·d7 이 상자를 감싼다
바뀜   d2 벨트 · d3 인서터 · d4..dS-1 진입로 · **dS 상자**      S = surfaceDepth
```

포트 인서터는 레인 바로 옆(`d3`)에 그대로 둔다 — 팔이 벨트를 집는 관계가 안 바뀐다.
바뀌는 것은 **상자 자리와 그 사이를 잇는 벨트**뿐이다.

### 3.3 진입로 — 가로막는 것을 어떻게 지나나

진입로는 상자의 **행**을 따라 가로로 간다. 그 행에서 더 깊은 레인이 무엇인가에 달렸다:

```
빈 깊이        그냥 지난다
구간 레인      그 레인이 이 행에 없으면 지난다 (구간은 자기 좌석 행에만 있다)
               있으면 → 상자 행을 **그 레인이 비는 행**으로 고른다
관통 레인      지상으로 못 지난다 → **지하벨트**로 통과
               지하도 못 쓰면 → **정직한 실패**(unroutedLines). 지어내지 않는다
```

**관통이 흔치 않다는 것이 이 계획의 전제다.** 2026-08-17 에 관통을 기둥 끝으로 보냈으므로
(`portEnd`), 면에 남는 것은 대개 구간이다. 이 전제가 깨지면 지하 사용이 늘고, 그것도 안 되면
실패가 는다 — **둘 다 조용하지 않다**(§5 불변).

## 4. 단계

### Step 1 — 표면 깊이를 계획이 낸다

```
전제:  `lanes` 장부가 그 면의 모든 점유 깊이를 갖는다.
       확인 = tryLinkFace 를 지나지 않고 면에 앉는 것이 있나 (유체 파이프가 그렇다 → linkFaceDepths 를 함께 본다)
불변:  `LinkFacePlan.surfaceDepth` 는 그 면 최대 laneDepth+2 **이상**이다
       (기전: 배정이 끝난 뒤에 읽으므로 나중에 더 깊은 것이 앉을 수 없다)
관문:  방출이 "이 면의 표면이 어디냐" 를 물을 수 있게 한다.  지금은 물을 데가 없다
```

### Step 2 — 상자를 표면으로 + 진입로

```
전제:  makeLinkPortChest 가 상자 자리의 유일한 출처다.  확인 = rg 로 chestAt 생성처 세기
불변:  포트 인서터의 pickup 이 여전히 레인 벨트를 가리킨다
       (기전: 인서터 자리를 안 건드리고 상자만 민다 — 팔 관계식이 코드에 안 남는다)
관문:  상자가 모듈 extent 의 **경계**에 서게 한다
```

### Step 3 — 불변식을 규칙 검사에

```
R-표면   모든 포트 상자는 자기 모듈 extent 의 경계에 있다
```

**이게 이 계획의 진짜 산출물이다.** 상자가 속으로 들어가는 회귀는 조용히 지나가고
(2026-08-17 에 두 턴을 썼다), 검사가 있으면 **다시는 못 지나간다.**

### Step 4 — 방향: 계획과 방출의 경계를 되돌아본다

> 여기는 **확정이 아니라 방향**이다. Step 3 을 끝낼 때 전제를 다시 확인한다.

상자가 표면에 서면 `buildPlannedChain` 의 `push(e)` 가 **0칸 또는 1칸**이 된다. 그러면
`eligible`·`wrapAround` 같은 특수 모양이 필요 없어질 수 있다 — 확인하고, 맞으면 지운다.

## 5. 불변 — 기전으로

```
불변 1   상자를 미는 것은 makeLinkPortChest 한 곳이다
         → 다른 자리에서 상자를 만들면 타입이 안 맞아 안 컴파일된다 (surfaceDepth 를 요구한다)

불변 2   진입로는 **모듈 자기 셀**이다
         → occupancy 장부에 자동으로 올라가 남이 못 뺏는다.  별도 예약이 필요 없다

불변 3   지나갈 수 없으면 **unroutedLines** 다
         → 지어낸 경로가 없다. 실패가 화면에 뜬다 (moduleWizard 의 이슈 경로)
```

> **"산출물이 안 바뀐다" 를 불변으로 쓰지 않는다.** 이 계획은 좌표를 **바꾸는** 것이 목적이다.
> 안 바뀌었다면 상자가 이미 표면이었다는 뜻이거나, 밀어내기가 안 돈 것이다.

```
동반 지표   dijkstra ↓ · 예약침범 0 유지 · 반출 skip 0 유지

도구        flg.run() → flg.report() → flg.check() → flg.face(모듈, 면)
금지        스크린샷 눈대중.  가설을 코드로 확인하기 전에 계획 세우기
```

## 8. 대가 — 받아들이는 것

**면이 넓어진다.** 상자가 표면으로 밀리면 그만큼 모듈이 커진다.

그 값으로 사는 것: 예약 철학이 **전 구간에서** 성립하고, 채널 계획의 좌표계가 거짓말을
멈추고, 상자가 갇히는 사고가 **구조적으로** 불가능해진다.

2026-08-17 에 관통 포트를 기둥 끝으로 옮겼을 때 이미 같은 거래를 했다 —
셀 228 → 239(+11)를 내고 반출 skip 1 → 0, penalty 13 → 8 을 얻었다. **그 원리의 일반화다.**
