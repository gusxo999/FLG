## J-표면 — **마지막 구간이 예약 밖이다** (`planned = 0` 의 원인)

**이 계획이 안 푸는 문제다.** 헤매지 않도록 여기 적는다.

```
계획   staircaseShape 의 진출 세그먼트 =  hseg(endY, **-1**, track)   "W 벽까지"
방출   buildPlannedChain               =  … push(e)                   "**상자까지**"
```

`-1` 은 채널 계획의 가상 벽 마진 열이다. 상자는 부모 면의 어느 깊이에 있고, 방출은 벽에서
상자까지 **모듈 면 안쪽을 몇 칸 더 간다.** 그 구간을 아무도 예약하지 않는다.

```
실패 사유   chain-blocked: **모듈 몸통** (12,0) · (12,6)
                           base.has(k) — 부모 모듈 **자기 셀**.  예약 충돌이 아니라 물리적 장애물
```

**더미 모듈로 안 고쳐진다** — 공급하는 쪽이 자식이든 더미든 **받는 쪽 기하가 같다**.
더미는 *예약 충돌*을, 표면화는 *물리적 가로막힘*을 없앤다. 다른 층이다.

**길 셋**

| | 무엇 | 성질 |
|---|---|---|
| 가 | **포트 상자를 면 표면으로** 밀고 진입로를 모듈 자기 셀로 깐다 | 규약 회복(*"모듈은 불투명 블록"*). 면이 넓어진다 |
| 나 | 채널 계획의 좌표계를 상자까지 넓힌다 | 채널 계획이 모듈 내부를 알게 된다 — 계층 경계가 깨진다 |
| 다 | 포트가 `approach` 셀을 들고 다닌다 | 작지만 **증상 처치** — 여전히 계획 밖. 감지만 앞당긴다 |

**근거 있는 관측:** 2026-08-17 에 관통 포트를 기둥 끝으로 옮기자(면 깊이 d7 → d3)
반출 skip 1 → 0, penalty 13 → 8. **상자를 표면에 가깝게 만든 것이 실제로 들었다** —
(가)는 그 원리의 일반화다.

**착수 조건:** 이 계획의 Step 2 가 끝난 뒤. 예약 주체가 하나가 된 상태에서 다시 재야
*"남은 실패가 정말 기하 때문인지"* 가 깨끗하게 갈린다.

## J-DAG — 1:N 의 세부 (Step 3 안에서 정한다)

```
· 자식 산출을 부모들에게 **어떻게 나누나** — rate 배분. 균등? 수요 비례? 정해야 한다
· 부모들의 깊이가 다르면 자식은 **어느 깊이**에 서나
· 채널을 **여럿** 가로지르는 납품 경로를 planChannelGeometry 가 그릴 수 있나
  (지금은 채널 하나 안의 (열, 행) 좌표계다 — 여러 채널은 좌표계 밖이다)
```

**가장 얇은 곳은 `layoutY`** 다. tidy-tree 는 트리를 전제하고, 부모가 여럿이면 자식의 y 를
누가 정하는지 정의가 없다. DAG 배치는 layered graph drawing 이라 **다른 종류의 문제**다.

**착수 조건:** Step 2 완료. 그 전엔 재도 의미가 없다.

## J-폭 — 채널 트랙이 모자란다 (`no free lane track in channel`)

**사실:** 2026-08-17 에 관통 포트를 기둥 끝으로 옮기자 채널 트랙 수요가 늘어 반출 상자가
트랙을 못 받는 경우가 생겼다. 테스트 6건이 이걸 본다.

```
옛 옆 포트    포트 y = 자기 좌석 행   → 세로 구간이 짧다
새 끝 포트    포트 y = 기둥 끝 **밖** → 구간이 기둥 전체 + α → 겹침 급증 → 트랙 수요 ↑
```

**전제:** 채널 폭은 **폭 역전**으로 배정 결과에서 나온다
(`channelWidthFromTracks(trackCount, MODULE_CHANNEL_MIN)`). 수요가 늘면 폭도 따라 늘어야
하는데 **안 늘었다.**

**길 셋**

| | 무엇 | 확인해야 할 것 |
|---|---|---|
| 가 | `cap` 상한이 막는다 | `cap = max(MIN_TRACK_CAP, 납품+반출 수)` 가 실제 수요보다 작은가 |
| 나 | ④ phantom 예약이 그 구간을 안 센다 | fallback 경로의 폭 예약이 긴 세로 구간을 반영하나 |
| 다 | 폭은 맞는데 **배정이 못 찾는다** | ②의 백트래킹이 반출을 뒤로 미뤄 굶기나 |

**착수 조건:** 이 계획의 Step 2 이후. **반출 패스가 사라지면 이 문제 자체가 없어질 수 있다**
(반출이 채널 트랙을 안 쓰게 되므로) — 그 전에 가르면 헛수고다.

## J-도달규칙 — `flg.check()` 의 R-도달이 기둥 끝 포트를 모른다

**사실:** 2026-08-17 기준 위반 5건. 대부분은 **규칙이 낡은 것**이다 — 기둥 끝 포트는 머신에
안 붙는 게 정상인데(상자가 기둥 밖) 규칙이 *"포트와 머신 사이"* 를 잰다.

```
n0-concrete 포트 (8,3) E 와 머신 사이가 비었다 — (7,3)          ← 기둥 끝 포트.  정상
n0-concrete 포트 (13,5) E 와 머신 사이가 비었다 — (9,5)…(12,5)  ← **네 칸. 진짜 결함일 수 있다**
```

**아직 안 가렸다.** 다섯 중 몇이 진짜인지 모른다.

**길 둘:** ⓐ 규칙이 `portEnd` 를 알고 벨트를 통한 도달을 본다 · ⓑ `R-도달(옆)`·`R-도달(끝)`
로 나눈다.

**착수 조건:** 아무 때나. 작다. 다만 **표면화(J-표면 가)를 하면 위반의 절반이 사라질 수
있어** 그 뒤가 싸다.

**전제 부패 신호:** 표면화 뒤에도 `(13,5)` 류가 남으면 규칙 문제가 아니라 **진짜 결함**이다.
