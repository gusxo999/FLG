# 1 · 되먹임 — **전수 조사(끝남)** 와 제거 지도

> **2026-08-29 정정.** 첫 판에서 *"높이를 재서 고리인지 판정한다"* 고 썼다. **틀렸다.**
> 되먹임은 **호출 그래프의 성질**이라 코드만 읽어 판정한다. 그리고 **값이 같아도 고리는
> 고리다** — 오늘 우연히 같을 뿐, 내일 누가 그 값에 영향을 주면 아무도 모르는 채로 문다.
> 그래서 이 문서는 이제 계측 계획이 아니라 **조사 결과 + 제거 지도**다.

## 정의 — 코드만으로 판정한다

> **되먹임** = 어떤 단계 `S` 의 출력이 (간접이라도) `S` 의 입력으로 돌아와 **`S` 를 다시
> 실행하게 만드는 것.**

**판정 절차(계측 없음):**

```
① 두 번 이상 불리는 단계를 찾는다          rg "함수이름\(" src
② 그 두 번째 호출의 **인자**를 거슬러 올라간다
③ 첫 번째 호출의 출력에 닿으면 → 되먹임
```

세 모양을 **가른다** — 셋 다 "계산을 버린다"는 냄새가 나지만 처방이 다르다:

| 모양 | 무엇인가 | 비용 | 예 |
|---|---|---|---|
| **파생** | 앞의 결과로 뒤를 계산. 앞을 다시 안 돈다 | 없음 | 배정 → gap 폭 → 좌표 |
| **폴백/분기** | 앞이 실패하면 **다른 방법**이 같은 일을 한다. 앞을 다시 안 돈다 | 앞의 계산을 버린다 | ③ 탭 실패 → ③′ 기계별 포트 |
| **되먹임** | 앞을 **다시 실행**한다 | 앞을 통째로 다시 | `gen` ×3 |
| (탐색) | 한 단계 **안**에서 후보를 되돌린다 | 그 단계 안 | 채널 기하 백트래킹 |

## 조사 결과 — 파이프라인 전체 (2026-08-29)

### 되먹임은 **정확히 둘**이고, **둘 다 `generateModule` 로 닫힌다**

```
A   gen(:431) ─→ moduleExtent ─→ heightOf ─→ layoutY ─→ topY ─→ lineEnds ─→ gen(:597)
                                                                              ▲
    ────────────────────────────────────────────────────────────────────────┘

B   gen(:431) ─→ laneShortages ─→ resolveSpanBlock ─→ splitLinkAtRows ─→ linkCache ─→ gen(:482)
                                                                                        ▲
    ──────────────────────────────────────────────────────────────────────────────────┘
```

| | 도입 | 커밋 | 깨는 방법 |
|---|---|---|---|
| **A** (끝 선호) | **2026-07-11** | `b9deaf4` | **`2-짝`** — 끝 방향을 `gen` **앞**에서 안다 |
| **B** (사다리) | **2026-08-26** | `46648dd` | **`3-순서`** — 못을 안 만들면 쪼갤 일이 없다 |

> **A 가 사다리보다 6주 먼저다.** 사장님 우려가 맞았다 — 되먹임은 사다리가 처음 만든 것이
> 아니고, 사다리는 **둘째** 고리다.

### 다른 모든 단계는 **정확히 한 번**씩 불린다

`rg` 로 호출부를 전수했다. 두 번 이상 불리는 것은 `generateModule` 하나뿐이다.

```
packModuleTree      moduleWizard.ts:442        1회
insertingPlanner    planModulePorts.ts:281     1회
allocateFlows       edgeLinks.ts:144           1회
chooseFluidTrunkPlan moduleWizard.ts:223       1회 (노드마다)
routeDeliveryRoutes moduleWizard.ts:550        1회
rePathToPerimeter   moduleWizard.ts:618        1회
planChannelGeometry modulePacking.ts:830       1회
generateModule      modulePacking.ts:420       ← **3회 돈다**
```

### 되먹임은 아니지만 **계산을 버리는** 자리 셋 (참고 — 이 계획 밖)

| 자리 | 무엇을 버리나 | 왜 되먹임이 아닌가 |
|---|---|---|
| `planModulePorts` ③ → ③′ | `insertingPlanner` 가 `complex` 를 내면 그 줄들을 **다른 배분기**(`allocateLinkFaces`)가 다시 맡는다 | `insertingPlanner` 를 **다시 안 돈다**. 분기다 |
| `deliveryRoute` 3단 | 계획 체인 → dijkstra → **예약 무시** | 앞 단계를 다시 안 돈다. 폴백이다 |
| `spillLinkFacesToGap` | 선호 면 실패분을 다른 면으로 | 같은 단계의 2단계다(`deferred` 만 본다) |

`channelGeometryPlanner` 의 **iterative-deepening 백트래킹**은 한 단계 **안**의 탐색이라
되먹임이 아니다 — R2 가 말하는 *"탐색을 안전한 곳으로 옮긴다"* 의 그 자리다.

## 제거 지도 — **이 계획 자체는 코드를 안 고친다**

```
A 를 깨려면:  lineEnds 가 gen 의 출력에 의존하지 않으면 된다
              → 끝은 **이진값**("min"|"max")이고, 방향은 **트리 구조**로 안다
                (자식 순번: 앞쪽 자식은 부모 위, 뒤쪽은 아래)
              → gen 앞에서 계산 가능 → **고리가 열린다**            ⇒ `2-짝`

B 를 깨려면:  못이 없으면 쪼갤 일이 없다
              → 못은 **도착 순서**가 만든다(짧은 줄이 먼저 앉아 얕은 레인을 조각냄)
              → 자유도 낮은 줄을 먼저 앉힌다                          ⇒ `3-순서`
              (쪼갬을 배정 안으로 옮기는 길은 **막혀 있다** — 신원(`linkCache`)을
               모듈 안쪽이 못 만진다)
```

**그래서 이 계획의 산출물은 문서 둘이고, 실행은 2·3 이 한다.**

```
Step 1  §4.6 의 틀린 문장을 고친다 — "높이가 불변이면 고리가 아니다" 는 거짓
        전제: 없음(사실 정정)
        불변: 코드 무변경
        관문: 다음 세션이 값 비교로 고리를 판정하려 드는 것을 막는다        ✅ 완료

Step 2  이 문서(조사 결과)를 남긴다 — 호출부 전수와 두 고리의 도입 시점
        전제: `rg` 전수가 빠짐없다 → 확인 방법: 각 단계 함수명으로 재검색
        불변: 코드 무변경
        관문: 2·3 이 "고리를 안 늘렸다"를 **셈으로** 증명할 수 있게 한다 (기준 = **2**)

Step 3  2·3 이 끝난 뒤 다시 세어 **0** 인지 확인하고, §4.6 을 갱신한다
        전제: 2·3 이 새 고리를 안 만든다 → 확인 방법: 같은 절차를 다시 돌린다
        불변: —
        관문: 되먹임 0 을 **문서화된 사실**로 만든다
```

## 남는 질문 (2·3 착수 전에 답할 것)

**`gen` 을 한 번만 돌리면 `heightOf` 는 누가 주나?** — tidy-tree 는 여전히 높이가 필요하고,
높이는 `gen` 이 준다. 하지만 그건 **`gen` → tidy-tree 단방향**이라 고리가 아니다.
`gen` 을 **다시 안 돌면** 되고, 그러려면 `gen` 의 모든 입력이 `gen` 이전에 확정돼야 한다:

```
gen 의 입력          어디서 오나                        gen 이후인가?
─────────────────────────────────────────────────────────────────
toModuleInput(spec)  트리                               아니오 ✔
outputLinks/inputLinks  linkCache ← edgeLinkGroups      아니오 ✔ (**사다리가 고치기 전엔**)
nsExposure           트리                               아니오 ✔
lineEnds             topY ← heightOf ← gen              **예** ✘ ← A
```

**즉 `lineEnds` 하나만 `gen` 앞으로 당기면 A 가 열린다.** 그게 `2-짝` 의 실질이다.
