# 1 · 되먹임을 없앤다 — 먼저 **몇 개인지** 센다

> **되먹임** = 뒤에서 알게 된 것이 앞 단계의 입력으로 돌아가 **그 단계를 다시 돌리는 것.**
> 고리가 닫혀야 되먹임이다. 안 닫히면 **파생**(앞의 결과로 뒤를 계산할 뿐)이다.

## 지금 — 생성이 세 번 돈다

```
modulePacking.ts:431   1차 생성 (트리 전체)      ← 높이를 재려고
          :446-482     사다리 — linkCache 를 쪼갠다
          :482         1차 재생성                 ← 되먹임 ②
          :487         tidy-tree — 높이로 세로 배치
          :572         lineEnds — |Δy| 최소 끝 조합
          :597         2차 생성                   ← 되먹임 ①?
```

## Step 1 — **①이 진짜 고리인지 판정한다**

**전제(의심스러움):** 2차 생성은 `lineEnds` 를 받아 다시 돈다. 고리가 닫히려면
*"끝 선택이 tidy-tree 의 입력(= 모듈 높이)을 바꿔야"* 한다.

**그런데 안 바꿀 가능성이 크다.** `portEnd` 가 `N` 이면 포트 칸이 기둥 **위**로, `S` 면
**아래**로 자란다 — `moduleExtent` 는 bbox 라 **어느 쪽이든 같은 양이 는다.** 그러면
`heightOf` 가 같고, tidy-tree 가 안 흔들리고, **고리가 안 닫힌다**(= 2단 계산일 뿐 되먹임이
아니다).

```
전제: 끝 선택(N/S)은 moduleExtent().h 를 안 바꾼다
      → 확인 방법: 1차와 2차의 heightOf 를 전 모듈 비교. 하나라도 다르면 전제가 깨진다
불변: 이 단계는 코드를 안 고친다. 계측만 붙였다 뗀다
관문: "고리가 둘인가 하나인가" 를 연다 — 2·3 의 불변이 이 수에 달렸다
```

> **왜 '거의'가 아니라 '전부' 를 세나** — 기둥이 이미 다른 이유로 위로 자라 있으면
> `N` 이 0칸을 더하고 `S` 가 k칸을 더할 수 있다. 그 예외가 **하나라도** 있으면 고리다.

## Step 2 — **②(사다리)는 진짜 고리다. 없앨 조건을 적는다**

사다리는 `linkCache` 를 바꾼다 → 그룹 수가 바뀐다 → 팔·좌석·gap 폭이 바뀐다 →
**높이가 바뀐다.** 그래서 1차를 다시 만들어야 한다. **이건 확실한 고리다.**

**없애는 길은 둘뿐이고, 둘 다 이 계획 밖이다:**

| 길 | 내용 | 어디 |
|---|---|---|
| (가) **못을 안 만든다** | 못이 없으면 쪼갤 일이 없다 | **`3-순서`** |
| (나) 쪼갬을 배정 **안**에서 한다 | `tryLinkFace` 가 실패하는 자리에서 쪼갠다 | 신원(`linkCache`)이 막는다 — 아래 |

**(나)가 막히는 이유:** 자식 출력과 부모 입력이 **같은 `Link` 객체**를 봐야 하고
(`pairDeliveryPorts` 가 `linkId` 로 짝짓는다), 그 객체를 쥔 것은 `linkCache` 뿐이다.
모듈 안쪽에서 한쪽만 쪼개면 짝이 깨진다.

```
전제: 사다리를 켜면 높이가 실제로 바뀐다(= 고리가 맞다)
      → 확인 방법: 플래그 끔/켬으로 heightOf 를 비교. 안 바뀌면 고리가 아니었다
불변: 사다리의 동작을 이 단계에서 안 바꾼다 — 조건만 적는다
관문: "3-순서가 성공하면 사다리를 끌 수 있나" 의 판정 기준을 연다
```

**끄기 판정 기준(이 단계의 산출물):**

> `3-순서` 뒤에 **사다리가 자르는 횟수가 0**이면 사다리를 끄고 되먹임 ②를 없앤다.
> 0이 아니면 **남은 것이 무엇 때문인지 분류**하고(= `span-blocked` 가 몇 개인지),
> 그때 다시 판단한다. **총계가 줄었다는 이유로는 끄지 않는다.**

이 계획이 끝나면 **몇 개인지 확정**이어야 한다.

```

불변: 코드 무변경

```
