# 2 · 짝을 보게 한다 — 끝은 **`Link` 의 필드**여야 한다

## §1 판정 — *"짝의 생성 함수는 `Link` 의 자료구조를 알아야 한다"*

> **맞습니다.** 근거는 취향이 아니라 **열쇠가 갈려 있다**는 사실이다.

같은 짝을 **두 체계가 다른 열쇠로** 부르고 있다:

```
끝 선호   lineEnds:  `output:구리선` → "min"|"max"      ← 열쇠 = **품목 이름**
짝짓기    pairDeliveryPorts:  linkId 토큰 조회          ← 열쇠 = **linkId**
```

**그래서 실제로 틀린다:**

| 상황 | 지금 무슨 일이 나나 |
|---|---|
| 한 간선에 벨트 줄이 셋 | **셋이 전부 같은 끝 선호**를 받는다. 줄마다 다를 수 있는데 구분이 없다 |
| 사다리가 줄을 쪼갬 | `id` 는 `…/0` `…/1` 로 갈리는데 **끝 선호는 안 갈린다**(품목 이름이 그대로다) |

R3(*같은 사실을 두 곳이 세지 않는다*) 위반이고, 처방은 사장님 말씀 그대로다 —
**끝의 열쇠도 `linkId` 여야 하고, 그러면 그것은 `Link` 의 필드다.**

### 다만 한 가지는 짚어 둔다 — **Link 는 답을 *담고*, 답을 *구하지는* 않는다**

*"짝이 위냐 아래냐"* 는 `Link` 안에 **없다.** 두 모듈의 상대 위치는 **트리**가 안다.
그러니 `Link` 는 그 답을 **담는 자리**(필드)를 갖고, **채우는 것은 트리를 아는 층**이다.

이건 새 규칙이 아니라 **`Link.id` 가 이미 그렇게 산다**:

> *"값 자체는 불투명 토큰이다. 간선의 양끝을 아는 호출자(`planner/modulePacking`)가 채우고,
> 이 폴더는 파싱하지 않는다."* — `link.ts:66`

끝도 **같은 방식**으로 산다. 자료구조에서 파생되되, 값은 위층이 준다.

## §2 그런데 **되먹임 없이** 채울 수 있나

지금 `lineEnds` 는 **tidy-tree 뒤**에서 계산된다(정확한 y 가 필요해서). 그대로 링크
배정에 주면 배정이 바뀌고 → gap 폭이 바뀌고 → 높이가 바뀌고 → **tidy-tree 가 틀려진다.**
고리가 하나 더 닫힌다. **그건 결정 1에 어긋난다.**

**해법: 정확한 y 가 필요 없다.** `lineEnds` 의 출력은 `"min" | "max"` — **이진값**이다.
그리고 위/아래 방향은 **tidy-tree 전에 이미 확정**돼 있다:

```ts
const centers = kids.map(layoutY);              // 자식들을 배열 순서대로 위 → 아래
const center = (centers[0] + centers.at(-1)) / 2;
topY.set(id, center - height / 2);              // 부모는 자식들 **중앙**
```

**즉 자식 목록의 앞쪽 자식은 부모보다 위, 뒤쪽 자식은 부모보다 아래에 온다.** 높이를
몰라도 **순번만으로 방향을 안다.**

```
kids = [A, B, C]          A ─┐
                          B ─┼─ 부모 (중앙)
                          C ─┘

A(앞) → 부모보다 **위**  → A 의 출력 포트는 **아래 끝**, 부모의 입력은 **위 끝**
C(뒤) → 부모보다 **아래** → C 의 출력 포트는 **위 끝**, 부모의 입력은 **아래 끝**
```

> **가운데 자식(B)은 부모와 겹친다.** 순번만으로는 못 가른다 — 그때는 오늘처럼
> **선착순으로 둔다.** 지어내지 않는다. 자식이 하나뿐일 때도 같다(완전히 겹친다).

## Step 1 — `Link` 에 끝을 담는 자리를 만든다

```ts
interface Link {
  id?: string;
  /**
   * **짝이 있는 쪽 끝** — 이 줄의 포트가 기둥 어느 끝에 서야 짝과 가까운가.
   * `undefined` = 모른다(짝이 나와 겹친다) → 배정이 오늘처럼 선착순으로 고른다.
   * `id` 와 같은 규칙으로 산다: **위층(modulePacking)이 채우고 이 폴더는 안 만든다.**
   */
  end?: { from: "N" | "S"; to: "N" | "S" };
}
```

`from`/`to` 로 나누는 이유: **한 줄의 두 끝은 서로 반대쪽을 본다**(자식이 아래 끝이면
부모는 위 끝). 하나만 들면 어느 쪽 이야기인지 매번 되유도해야 한다.

```
전제: `Link` 를 만드는 곳은 `createLinks` 하나, id 를 얹는 곳은 `edgeLinkGroups` 하나
      → 확인 방법: `rg "item," src --type ts` 로 Link 리터럴이 그 둘뿐인지
불변: 필드를 **아무도 안 읽는 상태**로 먼저 넣는다 — 이 단계만으로는 배치가 한 칸도 안 움직인다
관문: 짝 정보가 배정까지 **전달될 통로**를 연다
```

## Step 2 — 위층이 채운다 (**tidy-tree 앞**에서)

`modulePacking` 의 `linkCache` 를 만드는 자리(`:397-404`)에서, 자식 순번으로 채운다.

```
자식 순번 i, 형제 수 n
  i 가 앞쪽 절반  →  { from: "S", to: "N" }   (자식이 위 → 자식은 아래 끝, 부모는 위 끝)
  i 가 뒤쪽 절반  →  { from: "N", to: "S" }
  n === 1 또는 가운데 →  undefined            (겹친다 — 모른다)
```

```
전제: layoutY 가 kids 를 **배열 순서대로** 위→아래로 놓는다
      → 확인 방법: modulePacking.ts:489-501 을 읽는다. 이미 확인함(2026-08-29)
불변: `end` 를 아무도 안 읽으므로 **여전히 배치가 안 움직인다**
관문: 값이 실제로 채워지는지를 연다 — `flg.report()` 에 채운 수를 낸다
```

## Step 3 — 배정이 그것을 본다

`tryLinkFace` 의 `portEnd` 선택을 **선호 끝 먼저**로 바꾼다.

```ts
// 지금
const portEnd = spanning ? (["N","S"] as const).find((e) => !endsTaken?.has(e)) : undefined;

// 바꾼 뒤 — 선호가 있으면 그것부터, 없거나 찼으면 오늘 순서
const want = group.end?.[side];
const order = want ? ([want, want === "N" ? "S" : "N"] as const) : (["N","S"] as const);
const portEnd = spanning ? order.find((e) => !endsTaken?.has(e)) : undefined;
```

**`ModulePortPlannerInput` 은 안 건드린다** — 끝이 `Link` 안에 있으므로
`outputLinks`/`inputLinks` 를 타고 이미 들어와 있다. **그게 §1 판정의 실질이다.**

```
전제: `Link.end` 가 배정까지 그대로 온다(중간에 복사·재생성되지 않는다)
      → 확인 방법: `splitLinkAtRows` 가 `...orig` 스프레드로 만드는지 확인. 만들면 `end` 가 따라간다
불변: `end` 가 `undefined` 인 줄은 **오늘과 한 칸도 안 다르다** — 기전: `order` 가 `["N","S"]` 로
      같아진다. (관통이 아닌 줄은 `portEnd` 자체가 `undefined` 라 무관)
관문: **짝을 보는 배정**을 연다
```

## 무엇을 얻나 (재는 법)

| | 재는 값 | 어디서 |
|---|---|---|
| 직접 | 납품 경로의 총 `|Δy|` | `deliverySeeds` 의 `startY`/`endY` 차 합 |
| 파생 | 채널 트랙 수 · 채널 폭 | `flg.report()` 채널 줄 |
| 구조 | `end` 를 채운 줄 / 그중 원하는 끝을 실제로 받은 줄 | 새 계측 |

> **③(*"그 문제가 풀렸나"*)로 잰다.** 겨냥한 문제는 *"관통 줄의 포트가 짝 반대편에 선다"*
> 이므로, 물음은 **"원하는 끝을 받았나"** 다. 총 폭이 줄었는지는 그다음이다.
