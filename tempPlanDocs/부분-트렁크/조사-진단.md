# 조사 · 지도 A 는 **어떤 진단을 하나** — 지우기 전에 (2026-09-02)

> **사실 문서.** 물음은 하나다: *`planClusterPorts`·`insertingPlanner` 가 내는 사유 중
> **뒤에 의미 있는 흐름이 이어지는 것**이 무엇인가.* 이어지면 이식하고, 안 이어지면 지운다.

## 0. 결론 먼저

```
내는 사유 다섯 중
  실서비스에서 **도달 가능**한 것        둘   (lanes-exceed-capacity · seats-exceed-capacity)
  뒤에 **흐름이 이어지는** 것            하나  (lanes-exceed-capacity → 위저드 인서터 단계)
  도달 불가                             셋   (fluid-handled… · no-inserter · belt: demand>beltCap)
```

**그리고 그 하나조차 지금 잘못된 물음에 답하고 있다**(§4).

## 1. 사유 전수

| # | 사유 | 어디서 | 조건 |
|---|---|---|---|
| ① | `fluid-handled-by-generateModule` | `clusterPortPlanner.ts:267` | 유체 줄이 섞여 들어왔다 |
| ② | `no-inserter` | `:272` | 인서터 목록이 비었다 |
| ③ | `lanes-exceed-capacity (…)` | `:508` | 줄이 슬롯을 못 잡았고 사유가 **레인** |
| ④ | `seats-exceed-capacity (…)` | `:514` | 〃 사유가 **좌석** |
| ⑤ | `belt: demand>beltCap (…)` | `:965` | 줄 수로 못 감당한 수요가 `beltCapacity` 를 넘는다 |

## 2. 도달성 — **셋은 실서비스에서 못 온다**

### ① 유체 — **호출부가 먼저 거른다**

```ts
// planModulePorts.ts:504 — 유일한 호출부
const restLines = input.lines.filter((l) => l.kind !== "pipe" && !linkedKeys.has(...));
```

`kind === "pipe"` 인 줄은 들어가지 않는다. **단위 테스트에서만 닿는다.**

### ② 인서터 없음 — **상위가 먼저 abort 한다**

```ts
// moduleWizard.ts:178 — 파이프라인 진입 직후
if (options.inserters.length === 0) { issues.push(fail("no-inserter", …, { fixStep: "inserter" })); }
if (issues.length > 0) return abort();
```

같은 사유·같은 처방을 **한 층 위에서 이미 낸다.** 아래 것은 중복이고 도달하지 않는다.
따라서 `moduleWizard.ts:468` 의 `why.includes('no-inserter')` 갈래와 `scope = '입력'` 도
함께 죽어 있다.

### ⑤ 벨트 초과 — **`beltCapacity` 를 아무도 안 채운다**

```
beltCapacity 를 넣는 곳:  src/autoLayout/module/testScale.ts (픽스처) — **그것뿐**
moduleWizard.ts:324:     "v1 은 벨트 처리량(beltCapacity)은 안 잰다"
```

`capacity.beltCapacity !== undefined` 가 거짓이라 조건문이 **언제나 건너뛴다.**
`why.includes('demand>beltCap')` → `fixStep: 'belt'` 갈래도 같이 죽어 있다.

> **같은 사실의 살아 있는 형태는 따로 있다.** 벨트를 못 고르면 `determineBeltCount` 가
> 빈 손으로 답하고 → `externalLineGroups.pour` 가 빈 배열 → 그 줄은 `unpourableLines` 로
> 간다. **사실은 살아 있고 처방(`fixStep: 'belt'`)만 없다.**

## 3. 남은 둘이 **무엇을 정하나** — 흐름은 실재한다

```
supply.reason ──▶ moduleWizard.ts:468  fixStep = 'inserter' | 'belt' | undefined
                                        scope   = '입력' | '모듈'
              ──▶ LayoutIssue.fixStep
              ──▶ UI 버튼 「인서터 단계로」  (ModuleInfoPanel.tsx:215 · AutoLayoutContainerPanel.tsx:637)
                  onClick={() => setStep(i.fixStep)}     ← **위저드 단계를 실제로 되돌린다**
```

**이것은 문장이 아니라 판단이다.** 사용자를 *어느 단계로 돌려보낼지* 를 정하므로,
사용자가 말한 기준(*"판단을 내리기 위해서라면"*)에 **해당한다 → 이식 대상**이다.

```
③ lanes-exceed-capacity  →  fixStep 'inserter'    **살아 있는 유일한 처방**
④ seats-exceed-capacity  →  fixStep undefined     버튼이 없다(처방 미정)
```

## 4. 발견한 결함 둘 — 이식할 때 함께 고칠 것

### (가) 처방을 **문장에서 읽는다**

```ts
const fixStep = why.includes('no-inserter') || why.includes('lanes-exceed-capacity')
  ? 'inserter' : why.includes('demand>beltCap') ? 'belt' : undefined;
```

주석이 스스로 그 위험을 적고 있다 — *"이름이 둘 다 `belt` 로 시작해서 예전엔 정확히
반대로 붙어 있었다(2026-08-04 실측)"*. 저장소는 이미 같은 교훈을 한 번 배웠다:
`layoutIssue.LayoutIssue` 가 `moduleWizard.RejectReason` 을 흡수하면서
**어디가 막혔나와 무엇을 고쳐야 하나가 문장에서 필드로 갈렸다**(`CLAUDE.md`).
지도 A 의 사유만 아직 문자열이다.

> **이식은 문자열이 아니라 필드로 한다.** `fixStep` 을 진단이 **값으로** 내면
> `includes` 세 개가 사라진다.

### (나) **다른 물음에 답하고 있다**

```ts
const rungs = pl.module.laneShortages && summarizeRungs(pl.module.laneShortages);
const why = pl.module.supply?.mode === "direct" ? pl.module.supply.reason
  : rungs ? `사다리 ${rungs}` : "사유 없음";
```

이슈가 뜨는 조건은 **`unroutedLines.length > 0`** — 즉 물음은 *"이 줄이 왜 못 앉았나"* 다.
그런데 모듈이 `direct` 이면 `supply.reason`(= *"탭 계획이 왜 깨졌나"*)을 **먼저** 쓰고,
그 줄이 실제로 왜 못 앉았는지를 담은 `laneShortages` 는 **보지도 않는다.**

두 물음은 다르다. 특히 `g` 의 주인이 레인 예산으로 바뀐 뒤로는 — 탭 계획이 깨진 것과
그 줄이 못 앉은 것 사이에 **인과가 없다.**

```
지금   모듈이 direct 다  →  화면: "complex: lanes-exceed-capacity (…)"
사실   그 줄은 좌석이 모자라 gap 으로도 못 갔다   ← laneShortages 에 있는데 안 읽는다
```

## 5. 판정표

| 사유 | 도달 | 흐름 | 판정 |
|---|---|---|---|
| ① `fluid-handled-by-generateModule` | ❌ | — | **지운다** |
| ② `no-inserter` | ❌ | 상위가 같은 처방을 이미 냄 | **지운다**(중복) |
| ⑤ `belt: demand>beltCap` | ❌ | — | **지운다.** 다만 `fixStep: 'belt'` 는 `unpourableLines` 쪽에 **새로 달아야** 한다 |
| ③ `lanes-exceed-capacity` | ✅ | **위저드 인서터 단계로** | **이식한다 — 값(field)으로** |
| ④ `seats-exceed-capacity` | ✅ | 없음(버튼 없음) | 사실은 `LaneShortage.seats {need,budget}` 가 **더 정확히**(머신마다) 안다 → 그쪽으로 |

## 6. 이식 대상이 낼 수 있는 곳

```
"레인이 모자라 관통을 못 샀다"     planBundles 가 안다 — Σ R_f 와 관통 후보 수를 들고 있다
"이 줄이 어디서 막혔나"            LaneShortage — (면, 레인, 막힌 행 / 좌석 need·budget)
"부을 수조차 없었다"               unpourableLines — 벨트·수량 미상
```

**셋 다 지도 B 쪽에 이미 있다.** 없는 것은 그 사실을 **`fixStep` 으로 옮기는 표** 하나뿐이다.
