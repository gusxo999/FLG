# 채널 양보 명세 — **양보가 도는 유일한 곳에서 규칙을 확정한다**

> 장부는 충돌을 해결하려고 있는데, **어떻게 해결하는지가 어디에도 문장으로 없다.**
> 그런데 양보는 이미 한 곳에서 돌고 있다 — 세로 채널이다.
> **새로 만드는 게 아니라 도는 것을 확정한다.** 그 문장이 행 채널의 사양이 된다.

```
1  세로 채널의 양보 규칙을 시나리오로 확정한다     ← 이 계획
2  행 채널을 같은 급으로 승격한다                  ← 방향 (순환을 끊어야 한다)
3  행 × 세로 교차로                                ← 방향
```

---

## 1. 요소와 우선순위 — **이미 코드에 있다**

`planChannelGeometry` 가 한 채널을 지나는 셋을 **함께** 배정한다.

```
요소 셋      ① 유체 납품    ② 반출    ③ 아이템 납품

우선순위     **실패 비용 순** (같은 파일 주석 — §3.5 피해 등급의 채널판)
             유체   지하로 못 도망간다 → 배정 실패 = **트리 전체 실패**
             반출   실패해도 상자가 로컬 ring 에 남는다 — **되돌릴 수 있는 손해**
             아이템 실패하면 지하 횡단이 회수한다 — 사실상 손해 없음

양보 경로    **선형 사다리가 아니다 — 요소 종류로 갈린다** (2026-08-21 Step 0 정정)

             공통 1단   tryFlip   반출이 진출 변 N↔S 를 뒤집는다
                                  (**다른 납품을 새로 안 가둘 때만** — 양보의 조건)
             ├ 유체가 갇혔는데 못 뒤집으면 → **반출이 물러난다**(`yieldedExports`)
             └ 아이템이 갇혔는데 못 뒤집으면 → `cutOff` → **지하 횡단** → 안 되면 `fallback`

             **유체는 지하로 안 간다**(결정 D2 — 지하파이프 페어링 절단은 셋째 제약).
             그래서 유체 쪽 가지의 끝이 *"반출이 물러난다"* 이고, 그것이 이 채널에서
             **피해 등급이 실제로 발동하는 유일한 자리**다

배정         iterative-deepening 백트래킹 · id 정렬로 결정적 · 폭은 결과에서 나온다
```

**여기가 §3.5 가 말한 *"경쟁이 풀리는 유일한 곳"*(#14)이다.** 그리고 그 이유는 똑똑해서가
아니라 **로컬 좌표**(트랙 index)를 가져서다 — 자기 안의 자리를 자기가 전부 알기 때문에
공동 배정이 성립한다.

## 2. 흔들 수 있는 레버 — **드래그는 아니다**

`planChannelGeometry` 의 호출처는 **하나**다: `modulePacking.ts:759`, `packModuleTree` 안.
채널 계획은 **팩 시점에 얼고**, 드래그는 그 뒤 Area 를 만진다.

```
먹는 레버     포트 행(startY · endY) · 진출 변 선호(preferredExit) · 유체 여부(fluid)
              · 트리 모양(깊이·형제 수) · 지하 상한(maxJump)
안 먹는 레버   드래그 · 수동 편집 — 파이프라인 **뒤**
```

**대신 더 좋은 것이 있다** — `planChannelGeometry` 는 **순수 함수**다
(입력 = `DeliveryInput[]` + `ExportInput[]` + `GeometryContext`). 드래그보다 정밀하게,
**한 변수만 바꾼 대조군**을 만들 수 있다. S8 이 그것에 기댄다.

## 3. 관측 — **양보 셋 중 둘이 결과에서 사라진다**

`ChannelGeometryPlan` 은 셋을 다 알고 있다. 그런데 `PackResult` 로 나오는 것은
`materializeChannelGeometry` 가 만든 **투영**이고, 거기서 `exports` 맵이 버려진다.

```
① 진출 변 뒤집기   `a.exitEdge = plan.exitEdge` 로 trackPlan 을 **덮어쓴다**
                  → 원본(preferredExit)이 사라져 **뒤집혔는지 사후에 못 안다**

② 반출 물러남      exports 의 `{kind:"fallback", reason:"yielded-to-fluid"}` 가
                  `PackChannelGeometry` 에 **안 실린다** — 소비되고 버려진다

③ 아이템 지하행    ✅ `DeliveryDirective`(undergroundCrossing)로 남는다.
                  납품이 장부에 못 든 사유도 `skips` 로 남는다
```

> **그래서 시나리오를 짜도 ①②는 확인할 방법이 없다.** 양보가 일어났는지 자체를 못 본다.
> **Step 1 이 여는 것이 이 구멍이다.**

## 4. 시나리오 — **둘이 비어 있고, 그중 하나가 우선순위 그 자체다**

| | 무엇을 흔드나 | 기대 | 테스트 | **실측**(Step 0) |
|---|---|---|---|---|
| S1 | 반출이 납품을 가둠 | 반출이 진출 변을 **뒤집는다** | ✅ 유닛 | 파이프라인 **1건** |
| **S2** | 유체를 가뒀는데 못 뒤집음 | **반출이 물러난다** — `yielded-to-fluid` | ❌ **0개** | **0건** |

| S5 | 끝 순서가 엇갈린 완전 교차 | 지상 해법 없음 → `fallback` | ✅ 유닛 | 6건 |
| S6 | 겹치는 납품을 늘림 | `trackCount` 가 배정 결과에서 자란다 | ✅ 유닛 | — |
| S7 | 같은 입력 두 번 | 같은 배정(결정성) | ✅ 유닛 | — |
| **S8** | **같은 상황에서 `fluid` 만 켠다/끈다** | **승자가 뒤집힌다** | ❌ **없음** | **불가**(전제 0건) |

> **S2 는 원래 ✅ 로 적었는데 틀렸다(Step 0 정정).** *"해소 사다리 ②"* 라는 이름의 기존
> 테스트는 **지하 횡단**을 보는 것이지 *반출이 물러나는 것*을 보지 않는다.
> `grep yielded` — 테스트 **0개**. **피해 등급이 발동하는 유일한 자리에 테스트가 없다.**

**S8 이 이 계획의 심장이다.** 지금 우선순위는 **주석에만** 있다 — *"정말 유체가 이기나"* 를
증명하는 대조군이 없다. 한 변수만 바꿔 승패가 뒤집히는 것을 보이면, 그게 우선순위가 코드에
**실재한다는 증거**다. 그리고 이건 [[layout-models]] §3.5 의 피해 등급이 **채널 안에서만
쓰인다**는 진단의 실물 확인이기도 하다.

S4 는 다르다 — `columnSwitch` 는 `DeliveryPlan` 에 자료형이 있는데 **테스트가 하나도 없다.**
쓰이고는 있는지조차 확인되지 않았다(Step 0 이 답한다).

## 5. 단계

### Step 0 · 사실 확인 — ✅ **완료** (2026-08-21, 코드 변경 0)

`modulePacking` 에 임시 계측을 넣고 전 테스트를 돌린 뒤 되돌렸다.
표본 = `packModuleTree` 를 타는 **`planChannelGeometry` 호출 52건**(테스트 12파일).

```
총 52건   전부 d=1 — **깊이 2 이상 채널이 테스트에 하나도 없다**

flip (반출이 진출 변을 뒤집음)          1건    modulePacking.fluidLink.test.ts 만
yielded (반출이 유체에게 물러남)        0건    ← **전제가 코퍼스에 없다**(아래)
undergroundCrossing (아이템이 지하로)  38건
fallback: crossing-needs-underground    5건    지하 상한이 모자라 지하로도 못 건넘
fallback: cut-different-side            1건    **반출 절단선 때문에 죽은 것은 이 하나뿐**
columnSwitch                            0건
reserve intervals                       항상 0
```

**셋이 드러났다:**

```
① 유체와 반출이 한 채널에서 **만난 적이 없다**
   유체가 든 호출은 2건뿐이고 **둘 다 exps=0**.  yieldedExports 는 발동 조건 자체가
   테스트에 없다 → S2·S8 은 **합성 입력**으로 짤 수밖에 없다

② columnSwitch 0건은 **구조적이다**
   백트래킹이 실패한 **뒤**의 탐욕 폴백에서만 시도된다(`if (done) continue` 다음).
   백트래킹이 성공하는 한 영영 안 나온다 → S4 의 값이 낮다.  **뒤로 미룬다**

③ 지하 횡단 38건은 거의 전부 **반출 때문이 아니다**
   코드 주석대로 1:1 에선 **교차(Jordan)가 압도적**이고, 반출 절단선 때문에 죽은 것은
   `cut-different-side` **1건**.  즉 이 채널에서 실제로 다투는 것은 대부분 **납품끼리**다
```

> **표본의 한계:** 이건 **테스트 코퍼스**지 실물 트리가 아니다. 실물은 `flg.run()` 이
> 도는 브라우저에서만 나온다 — 특히 ①(유체+반출 동시)은 실물에서 흔할 수 있다.
> **실물 표본을 받기 전까지 위 수치는 "테스트가 무엇을 덮고 있나"로만 읽는다.**

```
관문(닫힘):  S4·S8 이 실물 경우인지 지어낸 경우인지 갈렸다 —
             **S8 은 합성, S4 는 뒤로 미룸.**  그리고 **S2 가 ✅ 에서 ❌ 로 바뀌었다**
```

③ debug/runStats · report

```

```

### Step 3 · 행 채널 승격 — *(방향)*

행 채널은 `channelPlanner` 급(구간→트랙→폭)에 있고 `channelGeometryPlanner` 급
(기하 + 양보)이 **없다**. 그리고 그냥 옮겨 심을 수 없다 — `rowChannelPlanner` 머리 주석이
**순환**을 경고한다:

```
topY → absPortY → 행 채널을 지나는 경로 → 행 채널 폭 → topY
```

세로 채널은 y 를 상수(`STACK_GAP`)로 **먼저 못박아** 순환을 끊었다. 행 채널은 **같은 축**이라
그 수가 안 통한다. 처방(임시 간격 배치 → 통과 경로 계산 → 폭 확정 → 재배치, **2패스**)은
`tempPlanDocs/행채널-모델/` Step 3 에 이미 있다.

```
관문:  행 채널이 **셀을 예약한다**(#15 가 닫힌다).  지금은 트랙만 배정하고
       결과를 아무 장부에도 안 싣는다
전제(확인 필요):  Step 2 가 확정한 우선순위 문장이 행 채널에도 그대로 적용되나 —
                  행 채널을 지나는 것은 납품뿐인가, 반출도 지나는가
```

## 6. 유체는 **이미 들어가 있다** (세로 채널 한정)

빠뜨린 것이 아니다. `DeliveryInput.fluid` · 인접 halo(`haloOf`) · 지상 우선권(배정 순서 맨 앞) ·
`yieldedExports` 가 전부 유체를 위해 있다. **행 채널로 확장할 때 같이 가야 하는 것**이지
따로 만들 것이 아니다.

다만 **채널 밖의 유체는 여전히 부분적용된 지도**(`fluidBlocked`)로 처리되고, 그건 이 계획이
아니라 셀장부 축 3 · J-인접흡수의 자리다.

## 8. 이 계획이 **셀장부와 겹치지 않는 이유**

```
셀장부       전역 격자의 **1항 겹침** 장부를 하나로 — 판정은 정책 A(먼저 온 쪽) 그대로
이 계획      한 채널 **로컬**의 양보 규칙을 확정 — 판정이 이미 여럿이고 우선순위가 있다
```

**둘은 다른 층이다.** 오히려 순서상 이쪽이 먼저일 수 있다 —
`셀장부/judgements.md` **J-충돌차수**가 *"양보가 실제로 어떻게 생겼나"* 를 모르는 채로
다섯째 축을 논하고 있는데, **그 모양을 여기서 본다.**
