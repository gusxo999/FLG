## J-나머지줄순서 — 순서 규칙이 나머지 줄에 안 닿는다

**무엇이 미결인가.** 순서 규칙(방문 수 → 합류 쌍)은 **링크 줄끼리만** 줄을 세운다. 나머지 줄(원료 · 완제품)은 링크가 전부 앉은 뒤
`generateModule` 안에서 앉는다. 그래서 모든 머신을 지나는 **긴 원료 줄**이 짧은 링크 토막 뒤에 오면, `electronic-circuit` 과 같은
모양(먼저 온 짧은 줄의 포트가 긴 줄의 길을 막는다)이 이론상 날 수 있다.

**길 셋:**

| | 무엇 | 대가 |
|---|---|---|
| (가) 오늘 순서를 이어받는다 | 링크 → 나머지 줄 | 막힘의 대부분은 잠수(Step 3)가 흡수한다. 남는 것은 인서터 행끼리 부딪히는 경우다 |
| (나) 창구를 열 때 모듈이 자기 **관통** 나머지 줄을 먼저 앉힌다 | 관통 원료 줄 → 링크 → 나머지 짧은 줄 | 링크 쪽이 받는 대답에 모듈의 사정이 먼저 끼어든다. 좌석 단계가 원료 줄의 `g` 를 알아야 한다(`planMachinesPerBeltLine` 가 앞당겨진다) |
| (다) 링크와 나머지 줄을 한 줄로 세운다 | 방문 수 하나로 | 좌석 단계가 모듈의 나머지 줄까지 쥐어야 한다 — **한 자원을 두 주체가 다루는 문제**(이 계획이 풀려는 것)가 되살아난다 |

**오늘 고른 것: (가).** 기본값을 이어받는다. (다)는 이 계획의 방향과 맞서므로 사실상 후보가 아니다.

**착수 조건 (트리거) · 종류: 해금형 → 성질형**

```
Step 3(잠수)이 끝난 뒤,
관통 나머지 줄이 링크 토막의 인서터 행 · 포트와 부딪혀 잠수로도 못 앉는 입력이 들어오면 착수.
(잠수가 없는 동안은 이 경우와 구간막힘이 구분되지 않는다 — 그래서 해금형이 앞에 선다)
```

**코드 역참조** — `module/policy/port.ts` `planModulePorts` ④(`seatRestLines` 호출). 2026-09-24 Step 4 뒤에 달았다.

## J-모양문법 — 한 열에 두 줄을 들이나

**무엇이 미결인가.** 계획서 §4.6 은 모양을 *지면 띠 + 잠수* 까지만 넓혔다. 세 모양을 뺐다.

```
얹기       짧은 줄이 긴 줄의 터널 몸통 위, 같은 열에 앉는다        터널 하나 — 게임은 허락한다
짜깁기     두 줄이 번갈아 잠수한다                                터널 둘이 겹친다 — 같은 종류면 불가능
열 바꾸기  줄이 중간에 다른 깊이로 옮긴다                          경로가 2차원이 된다
```

**얹기가 가장 가깝고, 대가도 가장 크다.** 얹기는 [[trunk-assignment]] §4.2 가 이미 적어 둔 느슨함이다 — *"관통 줄이 팔 없는 구간을
잠수해서 지나가면 그 행의 지면이 살아나므로, **같은 깊이에 다른 줄이 들어올 수 있다**."* 그런데 그 순간 깊이 예산의 부등식
*"(g>1 줄 수) + (g=1 이 있으면 1) ≤ R_f"* 가 거짓이 된다. 예산이 `g` 를 정하므로 **`g` 를 다시 정하는 일**이 된다 —
이 계획과 `자리-배정` 이 둘 다 *"하지 않는 것"* 으로 둔 축이다.

**짜깁기는 입력이 열어 준다.** 같은 열의 두 터널은 **종류가 다르면** 겹쳐도 된다
(`isJumpAllowed` — *"축 다름 · line 다름 · 티어 다름 → 전부 무해"*, 옛 J12).

**열 바꾸기는 형태가 열어 준다.** 면이 한 줄 기둥인 동안에는 줄이 옮겨 갈 이유가 잠수로 다 흡수된다. 기둥이 여럿이 되어
면 사이에 통로가 생기면 다시 본다.

**오늘 고른 것: 셋 다 안 들인다.** *"한 열에서 두 줄의 구간은 안 겹친다"* 를 그대로 둔다.

**착수 조건 (트리거) — 모양마다 따로**

```
얹기      · 종류: 해금형 → 성질형
          Step 3 이 끝난 뒤, 좌석은 남는데 깊이 예산 때문에 g=1 줄이 gap 으로 밀려 모듈이 벌어지는 입력이 들어오면.
          착수하면 planMachinesPerBeltLine 의 부등식을 다시 세는 것이 첫 일이다

짜깁기    · 종류: 성질형
          지하벨트를 두 종류 이상 고른 입력에서, 한 면의 관통 줄 수가 그 면의 깊이 수를 넘는 트리가 나오면

열 바꾸기 · 종류: 해금형
          격자-클러스터 Step 3(기둥 수 C · 내부 열 채널)이 착수되면
```

**코드 역참조** — `module/ledger/face.ts` 머리말 §칸의 종류(한 열 구간 불겹침 — `depthClear`)와 `module/arith/depth.ts` `planMachinesPerBeltLine`
머리말(부등식). 2026-09-24 Step 3 에서 달았다.

**Step 3 이 끝났다(2026-09-24, 플래그 뒤)** — 얹기의 해금 조건 앞 절반(*"Step 3 이 끝난 뒤"*)이 섰다. 뒤 절반(좌석은 남는데 깊이 예산
때문에 g=1 줄이 gap 으로 밀리는 입력)은 아직 관측된 적이 없다.

## J-통로 — 자리 고르기가 머신 사이 통로를 안 본다

**무엇이 미결인가.** 자리-1(포트 쪽 끝부터)은 머신마다 **따로** 행을 고른다. 흐름이 S 인 **한 머신짜리** 줄은 그 머신의 맨 아래
행에 앉는데, 그 행은 같은 깊이에서 그 머신과 **아래 머신을 잇는 줄**이 반드시 지나야 하는 통로다. 뒤에 온 그 줄은 남의 **벨트**
(인서터 행이라 단단하다)에 막혀 잠수로도 못 건넌다 — 구간막힘. 옛 규칙(앞에서부터)은 한 머신짜리 줄을 위쪽에 모아 이 통로를 비워 뒀다.

**관측 — `AUTO_LAYOUT_LINK_DIRECT` 실험 판에서만**(2026-09-24, 합성 32 픽스처): 셋을 켜니 되던 배치 둘(`item-deep` · `item-fast`)이
깨지고 구간막힘 이름표가 0→61 이 됐다. 셋 중 **자리 고르기만** 끈 판은 옛 판과 바이트가 같다 — 원인이 자리-1 이다. 기본 판(다이렉트 꺼짐)
에서는 이슈가 는 픽스처가 없다. 다이렉트는 **자식 쪽 끝이 여러 머신**에서 출발하는 줄(`from` 이 머신 둘)을 만든다 — 순서 규칙의 전제
*"자식 쪽 끝은 언제나 자식 머신 한 대"* 도 그 판에서는 거짓이라, 부모 쪽 방문 수만으로는 그 줄을 앞세우지 못한다.

**길 셋:**

| | 무엇 | 대가 |
|---|---|---|
| (가) 자리-1 을 여러 머신 줄에만 | 한 머신짜리 줄은 옛 규칙(앞에서부터) | 한 머신짜리 줄의 기둥 끝 포트 이득(표를 안 먹는다)은 원래 없다 — 잃는 것이 작다. 흐름 N 인 여러 머신 줄의 위쪽 통로는 그대로다 |
| (나) 행을 고를 때 **통로 행**을 뒤로 미룬다 | 머신 경계에 붙은 행(흐름이 지나는 쪽)을 후보 끝으로 | 뒤에 그 통로를 쓸 줄이 올지는 모른다 — 예약이 아니라 선호다 |
| (다) 순서 규칙이 **양끝** 방문 수를 본다 | 자식 쪽이 여러 머신인 줄도 앞세운다 | 순서 열쇠가 바뀐다 — 사용자 결정(2026-09-24 *"방문수 먼저"*)의 뜻을 넓히는 일이라 묻고 한다 |

**오늘 고른 것: 없음.** 기본 판에서 관측되지 않았고 다이렉트는 실험 플래그다(주인 `부분-링크` J14).

**착수 조건 (트리거) · 종류: 해금형** — `부분-링크` 가 `AUTO_LAYOUT_LINK_DIRECT` 의 기본값을 켜기로 하면. 또는 **성질형** — 기본 경로에서
자식 쪽 끝이 여러 머신에서 출발하는 링크 줄이 나오면.

**코드 역참조** — `module/policy/link.ts` `seatRowsOf` 머리말.

### J1 — `L_f = |ℛ|` 을 일반 `ℛ` 에 대해 증명하지 않았다

**무엇이 미결인가.** §1 은 면당 동시 벨트 레인 수를 `R = |ℛ|` 로 놓는다.
`R = 1, 2, 3` 은 `(s, r)` 짝을 **손으로 열거**해 확인했지만 임의 `ℛ` 에 대한 증명이 없다.
느슨한 상한(`k ≤ 2R − 1`)만 나와 있어 `R=2` 에서 3 — 열거로 얻은 2 보다 헐겁다.

**착수 조건 (트리거) · 종류: 성질형 — 입력의 성질**

```
서로 다른 reach 가 4종 이상인 인서터 집합이 입력으로 들어올 수 있게 되면 착수.
그전까지는 **열거표가 곧 증명**이다(1·2·3 을 다 셌다).
```

**코드 역참조 — 아직 안 달았다.** 달 자리는 `module/shape/cluster.ts:90`(`columnTapCapacity`).
부모 폴더 정책상 **코드 변경 0** 을 지키느라 보류했고, 착수하는 단계에서 단다.

> **부수 발견 (미결이 아니라 사실):** `columnTapCapacity` 의 **수는 맞고 주석의 이유는 좁다.**
> 주석은 *"좌석은 d1"* 을 전제하지만 `(s=2, r=2) → belt d4` 배열도 성립한다.
> 같은 `R` 을 **다른 깊이 집합**으로 살 수 있고, **유체 파이프가 `d2` 를 먹은 면**에서만
> 차이가 드러난다.

### J8 — 유체 레시피 UI 비활성화 — **이 브랜치 밖** (2026-08-17 사용자)

**결정:** 지하 파이프를 안 고르면 유체 처리 레시피를 **선택하지 못하게 막는다**(UI 비활성화).
그러면 `no-underground` 는 도달 불가능해지고, 케이스 B 가 사라진 근거가 완성된다.

**미룬다.** UI 는 다른 계층이고 지금 하면 범위가 두 배가 된다.

```
planner 는 그 게이트를 **전제로 삼지 않는다** — `no-underground` 거절 사유를 코드에 남겼다.
UI 가 새는 날 조용히 깨지는 것보다 정직한 거절이 낫다.
```

착수 조건 (트리거) · 종류: **해금형** — 트렁크 벨트 경로 모델이 끝나고 초록이 된 뒤.

### J11 — 같은 품목의 **외부 접점을 하나로** (삭제된 두 계획의 목적)

**목적만 살아남았다.** `공급원-모듈화`(더미 모듈 승격 + 트리→DAG)와 `공급-버스`(테두리에서
합치기)가 같은 목적을 다른 수단으로 풀려 했고, 2026-08-18 에 **둘 다 삭제**됐다.

```
문제   n0 이 iron-plate 필요 → 외부 상자 A       사용자가 **두 곳에** 철판을 넣는다
       n1 도 iron-plate 필요 → 외부 상자 B
목적   같은 품목은 **한 곳에서** 받는다 — 사용자가 체감하는 문제다
```

**수단 둘이 다 기각된 이유**

| 수단 | 기각 사유 |
|---|---|
| 더미 모듈 승격 | **외부 접점을 하나도 안 줄인다**(2026-08-18 확인). 상자가 모듈이 될 뿐 개수가 그대로다 |
| 트리 → DAG | `layoutY`(tidy-tree)가 트리를 전제한다. layered graph drawing 은 다른 종류의 문제 — 목적에 비해 너무 크다 |
| 테두리에서 합치기 | 상자는 이미 테두리에 있다. 부족한 것은 위치가 아니라 **개수**이고, 합치려면 결국 1:N 이 필요하다 |

**착수 조건 (트리거) · 종류: 성질형 — 입력의 성질**

```
한 트리에서 **같은 품목의 외부 상자가 2개 이상** 나오면 착수.
concrete 트리(raw 5)에서는 전부 다른 품목이라 이 문제가 안 났다.
겹치는 트리가 나오면 그때 수단을 다시 고른다 — 지금 고르면 근거가 없다.
```

> **2026-09-11 재감사:** 본문이 *"실제로 **흔한가**"* 로 적혀 있었다 — 라벨은 성질형인데
> 묻는 것은 **분포**였다(D3 가 금지하는 형식). 트리 하나가 그 성질을 가지면 그만이므로
> *"나오면"* 으로 고쳤다. 세는 것이 아니라 **만나는 것**이다.

**전제:** 면까지 인도(§19.4 새)가 끝나면 외부 상자가 표면에 서므로, 합치기의 **기하 조건이
쉬워진다.** 그 뒤에 재는 것이 싸다.

### J-포트막힘 — 남의 **포트**에 막힌 포트 칸 (옛 `자리-배정` §2 (다) · §3 Step 1 · 3)

**무엇이 미결인가.** 포트 칸(`d+1` · `d+2` 또는 기둥 끝 `d`)이 **남의 포트 인서터 · 상자**에 막히면 오늘 해소자가 없다 —
잠수로는 못 푼다(포트는 땅속으로 못 간다). 이 계획은 두 경우를 풀었다: 남의 **벨트**면 그 줄이 비켜 주고(Step 3), 끝 머신의 막힌
행은 미리 거른다(Step 2 자리-2). 남은 것은 포트끼리 부딪히는 경우다.

**길 둘(옛 `자리-배정` §3 Step 3 — 둘 다 `g` 와 얽힌다):**

| | 무엇 | 대가 |
|---|---|---|
| (가) 그 줄을 관통으로 민다 | 포트가 기둥 끝으로 가 표를 안 먹는다 | 줄의 `g` 가 바뀐다 — `부분-링크` · 레인 예산과 만난다 |
| (나) 깊이 방향 포트(TR6)를 연다 | 포트가 다른 깊이로 비켜 선다 | 새 포트 모양 — [[trunk-assignment]] TR6 |

**오늘 고른 것: 없음** — 막히면 넘침(다른 면)으로 간다. 옛 `자리-배정` Step 1(막은 주인의 `g` 를 수로 내는 진단)은 이 판단의 재료다.

**착수 조건 (트리거) · 종류: 해금형** — `부분-링크` 가 링크 줄의 `g` 를 정하는 산출물을 내면(그 계획 `부분-링크.md` 이 *"사다리 2단이 후보 하나를
얻는다"* 로 적어 둔 자리).

**코드 역참조** — `module/policy/link.ts` 의 `LadderRung` 머리말(`port-blocked` 행)이 해소자 없음을 적고 있다.
