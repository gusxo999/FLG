# 트랙 배정 — **순서가 문제의 전부다**

> 상태·읽을 것·범위는 [CLAUDE.md](CLAUDE.md). 대화의 A/B/C/D = 여기의 **T-A ~ T-D**.

## 0. 한 줄

채널 트랙 배정은 **두 그래프의 문제**다 — **구간 겹침**(무방향)과 **서·동 순서**(방향).
`channelGeometryPlanner` 는 둘을 가르지 않고 한 백트래킹으로 함께 푼다.
**넷은 전부 *"둘을 갈라 보면 무엇이 계산으로 떨어지나"* 의 답이다.**

그리고 이 저장소에는 **이미 갈라서 계산으로 푼 자리가 하나 있다** — `rowChannelPlanner` 다.
세로 채널이 탐색인 이유는 난이도가 아니라 **순서 그래프의 모양**이다(§2).

---

## 1. 문제의 두 축 — 충돌 규칙에서 유도한다

### 1.1 도형과 기호

`routeShape`(`channelGeometryPlanner.ts:313`)가 내는 경로 하나:

```
경로 A = (출발행 sA[E벽], 도착행 eA[W벽], 트랙 tA),  세로 구간 IA = [min(sA,eA), max(sA,eA)]

  가로 진입   행 sA,  열 [tA … capCol]     ← 내 트랙보다 **동쪽 전부**
  세로 주행   열 tA,  행 IA
  가로 진출   행 eA,  열 [-1 … tA]         ← 내 트랙보다 **서쪽 전부**
```

반출도 같다 — 도착 끝이 `edge` 라 **가로 진출이 없고**, 세로 구간이 바깥 변까지 뻗을 뿐이다.
`straight`(sA = eA)는 가로 하나가 `[-1 … capCol]` 을 **통째로** 덮는다.

### 1.2 충돌 규칙 다섯 (이 문서 안에서만 쓰는 번호)

`shapesConflict` 를 두 경로에 펴면 이것이 전부다:

| # | 무엇 ↔ 무엇 | 성립 조건 | 트랙이 나타나는 방식 | 부류 |
|---|---|---|---|---|
| 1 | 세로 ↔ 세로 | `tA = tB` ∧ `IA ∩ IB ≠ ∅` | **같음** | **무방향**(구간) |
| 2 | 가로 ↔ 가로, 같은 벽 | `sA = sB` (또는 `eA = eB`) | **안 나타남** | **절대**(트랙 무관) |
| 3 | 가로 ↔ 가로, 다른 벽 | `sA = eB` ∧ `tA ≤ tB` | 비교 | **방향**(순서) |
| 4 | A 가로 **진입** ↔ B 세로 | `tB ≥ tA` ∧ `sA ∈ IB` | 비교 | **방향**(순서) |
| 5 | A 가로 **진출** ↔ B 세로 | `tB ≤ tA` ∧ `eA ∈ IB` | 비교 | **방향**(순서) |

> **읽는 말:** 내 **출발 행**을 가로지르는 놈은 반드시 **내 서쪽**, 내 **도착 행**을
> 가로지르는 놈은 반드시 **내 동쪽**. (내 가로 진입이 동쪽을 다 덮고, 진출이 서쪽을 다 덮으니까.)

`straight` 는 규칙 2 의 극단이다 — **트랙을 0개 쓰면서 그 행을 통째로 잠근다.** 그 행을
지나는 모든 세로 주행이 트랙과 무관하게 막힌다. *"폭을 안 먹으니 공짜"* 가 아니다.

### 1.3 여기서 나오는 정리 셋

**정리 1 (순서 충족성).** 배정의 유효성은 트랙 번호의 **비교 결과**에만 의존한다.
절대값은 어디에도 안 쓰인다.
*증명:* 규칙 1~5 에서 `t` 가 나타나는 자리가 전부 `=` · `≤` · `≥` 다. 고정 상수인 벽
(`-1` · `capCol`)은 언제나 모든 트랙의 바깥이라 비교 결과를 안 바꾼다. ∎

- **따름 1 — 압축은 언제나 안전하다.** 유효한 배정에서 쓰인 트랙 값을 **순서를 지킨 채**
  `0,1,2,…` 로 눌러도 유효하다. 즉 **빈 트랙을 남기는 배정은 항상 더 좁은 배정으로 접힌다**
  → 최소 T = **필요한 서로 다른 계급의 수**.
- **따름 2 — 값 대칭은 없다.** 트랙 번호는 **교환 가능하지 않다**(§3 T-B 의 반례).

**정리 2 (하한).** 세로 구간이 겹치는 둘은 같은 트랙에 못 온다(규칙 1) →
**T ≥ 세로 구간의 최대 동시 겹침 수(density)**. 그리고 그 수는
`assignTracksLeftEdge(구간들).trackCount` 가 **이미 낸다**(옆 파일에 있다).

**정리 3 (불가능).** 규칙 3·4·5 를 방향 간선으로 모은 **순서 그래프에 순환이 있으면**,
**어떤 T 로도 지상 해가 없다.** 폭을 넓히는 것으로는 못 푼다.

```
반례(순환):  A: 10 → 30      B: 20 → 5
             B 의 세로가 A 의 출발행 10 을 지난다  →  규칙 4:  tB < tA
             A 의 세로가 B 의 출발행 20 을 지난다  →  규칙 4:  tA < tB    모순
```

이것이 문서 §5-3 의 *"완전 교차"* 이고, 코드 주석의 **조르당 곡선 논증**의 대수 버전이다.
그때 필요한 것은 폭이 아니라 **차원**이다 — 지하 횡단(층 바꾸기) · 열 갈아타기(dogleg).

### 1.4 그래서 이 문제의 정식 이름

**VLSI 채널 라우팅**이다. 규칙 1 = 수평 제약(구간 그래프), 규칙 3·4·5 = **수직 제약 그래프
(VCG)**. 알려진 것:

```
VCG 가 없다      →  left-edge 로 O(n log n), **최적**
VCG 비순환       →  해는 있다. 최소 폭은 어렵다(일반형은 NP-완전, Szymanski 1985)
VCG 순환         →  dogleg / 층 바꾸기 없이는 **해가 없다**
```

`rowChannelPlanner` 머리말이 같은 말을 이미 쓰고 있다 — *"그 세로선이 위에서 오는지 아래서
오는지가 순서를 정한다(**VLSI 채널 라우팅의 단자 위치**)"*.

## 2. 전수 — 같은 축의 배정기는 다섯이고, **넷은 이미 계산이다**

> 메모리 규칙(*개념 정리는 표본 하나가 아니라 같은 축의 기능 전수로*)에 따라 머리말 주석을
> 훑어 만든 표다. 축 = *"구간을 자리로 바꾸는 기능"*.

| 배정기 | 구간(규칙 1) | 순서(규칙 3·4·5) | 오늘 푸는 법 | 왜 그것으로 되나 |
|---|---|---|---|---|
| `channelPlanner.assignTracksLeftEdge` | ✅ | **없다**(폭만 센다) | **계산** — 정렬 first-fit | 구간 그래프뿐이라 최적이 증명된다 |
| `rowChannelPlanner.planRowChannel` | ✅ | ✅ 있는데 **전순서로 풀린다** | **계산** — 정렬 두 번 | *"서쪽 끝이 공통"* 이라 부등식이 한 방향으로 모인다 |
| **`channelGeometryPlanner`** | ✅ | ✅ **순환이 날 수 있다** | **탐색** — 반복심화 백트래킹 + 사다리 | 양 끝이 다 자유로워 순서가 안 모인다 |
| `perimeterExitPlanner` | 구간만 **낸다** | — | 자격·선호만. 트랙은 위에 위임 | 머리말 §(A): *"폭만 예약 — 트랙 index 는 못박지 않음"* |
| `planner/module/*`(`faceTable`) | 좌석·깊이 축 | 다른 축 | 표 복사 + 사다리 | *"채워 보고 버리는 시도"*(`faceTable.ts:95`) |

**여기가 이 문서의 중심 발견이다:**

> **행 채널은 이미 「계산」이다.** 같은 규칙 4·5 를 갖고도 탐색이 없다 — *"통과 경로가 전부
> 그 열의 서쪽 변까지 달린다"* 는 사실 하나가 순서 제약을 **전순서**로 만들기 때문이다.
> 세로 채널이 탐색인 것은 알고리즘 취향이 아니라 **입력의 모양이 다르기 때문**이고,
> 그 차이는 한 문장으로 적힌다: **한쪽 끝이 공통이면 계산, 양 끝이 자유로우면 탐색.**

그리고 `trunk-assignment.md` ㉢ 가 *"정렬 first-fit → 반복심화 백트래킹 → 탐욕 폴백"* 3단을
**세 번째 축에서 다시 쓰겠다**고 적어 뒀다. 그러니 여기서 정리하는 것은 한 파일의 개선이
아니라 **저장소가 세 번 쓸 뼈대**다.

## 3. 처방 넷 — 무엇을 사고 무엇을 못 사나

### T-A — 하한(density)에서 T 를 시작한다

**개념:** 정리 2. `T = 1` 부터 올리는 지금의 루프는 **하한을 선형 탐색으로 다시 발견**하고
있다. 그 값은 `assignTracksLeftEdge` 가 O(n log n)로 즉시 낸다.

```
지금   for T = 1 … cap        T < density 인 라운드는 **반드시 실패한다** (증명 가능)
후     T0 = density(items)     for T = T0 … cap
```

| | |
|---|---|
| **산다** | 실패가 보장된 라운드 전부. **그 라운드의 비용은 「불가능의 완전 증명」이라 지수일 수 있다** |
| **못 산다** | 최적 T 자체(하한 = 최적이라는 보장은 없다). 순환 판정도 아니다 |
| **위험** | 낮다 — 하한을 **크게** 잡으면 해를 놓친다. 구간 집합이 `items` 와 정확히 같아야 한다(`straight` 제외 · `yielded` 반출 제외 · `cutOff` 납품 제외) |
| **확인** | `T0 == 오늘의 최종 trackCount` 인 채널 비율. 1에 가까우면 **탐색은 거의 하한을 확인만 하고 있다** |

### T-B — **순서만이 뜻이다** (원래 제안의 **정정**)

> **대화에서 제안했던 *"첫 경로를 `t=0` 에 못박는 대칭 깨기"* 는 틀렸다.**
> 정리 1 따름 2 — 이 문제에는 **값 대칭이 없다.** 트랙 번호는 이름표가 아니라
> **서·동 좌표**이고, 규칙 4·5 가 그 값을 비교한다.
>
> ```
> 반례:  A: 10 → 30,  B: 8 → 12       B 의 구간이 A 의 출발행 10 을 덮는다 → tB < tA 필수
>        A 를 t=0 에 못박으면 tB < 0  →  해가 있는데 없다고 답한다
> ```

**대신 참인 것:** 유효성은 **순서(약순서)** 에만 달렸다. 그래서 진짜 탐색 공간은
*"n 개에 T 개 값을 배정"*(T^n)이 아니라 **n 개의 약순서**다. 오늘 탐색은 같은 순서를 갖는
배정을 **여러 번** 방문한다.

| | |
|---|---|
| **산다** | 탐색 공간의 차원. 그리고 **개념의 정정** — *"트랙은 이름표"* 라는 오해가 여기서 끝난다 |
| **못 산다** | 순환이 있는 입력. 순서 공간을 아무리 잘 훑어도 해가 **없다** |
| **위험** | **높다** — 탐색기 자체를 바꾸는 일이다. 지금의 결정성(같은 입력 → 같은 그림)을 새 알고리즘에서 다시 세워야 한다 |
| **안전한 축소판** | *"쓰인 트랙 집합에 빈 칸을 남기지 않는다"*(따름 1)만 강제하는 것은 안전하다. 단 **항목 순서에 기댄 `t ≤ max+1` 은 안 된다** — 그건 값 대칭을 가정한 가지치기다 |

### T-C — 순환을 **먼저** 검출한다

**개념:** 정리 3. 규칙 3·4·5 로 방향 그래프를 세우고(O(n²)) 순환을 찾는다. 순환이 있으면
`T = density … cap` 전 라운드가 **전부 실패할 것이 이미 정해져 있다.**

| | |
|---|---|
| **산다** | ① 불가능한 입력에서의 전 라운드 탐색 ② **진단** — 지금은 `no-surface-assignment` 한 마디인데, *"이 두 경로가 순환이다"* 를 말할 수 있다 |
| **못 산다** | 순환이 없는데 폭이 큰 경우(그건 T-A·T-B 의 몫) |
| **위험** | 낮다 — **판정만** 추가하고 배정 경로는 안 건드린다. 순환이 없으면 오늘과 완전히 같은 길을 간다 |
| **왜 값이 큰가** | 이 저장소의 규칙이 *"실패를 삼키지 않는다"* 이고, 사유 카탈로그가 이미 `cut-different-side` / `crossing-needs-underground` 로 갈려 있다. **순환은 그 사유의 정확한 근거**다 |

### T-D — 탐색 루프의 공학 (개념이 아니라 **사실 둘**)

**D1 — 예산이 라운드 사이에 공유된다.** `budget` 은 `T` 루프 **밖**에서 만들어지고
안에서 초기화되지 않는다(`channelGeometryPlanner.ts:602–624`). 그래서 앞 라운드가 예산을
태우면 **해가 있는 뒤 라운드를 시도조차 못 하고** 탐욕으로 내려간다.

```
budget = { left: 200000 }            ← 루프 밖
for T = 1 … cap:
    if (search(0, T, acc)) …
    if (budget.left <= 0) break      ← 앞 라운드가 태우면 여기서 끝난다
```

**T-A 와 한 몸이다** — 태워지는 라운드가 대개 `T < density`(반드시 실패)라서다.
T-A 를 넣으면 D1 의 해악이 구조적으로 준다.

**D2 — 탐욕 폴백은 left-edge 가 아니다.** 폴백의 항목 순서는 **실패 비용 순 + id 순**이고,
left-edge 의 최적성은 **구간 시작(lo) 순 정렬**에서 나온다. 지금 순서에는 아무 성질이 없다.

> **다만 이건 버그가 아니라 교환이다.** 유체를 앞에 두는 것은 *"실패 비용이 다르다"*
> 는 판단이고(머리말 §4.3), 그 판단이 최적성보다 중요하다. **우선순위 그룹 *안에서만*
> lo 로 정렬**하면 둘 다 지킬 수 있다 — 그룹 사이 순서는 그대로 두고.

## 4. 넷의 관계 — 순서가 정해져 있다

```
T-C(순환 판정)  →  T-A(하한)  →  T-D1(예산)  →  T-D2(폴백 정렬)  →  T-B(탐색기 교체)
   판정만 는다      라운드가 준다    남은 낭비가 준다     폴백 품질          구조 변경
```

- **T-C 가 먼저인 이유:** 가장 싸고(판정만), 가장 위험이 낮고, **다른 셋이 못 사는 것을 산다**
  (불가능한 입력). 그리고 진단이 좋아지면 나머지 셋의 실측 근거가 그때 생긴다.
- **T-B 가 마지막인 이유:** 유일하게 **탐색기 자체**를 바꾼다. 앞 셋이 서면 탐색이 도는
  구간 자체가 좁아지므로, T-B 의 값이 그때 다시 재진다 — **작아져 있을 수 있다.**

> **넷 다 안 해도 오늘의 답은 안 틀린다.** 지금 배정은 **옳고**(불변식이 테스트로 잠겨 있다),
> 넷은 전부 *"같은 답을 더 싸게, 실패를 더 정확하게"* 다. 그래서 **트리거 없이 착수하지 않는다.**

## 5. 무엇을 재야 고를 수 있나 — 실측 레시피

지금 **아무 수치도 없다**(❓). 넷 중 무엇이 실물에서 물리는지는 다음 다섯을 재면 갈린다:

```
채널 하나마다:   n(항목 수) · density(하한) · 최종 trackCount · 소진 예산 · 탐욕으로 내려갔나
```

- **찍는 자리:** `planChannelGeometry` 의 반환 직전 한 줄(`AUTO_LAYOUT_COORD_DUMP` 뒤에).
  `flg.report()` 의 형태 줄과 같은 규약으로 낸다(`docs/debug/ai-console.md` §5).
- **판정:**

| 관측 | 무엇이 정당해지나 |
|---|---|
| `density < trackCount` 가 흔하다 | 탐색이 하한을 **못 맞추고** 있다 → T-B 의 값이 실재 |
| `density == trackCount` 가 대부분 | 탐색은 하한을 **확인만** 한다 → **T-A 로 라운드를 걷어내는 것이 거의 전부** |
| 예산 소진이 0건 | **D1 은 이론적 결함**이다 — 우선순위를 내린다 |
| 예산 소진이 잦다 | D1 이 실재. **탐욕이 실제 배정기**라는 뜻이므로 D2 가 함께 올라온다 |
| 순환 검출 > 0 | T-C 가 진단으로 값을 한다. 0이면 T-C 는 **보험**일 뿐 |

> **주의 — 이 계측은 브라우저에서만 의미가 있다.** 단위 테스트의 픽스처는 손으로 만든
> 소수 경로라 `n` 이 작다. 실물 트리의 수가 아니면 넷의 우선순위를 못 정한다.

## 6. 이 문서가 여는 문

```
① 트랙 배정을 **두 그래프**로 말할 수 있게 된다 — 구간과 순서. 그 전에는 "충돌"이 한 덩어리였다
② 새 축(트렁크·행 채널)에서 **같은 질문 하나**로 알고리즘을 고를 수 있다:
   「한쪽 끝이 공통인가?」 → 예면 계산, 아니면 탐색
③ 실패 사유가 **구조로** 갈린다 — 폭 부족(하한)인가, 순환(불가능)인가
```

**끝나면 `docs/auto-layout/channel/` 로 옮긴다.** §1(규칙 다섯 · 정리 셋)과 §2(전수표)는
코드를 바꿔야 무효가 되는 사실이라 `docs/` 소속이고, §3~§5(처방·트리거·레시피)는
`judgements.md` 에 남는다.
