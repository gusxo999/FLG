## 확정된 판단 (근거와 함께)

### J-정정 — **"트랙은 이름표"가 아니다** (결론 남. 판단 아님)

2026-09-10 대화에서 *"첫 경로를 `t=0` 에 고정하는 대칭 깨기"* 를 제안했다가 **코드에서 유도해
보고 철회**했다. 트랙 번호는 **서·동 좌표**이고 규칙 4·5 가 그 값을 비교하므로 값 대칭이 없다.
반례는 본문 §3 T-B.

> **남길 값:** *"자리 번호가 이름표인가 좌표인가"* 를 **먼저 묻는다.** 이름표면 대칭 깨기가
> 공짜이고, 좌표면 같은 가지치기가 **해를 지운다.** 트렁크 축(`trunk-assignment` ㉢)에서
> 같은 질문이 다시 나온다 — 거기서 깊이는 이름표인가 좌표인가?

### J-축 — 계산이냐 탐색이냐는 **입력의 모양**이 정한다

```
한쪽 끝이 공통이다   →  순서 제약이 전순서로 모인다  →  정렬로 끝난다 (rowChannelPlanner)
양 끝이 다 자유롭다  →  순환이 날 수 있다           →  탐색 + 사다리 (channelGeometryPlanner)
```

**근거:** `rowChannelPlanner` 머리말 — *"순환이 없으므로 dogleg 도 지하도 필요 없다. 다만 그
근거는 **서쪽 끝이 공통**이라는 것 하나다. 통과 경로가 서쪽 변까지 안 가는 날이 오면 순환이
생길 수 있고, 그때 ⓑⓒ 가 살아난다."*

**따름:** 세로 채널을 *"계산으로 바꾸자"* 는 제안은 **입력을 바꾸지 않는 한 불가능**하다.
바꿀 수 있는 것은 탐색이 **도는 범위**(T-A·T-C)와 **공간의 차원**(T-B)뿐이다.

## 미결 넷 — 착수 조건(트리거) · 종류: **넷 다 실측형**

**공통 전제:** 아래 트리거는 전부 §5 실측 레시피의 수치에 걸려 있다. **지금은 그 수치가
하나도 없다.** 그래서 넷 다 *"측정 먼저"* 다 — 측정 없이 착수하면 안 물리는 것을 고친다.

> **2026-09-11 재감사 — 넷 중 셋의 「세는 눈」 상태가 다르다.**
>
> ```
> T-C   `no-surface-assignment`   **볼 수 있다** — `flg.report()` 의 `납품장부` 줄(2026-09-11 신설)
> T-A   `density == trackCount`   **세는 눈이 없다** — 이 계획 Step 0 이 만들 것
> T-D1  예산 소진                  **세는 눈이 없다** — `channelGeometryPlanner` 의 `budget.left`
>                                  가 소진돼도 아무 데도 안 남는다
> ```
>
> 공통 규칙(`tempPlanDocs/CLAUDE.md` §①)의 셋째 규율대로 **읽는 자리까지** Step 0 에 넣는다.
> 넣지 않으면 *파이프라인 계측기* 와 같은 길이다(소비처 0 → 삭제).

| # | 처방 | **착수 조건** | 안 하면 무엇이 남나 |
|---|---|---|---|
| **T-C** | 순환 선검출 | 폴백 사유 `no-surface-assignment` 가 실물 트리에서 **1건이라도** 나오고, 그 원인이 순환인지 폭인지 **로그로 못 가릴 때** | 사유가 뭉개진 채로 남는다. 조사할 때마다 손으로 다시 판정 |
| **T-A** | 하한에서 시작 | 측정에서 **`density == trackCount` 가 대부분**이거나, 예산 소진이 **1건 이상** | 라운드 낭비. 눈에 안 보이는 대신 D1 을 통해 **탐욕 강등**으로 새어 나온다 |
| **T-D1** | 예산 라운드별 분리 | 예산 소진 **1건 이상**. 0건이면 **영구 보류**(이론적 결함으로 본문에만 남긴다) | 큰 채널에서 백트래커가 조용히 탐욕이 된다 |
| **T-D2** | 폴백을 그룹 안에서 lo 정렬 | T-D1 이 서고 나서도 **탐욕 경로가 실제로 도는 것이 확인될 때** | 폴백 폭이 필요 이상. 단 **결과는 여전히 옳다**(폭만 넓다) |
| **T-B** | 순서 공간 탐색 | 위 넷이 다 서고도 **`density < trackCount`** 가 흔할 때 | 탐색이 최적을 못 맞추는 만큼 폭이 넓다 |

> **T-B 는 트리거가 가장 높다.** 앞의 넷이 서면 탐색이 도는 범위가 좁아져 **T-B 의 값이
> 그때 다시 재진다.** 지금 재고 착수 순서를 정하면 틀린 수를 쓰게 된다.

## 이 판단이 썩는 조건

| 전제 | 깨지면 |
|---|---|
| 세로 채널의 양 끝이 **포트에 고정**돼 있다 | 끝이 자유로워지면(예: 포트 재배치가 가능해지면) 문제 자체가 다른 것이 된다 — 넷 다 다시 잰다 |
| 한 채널의 경로 수가 **수십**이다 | 수백이 되면 T-A·T-B 가 트리거 없이도 필수가 된다 |
| `straight` 가 **드물다** | 흔해지면 규칙 2(행 통째 잠금)가 지배 요인이 되고, 그때는 넷 중 무엇도 안 듣는다 — 새 처방이 필요하다 |
| 사다리(지하·dogleg)가 **살아 있다** | 순환을 사다리가 회수하지 못하게 되면 T-C 는 진단이 아니라 **차단**이 된다(우선순위 급상승) |
