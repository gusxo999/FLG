# 케이스 B 본체(옵션 B)를 할 것인가 — 판단

> 작성 2026-08-08 · **미결** · 착수 조건은 §4
> 계획서: [케이스B-링크배분기-계획.md](케이스B-링크배분기-계획.md) — 그 계획서는 **옵션 A**
> (점프 면 회수)만 다룬다. 옵션 B는 여기 남긴다.

## 0. 무엇이 미결인가

유체가 붙는 면에서 탭은 두 가지 능력을 갖는데, 링크·다이렉트는 **둘 다 없다.**

| | 능력 | 계획서가 다루나 |
|---|---|---|
| **①** | 점프 면 — 유체 상자 행만 건너뛰고 앉기 | **예** (옵션 A) |
| **②** | **케이스 B** — 좌석을 d2 로 밀고 `2+r` 벨트를 긴팔로 집기 | **아니오 → 이 문서** |

②는 파이프가 **점프하지 못하는** 면에서만 필요하다. 그 면이 실물 트리에 얼마나 있는지
**아직 안 세어 봤다.**

## 1. 전제

**전제 ①** — 옵션 A 가 먼저 끝나 있어야 한다. A 없이 B 만 하는 것은 의미가 없다
(점프 면이 훨씬 흔한데 그쪽을 안 풀고 드문 쪽부터 여는 셈).

**전제 ②** (2026-08-08 코드 기준) — 링크 배분기에는 `reach` 개념이 **하나도 없다.**
`LINK_LANE_DEPTH = 2` 상수이고, 방출기는 `input.inserterEntityName` 을 그대로 쓴다.

**전제 ③** — `emitOutputLinks` 가 이 지점을 스스로 경고해 뒀다:

> 팔 종류는 레인 깊이와 짝이다 — 좌석은 언제나 d1 이므로 벨트가 d`laneDepth` 면 팔이
> `laneDepth-1` 칸을 던져야 한다. v1 은 모든 링크 벨트가 기본 레인(d2)이라 기본 팔이
> 언제나 맞다. **깊은 레인이 다시 생기면 여기가 그 짝을 따라가야 한다** — 상수를 쓰면
> 짧은 팔이 벨트에 못 닿아 그 자리가 **조용히 굶는다.**

## 2. 옮기면 얻는 것 / 드는 것

### 얻는 것

- 링크·다이렉트가 **탭과 능력이 같아진다** → 유체 면을 통째로 양보하는 일이 사라진다
- *"탭을 다이렉트에서 유도하는 합류 패스"* 의 **마지막 장애물**이 없어진다.
  A 만으로는 점프 불가 면이 남는다

### 드는 것

| 무엇 | 변경 |
|---|---|
| `LinkFacePlan` | `laneDepth` 가 상수가 아니게 되고 `seatDepth` · `reach` 가 새로 필요 |
| `LINK_LANE_DEPTH = 2` | 해체 — **`gapRowsFromPlans` 가 이 값으로 gap 폭을 낸다** |
| `emitOutputLinks` / `emitInputLinks` | 인서터 종류를 `reach` 로 골라야 한다(전제 ③) |

**실패 양상이 나쁘다.** 짧은 팔이 벨트에 못 닿으면 겹침도 미배치도 아니고 **조용히
굶는다.** 그리고 `LINK_LANE_DEPTH` 는 gap 폭 산출과 방출 기하가 **함께 읽는 값**이라,
푸는 순간 두 곳이 어긋날 수 있다.

## 3. 옵션

| | 무엇 | 값 | 대가 |
|---|---|---|---|
| **0** | 영구 보류 | 0 | **지하파이프를 안 고른 사용자를 받을 길이 없어진다** |
| **B** | 케이스 B 본체 | 탭과 동등 + 지하파이프 없는 사용자 수용 | 위 표. 조용히 굶는 실패 |
| **B′** | 케이스 B 를 **거절 사유로만** 노출 | 싸다 — *"긴팔 인서터를 고르면 이 면이 열린다"* 를 알려 준다 | 자동으로 나아지지 않는다 |

### 3.1 옵션 0 이 사실상 탈락한 이유 (2026-08-09)

초안은 *"케이스 B 는 성립 조건이 좁으니 B′ 로 대부분 회수된다"* 고 봤다. **두 전제가 다
무너졌다:**

| 무너진 전제 | 무엇이 밝혀졌나 |
|---|---|
| *"케이스 B 는 점프의 열등한 대체물"* | 반대다 — **지하파이프 없음의 기본형**이고 점프이 최적화다(계획서 §1.3) |
| *"처방은 사용자가 지하파이프를 고르는 것"* | **우리가 정할 일이 아니다.** 안 고른 상태도 받아야 할 입력이다 |
| *"안 되면 유체 다이렉트로 물러나면 된다"* | **기하가 성립하지 않는다** — 팔이 없다 · 깊이 1의 특권 · 평면성(계획서 §1.5) |

**폴백이 없다는 것이 결정적이다.** 아이템은 탭이 깨져도 다이렉트가 받는데, 유체는 케이스 B
말고 물러설 곳이 아예 없다. 그래서 옵션 0 은 *"그 사용자는 못 받는다"* 와 같은 말이 된다.

**B′ 는 여전히 값이 있다** — 다만 B 의 **대체재가 아니라 선행 조치**다. reach≥2 를 고르면
열리는 면이라면 알려 주는 것이 맞고, 그건 B 가 있어도 마찬가지다.

## 4. 착수 조건

> **B 는 "할 것인가"가 아니라 "언제"의 문제가 됐다.**

**실측은 착수 조건이 아니다** (2026-08-09 정정). 초안은 *"점프 꺼진 면이 몇 건인가"* 를
세어 정하려 했는데, **빈도가 이 판정에 답을 못 준다** — 케이스 B 부재는 손해가 아니라
**모듈 실패**이고, 지하파이프 미선택은 트리의 성질이 아니라 **사용자 입력**이다(계획서 §5).

착수 조건은 **순서**뿐이다:

| # | 선행 | 왜 |
|---|---|---|
| 1 | 옵션 A 의 1단계(`beltMaxOn`) | **회귀 0** 이면서 B 의 안전망이다. 없으면 깊이를 맨몸으로 건드린다 |
| 2 | 계획서 §5 의 **경계 표**가 빈 칸 없이 채워짐 | B 가 정확히 어느 칸을 여는지 모른 채 시작하면 범위가 흐른다 |
| 3 | `seatDepth` 도입 | 케이스 B 를 **분기가 아니라 값**으로 만들어야 배분기가 분기 복사 없이 읽는다([[자리배정-축-정리-계획]] judgements §5.7) |

### 보조 트리거

- **합류 패스가 실제로 검토되면** — 그때는 이 능력이 *"있으면 좋은 것"* 이 아니라
  **회귀를 막는 필수 조건**이 된다. 판정 기준이 통째로 바뀌므로 이 문서를 다시 연다

## 5. 폐기 조건

- 옵션 B 로 승격 → 계획서로 옮기고 삭제
- 전제 ②가 깨지면(누가 다른 이유로 `LINK_LANE_DEPTH` 를 해체하면) → 삭제, 다시 조사
- ~~실측값이 0 → 삭제~~ — §3.1 로 철회. 지하파이프 미선택 수요가 0 이어야 하는데,
  그건 사용자 선택이라 0 이라고 가정할 수 없다
