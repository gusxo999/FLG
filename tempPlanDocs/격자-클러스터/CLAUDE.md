# 격자-클러스터 — 상태와 고유 컨텍스트

> 상태: **승인 대기** (2026-09-24 갱신 · 코드 변경 0)
>
> **Step 1(= D8 · gap 출구의 교차)은 확정됐다. 이제 착수를 막는 것이 없다.** 구조-2축이 2026-09-23 에
> 끝났고(계획 4 취소), D8 은 이 계획의 Step 1 이 맡는다. Step 2 · 3 은 방향만 있다. Step 3 의 형태 기준은
> **유도됐다** — 기둥 높이 = 트렁크 방문 수(2026-09-24 사용자). 그래서 `k` 를 기다리지 않는다.

**한 문장:** 오늘 클러스터는 세로 한 줄(`dx ≡ 0`)이고, 모듈 안의 빈 채널은 가로 채널(gap) 하나뿐이다.
이 계획은 *언제 기둥 대신 격자를 쓰나* 를 **유도한 기준**으로 정한다. 그 전에 gap 이 모델만큼 일하게
만든다. 계획서는 [격자-클러스터.md](격자-클러스터.md), 미결은 [judgements.md](judgements.md).

## 이 폴더의 어휘

| 낱말 | 뜻 | 사는 곳 |
|---|---|---|
| **격자 클러스터** | 한 모듈 **안**의 머신 배열이 2차원인 것 | 이 계획 |
| **교차로 격자** | 열 채널 × 행 채널의 교차로. 모듈 **사이**의 통로망이다 | `채널-양보-명세/judgements.md` `J-관리관` |
| **바깥 기둥 · 안쪽 기둥** | 옆면 하나가 모듈 변에 닿는 기둥 · 양 옆면이 다 가운데 길을 보는 기둥. **안쪽 기둥은 `C ≥ 3` 부터 생긴다** | 계획서 §2.6 |
| **트렁크 방문 수 `g`** | 벨트 한 줄이 감당하는 머신 수 = `min(N, ⌊벨트 처리량 ÷ 한 대 소비량⌋)`(`bundleCap`). `G` = `C=1` 에서 트렁크로 서는 줄들 중 최대값 | 계획서 §2.5 |

**그냥 "격자"라고 쓰면 앞의 것이다.** 뒤의 것은 반드시 *교차로 격자*라고 쓴다.

**모듈 안의 채널 — `innerRowChannel` · `innerColumnChannel`** (2026-09-04 사용자 · 용어사전 §채널이 인용한다)

| 트랙 축 | 전역(모듈 사이) | **모듈 전용(모듈 안)** |
|---|---|---|
| 행(가로로 달린다) | 행 채널 | `innerRowChannel` = 오늘의 **gap** 을 일반화한 것 |
| 열(세로로 달린다) | 열 채널 | `innerColumnChannel` = **기둥 사이** 가운데 길. 오늘은 없다 |

두 종류에 같은 이름을 쓴다. **배정 알고리즘이 축과 소유자에 무관하게 같기 때문이다**(`assignTracksLeftEdge`).
`column` 은 코드에서 두 뜻으로 쓰인다(`ColumnCluster` = 기둥, `columnSwitch` = 트랙 열). `innerColumnChannel` 은
뒤의 뜻을 따른다. 앞의 뜻과 헷갈릴 자리에서는 *기둥*이라고 쓴다.

## 하지 않는 것

- **오늘 배치의 분포로 기준을 세우지 않는다.** 오늘 산출물에는 오늘 모델이 통과시킨 것만 있다. 실측은 회귀 검사로만 쓴다.
- **밖의 통로를 재설계하지 않는다.** 열 채널과 행 채널은 그대로 둔다. 교차로 격자는 `J-관리관` 이 맡는다.
- **내부 행 채널을 모듈 폭 전체로 관통시키지 않는다**(v1 = 내부 (E)). 이 판단은 `J-내부교차` 가 맡는다.
- **블루프린트를 관통하는 가로 벨트를 만들지 않는다.** *모듈 전용*은 *남이 못 쓴다*는 뜻이다. `J-관통허용` 이 맡는다.
- **형태 판정은 처리량이 정한 `g`(`bundleCap`)만 읽는다.** `planBundles` 가 깊이로 깎은 `g` 는 기둥 수의 **결과**다. 그것을 읽으면 되먹임이 생긴다.
- **가운데 길의 차선을 끊지 않는다**(v1). 끊으면 배달함을 세울 자리가 없다(계획서 §2.6).
- **배정이 실패했다고 기둥 수를 바꿔 다시 돌리지 않는다**(되먹임 0). 판정이 불확실하면 `C = 1` 로 간다.
- **좌석 한계를 형태로 풀지 않는다.** `Σ팔 > 2h+2w` 는 머신 수와 인서터로 풀 문제다.
- **Step 1 은 먼저 앉은 줄의 도형을 바꾸지 않는다.** 교차를 만든 gap 줄이 잠수로 값을 치른다(계획서 §4 Step 1).
- **포트 인서터 수는 건드리지 않는다.** `known-limits` §13 의 몫이다. **DAG·트리 구조도 건드리지 않는다.**

## 실제로 밟은 함정

| 무엇 | 왜 그랬나 |
|---|---|
| **초판 Step 0 이 "오늘 배치를 계측한다" 였다**(2026-09-04, 사용자 지적으로 철회) | *새 기능의 근거를 옛 산출물에서 찾으려 했다.* 오늘 트리는 오늘 모델이 받아들인 것이라, 격자가 필요한 입력은 거기 **있을 수가 없다.** 같은 규율이 `자리-배정`(D3)에 이미 있었는데 그 문서를 읽고도 옮겨 오지 못했다 |
| **초판 §3.4 의 판정식이 틀렸다**(2026-09-04) | *"긴 줄이 `2R` 을 넘으면 격자"* 는 **모듈 전체 슬롯**과 **머신당 슬롯**을 섞었다. 자원을 셀 때 *누구의* 자원인지를 적지 않으면 이 실수가 난다 |
| **"`C = 2` 는 공짜" 를 조건 없이 적었다**(2026-09-04 → 2026-09-23 정정) | 공유 내부 열 채널의 도달(`N`)만 보고 **바깥 두 면의 도달이 `N/2` 로 준다**는 것을 세지 않았다. 위 함정과 같은 종류다. 이번에는 *어느 줄이* 공유 자리를 받는지를 적지 않았다 |
| **내부 (E) 를 "교차 0" 이라 적었다**(2026-09-04 → 2026-09-23 정정) | 채널 **안**만 보고 **출구**를 보지 않았다. gap 벨트는 옆 변으로 나가는 순간 옆면 세로 벨트를 건넌다. 그것이 D8 이었다 |
| **일괄 치환이 축을 뒤집었다**(`04bcf82` 2026-09-07 → 2026-09-23 발견) | `띠 → 행 채널` 을 기계적으로 바꾸다가 **기둥 사이 세로 띠**(= 내부 열 채널)까지 행 채널이 됐다. 계획의 핵심 문장(`C = 2`)이 2주 동안 축이 뒤집힌 채 남아 있었다. 유(類) 이름을 지울 때는 자리마다 종(種)을 골라야 한다 |
| **종횡비를 "근거 없는 취향 값 `k`" 로 남겼다**(2026-09-04 → 2026-09-24 사용자 제안으로 유도) | 트렁크가 **이미 `g` 대마다 끊겨 있다**는 것을 보지 않았다. 기둥이 `g` 대보다 길면 그 초과분은 배달함을 하나도 아끼지 못한다. 그러니 높이의 근거는 처음부터 입력에 있었다. *"취향"* 이라고 적기 전에 *"이 값이 무엇을 사나"* 를 먼저 물어야 한다 |
