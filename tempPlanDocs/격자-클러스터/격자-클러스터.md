# 격자 클러스터 — 방법론

## 0. 한 줄 요약

**첫 물음은 "격자를 어떻게 만드나" 가 아니라 "언제 기둥 대신 격자를 쓰나" 다.**
그 기준은 **유도된다** — 실물 배치에서 관측하는 것이 아니다(§1.1).

유도해 보니(Step 0 · [조사-형태판정.md](조사-형태판정.md)) 답이 상식과 다르다:

```
격자는 **머신 한 대가 받을 수 있는 것을 하나도 안 늘린다.**
  좌석 2h+2w 도, 머신에 닿는 관통 줄 2R 도 그대로다.
형태가 정하는 것은 **포트 수와 모듈 치수**뿐이다.
  그리고 내부 (E)(가로 띠를 자기 기둥 안에 둠)에서는 **치수뿐**이다.
```

**그래서 격자는 가동률로 정당화되지 않는다.** 형상(치수)이 이유이거나, 아니면
가로 띠를 기둥 밖으로 관통시켜(내부 (B)) 포트를 사야 한다 — 그건 교차를 치르는 별개 결정이다.

이 문서는 **방법론**이다: §1 순서 · §2 이미 있는 것 · §3 판정 · §4 행 채널과의 관계 ·
§5 규율 · §6 단계.

## 1. 순서 — **기준이 먼저다**

```
① 언제 기둥 대신 격자인가 — **기준**      ← 이것부터.  없으면 나머지가 무의미하다
② 머신 100% 가동                          ← 목적.  다만 §3 이 보이듯 **형태가 이걸 못 산다**
③ 형상(종횡비·면적)                        ← 비용.  (E) 격자의 **유일한** 근거다
```

### 1.1 기준은 **실측이 아니라 유도**다

**초판의 Step 0(오늘 배치 계측)을 철회했다.** 재려던 것과 안 되는 이유:

| 재려던 것 | 얻으려던 힌트 | 왜 안 되나 |
|---|---|---|
| 실패 이름표 분포 | 격자가 필요한 입력이 실재하나 | 오늘 트리는 **오늘 모델이 받아들인 것**이다. 격자가 필요한 입력은 거절됐거나 만들어진 적이 없다 |
| gap 이 열리는 빈도 | 가로축이 쓰이나 | *안 쓰인다*가 **필요 없다**인지 **못 쓴다**인지 못 가른다(오늘 코드는 가로 줄이 두 대를 못 먹인다) |
| 종횡비 | 얼마나 늘어지나 | **계산으로 나온다**(`(N/C)·h + Σ띠`). 실행할 이유가 없다 |

그리고 이건 저장소가 이미 내린 판단이다 — `자리-배정/judgements.md` 머리말:
*"분포는 무엇이 흔한지를 말할 뿐 무엇이 옳은지를 말하지 않고, 모드팩이 바뀌면 분포도 바뀐다.
트리거는 전부 **입력의 성질**로 적는다."*

**실측이 들어오는 자리는 회귀 검사 하나다** — 유도한 식이 `C = 1` 에서 오늘 값을 재현하나.

### 1.2 기준이 `②`보다 먼저인 이유 — **확인됐다**

§3.1 이 보인다: 머신 한 대의 좌석은 어느 형태에서도 `2h + 2w`, 닿는 관통 줄은 `2R`.
**기둥이 gap 을 다 열면 격자와 같다.** 그러니 *"100% 가동이 안 되니까 격자"* 는 성립하지 않는다.
가동이 막힌 이유가 좌석이면 격자로도 안 풀리고, 그 안이면 형태와 무관하게 앉는다
(막히면 `g` 를 내려 앉힌다 — 포트가 늘 뿐이다).

## 2. 이미 있는 것 — **새로 만드는 것은 셋뿐이다**

| 있는 것 | 어디 | 그래서 |
|---|---|---|
| 자리마다 다른 띠 폭 | `layoutCluster(rowGap)` 가 배열을 받는다 | 자료구조가 **가로축은 이미** 격자를 받는다 |
| 폭 역전(배정 → 폭) | `gapRowsFromPlans` · `channelWidthFromTracks` | 같은 원리가 세 층에. 네 번째로 같은 것을 한다 |
| 구간 겹침 → 최소 트랙 | `assignTracksLeftEdge` · `planRowChannel` | **축과 무관한 순수 배정.** 내부 채널에 그대로 |
| 면 좌석표 | `planner/module/faceTable.ts` | 칸 = `(행, 깊이)`. **낟알만** 면 → 띠로 |
| 머신 자기 면에서 깊이 재기 | `emitModule` 의 `mExt` gap 분기 | 격자의 기하가 **이미 절반 있다** |
| 내부 띠 벨트가 변에서 꺾여 **평범한 변 포트**가 되기 | `emitOutputLinks` 의 모서리 포트 | 밖의 장부가 **새 도형을 안 배워도 된다** |
| 모듈 범위 = 머신 ∪ 셀 | `moduleTransform.moduleExtent` | 넓어진 모듈을 배치가 이미 셈에 넣는다 |
| **판정에 필요한 수 전부** | `clusterBeltDepthsOf`(R) · `faceSeatArms`(좌석) · `bundleCap`(g_max) · `columnTapCapacity`(2R) | **전부 배정 전에 답이 나온다** → 형태를 입력으로 둘 수 있다([조사](조사-형태판정.md) §1) |

**새로 만드는 것 셋:**

```
① 형태 판정        입력 → (C, 어느 경계에 띠)                 ← Step 0 이 골격을 냈다
② 장부의 낟알      표를 **면마다** 가 아니라 **띠마다** 한 장으로  ← Step 1 이 리허설
③ 내부 열 채널     그 배정과 폭 — ②의 전치(轉置)
```

## 3. 판정 — 형태가 **무엇을 바꾸고 무엇을 못 바꾸나**

> 유도 전문과 코드 근거는 [조사-형태판정.md](조사-형태판정.md). 여기는 결론만 옮긴다.

### 3.1 면의 제약은 셋이고, 형태는 그중 **하나만** 건드린다

```
① 좌석   Σ_j a_j(m, f) ≤ faceSeatArms(f)         면마다.  d1 칸이 물리로 그것뿐
② 깊이   그 면에서 **전 구간을 덮는 줄** 수 ≤ R_f   ← 토막 난 줄들은 한 깊이를 나눠 쓴다
③ 포트   Σ_j ⌈N ÷ reach_j⌉
```

| | 격자가 바꾸나 | 왜 |
|---|---|---|
| ① 좌석 | **아니다** | 머신의 면은 어느 형태에서도 넷. `2h + 2w` 가 상한이고 기둥도 gap 을 열면 같다 |
| ② 깊이 | **머신 하나에는 아니다** | 모듈 전체 관통 슬롯은 `2R → 최대 2RC` 로 늘지만, **클러스터는 같은 레시피 N대**라 모든 머신이 같은 품목을 받아야 한다. 머신에 닿는 면은 여전히 W·E뿐 |
| ③ 포트 | **바꾼다** | 줄의 도달(`reach`)이 형태로 바뀐다 — 아래 |

> **초판 §3.4(`L_long > 2R → 격자`)를 여기서 철회한다.** *모듈 전체 슬롯*과 *머신당 슬롯*을
> 섞은 식이었다. 늘어나는 것은 앞이고 막는 것은 뒤다.

### 3.2 형태가 바꾸는 것 — 도달, 그래서 포트

```
포트 수 P(C) = Σ_j ⌈ N ÷ reach_j(C) ⌉        reach_j = min(g_max_j, 그 줄이 닿는 대수)

세로(관통)   기둥 C=1              닿는 대수 = N
             격자 + **공유** 내부 띠  = 2·(N/C)     ← C=2 면 **N 그대로**
             격자 + 전용(넓은) 띠    = N/C
가로(gap)    기둥 · 내부 (E)        = 2   (오늘 코드는 1 — [조사](조사-형태판정.md) §3)
             내부 (B)              = 2C
```

내부 띠 폭이 도달을 정한다(전치 계산, `ℛ={1,2}`): 폭 3 → 공유 1줄 · 폭 4 → 공유 2줄 ·
폭 6 → 공유 0(좌·우 각자 2줄). **폭 역전이 여기서도 손잡이다.**

### 3.3 그래서 기준

```
① Σ_j a_j(m) > 2h + 2w        → **어떤 형태로도 안 된다.**  머신 수·인서터의 몫이다
② 그 안이면 가동은 형태와 무관   → 막히면 `g` 를 내려 앉는다(포트가 늘 뿐)
③ 형태는 **포트 수와 치수**를 고르는 일:

   C = 1     기본.  세로 도달이 가장 크다
   C = 2     **특이점 — 공짜다.**  공유 내부 띠의 도달이 2·(N/2) = N 이라 **포트가 안 는다.**
             높이 절반 · 폭은 기둥 하나 + 띠(3~4칸)만큼
   C ≥ 3     도달이 2N/C 로 줄어 **포트를 팔아 형상을 산다**
   내부 (B)  가로 도달 2 → 2C.  gap 으로 밀린 품목의 포트가 준다.  **교차를 치른다**
```

**검산:** `C = 1` 이면 관통 슬롯 `2R` — `columnTapCapacity = 2 × |reaches|` 와 같다. ✔

### 3.4 `C = 2` 가 공짜인 것이 이 계획의 실질이다

같은 줄 수 · 같은 포트 수 · **높이 절반**. 기둥 20대가 `13×64`(1 : 4.9)이던 것이
두 기둥이면 대략 절반 높이가 된다. **다만 값이 하나 붙는다** — 공유 내부 띠의 벨트는
세로로 달려 **N/S 변으로 나간다.** 그 통로가 행 채널이고, 계획이 아직 없다(§4).

### 3.5 가로 띠도 길어질 수 있다 — 그러면 교차로가 생긴다

격자에서는 가로 띠가 기둥 여럿을 가로질러 한 줄이 `2C` 대를 먹일 수 있다. **그 순간 내부 열
채널과 지상 교차가 난다.** 밖에서 같은 문제에 `(E)`를 고른 것처럼 안에도 두 길이 있다:

```
내부 (E) — v1   가로 띠를 **자기 기둥 안**으로 → 교차 0.  가로 줄은 2대짜리로 남는다
내부 (B)        가로 띠를 모듈 폭 전체로 → 한 줄이 2C 대.  **교차 해소가 필요하다**
```

**v1 은 (E)다.** 그리고 §3.1 이 보였듯 (E)의 근거는 **형상 하나**이므로, 형상을 원하지
않는다면 v1 은 켤 이유가 없다 — 그 판단이 `J-형상기준` 이다.

## 4. 행 채널(⑤)과의 관계 — 접점 셋

### 4.1 재사용 — 전치 기계는 하나다

`assignTracksLeftEdge`(구간 겹침 → 최소 트랙)와 그것을 감싼 `planRowChannel` 은 축과
무관하다. **내부 채널도 같은 것을 쓴다.**

### 4.2 비대칭 — 순환은 밖에만 있다

```
밖   topY → 포트 절대 y → 띠를 지나는 경로 → 띠 폭 → topY     ← 순환. 두 패스가 필요하다
안   배정(plans) → 띠 폭 → 머신 좌표                           ← 한 방향. 오늘 gap 이 그렇다
```

밖의 띠를 지나는 것은 *남의* 절대 좌표에 달렸고, 안의 띠를 지나는 것은 **자기 줄**이라 좌표
전에 안다. 그래서 두 계획은 서로를 기다릴 필요가 없다.

### 4.3 되먹임 — **나가는 변이 순서를 가른다**

```
innerRowChannel     가로로 달리다 W/E 변에서 꺾인다(출력 W · 입력 E)
                    → 나가는 곳이 **세로 채널**.  오늘 있는 통로다        → ⑤ 와 무관
innerColumnChannel  세로로 달리다 N/S 변에서 꺾인다
                    → 나가는 곳이 **행 채널/마진**.  계획이 없다          → **⑤ 가 선행**
```

> **§3.4 의 `C = 2` 가 여기에 걸린다.** 공짜 형상을 실제로 쓰려면 그 포트가 N/S 로 나가야
> 하고, 오늘 그 자리가 `planned = 0` 이다. **행 채널 모델이 이 계획의 선행 조건이다.**

## 5. 방법론 — 판정 순서와 규율

### 5.1 [[layout-models]] §5 의 질문

| 질문 | 답 |
|---|---|
| 0. 도형인가 자리인가 | **자리** — 그리고 §3 이 *어느 자리인지*(포트·치수)까지 좁혔다 |
| 0b. 절대 좌표로 쓰나 | 아니다 — 모듈 로컬. 그래서 양보가 아니라 **자원 재배치**가 답이다 |
| 1. 어느 모델인가 | ① 모듈 모델. ②는 `extent` 만 본다(`moduleExtent` 가 이미 견딘다) |
| 2. 그릴 수 있나 | **아니다** — ①의 *못 그리는 것* 첫 줄이 격자다 |
| 3. 접점이 바뀌나 | **안 바뀐다** — 내부 채널 벨트는 모듈 변에서 꺾여 *평범한 변 포트*가 된다(`emitOutputLinks` 의 모서리 포트가 이미 그렇다) |

### 5.2 데이터냐 분기냐 — [[code-folders]]

| 축 | 자원의 **종류**가 바뀌나 | 판정 |
|---|---|---|
| 내부 행 채널을 두 머신이 공유 | 아니다. *같은 칸을 두 표가 본다* 가 바뀐다 | **낟알**(면 → 띠) |
| 기둥 수 `C` | 아니다 | **값** |
| 내부 열 채널 | 아니다 — 전치다 | **값 + 낟알 재사용** |

**새 분기 0.** 격자는 경우의 수를 곱하지만 **경로를 더하지 않는다.**

### 5.3 되먹임 0을 지킨다

`generateModule` 은 트리마다 한 번만 돈다. 형태를 두 반쪽으로 가르면 그 값이 지켜진다:

```
기둥 수 C          배정의 **입력**    ← §3.3 의 식이 입력만 보고 답한다([조사](조사-형태판정.md) §1)
띠를 여나 · 폭      배정의 **부산물**  ← 오늘 gap 이 이미 그렇다
                                       (spillLinkFacesToGap → gapRowsFromPlans)
```

`C` 는 작은 정수라 **열거로 고른다**(1..4 를 다 계산해 `P(C)` 와 치수를 비교) — 최적화가
아니라 셈이다.

### 5.4 무엇으로 재나

```
1차   판정이 **입력만으로** 답하나 (코드로 읽어 확인) · C=1 에서 오늘 값을 재현하나
2차   머신 100% 가동 — unrouted-lines = 0 · DepthShortage 이름표.  **형태와 무관해야 정상이다**
3차   형상 — extent 종횡비 · 면적.  동반으로 **포트 수 · 채널 폭**을 함께 적는다
회귀  flg.check() 위반 0 유지
도구  flg.run() → copy(flg.report()) → flg.check() → flg.face(모듈, 면)
금지  **오늘 배치의 분포를 기준의 근거로 쓰기**(§1.1) · 스크린샷 눈대중
```

### 5.5 실행 규율

- **다음 한 단계만 확정한다.** 뒤 단계는 방향으로 적는다.
- **불변은 기전으로.** *"산출물이 안 바뀐다"* 를 불변으로 쓰지 않는다.
- **판단을 중복해서 만들지 않는다.** *생긴 교차를 어떻게 푸나*는 `행채널-모델` 의 `J-교차`
  를 상속한다. 이 폴더가 갖는 것은 *교차를 만들 것인가*(`J-내부교차`)뿐이다.

산출은 [조사-형태판정.md](조사-형태판정.md) 이고, 결론은 §3 이다.

> **착수해 보니 초판의 식이 틀렸다.** *"긴 줄이 `2R` 을 넘으면 격자"* 는 **모듈 전체 슬롯**과
> **머신당 슬롯**을 섞은 것이었다. 코드를 읽어 셋을 가르고 나서야(좌석·깊이·포트) *격자가
> 건드리는 것은 포트와 치수뿐*이 드러났다. **그래서 §1 의 순서 판단이 옳았다** — 기준을 먼저
> 세우지 않았으면 *"가동이 안 되니 격자"* 라는 틀린 근거로 만들 뻔했다.

```
전제:  형태를 가르는 값이 전부 좌표·배정 전에 계산된다        → 확인됨(조사 §1 전수표)
불변:  기준이 C = 1 에서 오늘 용량과 같은 수를 낸다            → 확인됨(2R = columnTapCapacity)
관문:  **언제 격자를 쓰는지에 답이 생긴다**                     → 열렸다(§3.3)
```

**남은 빈칸 넷**(조사 §6): 유체 면의 `R` 감소 · 못의 되먹임 · 치수 식 · 가로 띠의 실제 능력.
넷 다 **다음 단계의 입력이 아니라** 정밀도의 문제라, Step 1 을 막지 않는다.

### Step 1 — 내부 행 채널을 **진짜 띠로** 만든다 *(다음 단계)*

`tryLinkFace` 의 `machinesOn(group, side) !== 1` 을 푼다 — 가로 벨트 한 줄이 위·아래 **두 대**를
먹인다. **모델과 코드의 거리를 좁히는 일이다**([조사](조사-형태판정.md) §3: 모델은 2대·`R`줄,
코드는 1대·1줄).

```
전제:  표가 면마다 한 장이라 두 머신이 같은 벨트 행을 공유하는 것을 **표현할 수 없다**
       확인 = gapRowsFromPlans 가 마주 보는 두 면을 **더한다**(공유하면 이중 계산이 된다)
불변:  좌석은 여전히 띠의 양 끝 행에만 앉는다 — 그 사이가 벨트다
       (기전: 팔이 집는 칸이 `좌석 ± reach` 라 띠 폭이 `2 + 벨트 줄 수` 로 유일하게 정해진다)
관문:  ① 좌석 예산 `2h → 2h+2w` 가 **실물이 된다**(오늘은 가로 줄이 한 대만 맡아 절반이다)
       ② 표의 낟알을 면 → 띠로 옮겨, 내부 열 채널(Step 3)을 **형태를 안 바꾼 채** 리허설한다
       ③ 내부 (B)의 값(`2C`)을 잴 수 있게 된다 — 그 전엔 잴 대상이 없다
```

### Step 2 — 방향: 기둥 수 `C` 를 입력으로

`layoutCluster` 가 `dx` 를 낸다(+ `size.w` 를 positions 에서 유도 → `bbox`·ring 이 따라온다).
`C` 의 출처는 §3.3 의 셈이다. **`C = 2` 부터 시작한다** — 공짜인 지점이라 값을 가장 싸게 보인다.

**내부 열 채널 없이 `C` 만 늘리는 배치는 만들지 않는다** — 두 기둥이 서로의 안쪽 면을 뺏어
순수한 손해다.

### Step 3 — 방향: **내부 열 채널** — Step 1 의 전치

표(띠마다 한 장) · 폭 역전(`colGapsFromPlans`) · 배정(gap 스필의 세로판). 새 알고리즘 0.

### Step 4 — 방향: N/S 출구 — **행 채널 모델(⑤)이 선행**(§4.3).

> **순서가 §3.4 로 굳었다.** `C = 2` 의 값이 N/S 출구에 걸려 있으므로, ⑤ 없이는 Step 2·3 이
> 배치에서 값을 못 낸다. 계획 둘의 순서를 여기서 확정해 둔다.
