# 격자 클러스터

## 0. 한 줄 요약

**격자는 머신 한 대가 받을 수 있는 것을 하나도 늘리지 않는다.** 좌석 `2h+2w` 도, 머신에 닿는 관통 줄 `2R` 도
그대로다. 오히려 **머신의 자유로운 면을 줄인다**(§2.6). 격자가 사는 것은 **모양**이고, 그 값은 배달함(포트)이다.
그래서 모양은 **값을 안 치르는 데까지만** 산다 — 기둥 높이를 트렁크가 실제로 들르는 머신 수에 맞춘다(§2.5).

```
Step 1  gap 출구의 교차를 장부에 올린다 (= D8)   ← 확정.  오늘 배치에 있는 결함이다
Step 2  gap 벨트 한 줄이 위·아래 두 대를 먹인다    ← 방향.  모델과 코드의 거리를 좁힌다
Step 3  기둥 수 C + 내부 열 채널                  ← 방향.  기준은 §2.7
```

## 2. 판정 — 형태가 바꾸는 것과 못 바꾸는 것

### 2.1 기준은 유도한다

오늘 배치의 분포로는 기준을 세울 수 없다. 격자가 필요한 입력은 오늘 모델이 거절했거나 애초에 만들어지지 않았다.
판정에 드는 수는 **전부 배정 전에 답이 나온다.** 그래서 `C` 를 배정의 **입력**으로 둘 수 있고, 되먹임 0 이
지켜진다([[module-planning]] §4.6).

```
R_f     clusterBeltDepthsOf   reach 종류 수. 유체 면은 depthCap 으로 깎인다.  장부를 안 읽는다
좌석    faceSeatArms          W/E = h, N/S = w (유체 행을 뺀다)
g       bundleCap             min(N, ⌊벨트 처리량 ÷ 한 대 소비량⌋) — 처리량만 본다
L       줄 수                 그 레시피가 받고 내는 아이템 품목 수
2R      columnTapCapacity     ← C = 1 회귀 검산:  기준식에 C = 1 을 넣으면 이 값과 같아야 한다
```

### 2.2 면의 제약은 셋이고, 형태가 건드리는 것은 하나다

```
① 좌석  Σ_j a_j(m,f) ≤ faceSeatArms(f)     형태가 안 바꾼다.  머신의 면은 어느 형태에서도 넷이고 2h+2w 가 상한이다
② 깊이  전 구간을 덮는 줄 ≤ R_f            머신 하나에게는 안 바꾼다.  클러스터는 같은 레시피 N대라 모든 머신이
                                           같은 품목을 받는다.  늘어나는 것은 모듈 전체 관통 슬롯뿐이다
③ 포트  Σ 길마다 ⌈들르는 수 ÷ g⌉          **바꾼다**.  한 차선이 들르는 머신 수가 형태에 달려 있다
```

②는 관통 줄에만 걸린다. 토막 난 줄(`g < N`)은 구간이 안 겹쳐서 한 깊이를 나눠 쓴다(`depthClear` 는 겹침만 본다).
**다만 ①②는 "그 면을 쓸 수 있을 때" 의 이야기다** — 격자는 일부 면을 제한된 면으로 바꾼다(§2.6).

### 2.3 차선이 들르는 머신 수 — 길 셋

```
                                  들르는 수      끊을 수 있나
바깥 길(모듈 변에 닿는 옆면)        N/C            있다 — 토막의 배달함을 옆에 세운다
가운데 길, 공유 차선(폭 R+2)        2N/C           없다 — 양옆이 다른 차선과 반대편 좌석이다
가운데 길, 전용 차선(폭 2R+2)       N/C            없다 — 같은 이유
골목(gap)                          모델 2 · 코드 1 (Step 2) · 내부 (B) 2C
```

폭과 공유 차선 수의 관계는 [[trunk-blocked]] §5 의 gap 폭 표를 90° 돌린 것이다(`ℛ={1,2}` 면 폭 4 에 공유 2줄,
폭 6 이면 공유 0). **폭 역전이 여기서도 손잡이다.** 가운데 길의 차선은 **끝까지 달리는 줄 전용**이고,
그 끝은 모듈 위/아래 변 한가운데로 나가 행 채널을 탄다.

### 2.4 트렁크는 이미 `g` 대마다 끊겨 있다

벨트 한 줄은 `g` 대까지만 먹인다. 머신이 더 많으면 **`g` 대마다 토막 나고 토막마다 배달함이 선다.** 그러니
기둥이 `g` 대보다 길어도 그 줄의 배달함은 줄지 않는다.

```
N=20 · 줄 A(g=15) · 줄 B(g=7)                    C=1         C=2 (바깥 길 둘, 10대씩)
  A   20 ÷ 15 → 2 토막                           2           10 ÷ 15 → 1 × 2 = 2     그대로
  B   20 ÷ 7  → 3 토막                           3           10 ÷ 7  → 2 × 2 = 4     +1 (반올림)
```

```
g ≤ 기둥 높이인 줄   바깥 길에서 끊으면 된다.  손해는 반올림뿐 — 줄마다 최대 C−1
g > 기둥 높이인 줄   바깥 길로는 토막이 는다.  가운데 길(두 기둥을 들른다)에 앉아야 하는데
                    공유 차선은 R 개뿐이고 끊을 수 없다(g ≥ 2N/C 여야 한다)
```

2026-09-23 판의 *"`C=2` 는 `#{j : g_j > N/2} ≤ R` 일 때 공짜"* 는 이 표의 둘째 줄을 `C=2` 에 적용한 것이다.

### 2.5 형태 기준 — 기둥 높이 = 가장 긴 트렁크의 방문 수 (2026-09-24 사용자)

```
G = max_j g_j            (C=1 에서 트렁크로 서는 줄들 중 — 깊이 예산(planBundles)을 C=1 로 셈한다.  입력만 본다)
기둥당 머신 수 ≤ G   →   C_목표 = ⌈N ÷ G⌉
```

- **가장 긴 트렁크는 배달함이 안 는다.** 기둥 하나에 토막 하나씩, 합이 `⌈N ÷ G⌉` 로 오늘과 같다. 짧은 줄의 손해는 §2.4 의 반올림뿐이다.
- **트렁크가 하나도 안 서면 높이가 아끼는 것이 없다.** 그때 모양을 막는 것은 자격(§2.6)뿐이다.
- **비율이 아니라 "기둥당 머신 수" 로 적는다.** 비율은 머신 크기·채널 폭에 따라 흔들리지만 방문 수는 머신 단위다.
- **`G ≥ N` 이면 `C = 1`.** 벨트가 전부를 한 번에 먹이면 긴 기둥은 제값을 하는 높이다. 그래도 낮추는 것은 `J-형상손잡이`.
- **벨트 등급이 모양을 정한다.** 빠른 벨트 → `g` 가 크다 → 기둥이 길다. **형태 악화가 아니다**(사용자 확인) — 배달함을 아끼는 높이다.
- **`g` 는 처리량이 정한 값(`bundleCap`)이다.** `planBundles` 가 깊이 예산으로 더 깎은 `g` 는 `C` 가 바꾸는 면 수에 달려 있어, 읽으면 되먹임이 된다.

### 2.6 자격 — **격자는 머신의 면을 줄인다** (2026-09-24 사용자 질문)

기둥이 여럿이면 기둥 사이 옆면은 **가운데 길**을 보게 된다. 가운데 길의 차선은 끊을 수 없고(§2.3), 골목의 출구도
그쪽으로는 못 나간다(출구가 모듈 변이 아니다). 그래서 기둥마다 머신이 **자유롭게** 쓸 수 있는 면이 다르다:

```
                   옆면 — 모듈 변 쪽           옆면 — 가운데 길 쪽               위·아래(골목)
C=1 기둥            ×2  무엇이든                —                               출구 있음
바깥 기둥 (C≥2)     ×1  무엇이든                ×1  끊지 않는 줄만                 출구 있음 — 모듈 변 쪽으로만
안쪽 기둥 (C≥3)     —                          ×2  끊지 않는 줄만                 출구 없음
```

*무엇이든* = 관통 · 토막 · 머신별(`g=1`) 줄. 토막의 배달함과 골목 출구가 옆에 설 자리가 있다.
*끊지 않는 줄만* = 그 차선이 들르는 머신 전부를 한 벨트가 감당하는 줄(`g ≥` 들르는 수). **한 면에 R 개까지** —
인서터가 닿는 깊이가 그것뿐이다.

```
안쪽 기둥의 자격    L ≤ 2R   그리고   그 L 개가 모두 끊지 않고 달린다(g ≥ 들르는 수)
바깥 기둥의 자격    ⓐ 트렁크  C=1 에서 트렁크로 서는 줄이 이 기둥에서도 트렁크 차선을 하나씩 얻는다
                            (기둥 하나의 트렁크 차선 = 모듈 변 쪽 R 개 + 가운데 길 쪽 R 개(끊지 않는 줄만))
                   ⓑ 좌석    머신별 줄이 앉을 좌석 = 모듈 변 쪽 h + 골목 2w      (C=1 은 2h + 2w)
```

**예 (2026-09-24 사용자):** `N=16` · `g=4` · `R=1` · 재료 5종 + 산출 1 = `L=6` · 머신 3×3

```
트렁크  R=1 이면 면마다 깊이가 하나다.  줄 여섯 중 하나라도 머신별(g=1)이면 그 깊이를 머신별 줄 몫으로
        예약하므로(trunk-assignment §4.2), C=1 에서 트렁크로 서는 줄이 **0** 이다.  G 는 모양을 정하지 않는다
C=4·3   안쪽 기둥이 생긴다.  L=6 > 2R=2                                           ✗  가운데 기둥이 재료를 다 못 받는다
C=2     바깥 기둥 둘.  ⓐ 지킬 트렁크가 없다.  ⓑ 좌석 3 + 3 + 3 = 9 ≥ 6               ✓
C=1     좌석 12.  배달함 수는 C=2 와 같다(전부 머신별 줄)                            ✓  같은 값에 두 배 길다
→ C=2 (기둥 둘 × 8대).  4×4 는 가운데 두 기둥 때문에 안 되고, 기둥 하나는 얻는 것 없이 길기만 하다
```

**재료가 많을수록 기둥 수의 상한이 낮아진다** — 안쪽 기둥(`C ≥ 3`)은 `L ≤ 2R` 인 레시피만 받는다. 그보다 많은
줄을 안쪽으로 보내려면 가운데 길 안에서 차선을 갈아타야 하는데(dogleg · 지하), 그건 `J-교차` ⓑⓒ 와 (B)의 몫이다.

### 2.7 판정 순서 — Step 3 의 기준

```
⓪ 유체 노드면 C=1                                   J-유체기둥이 풀릴 때까지
① 자격   안쪽 기둥이 생기는 C 는 L ≤ 2R 이고 전부 끊지 않고 달릴 때만   §2.6
② 바깥   C=1 의 트렁크가 모든 기둥에서 트렁크 차선을 얻고, 좌석이 맞나      §2.6 ⓐⓑ
③ 모양   ①②를 통과한 C 중 C_목표(§2.5) 이하에서 가장 큰 것
④ 없으면 C=1                                        오늘 동작을 이어 간다
```

**전부 입력만 본다**(`L` · `R` · `g` · `N` · 좌석) — 배정 전에 답이 난다. *"C=1 에서 트렁크로 서는 줄"* 은
[[trunk-assignment]] §4.2 의 깊이 예산 부등식을 `C=1` 로 고정해 셈한 것이라 `C` 에 기대지 않는다. ⓑ의 좌석은
팔 수(`armsFor`)로 센다. 판정이 애매한 입력은 `C=1` 로 간다.
**배정이 실패했다고 `C` 를 바꿔 다시 돌리지 않는다**(되먹임 0).

### 2.8 내부 (E) · (B) — 그리고 **출구는 이미 교차다**

```
(E) — v1  내부 행 채널(gap)을 자기 기둥 안에 둔다   → 내부 열 채널과 교차 0.  가로 도달 2
(B)       모듈 폭 전체로 뻗는다                     → 가로 도달 2C.  내부 열 채널과 교차한다
```

**(E)라고 교차가 0 인 것은 아니다.** gap 벨트는 기둥의 옆 변으로 나가 포트가 된다. 그런데 그 변에는 옆면 세로
벨트가 **기둥 전체를 덮으며**(gap 행 포함) 달린다. 오늘은 아무도 이 교차를 모른다. 면 표의 행은 머신 행뿐이고
(`module/ledger/face.ts` *"머신 사이 gap 을 안 세지만…"*), 방출 안전망이 뒤늦게 줄을 버린다. **그것이 D8 이다.**
옆면과의 교차는 C = 1 에서 이미 풀어야 하고(Step 1), 그 해법인 잠수는 (B)의 교차 해법과 같은 도형이다.

## 4. 단계

### Step 1 — gap 출구의 교차를 장부에 올린다 (= D8) *(확정 · 승인 대기)*

**푸는 문제.** gap 그룹의 포트가 옆면 관통 벨트 위에 선다. 방출 안전망이 그 줄을 버리고, 그래서 부모의
입력 포트가 생기지 않는다. 결과는 `link-mismatch` 로 번진다.

**실측** — 대조 32 픽스처 × 플래그 다섯에서 안전망 **630회가 전부 한 모양**이다([[work-kinds]] §7 D8 의 표).

```
gap 그룹의 포트 상자가 옆면 d2 의 gap 행에 선다 · 그 칸을 틈을 가로지르는 옆면 d2 벨트가 지난다

            M0 열       E d1   E d2
 y=2       ███████       i      ║      ║ = 옆면 d2 벨트. 여러 머신을 맡아 gap 행도 지난다
 y=3       ·  i  ·       ·      ║      M0 의 S 면 좌석
 y=4       ◀══════       i      ▣      gap 벨트 → 포트 인서터(d1) · 상자(d2)  = 벨트 칸  ✗
 y=5       ███████       i      ║
```

**전제** (근거 문장):

- 면 표에는 gap 행이 없다. `face.ts`: *"행 = 머신index × rowsPerMachine + 면에서의 칸. 머신 사이 gap 을
  안 세지만 사상이 단조라 '두 구간이 겹치나' 는 실제와 같은 답을 준다."* 겹침 판정은 맞다. 하지만 **gap 행에
  서는 칸**은 표 밖에 있다.
- gap 은 자리를 묻지 않는다. `seat.ts fitOnGap`: *"깊이가 언제나 LINK_LANE_DEPTH 라 고를 것이 없고 자리만 묻는다.
  장부는 읽기만 한다(좌석 수 · 그룹 수)."*
- 모델은 gap 행을 교차 자리로 이미 적어 두었다. [[trunk-blocked]] §5: *"gap 행은 세로 트렁크가 공짜로 잠수하는
  자리다 … 그 행에는 어차피 탭이 없다."*
- 지하 규칙은 다 있고 부를 자리만 없다. `자리-배정` J12: *"간섭 규칙·자료형·입구 방향 제약·방출이 전부
  구현돼 있다. 없는 것은 '모듈 안쪽 트렁크 계획이 그것을 부를 자리' 하나다."*
- 틈을 지나는 옆면 칸은 **벨트뿐**이고, 막는 벨트의 **역할은 가리지 않는다**. gap 좌석이 먼저 서고 옆면 줄이
  **나중에** 오는 순서도 있다([[work-kinds]] §7 *"D8 을 고칠 사람에게"*).

**무엇을 하나 — gap 줄이 잠수한다.**

```
① 셈   gap g 에서 옆면 f 를 건너는 깊이 = f 의 확정 배정(두 역할 모두) 중 구간이 머신 g 와 g+1 을 함께 덮는 것.
       그 면에 ClusterPipe 가 있으면 그것도 건넌다.  잠수 길이 = 건너는 최대 깊이 + 1.
       **확정 배정에서 유도한다**(gapRowsFromPlans · linkFaceDepths 와 같은 파일) — 그래서 앉는 순서와 무관하다
② 자격 배정 때(fitOnGap) 확인한다.  지하벨트가 없거나 사거리 < 그 면에서 건널 수 있는 최대 깊이 + 1 이면
       — 입력만으로 아는 상한(clusterBeltDepthsOf, 유체 면은 파이프 몫까지)이다 — gap 출구를 거절한다.
       방출까지 가서 버리지 않는다.  거절하면 seatLinkEdge 가 양끝을 함께 미배정으로 두므로 불일치는 기전으로 사라진다
③ 사유 넘침 단계(spillPair · spillLinkFacesToGap)는 tryLinkFace 를 why 없이 부르고 fitOnGap 도 사유를 안 남긴다.
       거절 사유가 화면까지 오는 길을 낸다
④ 도형 module/shape/body 의 gap 분기.  건너는 깊이가 있으면 기둥 변 칸에 입구, 그 바깥 첫 빈 깊이에 출구,
       포트는 그 바깥이다.  건너는 깊이가 없으면 오늘 도형 그대로다.
       입출구 칸에서 인서터가 집을 수 있는지는 확인하지 않았다 — 확인 전에는 포트 앞에 지상 한 칸을 덧댄다
⑤ 장부 run/ledger.terminusCorridorsOf 는 "모듈 셀 중 지하벨트 입구가 곧 종착" 이라고 전제한다.  그 전제가
       **깨진다** — 짝이 있는 잠수는 [입구, 출구] 구간으로 따로 읽는다(지금대로면 최대 사거리로 과잉 예약된다).
       새 장부는 두지 않는다(잠수 길이는 파생값).  두게 되면 cloneLinkFaceStage 에 싣는다
```

**왜 옆면 관통이 아니라 gap 줄이 잠수하나** — 모델 문장은 *세로 트렁크*가 잠수한다고 적었다. 이 계획은 그 문장을 따르지 않는다:

```
               옆면 관통이 잠수 (모델 문장)              gap 줄이 잠수 (채택)
순서           먼저 앉은 줄의 도형을 뒤 단계가 바꾼다      마지막에 앉은 줄이 자기 값을 치른다
건너는 수      관통마다 잠수가 하나씩                     출구마다 하나
입출구 자리    gap 행 안에 둘 다 있어야 한다. 폭 2 인 gap   한 행 안에서 가로로 끝난다
               이면 출구가 다음 머신의 탭 행에 떨어진다
               (J12: "탭 구간은 반드시 지상")
```

**불변** (기전):
- 옆면에 gap 을 건너는 것이 없으면 도형은 오늘과 같다. ④는 건너는 깊이 집합이 비어 있으면 다른 답을 낼 수 없다(단위 시험으로 못 박는다).
- 먼저 앉은 줄의 칸은 하나도 바뀌지 않는다. 잠수는 gap 줄 자기 도형 안에서만 일어난다.
- 되먹임 0. 잠수 길이는 확정 배정의 파생값이고, 자격은 입력만 본다.

**관문:**
- **방출 안전망 두 곳**(`emitInputLinks` 구간 · `emitOutputLinks` 포트)이 **발동할 수 없게 된다.** 배정이 교차를 알면
  방출이 새 사실을 만날 자리가 없다. 확인: [대조시험.test.ts](대조시험.test.ts) 플래그 다섯에서 `netTrips` 630 → 0.
- `link-mismatch`(플래그별 78 · 78 · 42 · 0 · 96)는 사라지거나(지하벨트 있음) **배정 단계 사유로 바뀐다**(`item-no-ug`).
- `flg.check()` 위반 0. 잠수한 gap 줄의 머신이 `flg.flow.machines()` 에서 미달로 나오지 않는다(흐름 모델은 지하를 보존으로 센다).
- 문서: work-kinds §7 D8 을 닫는다 · [[trunk-blocked]] §5 의 잠수 문장을 *누가* 잠수하는지까지 고친다(그 문장의 "TR7 (가)" 도 §3 번호로는 (나)다) ·
  [[trunk-assignment]] §0 의 TR7 행을 갱신한다 · `자리-배정` J12 에 부를 자리가 섰다고 알린다.

### Step 2 — 방향: gap 벨트 한 줄이 위·아래 두 대를 먹인다

- **모델:** [[trunk-blocked]] §5. 폭 3 이면 공유 1줄, 폭 4 면 공유 2줄이고, gap 은 두 대마다 하나(`⌈N/2⌉`)다. **코드:** `fitOnGap` 의 `machinesOn !== 1`, 벨트는 언제나 d2.
- **얻는 것은 좌석이 아니다.** `2h+2w` 는 오늘도 한 대짜리 그룹으로 N·S 를 둘 다 쓴다. 얻는 것은 gap 으로 간 품목의 **줄·포트·gap 높이가 반으로** 주는 것이다.
- **낟알:** gap g 를 **표 한 장**(내부 행 채널)으로 둔다. 오늘은 S(g)와 N(g+1) 두 표가 따로 세고 `gapRowsFromPlans` 가 둘을 **더한다.** 벨트를 공유하면 이 계산이 이중 계산이 된다.
- **생산자가 없다(기전).** `fitOnGap` 만 풀면 실물은 거의 바뀌지 않는다. 두 대짜리 줄을 gap 으로 보내는 곳이 없기 때문이다:
  ```
  planBundles   넘친 줄을 g=1 로 내린다  — depth.ts   "gap 도 같은 이유로 machinesOn !== 1 을 거절한다"
  붓기          넘치는 머신의 줄을 1:1 로  — arith/link "이 제약은 gap 능력의 그림자다"
  ```
  예외는 좌석이 넘친 자연 `g = 2` 줄(이웃한 두 대) 하나뿐이다. **두 그림자 중 어느 쪽을 걷어내나**가 착수 때 정할
  첫 물음이다. `g` 셈을 바꾸는 길이 있고, 넘침 단계에서 같은 품목의 이웃 두 `g=1` 그룹을 합치는 길이 있다.
- Step 3 의 리허설이다. 두 머신 줄이 표 한 장을 마주 보는 모양은 내부 열 채널을 90° 돌린 것이다.

### Step 3 — 방향: 기둥 수 `C` + 내부 열 채널

- **기준은 §2.7 이다** — 자격 → 트렁크 → 모양, 없으면 `C=1`. 입력만 본다.
- **둘은 함께 간다.** 내부 열 채널 없이 `C` 만 늘리면 두 기둥이 서로의 안쪽 면을 빼앗는다. §2.6 의 *"가운데 길 쪽"* 칸이 통째로 사라지는 셈이다.
- **가운데 길의 폭은 역전으로 정한다.** 공유 차선이 필요한 줄(g ≥ 2N/C)이 있으면 폭 R+2, 전용 차선만이면 2R+2, 둘 다 없으면 좌석 두 줄만.
- **정밀도 빈칸 셋:** 유체 면의 `R` 감소(`depthCap`) · 못(포트가 늘면 못이 늘고, 못은 다른 줄의 구간을 자른다 — [[module-planning]] §4.6 (2)) · 치수(채널 폭은 배정의 부산물이다).
- **깨지는 기둥 전제:** `face.ts` *"W/E 는 둘이 같다(모든 머신의 x 가 같다)"* · `body.ts` `mExt` *"W/E 면은 기둥이라 모든 머신의 x 가 같아…"* · `cluster.ts` `size.w = meta.w` · 골목 출구 방향이 **역할(출력 W · 입력 E)이 아니라 기둥의 모듈 변 쪽**을 따라야 한다 · 트렁크 파이프는 한 줄(`J-유체기둥`).
- **N/S 출구는 이미 있다.** 가운데 길 벨트는 N/S 변으로 나가 기둥 끝 포트처럼 행 채널을 탄다. 반출(광선 `perimeter/shape/rays`)이 모듈 한가운데의 N/S 포트를 받는지는 착수 때 확인한다.

## 5. 재는 법 · 규율

```
1차   판정이 입력만으로 답하나(코드로 읽어 확인) · C=1 에서 2R = columnTapCapacity
2차   머신 100% 가동 — flg.flow.machines().  **형태와 무관해야 정상이다**
3차   형상 — 기둥당 머신 수 ≤ G 인가 · extent 면적.  포트 수와 채널 폭을 함께 적는다
회귀  flg.check() 위반 0 · 대조 32 픽스처 × 플래그 다섯의 netTrips
금지  오늘 배치의 분포를 기준의 근거로 쓰기 · 스크린샷 눈대중
```

- **다음 한 단계만 확정한다.** Step 1 을 끝낼 때 Step 2 의 전제를 다시 확인한다.
- **불변은 기전으로 적는다.** *"산출물이 안 바뀐다"* 는 불변으로 쓰지 않는다. 이 단계의 비교 대상에는 D8 이 들어 있다.
- **판단은 한 곳에만 둔다.** *생긴 교차를 어떻게 푸나*는 `채널-양보-명세` 의 `J-교차` 가 갖는다. 이 폴더가 갖는 것은 *교차를 만들 것인가*(`J-내부교차`)뿐이다.
