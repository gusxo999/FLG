# 반출-환승 — self 반출도 **통로의 자리를 받는다**

**한 줄 요약:** 반출 경로 하나가 통로를 **자리도 안 받고 세로로 관통**한다. 그 관통이 남의
가로선을 밟는 조건은 **로컬 x 두 개를 비교하면 나온다.** 밟으면 환승시킨다 — 환승할 후보
목록은 **이미 만들어져 있고 아무도 안 읽는다.**

> **범위 축소 (2026-09-07).** 이 계획은 `채널-교통관리관` 이었고 행 채널 전체를 도형 장부로
> 올리려 했다. 잣대를 세우고 다시 재니 **위반자가 하나뿐**이라 그만큼으로 줄였다 —
> 근거는 §2.7.

---

## 1. 잣대

> **통로의 칸을 쓰면 그 통로가 배급하는 자리를 받아야 한다.**
> 통로마다 배급하는 자리는 **한 종류**다 — 열 채널은 세로 트랙, 행 채널은 가로 트랙.

이 저장소는 이미 그렇게 돈다. 자리가 모자라면 **통로가 넓어진다**(폭 역전). 열 채널의
배정은 문자 그대로 트랙 1개부터 시작해 안 들어가면 하나씩 넓히며 다시 푼다:

```ts
for (let T = 1; T <= cap && !solved; T++) { if (search(0, T, acc)) solved = acc; }
```

**폴백은 이 사다리의 마지막 칸이지 해답이 아니다.**

---

## 2. self 반출 — 무엇이고, 특권이 언제 깨지나

### 2.1 반출이 무엇인가

모듈은 저마다 *"자기가 루트인 척"* 생성되므로, 외부에서 넣고 빼야 하는 무한상자가 **그 모듈
자신의 테두리**에 앉는다. 모듈들을 깊이 열로 타일링하면 그 테두리가 **조립 결과의 한복판**이
된다 — 상자가 블루프린트 속에 갇힌다. 그래서 살아남은 외부상자를 **전역 외곽 변**으로
옮긴다. 그 옮기는 길이 **반출 경로**다.

반출은 **되돌릴 수 있는 손해**다. 실패해도 상자는 원래 자리(로컬 ring)에 남고 물류는 돈다 —
외곽 대신 안쪽에 있을 뿐이다. 그래서 배정 우선순위에서 유체 납품 다음, 아이템 납품 앞이다.

### 2.2 출구는 넷이고, 그중 둘만 자리를 먹는다

`enumerateOptions` 가 상자 하나마다 **쓸 수 있는 출구를 선호 순으로 전부** 나열한다:

| 출구 | 무엇 | 통로의 자리를 먹나 |
|---|---|---|
| `self` | 자기 열에서 **N/S 로 직진**해 바깥 변까지 | ❌ **안 먹는다** |
| `margin` | 맨 끝 열에서 바깥 W/E 마진으로 직출 | ❌ 안 먹는다 |
| `channel` (가까운 변) | 옆 **열 채널**로 가로 진입 → 채널 안에서 세로 주행 → N/S 변 | ✅ 트랙 하나 |
| `channel` (먼 변) | 같은 것, 반대쪽 변으로 | ✅ 트랙 하나 |

`margin` 은 **바깥**이라 다툴 것이 없다(진짜로 빈 자리다). **문제는 `self` 하나다.**

### 2.3 `self` 의 거래 — 자리를 안 받는 **대신 자유도가 0이다**

방출을 보면 거래가 그대로 보인다:

```ts
// self / margin — 직선. 옆으로 비킬 폭(offsets)이 **[0] 뿐이다**
tryNS(anchor, edgeCoord(edge, perimeter), occ, [0])

// channel — 예약된 트랙 + 실패하면 ±maxJog 스캔
if (hint.trackX !== undefined) offsets.push(hint.trackX - anchor.x);
for (let m = 1; m <= maxJog; m++) offsets.push(m * Math.sign(fv.x));
```

**`self` 는 한 칸도 못 비킨다.** 자기 상자의 x 그 한 열로 바깥까지 곧장 간다. 막히면 끝이다 —
`straight blocked to N` → `reservation not emittable` → **그 상자만 skip**(로컬 ring 에 남는다).

그리고 특권의 나머지 절반이 있다 — **예약 순서에서 앞선다.** 반출의 직선은 좌표가 서자마자
`reservedExportCells` 로 통째로 잡히고([modulePacking:1330]), 납품은 그 셀을 **막힌 칸으로
읽는다**(계획 체인도, 폴백 dijkstra 도). 즉 다투면 **반출이 이긴다.**

### 2.4 특권을 주는 조건 — **딱 하나만 묻는다**

```ts
const selfOpt = (e) =>
  can(e)                                   // 모듈 몸통이 그 방향을 막지 않나 (wayOuts)
  && !selfBlocked(p.depth, p.anchorY, e, ctx)   // ← 이것뿐이다
```

```ts
function selfBlocked(depth, anchorY, edge, ctx) {
  const spans = ctx.spansByDepth.get(depth) ?? [];   // 그 열의 **모듈 점유 구간**들
  …
  if (edge === "N" && b.top < myTop) return true;    // 나보다 위에 형제 모듈이 있나
  if (edge === "S" && b.bottom > myBottom) return true;
}
```

**묻는 것은 「같은 열에 나보다 바깥쪽 형제 모듈이 있나」 하나다.** 안 묻는 것:

```
행 채널의 가로 트랙       ← 그 직선이 반드시 지나는 통로다
다른 경로의 예약 셀
포트 사슬·합류 칸 (extent 안이지만 몸통은 아닌 칸)
```

### 2.5 **특권이 성립하지 않는 순간** — 부등식 하나로 나온다

형제 모듈이 없으므로 직선이 지나는 것은 이 셋뿐이다:

```
자기 모듈의 남은 몸통  →  **마진 행 채널**(높이 h)  →  바깥 perimeter 마진
```

그런데 마진 행 채널은 **바로 그 모듈의 기둥끝 납품이 가로로 달리는 통로**다. 그리고 그
가로선은 전부 **상자에서 그 열의 서쪽 변(로컬 x = 0)까지** 뻗는다([modulePacking:843]).
self 반출은 자기 상자의 한 열에 선다. 그러니:

```
반출의 로컬 x  =  cₓ
납품의 가로 구간 =  [0 … dₓ]        (dₓ = 그 납품 상자의 로컬 x)

밟는다  ⟺  cₓ ≤ dₓ
```

> ### **그 순간 = 반출 상자가 그 통로를 쓰는 어떤 납품 상자보다 서쪽(또는 같은 열)일 때.**

세로가 채널 **전 행**을 관통하므로 **어느 트랙 행이든 걸린다** — 납품의 트랙을 옮겨서는
못 피한다. 그리고 이 부등식은 **좌표가 필요 없다.** 로컬 x 둘이면 배정 시점에 계산된다.

관통이 아니라 **환승**이면(`host: channel`) 이야기가 다르다 — 그 경로는 열 채널에서 트랙을
하나 받고, 모자라면 채널이 넓어진다. **늘려서 풀린다.**

### 2.6 오늘 그 순간이 어떻게 나타나나 — **조용하다**

반출이 예약에서 이기므로 증상은 **반출이 아니라 납품에** 뜬다:

```
① 반출이 직선 셀을 통째로 예약한다                          (좌표 직후)
② 납품의 계획 체인이 그 셀을 지나면 → `chain-blocked:반출 예약` → 탐색 폴백
③ dijkstra 도 그 셀은 못 쓰므로 **우회한다** — 길은 난다
④ 우회도 못 하면 그 납품이 실패한다
```

**③이 압도적으로 흔하고, 실패가 아니라 저하다.** 화면에는 *"납품 N건이 탐색으로 떨어졌다"*
로만 뜨고, **그 원인이 반출이었다는 말은 어디에도 없다.**

### 2.7 왜 위반자가 이것 하나인가 — 나머지 둘은 이미 자리를 받는다

| 세로 주행 | 자리 | 왜 |
|---|---|---|
| **진입 다리** | ✅ 받는다 | 다리를 내는 납품은 **가로 트랙을 하나 갖는다.** 다리는 그 트랙에 닿는 부속이고, 모든 가로선의 서쪽 끝이 공통(`x1 = 0`)이라 **순환이 없어** 전순서가 교차를 없앤다(J-교차 ⓐ, 실측 폴백 2→0) |
| **세로 × 세로** | — | 같은 열에 둘이 서려면 같은 면·같은 깊이·같은 끝이어야 하는데 `ends`/`outside` 가 막는다. 반대쪽에서 오는 둘은 전순서가 가른다 |
| **self 반출** | ❌ **안 받는다** | §2.3~2.5 |

**행 채널은 열 채널보다 구조적으로 쉽다** — 가로선이 서쪽 끝을 공유해 순환이 안 생기므로
dogleg 도 지하도 원리상 필요 없다. 그래서 행 채널을 도형 장부로 올리는 큰 공사가 필요 없다.

## 3. 고칠 것은 **읽지 않는 배열 하나**다

`perimeterTrackPlanner` 가 이미 후보를 **선호 순으로 전부** 만들어 둔다:

```ts
export interface TrackAssignment {
  /** 쓸 수 있는 출구 후보들(선호 순, 전부 wayOuts 를 만족). …
   *  장부가 제약 때문에 다른 후보로 **양보**시킬 수 있다 — 그때 확정 필드도 함께 갱신한다. */
  options: TrackOption[];
  exitEdge: ExitEdge;   // ← 오늘은 언제나 options[0] 이 평평하게 복사된 값
  host: TrackHost;
  …
}
```

**그 「장부」가 없다.** `options` 를 읽는 코드가 `src/autoLayout` 전체에 **하나도 없다**
(2026-09-07 확인). 후보 목록은 만들어져서 그대로 버려진다.

그리고 순서가 이미 사다리 모양이다 — `self(가까운 변)` → `채널 환승(가까운 변·먼 변)` →
`self(반대 변)` → 남은 전부. **양보시킬 대상과 순서가 갖춰져 있고, 시키는 사람만 없다.**

---

## 4. 이 계획이 **안 푸는** 것

- **행 채널을 도형 장부로 올리지 않는다.** §2.7 이 필요 없다고 말한다. 측정이 그걸 뒤집으면
  그때 다시 연다.
- **열 채널의 폴백 도형.** 지상 배정에 실패한 경로는 `phantom` 이 **폭만** 잡고 실제 도형은
  dijkstra 가 정한다. 게다가 `phantom` 은 **세로선끼리만** 비교한다(주석이 의도를 밝힌다).
  열 채널에 남은 임시방편이고 **별개 항목**이다.
- **`margin` 출구.** 바깥이라 다툴 것이 없다.
- **`구간-밖-주행` A2**(기둥 밖 장부의 결정 이관) — 그 폴더에 남는다.
- **`wayOuts` 의 정확도** — 모듈이 답한 *"몸통에 안 막히는 방향"* 을 그대로 믿는다.

## 5. 단계

### Step 1 — **사유를 갈라 센다**

오늘 납품 폴백 사유는 *막은 칸의 주인*까지만 말한다. **반출 예약 때문인지**를 가른다.
그리고 §2.5 의 부등식(`cₓ ≤ dₓ`)을 만족하는 (반출, 납품) 쌍을 **배정 시점에** 세어,
방출에서 실제로 터진 수와 맞춰 본다.

- **전제:** 반출의 self 직선 셀은 `modulePacking:1330` 한 곳에서만 나온다. 납품이 그걸 막힌
  칸으로 읽는 곳도 `deliveryRoute:281` 한 곳이다.
- **불변:** 기전으로 — **세는 코드는 실패한 경로에서만 돌고 배정에 아무것도 안 넘긴다.**
- **관문:** *"납품 N건 폴백"* 이 **「반출이 밟아서」와 그 밖**으로 갈린다. 그리고 §2.5 가
  예측한 수와 실측이 **맞는지**가 이 계획의 문제 정의를 검증한다 — 안 맞으면 정의가 틀린
  것이고, 거기서 멈춘다.

### Step 2 — 밟으면 **환승시킨다**

배정 시점에 §2.5 의 부등식을 검사해, 밟는 self 후보를 **건너뛰고 다음 후보로 내린다.**
`options` 를 읽는 첫 코드가 된다.

- **전제:** 그 통로를 쓰는 납품의 로컬 x 는 `rowChannelNeeds` 의 `x2` 로 **이미 있다**
  (`planTracks` 보다 앞에서 만들어진다).
- **불변:** 기전으로 — **밟지 않는 반출은 `options[0]` 그대로다.** 검사가 거짓이면 다음
  후보를 보는 분기에 들어가지 않는다.
- **관문:** **밟는 반출이 트랙을 받는다.** 그 순간 채널 폭이 늘고, Step 1 이 센 「반출이
  밟아서」 폴백이 **0 으로 간다.** 늘어난 폭이 값이고, 그게 폴백보다 싸다는 것이 이 계획의
  주장이다.

### Step 3 — 남는 것을 정직하게 적는다 *(방향)*

후보를 다 내려도 자리가 없는 상자는 오늘처럼 로컬 ring 에 남는다. 그 사유를
*"나갈 길이 없다"* 와 *"양보하다 소진했다"* 로 가른다.

- **관문:** 남은 실패가 **몇 건이고 왜인지** 화면에서 세어진다.

---

## 6. 이게 끝나면 열리는 문

- **`options` 를 읽는 장부가 처음 생긴다.** 주석이 예고한 *"제약 센 곳부터 양보"* 가 실제로
  가능해진다 — 열 채널의 해소 사다리 ①(진출 변 뒤집기)과 같은 종류의 수단이 반출에 붙는다.
- **폴백 사유가 하나 갈린다.** *"납품이 탐색으로 떨어졌다"* 의 한 원인이 이름을 얻는다.
- **잣대가 코드로 선다** — *"통로를 쓰면 자리를 받는다"* 가 검사되는 자리가 하나 생기고,
  다음에 같은 위반이 들어오면 그 자리에 붙는다.
- **열 채널 폴백 도형**(§4)이 그다음 후보로 남는다 — 같은 잣대의 마지막 위반이다.
