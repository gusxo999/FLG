# tempPlanDocs/ — 착수 전 문서

**여기 있는 것은 아직 안 한 일에 대한 글이다.** 코드와 함께 사는 설계 문서는 `docs/` 에 있다.

## 구조 — 계획 하나 = 폴더 하나

```
tempPlanDocs/
├─ CLAUDE.md                       ← 공통 규칙 (이 파일)
└─ <계획이름>/
   ├─ CLAUDE.md                    ← **상태 + 이 작업 고유의 컨텍스트**
   ├─ <계획이름>.md                 ← 계획서: "이걸 하겠다"
   └─ judgements.md                ← 판단: "아직 안 골랐다" (필요할 때만)
```

**폴더명과 계획서 파일명이 같은 것은 의도다.** 파일명이 `plan.md` 면 여러 계획을 동시에
열었을 때 탭도 grep 결과도 구분이 안 된다.

**`CLAUDE.md` 는 중첩된다** — 이 파일(공통)과 계획 폴더의 것(고유)이 **함께** 로딩된다.
그러니 계획 폴더의 `CLAUDE.md` 에 공통 규칙을 복사하지 않는다. 갈린다.

## 계획 폴더의 `CLAUDE.md` 에 들어갈 것

### ① 상태 — 첫 줄에

```
> 상태: 승인 대기 | 진행 중 | 완료(폐기 예정) | 보류(트리거 대기)
```

**커밋하기로 하면서 생긴 유일한 새 위험이 이것이다.** git 밖에 있을 땐 낡은 계획서가
로컬만 더럽혔지만, 이제는 저장소에 남아 **다음 세션이 그것을 현재로 읽는다**
(`docs/CLAUDE.md`: *"틀린 문서는 다음 세션을 적극적으로 오도한다"*).

상태는 파일을 열면 자동 로딩되므로 **못 보고 지나칠 수 없다.** 그게 이 자리에 두는 이유다.

### ② 착수 전 반드시 읽을 것

이 작업의 전제가 되는 코드·문서를 **경로로** 적는다. 계획서 본문에 묻어 두지 않는다 —
자동 로딩되는 자리에 있어야 실제로 읽힌다.

### ③ 하지 않는 것

이 계획이 **의도적으로 손대지 않는** 범위. 없으면 착수한 사람이 범위를 넓힌다.

## 두 장르 — 계획서와 판단 문서

| | 주장 | 수명 |
|---|---|---|
| **계획서** | *"이걸 하겠다. 승인해 달라"* | 실행하면 폐기 |
| **`judgements.md`** | *"여기가 어긋나 있다. 길은 셋이고 아직 안 골랐다"* | 트리거가 당겨질 때까지 |

### 왜 판단이 `docs/` 로 가지 않나

`docs/CLAUDE.md` **Q2** 는 *"코드를 바꾸면 무효가 되나"* 로 자리를 가른다. 판단 문서는
그 질문에 답할 수 없다 — **코드를 안 바꿔도 무효가 된다.** 실물 트리가 달라지거나
우선순위가 바뀌면 그날로 전제가 썩는다. `docs/` 에는 그 부패를 잡을 장치가 없다.

**예외 — `docs/` 가 맞는 경우:** 어긋남이 **이미 출시된 코드에 실재**하면 그건 판단이
아니라 **사실**이다. `module-planning.md` §5("남는 비대칭")가 그 예다 — 장부 낟알이
실제로 다르고, 그 사실은 코드를 바꿔야만 무효가 된다. Q2 를 통과한다.

> **판정 한 줄:** 코드를 안 바꿔도 틀려질 수 있나 → 예면 `judgements.md`.

## `judgements.md` 에 반드시 있어야 할 것

### ① 착수 조건 (트리거)

**없으면 위시리스트가 된다.** 관측 가능한 사건이나 셀 수 있는 수치로 적는다.

```
좋음:  emitModule.ts:523 의 안전망이 실제로 발동하면 착수. 지금까지 발동 0건.
좋음:  실물 트리에서 이 경우가 N건 이상이면 착수. 0에 가까우면 영구 보류.
나쁨:  여유가 생기면 / 언젠가 / 리팩토링할 때
```

### ② 코드 역참조 — **이게 도달 경로다**

트리거가 발생하는 **그 코드 자리**에 한 줄 주석을 남긴다.

```ts
// 이 안전망이 발동하면 tempPlanDocs/<계획>/judgements.md 를 본다 — 착수 근거다.
```

문서가 코드를 가리키는 것만으로는 부족하다. **트리거를 만나는 사람은 코드를 보고 있지
문서를 보고 있지 않다.** 2026-07-29 실측(`docs/CLAUDE.md`): 들어오는 간선이 표 하나뿐인
문서는 아무도 못 찾는다.

### ③ 전제와 작성일

판단은 **전제와 함께 썩는다.** 무엇을 참으로 놓고 판단했는지 적는다 — 다음 사람이
*"그 전제가 아직 참인가"* 만 확인하면 문서 전체의 유효성을 판정할 수 있다.

### 견적표에 "목표"라고 이름 붙이지 않는다

같은 표라도 `목표 상태` 라고 쓰면 다음 세션이 로드맵으로 읽고, `비용 견적` 이라고 쓰면
견적으로 읽는다. **아직 안 골랐다는 사실이 이름에 남아야 한다.**

## 생애 — **끝나면 지운다**

```
계획서 ──승인──> 실행 ──> 폴더째 삭제 (커밋 히스토리에 남는다)
judgements ──트리거──> 계획서로 승격 ──> 원본 삭제
           └──전제 부패──> 삭제 (갱신하지 않는다 — 다시 조사하는 게 싸다)
```

### 삭제가 규칙이다

**계획을 실행하고 나면 그 폴더를 지운다.** 완료 표기로 남겨 두지 않는다.

| 왜 | |
|---|---|
| **컨텍스트가 계속 산다** | 계획 폴더의 `CLAUDE.md` 는 그 폴더를 건드릴 때마다 로딩된다. 끝난 작업의 *"착수 전 읽을 것"* 과 *"하지 않는 것"* 이 살아 있으면 다음 작업의 판단을 오염시킨다 |
| **현재가 둘이 된다** | 실행이 끝나면 **코드가 사실**이다. 그 코드를 설명하는 글은 `docs/` 에 있어야 하고, 계획서는 *"하려던 것"* 이라 둘이 어긋나기 시작한다 |
| **되찾을 수 있다** | 커밋하므로 삭제는 파괴가 아니다. *"혹시 몰라 남긴다"* 는 옛 감각은 git 밖에 있던 시절의 것이다 |

**남길 값이 있는 내용은 지우기 전에 옮긴다** — 설계 근거는 `docs/`, 작업 습관은 메모리,
미결 판단은 `judgements.md`(그 폴더가 아니라 후속 계획 폴더로). 옮길 데가 없으면
남길 값이 없는 것이다.

### 지우지 않는 유일한 경우

`judgements.md` 는 **계획서가 실행돼도 남을 수 있다** — 트리거가 아직 안 당겨졌으면
그 판단은 여전히 미결이다. 이때는 폴더를 지우면서 `judgements.md` 만 후속 계획
폴더로 옮기거나, 트리거가 사라졌으면 함께 지운다. **판단만 남은 빈 폴더를 두지 않는다.**

**결론이 난 판단은 판단이 아니다.** 계획서로 옮기고 원본은 지운다. 둘 다 남기면 어느
쪽이 현재인지 알 수 없게 된다.

## 옛 평면 문서

루트에 폴더 없이 놓인 `.md` 는 이 구조 이전의 것이다. 그 문서를 다시 손댈 때 폴더로
옮긴다 — **일괄 이관하지 않는다**(상태를 모르는 계획서에 상태를 지어내게 된다).
