# 채널 교통관리관 — 행 채널도 **도형**으로 신고받는다

**한 줄 요약:** 열 채널에는 모든 경로를 도형으로 받아 함께 배정하는 관리관이 있다.
행 채널에는 없다 — 가로 구간 하나만 받는다. 그래서 그 통로를 지나는 **세로 주행 둘**이
어느 장부에도 없다. 관리관을 전치해서 세운다.

---

## 1. 푸는 문제

### 1.1 한 통로를 셋이 지나는데, 장부는 하나만 안다

행 채널(모듈 행 사이의 가로 통로)을 실제로 지나는 것은 셋이다:

```
① 통과 가로선      납품이 행 채널을 가로로 달리는 부분        ✅ 신고된다
② 진입 다리        포트 상자 → 자기 트랙 행까지의 **세로**     ❌ 방출이 그 자리에서 그린다
③ self 반출 세로선  상자 → 바깥 N/S 변까지의 **세로**          ❌ 좌표가 선 뒤 사후 기록
```

신고 자료가 이게 전부다:

```ts
export interface RowCrossing { id: string; side: "top" | "bottom"; x1: number; x2: number; }
//                                                                ~~~~~~~~~~~~~~~~~~~~~~~~
//                                                                **가로뿐**
```

②는 방출의 한 줄이 그린다 — `if (g.fromRowChannel) push(s)`.
③은 `planTracks` 가 `{kind:"self"}` 로 정하고, 셀은 `modulePacking` 이 **좌표가 선 뒤**에
`addSeg(anchor, {x: anchor.x, y: seatRow})` 로 적는다. **행 채널은 그걸 볼 시각에 없다.**

### 1.2 그래서 무슨 일이 나나

**세로끼리 부딪힌다.** 두 다리가 같은 열을 공유해도 장부는 못 본다 — 각자 신고한 가로
구간이 **길이 0**(상자가 이미 서쪽 변에 있다)이면 배정은 *"안 겹친다"* 며 다른 트랙을 주고,
실제로는 같은 x 를 함께 올라간다. 2026-09-06 실측:

```
행 채널 자리:  d1 marginN,  트랙 [#0→0, #3→1]
신고한 가로:   #0 x0..0 · #3 x0..0        ← 둘 다 길이 0
실제 다리:     #0 행 0 → -4 · #3 행 6 → -3  ← **같은 열을 함께 올라간다**
```

**세로가 남의 가로를 가로지른다.** 오늘은 `side`(위에서 오나 아래서 오나) 하나로 **전순서**를
만들어 막는다(J-교차 ⓐ). 다리끼리는 막히지만, 그 근거는 *"서쪽 끝이 공통"* 이라는 **가정**
하나이고 — `rowChannelPlanner` 머리말이 그 가정을 명시하고 *"공통이 아니면 옛 left-edge 로
떨어진다(교차 보장 없이)"* 고 적는다. **전순서는 도형 장부의 근사다.**

**반출은 아예 밖에 있다.** self 반출은 마진 행 채널을 **세로로 관통**하는데, 행 채널은 그걸
모르고 반출도 행 채널의 트랙을 모른다. 부딪히면 납품 방출이 예약 셀을 막힌 칸으로 읽고
**탐색 폴백**으로 떨어진다 — 실패가 아니라 저하라 화면에 안 뜬다.

### 1.3 왜 「관리관」인가 — **이미 반쪽은 있다**

열 채널은 이 문제가 없다. 왜냐하면:

| | 열 채널 | 행 채널 |
|---|---|---|
| 신고 | `Shape { h[], v[] }` — **가로·세로 둘 다** | `{x1, x2}` — 가로만 |
| 관리 대상 | 납품 **+ 반출**을 한 장부에서 | 납품만 |
| 충돌 판정 | 셀 단위(`shapesConflict`) | 구간 겹침 |
| 산출 | 배정 결과에서 폭 유도 | 배정 결과에서 높이 유도 (같음) |

**그리고 이미 1패스다** — `planChannelGeometry` 가 폭보다 **먼저** 돌고, `channelWidth` 가
그 `trackCount` 에서 폭을 유도하고, 뒤의 `materializeChannelGeometry` 는 **재계획이 아니라
번역**이다. 즉 우리가 원하는 구조가 이미 한쪽에서 돌고 있다.

### 1.4 전치가 성립하는 근거

행 채널의 프레임은 **(로컬 x 열, 추상 트랙 행)** 이다. 열 채널의 (추상 트랙 열, 절대 행)을
90° 돌린 것이다. 둘 다 **주행축은 추상, 직교축은 실제**다.

- **직교축(x)에 로컬을 쓰는 것이 정확한 이유:** `절대 x = colX[깊이] + 로컬 x` 이고
  (배치가 `shiftModule(m, colX[d] − ext.x, …)` 로 **강제**한다), **한 행 채널의 신고자는 전부
  같은 깊이**다. 공통 상수라 겹침도 동등성도 답이 같다.
- **왜 절대 x 를 못 쓰나:** 의존 사슬이 `행 채널 높이 → topY → 열 채널 폭 → colX` 다.
  **행 채널이 사슬의 맨 앞**이라 기댈 절대 x 가 아직 없다. 열 채널이 자기 주행축(x)에
  추상 트랙을 쓰는 것과 정확히 같은 이유다.
- **주행축(행)에 추상을 쓰는데 높이가 아직 없는 문제:** 열 채널이 이미 답을 갖고 있다 —
  **고정 상한(`cap`)** 을 두고 도형을 그린 뒤 폭을 결과에서 줄인다. 행 채널도 같다.

### 1.5 다리가 그 프레임에서 어떻게 표현되나

```
가로선   h: 행 t, 열 [x1 … x2]                      (오늘 신고하는 것)
다리     v: 열 x2, 행 [t … cap−1]   (side = bottom)  ← 아래에서 올라온다
         v: 열 x2, 행 [0 … t]       (side = top)     ← 위에서 내려온다
```

이 표현이 **전순서를 대체한다.** 두 다리가 같은 열이면 `[t₁…cap−1]` 과 `[t₂…cap−1]` 이 반드시
겹치므로 배정이 거절한다. 다리가 남의 가로선을 가로지르는 것도 셀 비교로 그냥 나온다.
`cap` 값에 답이 안 달린다 — 양쪽이 같은 상한을 쓰기 때문이다.

self 반출도 같은 어휘로 들어온다: **열 = 상자의 로컬 x, 행 = 채널 전체** (통로를 통째로
관통하므로).

---

## 2. 이 계획이 **안 푸는** 것

- **겹쳤을 때 다른 도형을 고르는 것.** 이 계획은 **⑴ 발견**까지다. 다리의 x 는 상자 위치라
  고를 수 없으므로, 겹치면 오늘처럼 폴백한다. **⑵ 해결**(dogleg·지하)은 J-교차 ⓑⓒ 다.
  → 그러니 **이 계획이 끝나면 조용하던 것이 시끄러워진다.** 그게 관문이지 회귀가 아니다.
- **모듈 몸통을 뚫는 다리.** gap 포트의 다리가 자기 모듈 몸통을 지나는 건 모듈 층 문제다
  (*"그 포트가 애초에 못 나온다"*). 사유만 갈라 보여 준다.
- **열 채널.** 계단꼴·절단선·같은 쪽 판정·지하 횡단 전부 그대로.
- **기둥 밖 장부(`outside`)의 결정 이관.** `구간-밖-주행` A2 로 남는다 — 이 계획 **뒤**다.
- **왼쪽 정렬 항등식.** 보류(2026-09-07 지시).

## 3. 단계

### Step 0 — 규칙 ②를 고친다 (코드 변경 0)

`docs/auto-layout/common/pipeline-lifecycle.md` §5 규칙 ②(*"두 좌표계가 만나는 자리를
의심한다"*)는 **틀렸다.** 그 표의 세 줄이 전부 안 물리고, 셋 다 같은 이유다:

> **장부가 「순서」만 묻는다면 순서를 보존하는 좌표 변경은 답을 못 바꾼다.**
> `faceTable` 머리말이 이미 그렇게 적어 뒀다 — *"사상이 **단조**라 「두 구간이 겹치나」는
> 실제와 같은 답을 준다"*.

뒤집어 적으면 참이 되고, 그때 **진짜 감시 대상**이 나온다: 자리를 묻는 장부는 오늘
`outside`(`${끝}:${오프셋}:${깊이}` 동등성) 하나뿐이고, **이 계획이 둘째를 만든다**
(다리가 같은 열인가). §6 의 다섯 함정도 다시 분류하면 ②는 0건이다.

- **전제:** 규칙 ②의 세 줄이 전부 순서 질문이다 — 확인은 위 세 코드 자리.
- **불변:** 없다(문서만).
- **관문:** 착수한 사람이 **없는 위험을 고치러 가지 않는다.** 틀린 규칙 하나가 다음 시도를
  오도한다 — 실제로 2026-09-07 에 *"정렬 가정에 단언을 걸자"* 는 제안을 낳았다.

### Step 1 — 행 채널 신고를 **도형**으로 올린다

`RowCrossing` 을 `Shape` 로 바꾼다. 프레임은 (로컬 x 열, 추상 트랙 행), `cap` 은 열 채널과
같은 방식의 고정 상한. 배정은 `channelGeometryPlanner` 의 `shapesConflict` 를 그대로 쓴다.

가로선은 오늘 값 그대로(`x1..x2`), 다리는 `side` 와 배정 트랙에서 **유도된다** — 새로 정할
값이 없다.

- **전제:** 다리는 **상자의 x 에서 수직**이고 `side` 가 방향을 말한다 —
  `buildPlannedChain` 이 그렇게 그린다(`{x: s0.x, y: rowChannel.row}`). 확인은 그 한 줄.
- **불변:** *"산출물이 안 바뀐다"* 를 쓰지 않는다. 대신 **기전**으로 적는다 —
  **v 조각이 없는 신고는 오늘과 같은 답을 낼 수밖에 없다**(가로만 있는 도형끼리의
  `shapesConflict` 는 구간 겹침과 동치다). 다리가 있는 신고에서만 답이 갈린다.
- **관문:** **두 다리가 같은 열을 공유하는 입력에서 배정이 다른 답을 낸다.**
  의도로 짠 케이스로 건다 — 가로 구간 길이 0 둘 + 같은 로컬 x + 다른 트랙 희망.
  오늘은 *"안 겹친다"* 고 답하고, 이후엔 거절하거나 같은 트랙으로 몬다.

### Step 2 — 트랙 수가 다리를 센 결과가 된다

`planRowChannel` 의 `trackCount` → `height` 경로는 그대로 두되, 입력이 도형이므로
**높이가 다리 수요를 반영해 커질 수 있다.**

- **전제:** 높이 유도(`channelWidthFromTracks(n, ROW_CHANNEL_MIN)`)는 축과 무관하다 —
  이미 열 채널과 공유하는 함수다.
- **불변:** 통과 경로가 0인 행 채널은 `planRowChannel([])` 로 `ROW_CHANNEL_MIN` 을 낸다 —
  **입력이 빈 배열이면 도형이든 구간이든 같은 코드 경로다.**
- **관문:** 전순서(J-교차 ⓐ)를 **지울 수 있다.** 도형이 교차를 직접 보므로 `side` 기반
  정렬은 근사로서의 역할이 끝난다. 지우고도 답이 서면 근사가 대체된 것이다.

### Step 3 — self 반출을 신고자로 만든다 *(방향)*

self 반출은 마진 행 채널을 관통하는 **세로 도형 하나**다. 열 채널이 채널 반출을
`ExportInput` 으로 받는 것과 같은 자리다.

**장애물이 하나 있고, 그게 이 단계가 「방향」인 이유다.** `planTracks` 는 `topY` 를 받으므로
행 채널 **뒤**에 선다. 그런데 행 채널이 self 반출을 신고받으려면 **앞**에 서야 한다 — 순서
고리다. 끊는 후보는 `planTracks` 의 host 판정(N/S 중 어느 변이 가까운가 · 형제가 막나)을
**좌표가 아니라 순번**으로 내리는 것이다. 이 저장소가 두 번 쓴 수다(행 채널 배정, 중앙 정렬).

- **전제(확인 필요):** host 판정이 **순번만으로** 나온다. `planTracks` 를 끝까지 읽고
  `absPortY` 가 실제로 어디에 쓰이는지 확인한 뒤에 확정한다.
- **관문:** **self 반출이 마진 행 채널의 트랙을 실제로 소비한다** — 반출이 지나가면 통과
  납품이 다른 트랙으로 밀린다.

### Step 4 — 사유를 가른다 *(방향)*

`reservation not emittable: <reason>` 과 `chain-blocked:` 에 *"행 채널에서 세로가 겹쳤다"* 를
별개 사유로 넣는다.

- **관문:** ⑵ 해결(J-교차 ⓑⓒ)이 필요한 건수가 **화면에서 세어진다.** 이 계획이 시끄럽게
  만든 것이 얼마나 되는지 안 세면 다음 계획의 착수 근거가 안 생긴다.

---

## 4. 이게 끝나면 열리는 문

- **행 채널이 열 채널과 같은 기계가 된다.** 지금은 *"90° 돌린 같은 기계"* 라고 적혀 있지만
  실제로는 한쪽만 도형을 안다. 그 문장이 참이 된다.
- **전순서(J-교차 ⓐ)가 근사에서 정확으로 바뀐다.** *"서쪽 끝이 공통"* 이라는 가정과
  *"공통이 아니면 교차 보장 없이 떨어진다"* 는 갈래가 함께 사라진다.
- **J-교차 ⓑⓒ 의 착수 근거가 수로 생긴다** — Step 4 가 세는 건수가 곧 트리거다.
- **`구간-밖-주행` A2 가 다시 설 수 있다.** A2 가 막힌 이유가 *"포트를 기둥 끝으로 더 보내면
  다리가 더 드러난다"* 였다. 다리가 장부에 있으면 그 이득이 폴백으로 안 샌다.
- **`셀장부` 계획 4 가 등록할 자료가 완성된다** — 가로선만이 아니라 다리와 self 반출까지.
