# 채널-교통관리관 — 상태와 고유 컨텍스트

> 상태: **승인 대기** — 계획서 **재작성**(2026-09-07).
>
> **한 문장:** 다툼을 **늘릴 수 있는 자원**으로 보낸다. 폴백은 해답이 아니다.
>
> **첫 판을 버렸다.** *"다리의 x 는 상자 위치라 고를 수 없으니 겹치면 폴백"* 으로
> 끝났는데, 그 전제가 **검증되지 않았고 실제로 틀렸다** — 다리를 내는 것은 `portEnd` 포트이고
> 그 x 는 **면의 깊이 열**이라 `clusterBeltDepthsOf` 후보 중에서 **고른다**.
> 근거로 쓴 실측 사유 둘(`남의 납품 예약` · `모듈 몸통`)도 **다리 × 다리가 아니었다.**
> 계획서 §5 에 어디가 어떻게 틀렸는지 적었고, **Step 1 이 측정**으로 바뀌었다.

## 왜 이 계획인가 — **없는 것을 만드는 게 아니라 있는 것을 옮긴다**

`channelGeometryPlanner` 가 이미 교통관리관이다. 스스로를 *"통합 장부"* 라 부르고,
납품과 반출을 **한 장부에서 같이** 배정하고, 신고를 **구간이 아니라 도형**(`Shape{h,v}`)으로
받고, 트랙 수가 그 결과로 나온다. 행 채널에는 그게 없다 — 가로 구간 하나만 받는다.

```
             열 채널 (오늘 있는 것)              행 채널 (이 계획이 세울 것)
프레임        (추상 트랙 **열**, 절대 **행**)      (로컬 x **열**, 추상 트랙 **행**)
신고          Shape { h[], v[] }                 Shape { h[], v[] }
관리 대상      납품 계단꼴 + 반출 elbow            납품 가로선+**다리** + **self 반출** 세로선
산출          trackCount → **폭**                 trackCount → **높이**
변환          트랙 → 절대 x                       트랙 → 절대 y
```

## 이 폴더의 어휘

```
교통관리관     한 영역의 **모든 종류**의 경로를 **한 장부**에서 도형으로 배정하는 것
다리          포트/상자에서 자기 트랙 행까지 내려오(올라오)는 **세로** 주행
self 반출     상자에서 바깥 N/S 변까지 **자기 x 로 직진**하는 반출. 오늘 어느 장부에도 없다
로컬 x        모듈 extent 왼쪽 변 기준 x. 같은 깊이 안에서 절대 x 의 **상수 평행이동**이다
```

## 하지 않는 것

- **열 채널을 안 건드린다.** 이미 정답 모양이다. 베끼되 고치지 않는다.
- **세로 × 세로 를 안 푼다.** 두 세로가 같은 열이면 통로를 아무리 높여도 안 풀린다
  (둘 다 통로의 변까지 뻗기 때문이다). 이 계획은 그걸 **보이게 하고 세는** 데까지다 —
  푸는 것은 열을 정한 쪽(면 배정의 **깊이 선택**)이고, 몇 건인지 **먼저 세고 나서** 손댄다.
  **dogleg·지하는 첫 해법이 아니다** — 늘려서 되는지, 자리를 되돌려서 되는지가 먼저다.
- **모듈 몸통을 뚫는 세로는 범위 밖이다.** 다리가 모듈 몸통을 지나야 하는 건
  *"그 포트가 애초에 못 나온다"* 는 **모듈 층** 문제다. 사유만 갈라 보여 준다.
- **기둥 밖 장부(`outside`)의 A2 를 앞당기지 않는다.** 그건 `구간-밖-주행` 에 남는다.
- **왼쪽 정렬 항등식을 안 건드린다** (사장님 지시로 보류, 2026-09-07).

| 전제 | 근거 문장 (그 이유를 말하는 사람) |
|---|---|
| 열 채널은 **1패스**다 — 도형이 폭보다 앞이고 뒤의 호출은 좌표 번역이다 | `modulePacking:1146` — *"**폭 역전** — 폭은 기하 배정의 결과(사용 트랙 수)에서 유도된다"* |

| 다리는 **방출이 그 자리에서** 그린다 | `deliveryRoute:634` — *"**행 채널 진입** — 포트가 기둥 끝이면 상자에서 행 채널의 트랙 행까지 **세로로** 먼저 간다"* |
| 다리를 내는 것은 `portEnd` 포트뿐 — gap 좌석은 `portFace` 가 W/E 로 바뀐다 | `emitModule:293` — *"N/S(gap) 좌석이면 가로 벨트가 gap 을 따라 서쪽 변까지 와서 90° 꺾인다 — 그 꺾이는 곳"* |
| 그래서 다리의 x = 그 면의 **깊이 열**이고, 깊이는 **후보 중에서 고른다** | `linkPlanner` 깊이 후보 주석 — *"후보를 팔이 적게 드는 순으로 본다 — 좌석은 이 모델에서 **유일하게 못 늘리는 자원**이라"* |
| gap(N/S) 면은 벨트 칸을 표에 **안 적는다** | `linkPlanner` — *"그쪽은 모두가 서쪽 변까지 달려야 해서 겹침을 행이 아니라 **반출 깊이**(`exitDepth`)로 푼다 — 자원의 모양이 아예 다르다"* |

> **❓ 하나가 남았다 — 이게 이 표가 하는 일이다.**
> `modulePacking:1330` 이 `addSeg(anchor, {x: anchor.x, y: seatRow(exitEdge)})` 로 self 반출을
