## J-진입구간 — 기둥 끝 포트에서 나오는 **세로 구간**은 누구 것인가

**2026-08-18 실험1 이 드러낸 것.** 기둥 끝 포트의 상자에서 나온 벨트는 **자기 열을 따라
세로로** 마진/띠까지 올라간 뒤 가로로 꺾는다. 그 세로 구간은:

```
· 세로 채널 **밖**이다 (자식 모듈의 동/서쪽)
· 행 채널 **밖**이다 (아직 띠에 도달 전)
· 모듈 extent **밖**이다 (포트 상자보다 바깥)
→ **어느 장부도 관리하지 않는다.**  그래서 두 경로가 같은 열을 잡고 교착했다
```

**길 셋**

| | 무엇 | 성질 |
|---|---|---|
| ⓐ | **행 채널이 함께 배정한다** — 띠로 들어오는 진입 열까지 행 채널 장부가 | 소유자가 하나. 다만 행 채널이 띠 밖을 관리하게 된다 |
| ⓑ | **모듈이 자기 것으로 낸다** — 포트가 `approach` 를 들고 오듯 | `module/` 은 형제를 모르므로 이웃과의 겹침을 못 본다 |
| ⓒ | 세로 채널을 **확장** — 자식 모듈 동/서쪽에도 채널 인스턴스를 둔다 | 개념이 하나로 유지된다. 채널이 늘어 폭이 는다 |

**착수 조건:** 계획서 Step 1 착수 시. **§3(환승)보다 먼저 정해야 한다** — 진입 구간의
소유자가 정해져야 띠에서 무엇을 받는지가 정의된다.

> **직접 골라야 한다.** 통로 그래프 모델이 이 질문을 흡수할 수 있었으나 2026-08-18 에
> 철회됐다(배정으로 푸는 결을 지킨다).

## J-교차 — 행 채널 안에서 경로들이 **지상 교차**하면

```
A: 행 t_h^A 로 오다가 열 t_v^A 에서 꺾는다
B: 행 t_h^B 로 오다가 열 t_v^B 에서 꺾는다
   t_v^B 가 A 의 가로 구간 안이고 t_h^A 가 B 의 세로 구간 안이면 → 교차
```

지상 벨트는 서로 못 지난다. 셋 중 아직 안 골랐다.

| | 무엇 | 성질 |
|---|---|---|
| **ⓐ** | **순서 배정** — *"서쪽에서 꺾는 경로가 바깥 행"* 처럼 중첩(nested)으로 | 성립하면 교차가 **0**. 탐색도 지하도 안 쓴다. **증명이 필요하다** |
| **ⓑ** | 세로 채널의 **같은 쪽 판정**을 전치 | 이미 있는 도구. 다만 절단선은 *반출이 긋는* 개념이라 그대로는 안 맞을 수 있다 |
| **ⓒ** | **지하 횡단**(`placeWithJumps`) | 검증된 수단. 하지만 *"지하 위에선 인서터가 못 먹인다"* 제약이 붙는다 |

**순서: ⓐ → ⓑ → ⓒ 로 세 번 판단한다**(2026-08-18 사용자). ⓐ가 성립하면 지하도 탐색도
안 쓰고 끝나므로 먼저 시도하고, 안 되면 ⓑ, 그래도 안 되면 ⓒ.

**착수 조건:** 계획서 Step 2(트랙 배정)가 끝난 직후. 그때 **실제로 교차가 나는지**부터
센다 — 안 나면 이 판단은 영구 보류다.

**ⓐ 를 먼저 시도할 근거:** 세로 채널의 `assignTracksLeftEdge` 도 *순서*(lo 오름차순)만으로
최소 트랙을 낸다. 같은 성질이 가로에도 있을 가능성이 높다.

## J-띠선택 — 띠가 **여럿일 때 어느 것을 쓰나** — **유도된다** (2026-08-18 사용자)

> **어느 띠를 쓰는지는 중요하지 않다.** 포트와 외부상자의 위치에서 **유도**되고,
> 그 둘은 각자 강제 규칙을 갖는다.

**포트 위치를 강제하는 규칙 (확인됨)**

```
유체        wantFaceOf(role) — 출력 W · 입력 E.  **강제**.  못 맞추면 `no-rotation` 으로 트리째 거절
출력        outputSide: "W"  — 좌우 계층형(부모=좌)
관통        portEnd          — 기둥 끝 N/S (2026-08-17)
넘침 순서   선호 면 → 반대 면 → 유체 면 → gap
```

**외부상자 위치를 정하는 규칙 (확인됨 — `planner/perimeter/lanes.ts`)**

```
대상        납품으로 **짝 못 지은 포트 전부** (입력=공급 상자 · 출력=sink)
wayOuts     모듈이 답한 "나갈 수 있는 방향" — 못 쓰는 방향을 예약하지 않게
bandsByDepth 깊이별 모듈 밴드(top/bottom)  ← **띠를 가르는 재료가 이미 있다**
globalY     배치 전체 min/max — 진출 변(N/S) 좌표
```

**그래서 이 판단은 "고르는 문제"가 아니라 "유도가 맞는지 확인하는 문제"다.**

**남은 미확인 — 둘 다 답이 나왔다** (2026-08-18 사용자)

```
· 맨 위 모듈의 북쪽 끝 포트 → 위에 띠가 없다
  **답: 블루프린트 북쪽 면에 외부상자를 둔다.**  띠가 필요 없다 —
       배치 경계가 곧 그 포트의 목적지다 (반출 모델이 이미 하는 일)

· 목적지가 두 띠 건너 있으면
  **답: 교차를 덜 하는 쪽.**  어느 통로냐가 아니라 **교차 수**가 기준이다
```

**"교차 수가 기준"이 이 판단을 닫는다** — 띠를 갈아탈지 세로 채널로 우회할지는 취향이
아니라 **비용 비교**다. 그리고 그 비용이 정해지면 J-교차도 같은 잣대를 쓴다.
(비교를 **탐색이 아니라 배정**으로 한다 — 통로 그래프 안은 철회됐다.)

## ~~J-통로그래프~~ — **철회** (2026-08-18 사용자)

교차로를 노드로 보고 다익스트라로 고르자는 안. **내린다.**

> 계획 단계의 탐색은 예약 철학이 금하는 것(방출 단계 탐색)과는 다르지만, 이 저장소는
> **배정으로 푸는 쪽**을 일관되게 골라 왔다(`assignTracksLeftEdge` · 같은 쪽 판정 ·
> 폭 역전 — 전부 숫자 비교이지 탐색이 아니다). 통로 선택만 탐색으로 가면 결이 갈린다.

**살아남는 것: 비용 기준.** *"교차를 덜 하는 쪽"* 은 탐색과 무관하게 유효하다 —
갈아탈지 우회할지는 취향이 아니라 **교차 수 비교**다. 배정으로 그 비교를 하면 된다.

**그래서 [J-진입구간](#j-진입구간--기둥-끝-포트에서-나오는-세로-구간은-누구-것인가) 이
다시 살아난다** — 그래프 모델이 흡수해 줄 예정이었으나 철회됐으므로, ⓐⓑⓒ 를 직접 골라야 한다.

---|---|
| 교차 수 | 사용자가 지목한 것. 교차는 지하나 우회를 부르므로 진짜 비용이다 |
| + 통로 폭 증가 | 트랙을 새로 여는 경로에 벌점 — 폭 역전과 직접 이어진다 |
| + 길이 | 벨트 개수. 처리량엔 무해하나 면적엔 아니다 |

**착수 조건:** 계획서 Step 2(트랙 배정) 이후. 그때 **교차가 실제로 나는지**부터 세고,
안 나면 그래프 모델 자체가 과잉이다(경로가 둘뿐인 트리에선 최단이 자명하다).

## ~~J-버스~~ — **판단에서 내린다** (2026-08-18 사용자)

> 가로 벨트도 결국 외부상자와 이어져 빠져나간다. *"블루프린트를 관통한다"* 는 뜻이지
> **관통해야 하는 것이 가로 벨트인 건 아니다.**

아래는 기록으로만 남긴다.

### (기록) 

사용자 요구는 *"거의 전체 블루프린트를 관통하는 가로 벨트"* 다. 행 채널이 생기면
**같은 띠를 여러 모듈이 공유**하는 형태가 되는데, 그것이 곧 버스인가?

```
행 채널   두 모듈 **사이**의 띠.  그 띠를 지나는 것은 **경로들**(각자 출발·도착이 있다)
버스      한 벨트가 **여러 소비자**에게 나눠 준다 — 경로가 아니라 **공유 자원**
```

**다르다.** 버스는 *"하나의 벨트에서 여럿이 집어 간다"* 이고, 행 채널은 *"여러 벨트가 한 띠를
나눠 쓴다"* 다. 행 채널이 버스의 **무대**는 되지만 버스 자체는 아니다.

**착수 조건:** 행 채널 모델이 서고 난 뒤. 그때 *"같은 품목의 여러 경로를 한 벨트로 합칠 수
있나"* 를 묻는다 — 그건 [[트렁크벨트-경로모델]] 의 `g`(한 벨트가 먹이는 머신 수)와 같은 종류의
질문이고, **모듈 사이 판**이다.

**연결된 미결:** 트렁크벨트-경로모델 `judgements.md` 의 **J11**(같은 품목의 외부 접점을
하나로) — 목적이 겹친다. 행 채널이 서면 J11 의 수단이 하나 더 생긴다.
