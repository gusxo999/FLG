## J-관리관 — **통로망 모델이 필요한가** (2026-08-18 사용자, 옛 `J-진입구간` 흡수)

> 세로 채널과 행 채널을 관리하는 **교통 관리관**이 필요하겠군요. 새로운 모델이 아닐까요?

**그렇다.** 근거가 둘이고, 둘 다 이미 저장소에 적혀 있다.

### 근거 1 — 예약 주체는 하나여야 한다

`planner/CLAUDE.md`: *"큰 그림을 보는 주체 **하나**가 자리를 먼저 잡고 … **주체가 둘로
갈리면 무관한 판정이 이미 끝난 예약을 삼키는 버그가 난다**"*.

세로 채널 장부 + 행 채널 장부 = **주체 둘**이다. 2026-08-17 에 납품/반출이 정확히 그래서
서로를 망가뜨렸다(`예약 무시 재시도 — 남의 계획을 밟는다`). **축만 바꿔 같은 실수를 반복**하게 된다.

### 근거 2 — 순환은 위에서만 끊을 수 있다

```
띠 폭 → 모듈 위치 → 포트 절대 좌표 → 통과 경로 → 띠 폭
```

배치와 통로를 **동시에** 아는 주체라야 두 패스를 돌릴 수 있다. 오늘 그 자리에
`packModuleTree` 가 있으나 그건 **조율자**이지 모델이 아니다 — 자기 좌표계도 도형도 없다.

### 그래서 무엇인가

```
통로망 모델 (가칭)
  자원   세로 띠(깊이 사이) · 가로 띠(모듈 사이) · 그 **교차로**
  배정   경로마다 "어느 통로들 · 각 통로의 어느 트랙 · 어디서 갈아타나"
  폭     각 통로의 폭이 배정 결과에서 나온다 (**양축 동시** — 순환이 여기서 끊긴다)
  하위   planChannelGeometry 는 **한 세로 통로 안의 배정**을 맡는 부품이 된다
```

**옛 `J-진입구간`(ⓐ 행 채널 / ⓑ 모듈 / ⓒ 세로 채널 확장)은 이 모델이 서면 무의미해진다** —
진입 구간은 통로망의 **한 간선**일 뿐이고 *"누구 것인가"* 라는 질문이 없어진다.

### 아직 안 고른 것

| | 무엇 | 성질 |
|---|---|---|
| ⓐ | **통로망 모델을 세운다** — 위 그림대로 | 원칙에 맞다. **비싸다** — 세로 채널의 소유권이 바뀐다 |
| ⓑ | 세로 채널이 **겸한다** — 행 채널은 "넘기는 행" 하나만 반환 | 싸다. 다만 세로 채널이 행 채널의 존재를 알게 되어 순수함이 깨진다 |
| ⓒ | 두 패스만 `packModuleTree` 가 돌린다 — 모델은 그대로 | 가장 싸다. **순환만 끊고 주체 통일은 미룬다**(빚) |

### 결정 — **(E) 격자 없는 가로 띠부터** (2026-08-18 사용자)

```
(E)  가로 띠를 **자기 깊이 열 안으로** 제한한다 → 세로 채널과 안 겹친다 → **교차로 0**
     관리관도 지하도 필요 없다.  두 통로가 **닿기만** 하고 겹치지 않는다
     대신 "블루프린트를 관통하는 가로 벨트" 는 못 한다 — 그건 별개 요구다
```

**왜 (E)부터인가**

```
지금 막힌 것(planned = 0)은 "기둥 끝 포트가 세로 채널로 가는 길" 이고,
그건 **자기 깊이 안의 가로 띠**만으로 풀린다.  관통 벨트는 별개 요구다.

그리고 폭 순환이 **한 축씩 분리된다** — 가로 띠가 세로 채널과 안 겹치므로
오늘 세로 채널이 쓰는 방식(한 축은 상수, 다른 축만 수요 유도)을 그대로 뒤집어 쓴다.
(B)는 양축이 얽혀 **수렴을 따로 증명**해야 한다.
```

**다음 단계:** (E)로 `planned > 0` 이 되는지 잰다. 되면 관통 벨트가 실제로 필요해질 때
(B)로 격자를 연다. 안 되면 바로 (B).

### (보류) 관리관을 실제로 세울 때 — 설계는 정해져 있다 (2026-08-18 사용자)

```
관리관이 갖는 것    교차로 격자.  노드 = (세로 띠 i) × (가로 띠 j)
노드가 아는 것      그 교차로를 **어느 경로가 지나가나** (세로 · 가로 · 꺾음)
관리관이 안 갖는 것  트랙 배정 규칙 — 각 채널이 자기 것으로 갖는다
```

**"지나가는지만" 이 충분한 이유:** 교차로는 사각형이고, 세로 경로는 전 높이를 관통하는
**열**을, 가로 경로는 전 폭을 관통하는 **행**을 차지한다. 열 ∩ 행 = **반드시 한 칸** —
트랙 번호와 무관하게 **항상 교차한다.** 그래서 교차 수 = (세로 수) × (가로 수) 이고
트랙을 몰라도 센다. **접점이 얇은데 정보 손실이 없다.**

그리고 그 수가 곧 **J-띠선택의 비용 함수**다(*"교차를 덜 하는 쪽"*).

**남는 위험 셋**

```
① 교차는 못 없앤다, **해소만** 한다 — 모든 (세로,가로) 쌍이 반드시 만나므로 지하가 필수
② 꺾는 경로가 예외 — 열도 행도 아닌 ㄱ자라 "항상 교차" 규칙이 안 통한다(방향 셋을 알아야)
③ **두 패스가 수렴하나** — 폭↑ → 위치 밀림 → 통과 경로 바뀜 → 폭.  단조면 수렴하지만
   **증명이 필요하다.**  (E)를 먼저 하는 이유가 이것이다
```

---

|---|---|
| ⓐ | **행 채널이 함께 배정한다** — 띠로 들어오는 진입 열까지 행 채널 장부가 | 소유자가 하나. 다만 행 채널이 띠 밖을 관리하게 된다 |
| ⓑ | **모듈이 자기 것으로 낸다** — 포트가 `approach` 를 들고 오듯 | `module/` 은 형제를 모르므로 이웃과의 겹침을 못 본다 |
| ⓒ | 세로 채널을 **확장** — 자식 모듈 동/서쪽에도 채널 인스턴스를 둔다 | 개념이 하나로 유지된다. 채널이 늘어 폭이 는다 |

**착수 조건:** 계획서 Step 1 착수 시. **§3(환승)보다 먼저 정해야 한다** — 진입 구간의
소유자가 정해져야 띠에서 무엇을 받는지가 정의된다.

> **직접 골라야 한다.** 통로 그래프 모델이 이 질문을 흡수할 수 있었으나 2026-08-18 에
> 철회됐다(배정으로 푸는 결을 지킨다).

## J-양보 — **자유도가 큰 쪽이 길을 내주게 하나** (2026-08-19, J-순서를 대체)

> **J-순서(2026-08-18)는 철회한다.** *"B 가 가장 나중이라 밀린다 → A → B → C 로 뒤집자"* 는
> 코드를 덜 읽고 낸 진단이었다. 채널 안에는 그 순서가 없다.

**읽고 나서 드러난 것** (→ [[layout-models]] §3.5)

```
채널 안   channelGeometryPlanner 가 B·C 를 **공동 배정**한다
          ① 절단선 라운드: 유체가 갇히면 **반출이 물러난다**(yieldedExports)
          ② 유체 → 반출 → 아이템 순 백트래킹
          → 양보도 제약우선도 이미 있다.  순서를 뒤집어도 효과 0

채널 밖   host = self(자기 열 직진) · margin(끝 열 직출) 인 반출은
          공동 탐색을 **안 거치고** reservedExportCells 에 직선으로 박힌다
          → B 는 협상 상대를 만난 적이 없다.  여기가 밀리는 자리
```

**계측기가 이미 있는데 죽어 있다.** `perimeterLanePlanner.LaneAssignment.options: LaneOption[]`
— 주석이 의도까지 적어 뒀다(*"장부가 양보를 요구할 수 있으므로 후보를 남겨 고르게 한다.
스도쿠: 제약 센 곳부터"*). **읽는 코드가 0곳**이다. `options[0]` 이 박히고 끝난다.

### 실측 계획 — 판정 전에 이것부터

자유도는 **주체의 성질이 아니라 한 배정 순간의 성질**이라, *"C 가 B 보다 자유롭다"* 는
측정할 수 없다. 물을 수 있는 것은 하나뿐:

> 실제로 막은 그 셀을 만든 배정이, **그때 다른 선택지를 가지고 있었는가**

| | 무엇 | 비용 |
|---|---|---|
| 0 | `options` 사망 확인 | **끝남**(grep) |
| 1 | `reservedExportCells` 를 `Set<셀>` → `Map<셀, 배정id>`. 사유에 주인을 싣는다 | 자료형 한 줄 + 로그. 동작 불변 |
| 2 | 그 배정의 `host.kind` · `options.length` · *안 막는 대안 수* 를 `flg.report()` 에 | 계측만 |

지금 사유 `반출 예약 (8,15)` 는 **칸만** 말하고 주인을 안 말한다 — 주인을 모르면 위 질문을
못 던진다. **1단계가 계측기이자 곧 답이다.**

### 판정은 그 자리에서 갈린다

```
host = self/margin  →  협상 자체가 없었다.  **양보 미구현**이 원인 → 아래 (가)
host = channel      →  공동 탐색은 거쳤다.  예산·후보 부족이 원인 → 다른 처방
options.length == 1 →  자유가 없었다.  전제 거짓 — 자리를 늘리는 쪽(통로·마진)이 답
```

| | 무엇 | 성질 |
|---|---|---|
| **가** | `options` 를 살린다 — B 가 막히면 그 셀 주인에게 **다음 후보로 양보**를 요청 | 설계 의도 그대로. 순서와 무관하게 성립. 재예약 연쇄를 막을 상한이 필요 |
| 나 | `self`/`margin` 반출도 공동 탐색에 넣는다 | 원리적으로 옳다. 탐색 공간이 채널 밖까지 커진다 |
| 다 | 통로망 모델(J-관리관 ⓐ) | 순서·양보를 통째로 대체. 가장 비싸다 |

**착수 조건:** 1·2단계 계측이 먼저. 측정 없이 (가)·(나) 중 못 고른다.

## J-교차 — 띠 안의 **지상 교차** (2026-08-18 재정의)

### 문제 정의 — 가로끼리는 안 부딪힌다. **세로 진입이 부딪힌다**

```
        ┌─────────────────────────────────┐
위 모듈  │  ●A        ●B                    │   ● = 기둥 끝 포트(단자)
        ├─────────────────────────────────┤
 띠     │  트랙0 ─────────────────         │   ─ = 가로 주행
        │  트랙1        ────────────       │   │ = 세로 진입/진출
        ├─────────────────────────────────┤
아래 모듈│        ●C            ●D          │
        └─────────────────────────────────┘
```

가로 주행끼리는 **절대 안 부딪힌다**(각자 다른 행). 부딪히는 것은 **세로 진입/진출 구간이
남의 가로 트랙을 가로지를 때**다.

```
A: x=5 진입 → 트랙0 → x=20 진출
B: x=12 진입 → 트랙1 → x=30 진출
   B 가 트랙1(더 아래)로 가려면 x=12 에서 트랙0 을 통과해야 한다 → **충돌**
```

### 이건 VLSI 의 **채널 라우팅**과 같은 문제다

```
띠 = 채널 · 위아래 포트 = 단자 · 가로 트랙 = 트랙 · 세로 진입 = 세로 가지 · 지상만 = 단일 층
```

정석 해법이 있고, ⓐⓑⓒ 가 그것에 대응한다.

### ⓐ **세로 제약 그래프(VCG)** — 순서로 없앤다

```
같은 열 x 에서 위 단자가 P, 아래 단자가 Q 이면
  P 의 트랙이 Q 보다 **위**여야 한다   (P → Q 간선)
모든 열의 간선을 모으면 부분순서 → **위상정렬 순서로 left-edge 배정 → 교차 0**
```

**순환이 없으면 최적이다.** 탐색도 지하도 안 쓴다. 지금 `assignTracksLeftEdge` 는 겹침만
보고 이 제약을 안 본다 — **거기에 VCG 를 얹는 것이 ⓐ 다.**

### ⓑ VCG 에 **순환**이 있으면 — 경로를 쪼갠다(dogleg)

```
A 가 B 위여야 하고 ∧ B 가 A 위여야 하면 → 순환. 트랙 배정이 불가능
해법: 한쪽을 **두 트랙으로 쪼갠다** — 중간에서 세로로 한 칸 옮겨 탄다
```

> **원래 ⓑ 로 적은 *"같은 쪽 판정 전치"* 는 부정확했다.** 절단선은 **반출이 긋는** 개념이라
> 띠에 그대로 안 맞는다. **dogleg 가 정확한 대응**이다.

### ⓒ **지하** — 층을 하나 더

```
dogleg 로도 안 풀리거나 트랙이 너무 늘면 → 교차 지점을 지하로 건넌다
```

**띠에서는 ⓒ가 싸다** — *"지하 위에서는 인서터가 못 먹인다"*(J12)는 **좌석 줄** 제약이고,
띠에는 좌석이 없다. 모듈 안에서보다 훨씬 자유롭다.

### 순서와 착수 조건

```
ⓐ VCG + left-edge   순환 없으면 교차 0, 최적.  **대부분 여기서 끝날 것**
ⓑ dogleg            순환이 있을 때만.  트랙이 하나 더 들 수 있다
ⓒ 지하              둘 다 안 되거나 트랙이 너무 늘 때.  띠에서는 싸다
```

**착수 조건:** 계획서 Step 3 이후, **교차가 실제로 나는지부터 센다.** 띠 하나에 경로가
둘뿐이면 VCG 가 자명하다 — 오늘 실측 트리(띠 1개)가 그럴 가능성이 높다.

---

|---|---|
| **ⓐ** | **순서 배정** — *"서쪽에서 꺾는 경로가 바깥 행"* 처럼 중첩(nested)으로 | 성립하면 교차가 **0**. 탐색도 지하도 안 쓴다. **증명이 필요하다** |
| **ⓑ** | 세로 채널의 **같은 쪽 판정**을 전치 | 이미 있는 도구. 다만 절단선은 *반출이 긋는* 개념이라 그대로는 안 맞을 수 있다 |
| **ⓒ** | **지하 횡단**(`placeWithJumps`) | 검증된 수단. 하지만 *"지하 위에선 인서터가 못 먹인다"* 제약이 붙는다 |

**순서: ⓐ → ⓑ → ⓒ 로 세 번 판단한다**(2026-08-18 사용자). ⓐ가 성립하면 지하도 탐색도
안 쓰고 끝나므로 먼저 시도하고, 안 되면 ⓑ, 그래도 안 되면 ⓒ.

**착수 조건:** 계획서 Step 2(트랙 배정)가 끝난 직후. 그때 **실제로 교차가 나는지**부터
센다 — 안 나면 이 판단은 영구 보류다.

**ⓐ 를 먼저 시도할 근거:** 세로 채널의 `assignTracksLeftEdge` 도 *순서*(lo 오름차순)만으로
최소 트랙을 낸다. 같은 성질이 가로에도 있을 가능성이 높다.

## J-띠선택 — 띠가 **여럿일 때 어느 것을 쓰나** — **유도된다** (2026-08-18 사용자)

> **어느 띠를 쓰는지는 중요하지 않다.** 포트와 외부상자의 위치에서 **유도**되고,
> 그 둘은 각자 강제 규칙을 갖는다.

**포트 위치를 강제하는 규칙 (확인됨)**

```
유체        wantFaceOf(role) — 출력 W · 입력 E.  **강제**.  못 맞추면 `no-rotation` 으로 트리째 거절
출력        outputSide: "W"  — 좌우 계층형(부모=좌)
관통        portEnd          — 기둥 끝 N/S (2026-08-17)
넘침 순서   선호 면 → 반대 면 → 유체 면 → gap
```

**외부상자 위치를 정하는 규칙 (확인됨 — `planner/perimeter/lanes.ts`)**

```
대상        납품으로 **짝 못 지은 포트 전부** (입력=공급 상자 · 출력=sink)
wayOuts     모듈이 답한 "나갈 수 있는 방향" — 못 쓰는 방향을 예약하지 않게
bandsByDepth 깊이별 모듈 밴드(top/bottom)  ← **띠를 가르는 재료가 이미 있다**
globalY     배치 전체 min/max — 진출 변(N/S) 좌표
```

**그래서 이 판단은 "고르는 문제"가 아니라 "유도가 맞는지 확인하는 문제"다.**

**실측 확인 (2026-08-18):** concrete 트리의 통과 수요 3건 중 **2건이 띠 없는 깊이**(모듈
하나뿐인 depth 0)에서 났다. 즉 *"맨 위/아래 모듈"* 경우가 **예외가 아니라 흔하다** —
띠와 마진을 **같은 것으로** 다뤄야 한다(`planRowChannel` 을 둘 다에 쓴다).

**남은 미확인 — 둘 다 답이 나왔다** (2026-08-18 사용자)

```
· 맨 위 모듈의 북쪽 끝 포트 → 위에 띠가 없다
  **답: 블루프린트 북쪽 면에 외부상자를 둔다.**  띠가 필요 없다 —
       배치 경계가 곧 그 포트의 목적지다 (반출 모델이 이미 하는 일)

· 목적지가 두 띠 건너 있으면
  **답: 교차를 덜 하는 쪽.**  어느 통로냐가 아니라 **교차 수**가 기준이다
```

**"교차 수가 기준"이 이 판단을 닫는다** — 띠를 갈아탈지 세로 채널로 우회할지는 취향이
아니라 **비용 비교**다. 그리고 그 비용이 정해지면 J-교차도 같은 잣대를 쓴다.
(비교를 **탐색이 아니라 배정**으로 한다 — 통로 그래프 안은 철회됐다.)

## ~~J-통로그래프~~ — **철회** (2026-08-18 사용자)

교차로를 노드로 보고 다익스트라로 고르자는 안. **내린다.**

> 계획 단계의 탐색은 예약 철학이 금하는 것(방출 단계 탐색)과는 다르지만, 이 저장소는
> **배정으로 푸는 쪽**을 일관되게 골라 왔다(`assignTracksLeftEdge` · 같은 쪽 판정 ·
> 폭 역전 — 전부 숫자 비교이지 탐색이 아니다). 통로 선택만 탐색으로 가면 결이 갈린다.

**살아남는 것: 비용 기준.** *"교차를 덜 하는 쪽"* 은 탐색과 무관하게 유효하다 —
갈아탈지 우회할지는 취향이 아니라 **교차 수 비교**다. 배정으로 그 비교를 하면 된다.

**그래서 [J-진입구간](#j-진입구간--기둥-끝-포트에서-나오는-세로-구간은-누구-것인가) 이
다시 살아난다** — 그래프 모델이 흡수해 줄 예정이었으나 철회됐으므로, ⓐⓑⓒ 를 직접 골라야 한다.

---|---|
| 교차 수 | 사용자가 지목한 것. 교차는 지하나 우회를 부르므로 진짜 비용이다 |
| + 통로 폭 증가 | 트랙을 새로 여는 경로에 벌점 — 폭 역전과 직접 이어진다 |
| + 길이 | 벨트 개수. 처리량엔 무해하나 면적엔 아니다 |

**착수 조건:** 계획서 Step 2(트랙 배정) 이후. 그때 **교차가 실제로 나는지**부터 세고,
안 나면 그래프 모델 자체가 과잉이다(경로가 둘뿐인 트리에선 최단이 자명하다).

## ~~J-버스~~ — **판단에서 내린다** (2026-08-18 사용자)

> 가로 벨트도 결국 외부상자와 이어져 빠져나간다. *"블루프린트를 관통한다"* 는 뜻이지
> **관통해야 하는 것이 가로 벨트인 건 아니다.**

아래는 기록으로만 남긴다.

### (기록) 

사용자 요구는 *"거의 전체 블루프린트를 관통하는 가로 벨트"* 다. 행 채널이 생기면
**같은 띠를 여러 모듈이 공유**하는 형태가 되는데, 그것이 곧 버스인가?

```
행 채널   두 모듈 **사이**의 띠.  그 띠를 지나는 것은 **경로들**(각자 출발·도착이 있다)
버스      한 벨트가 **여러 소비자**에게 나눠 준다 — 경로가 아니라 **공유 자원**
```

**다르다.** 버스는 *"하나의 벨트에서 여럿이 집어 간다"* 이고, 행 채널은 *"여러 벨트가 한 띠를
나눠 쓴다"* 다. 행 채널이 버스의 **무대**는 되지만 버스 자체는 아니다.

**착수 조건:** 행 채널 모델이 서고 난 뒤. 그때 *"같은 품목의 여러 경로를 한 벨트로 합칠 수
있나"* 를 묻는다 — 그건 [[트렁크벨트-경로모델]] 의 `g`(한 벨트가 먹이는 머신 수)와 같은 종류의
질문이고, **모듈 사이 판**이다.

**연결된 미결:** 트렁크벨트-경로모델 `judgements.md` 의 **J11**(같은 품목의 외부 접점을
하나로) — 목적이 겹친다. 행 채널이 서면 J11 의 수단이 하나 더 생긴다.
