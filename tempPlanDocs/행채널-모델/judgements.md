# 판단 — 행 채널 주변에서 아직 안 고른 것

> **미결 3** (2026-08-18 작성). 전제는 그날의 실측(concrete 트리 · 머신 8대, `flg.report()`)과
> 코드 읽기다. 전제가 썩으면 갱신하지 말고 다시 조사한다.

---

## J-교차 — 행 채널 안에서 경로들이 **지상 교차**하면

```
A: 행 t_h^A 로 오다가 열 t_v^A 에서 꺾는다
B: 행 t_h^B 로 오다가 열 t_v^B 에서 꺾는다
   t_v^B 가 A 의 가로 구간 안이고 t_h^A 가 B 의 세로 구간 안이면 → 교차
```

지상 벨트는 서로 못 지난다. 셋 중 아직 안 골랐다.

| | 무엇 | 성질 |
|---|---|---|
| **ⓐ** | **순서 배정** — *"서쪽에서 꺾는 경로가 바깥 행"* 처럼 중첩(nested)으로 | 성립하면 교차가 **0**. 탐색도 지하도 안 쓴다. **증명이 필요하다** |
| **ⓑ** | 세로 채널의 **같은 쪽 판정**을 전치 | 이미 있는 도구. 다만 절단선은 *반출이 긋는* 개념이라 그대로는 안 맞을 수 있다 |
| **ⓒ** | **지하 횡단**(`placeWithJumps`) | 검증된 수단. 하지만 *"지하 위에선 인서터가 못 먹인다"* 제약이 붙는다 |

**착수 조건:** 계획서 Step 2(트랙 배정)가 끝난 직후. 그때 **실제로 교차가 나는지**부터
센다 — 안 나면 이 판단은 영구 보류다(concrete 트리는 납품이 2개뿐이라 안 날 수도 있다).

**ⓐ 를 먼저 시도할 근거:** 세로 채널의 `assignTracksLeftEdge` 도 *순서*(lo 오름차순)만으로
최소 트랙을 낸다. 같은 성질이 가로에도 있을 가능성이 높다.

## J-띠선택 — 띠가 **여럿일 때 어느 것을 쓰나**

모듈이 세로로 셋 쌓이면 띠가 둘이다. 기둥 끝 포트가 **북쪽 끝**이면 위 띠, **남쪽 끝**이면
아래 띠 — 자명해 보인다.

**그런데 자명하지 않은 경우:**

```
· 맨 위 모듈의 **북쪽** 끝 포트 → 위에 띠가 없다(배치 경계).  마진을 띠로 보나?
· 목적지가 **두 띠 건너** 있으면 — 띠를 갈아타야 하나, 세로 채널로 우회하나?
```

**착수 조건:** 계획서 Step 3(환승) 착수 시. 그 전엔 재도 의미가 없다.

**전제:** 오늘 실측 트리(depth 1 에 모듈 둘)에서는 띠가 하나뿐이라 이 문제가 안 난다.
**띠가 둘 이상인 트리**가 나와야 판단할 재료가 생긴다.

## J-버스 — "블루프린트를 관통하는 가로 벨트" 는 이 모델로 되나

사용자 요구는 *"거의 전체 블루프린트를 관통하는 가로 벨트"* 다. 행 채널이 생기면
**같은 띠를 여러 모듈이 공유**하는 형태가 되는데, 그것이 곧 버스인가?

```
행 채널   두 모듈 **사이**의 띠.  그 띠를 지나는 것은 **경로들**(각자 출발·도착이 있다)
버스      한 벨트가 **여러 소비자**에게 나눠 준다 — 경로가 아니라 **공유 자원**
```

**다르다.** 버스는 *"하나의 벨트에서 여럿이 집어 간다"* 이고, 행 채널은 *"여러 벨트가 한 띠를
나눠 쓴다"* 다. 행 채널이 버스의 **무대**는 되지만 버스 자체는 아니다.

**착수 조건:** 행 채널 모델이 서고 난 뒤. 그때 *"같은 품목의 여러 경로를 한 벨트로 합칠 수
있나"* 를 묻는다 — 그건 [[트렁크벨트-경로모델]] 의 `g`(한 벨트가 먹이는 머신 수)와 같은 종류의
질문이고, **모듈 사이 판**이다.

**연결된 미결:** 트렁크벨트-경로모델 `judgements.md` 의 **J11**(같은 품목의 외부 접점을
하나로) — 목적이 겹친다. 행 채널이 서면 J11 의 수단이 하나 더 생긴다.
