## J-교차지하 — 지하 횡단이 실패하는 진짜 축

### 관측

glass 100/s 에서 납품 54건 중 **2건**이 배정에 실패한다(인서터 설정 무관, 지하벨트 사거리 40):

```
[channelGeometry] 계획 포기 — n1-kr-sand→n0-glass:kr-sand#31 crossing-needs-underground
[channelGeometry] 계획 포기 — …#38                            crossing-needs-underground
```

그 둘은 `deliveryRoute` 의 dijkstra 폴백으로 간다(폭은 phantom 으로 이미 잡혀 있다).

### 왜 이게 단순한 "사거리 부족"이 아닌가 — 개념

해소 사다리는 **막힌 축과 같은 축의 자원**을 줘야 푼다. 지금 사다리가 주는 것은:

```
①  반출 진출 변 뒤집기      → 절단선을 옮긴다        (반출에만 있다)
②  다른 트랙               → **세로** 자원을 준다
③  지하 횡단               → 내 **가로 팔**이 남의 **세로선**을 지나게 해 준다
④  fallback(dijkstra)
```

그런데 계단꼴이 다투는 자원은 **셋**이다 — 세로 트랙 · **가로 팔이 놓이는 행** · 상자 접점.
사다리에는 *"행을 옮긴다"* 가 없다. 납품의 두 행(startY·endY)은 포트가 이미 정했고,
장부는 그것을 **입력으로 받는다**([ledger/geometry.ts](../../src/autoLayout/channel/ledger/geometry.ts) `DeliveryInput`).

> **가설:** 실패의 축은 세로가 아니라 **가로**다. 두 경로의 가로 팔이 같은 행에서 겹치면
> 트랙을 아무리 늘려도(②) 지하로 내려가도(③) 안 풀린다 — 지하는 *세로선 밑*을 건널 뿐이다.
> 그렇다면 이건 사거리 문제가 아니라 **사다리에 그 축의 칸이 없는 문제**다.

`cap`(트랙 상한 = 경로 수)이 54였고 실제로 쓴 트랙이 32였다는 점이 이 가설을 지지한다 —
**빈 트랙이 22개 남은 채로 실패했다.** 세로 자원이 모자란 게 아니다.

### 원인 후보 (아직 안 가름)

| | 후보 | 그렇다면 처방 |
|---|---|---|
| **(가)** | 가로 팔끼리 같은 행 충돌 (`blocked[0]`/`blocked[last]`) | 포트 행을 옮기는 칸을 사다리에 추가 — **모듈 계획으로 되먹임**이라 비싸다 |
| **(나)** | 지하 입구가 E벽 마진이라 거부 (`i - 1 === 0`) | 입구 규칙 완화 — 국소적이고 싸다. 주석에 *"거부 사유"* 가 이미 적혀 있다 |

### 판별 방법 (한 번이면 갈린다)

실패한 두 경로의 `startY`·`endY` 와, 그 시점 `placedShapes` 에서 **그 두 행에 놓인 가로
세그먼트**를 찍는다. `planChannelGeometry` 는 순수 함수라 입력만 있으면 브라우저 없이 된다.

```
(가) 라면 → 같은 행에 남의 팔이 있다
(나) 라면 → 행은 비었는데 첫 칸(capCol)이 막혀 있다
```

## J-플러스투 — `channelWidthFromTracks` 의 `+2` 는 무엇의 값인가

### 관측

```ts
return Math.max(minGap, trackCount + 2);   // 주석: "트랙 사이사이 + 양 끝 투입기 진입"
```

그런데 지금 채널을 건너는 것은 **상자 → 벨트 → 상자** 계단꼴이고, 투입기는 모듈 면의
좌석(d1)에 앉는다. **채널 안에 투입기가 서는지 확인된 적이 없다.**
`minGap`(=4)도 같은 출처의 값이라 함께 의심 대상이다.

### 왜 지금 안 고치나

`+2` 가 옛 기하(투입기-벨트-투입기 체인)의 유물이면 **면적을 매 채널마다 2칸씩 낭비**하는
것이지만, 반대로 계단꼴의 가로 팔이 벽 바깥 한 칸을 쓰고 있으면 **정확한 값**이다.
[[채널-장부-충실도]] Step 2 는 폭을 **넓히는** 변경이라, 같은 커밋에서 폭을 **좁히는** 변경을
섞으면 골든 diff 에서 둘을 구분할 수 없다.

### 판별 방법

방출된 셀에서 채널의 x 사용 범위를 세어 `trackCount + 2` 와 대조하는 테스트 하나.
`emitPath` 결과의 절대 좌표를 채널 구간으로 필터링하면 된다.
