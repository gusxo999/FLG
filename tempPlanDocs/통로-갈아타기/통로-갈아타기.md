# 통로-갈아타기 — 한 경로가 **두 장부에 동시에 예약한다**

**한 줄 요약:** 행 채널은 **바깥에 직접 안 닿는다** — 옆 열 채널에 닿는다. 거기서 갈아타려면
한 경로가 **두 장부에 동시에 자리를 사고, 그 둘이 한 코너에서 만나야** 한다.
오늘 이 저장소는 **갈아타기 0회**만 할 줄 안다.

> **상태·트리거·재현 탐색은 [CLAUDE.md](CLAUDE.md) 에 있다.** 이 문서는 *"무엇을 하겠다"* 만 적는다.

---

## 1. 지금 무엇이 문제인가

### 1.1 통로마다 닿는 곳이 다르다

```
열 채널   세로로 뻗어  →  **바깥 N/S 마진에 직접 닿는다**            1홉이면 끝
행 채널   가로로 뻗어  →  **옆 열 채널**에 닿는다                    2홉 필요
                        (깊이 0 의 서쪽 · 최대 깊이의 동쪽만 바깥)
```

```
[W 마진] [열 0] [열채널 1] [열 1] [열채널 2] [열 2] [E 마진]
                              ↑
                깊이 1 에서 행 채널을 타고 서쪽으로 달리면
                바깥이 아니라 **열채널 1** 에 도착한다
```

### 1.2 그래서 못 하는 것

- **대각 목표 일반형** — 통로 하나로 양 끝에 못 닿으면 오늘은 계획을 접고 탐색에 맡긴다
  (`eligible = false`).
- **행 채널로 나가는 반출**(2×2 의 빈칸 — [exit-ray §4](../../docs/auto-layout/common/exit-ray.md)) — 끝 열이 아니면 못 한다.
- **막힌 상자의 구제** — N 이 막히고 W/E 로도 채널을 못 잡는 상자는 오늘 **못 나간다**
  (후보 0 → 로컬 ring 에 남는다). 2홉이면 나갈 수 있는 경우가 있다.

### 1.3 갈아타려면 무엇이 걸리나

**⑴ 코너에서 두 배정이 만나야 한다.**

```
행 채널이 준 **가로 트랙의 행**  ┐
                              ├─ 이 둘이 **한 칸에서** 만나야 갈아탈 수 있다
열 채널이 준 **세로 트랙의 열**  ┘
```

지금까지 두 장부가 주고받은 것은 값 **하나**(`b.top + t` → `startY`)였고, 그것도
**행 채널이 먼저 끝나고 열 채널이 받는** 단방향이었다. 거래가 아니라 **상속**이다 —
거절권이 한쪽에만 있고 되돌릴 길이 없다. 갈아타기는 **양쪽이 같은 코너에 합의**해야 하니
성격이 다르다.

**⑵ 두 장부의 시각이 어긋나 있다.**

```
행 채널 트랙 배정  →  높이  →  topY  →  열 채널 배정  →  폭  →  colX
     (앞)                                  (뒤)
```

행 채널이 **먼저 닫히고** 열 채널이 **나중에 열린다.** 한 경로가 둘에 동시에 예약하려면
**두 장부가 같은 시각에 열려 있어야** 한다.

**⑶ 신고 형식이 다르다.** 행 채널은 **구간**(`x1,x2` + `side`)을 받아 겹침 수로 색칠하고
교차를 전순서로 없앤다. 열 채널은 **도형**(가로/세로 조각)을 받아 셀 충돌·유체 인접·지하
점프까지 본다. 갈아타는 경로는 **두 형식으로 동시에** 신고해야 한다.

**⑷ 그 사각형의 주인이 이미 정해져 있다.** 두 통로가 겹치는 직사각형은 `x` 분할로
**열 채널이 통째로 소유**한다(행 채널의 신고는 로컬 x ≥ 0 에서 시작한다). 갈아타는 칸은
그 경계에 서므로 **소유 규칙에 예외가 생긴다.**

---

## 2. 이 계획이 푸는 것

### 2.1 시각을 맞춘다 — **행 채널을 두 조각으로 가른다**

`planRowChannel` 은 지금 **높이와 트랙 배정을 같이** 낸다. 그런데 `topY` 가 필요로 하는 것은
**높이뿐**이고, 높이는 *"몇 개가 동시에 겹치나"* 라는 **수**만 있으면 나온다(배정이 아니라).

```
지금   [겹침 수 + 트랙 배정] → 높이 → topY → 열 채널 배정
바꾼 뒤 [겹침 수] → 높이 → topY → **행 채널 트랙 배정 + 열 채널 배정 (같은 시각)**
```

**이러면 두 장부가 같은 시각에 열린다.** 한 경로가 둘에 동시에 예약할 수 있다.

> 이건 열 채널이 이미 하는 것과 **같은 모양**이다 — 열 채널도 도형을 배정한 뒤 그 결과에서
> 폭을 낸다. 다른 점은 행 채널이 **사슬의 맨 앞**이라 높이를 먼저 확정해야 한다는 것뿐이다.

### 2.2 코너를 **한 값**으로 만든다

갈아타는 칸은 `(행 채널의 트랙 행, 열 채널의 트랙 열)` 이다. 이 둘을 **한 배정의 두 축**으로
묶으면 「합의」가 아니라 **한 번의 선택**이 된다 — 두 장부가 협상하는 것이 아니라, 한 경로가
*"이 행 × 이 열"* 한 쌍을 신청하고 두 장부가 각자 거절권을 갖는다.

### 2.3 광선이 재귀가 된다

광선의 네 경우([exit-ray §3](../../docs/auto-layout/common/exit-ray.md))에서 **②(환승)만 바뀐다.** 새 경우가 붙는 것이 아니다:

```
② 통로 · 환승
     그 통로를 따라 꺾어 나간다 → 트랙을 산다
     **그 통로가 어디에 닿나** 를 본다
         바깥에 닿는다     →  끝                       (오늘 = 열 채널)
         다른 통로에 닿는다 →  **거기서 다시 ①~④ 를 돈다**  (이 계획)
```

같은 통로를 두 번 타면 순환이니 금지한다. 실물에서는 **2홉이면 어디든 닿는다.**

### 2.4 **쉬운 절반이 따로 있다** — 끝 열의 행 채널은 바깥에 닿는다

행 채널이 *"옆 열 채널에 닿는다"* 는 것은 **중간 깊이** 이야기다. **끝 열은 다르다:**

```
[W 마진] [열 0] [채널 1] [열 1] … [열 D] [E 마진]
   ↑                                        ↑
   깊이 0 의 행 채널은 서쪽이 **바깥 마진**    최대 깊이의 행 채널은 동쪽이 **바깥 마진**
```

그러니 **끝 열에서는 행 채널 환승이 1홉이다** — 갈아탈 필요가 없다. 2×2 의 빈칸이
**둘로 갈린다:**

| | 홉 | 필요한 것 | 동시 예약인가 |
|---|---|---|---|
| **끝 열**의 행 채널 환승 | 1 | 행 채널 배정에 **반출을 신고자로 넣는 것**이 전부 | **아니다** — 기존 예약에 신고자가 하나 늘 뿐 |
| **중간 깊이**의 행 채널 환승 | 2 | 코너 합의 + 시각 맞추기(§2.1·2.2) | **그렇다** — 이 계획의 본체 |

> **앞 조각에서 마주칠 자리 하나:** `planRowChannel` 의 교차-없음 전순서는 **"서쪽 끝이
> 공통(`x1: 0`)"** 하나에 기대 있다. 반출이 끝 열에서 **동쪽으로** 나가면 `west` 가 갈려
> 옛 left-edge 로 떨어지고 교차 보장이 사라진다(그 파일의 마지막 테스트가 그 경계다).

---

## 3. 이 계획이 **안 푸는** 것

- **3홉 이상.** 실물 배치에서 필요한 근거가 아직 없다. 필요해지면 그때 연다.
- **격자 탐색.** 광선은 **영역 목록**을 훑지 칸을 훑지 않는다. 홉 상한을 상수로 못 박는다.
- **장부를 합치는 것.** 두 장부는 그대로 둔다(`x` 로 서로소라 합칠 이유가 없다).
  바뀌는 것은 **손님**이지 가게가 아니다.
- **1홉 자격 판정(`enumerateOptions`).** 이미 섰다 — 여기는 그 ②만 재귀로 연다.
- **위험군을 만드는 일.** 후보 0 이 나오는 모듈 모양(같은 면에 유체 줄 둘)은
  `커스텀-레시피` 의 몫이다 → [CLAUDE.md](CLAUDE.md) 재현 탐색.

---

## 4. 단계

**Step 0(계측)은 끝났다** — `flg.report()` 의 `반출배정` 줄이 막힌 상자를
**1홉 / 2홉 / 행채널불가**로 갈라 낸다(2026-09-11, `ExitBlocked`). 그 수가 아래 두 갈래의
착수 근거이고, 읽는 법은 [CLAUDE.md](CLAUDE.md) 에 있다.

### 앞 조각 — 끝 열 · 1홉 *(선행 없음. `1홉 > 0` 이면 착수)*

#### Step A1 — 행 채널 배정에 **반출을 신고자로 넣는다**

오늘 `rowChannelNeeds` 는 납품 경로의 끝만 담는다(짝짓기 루프에서만 채워진다).
반출은 행 채널에 **신고 자체를 못 한다.** 여기서 그 목록에 반출을 더한다.

- **전제:** 끝 열의 행 채널은 한쪽 끝이 바깥 마진이다 → 열 채널이 개입하지 않는다.
  근거 문장: `exit-ray.md` §3 표 — *"행 채널 … 환승하면 닿는 곳: **옆 열 채널**(끝 열이면 바깥)"*.
- **불변:** 납품 끝의 트랙 배정 규칙(전순서)은 **서쪽 끝이 공통일 때만** 성립한다 —
  동쪽으로 나가는 반출이 섞이면 그 분기는 옛 left-edge 로 떨어진다(그 갈래가 이미 코드에 있다).
- **관문:** *"끝 열 상자가 행 채널의 가로 트랙을 타고 바깥 마진으로 나간다"* 가 **배정된다.**

### 뒤 조각 — 중간 깊이 · 2홉 *(`커스텀-레시피` 선행. `2홉 > 0` 이면 착수)*

아래는 **방향**이다 — 확정은 앞 단계를 끝낸 뒤에 한다.

#### Step 1 — 행 채널을 **높이 산정**과 **트랙 배정**으로 가른다

높이는 겹침 수에서, 트랙은 `topY` 뒤에서.

- **불변(기전으로):** 겹침 수는 배정 없이도 같은 값이 나온다 — `assignTracksLeftEdge` 의
  트랙 수가 곧 최대 동시 겹침 수이고, 그 수는 구간만으로 정해진다.
- **관문:** 두 장부가 **같은 시각에 열린다.**
- **왜 게이트가 있나:** 이 단계가 곧 **순서 변경**이라 되돌리는 값이 비싸다.

#### Step 2 — 코너를 **한 쌍의 신청**으로 만든다

`(행 트랙, 열 트랙)` 을 한 배정으로 신청하고 두 장부가 각자 검사한다.

- **관문:** 갈아타기가 **표현될 수 있는 것**이 된다.

#### Step 3 — 광선의 ②를 재귀로 연다

홉 상한 2. 순환 금지.

- **관문:** *"행 채널로 환승해 W/E 로 나간다"* 가 **실제로 배정된다.**
  오늘 후보 0 이라 못 나가던 상자가 나간다 — 그 수를 센다(`반출배정` 의 `막힘` 이 준다).

---

## 5. 이게 끝나면 열리는 문

- **대각 목표가 계획으로 풀린다.** 오늘은 통로 하나로 못 닿으면 탐색에 맡긴다.
- **2×2 가 채워진다** — 네 칸이 다 선다([exit-ray §4](../../docs/auto-layout/common/exit-ray.md)).
- **못 나가는 상자가 준다** — 후보 0 으로 로컬 ring 에 남던 것들.
- **`채널-양보-명세` 의 판정들이 두 통로에 같이 적용된다.**
