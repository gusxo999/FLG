# 통로-갈아타기 — 상태와 고유 컨텍스트

> 상태: **보류(트리거 대기)** — 2026-09-11 **실물 실측에서 둘 다 0**
>
> **계획이 두 조각으로 갈렸고, 두 조각이 각자 다른 것에 막혀 있다**(§2.4):
>
> ```
> 앞 조각 (끝 열 · 1홉)     **못 쟀다** — manual 모드가 `unrouted-lines` 로 거절된다(선행 결함)
> 뒤 조각 (중간 깊이 · 2홉)  **0** — 위험군은 실물에 있는데 전부 단일 모듈 트리다
>                          (= 중간 깊이가 없다). 막는 것은 머신 모양이 아니라 **트리 모양**
> ```
>
> **그리고 실측이 다른 결함을 하나 찾았다** — `processing-unit` 의 상자 하나가
> `wayOuts = []`(네 방향 전부 자기 모듈 몸통에 막힘)로 **안 나간다**(`skipped 1`).
> **이 계획으로는 못 구한다**(행 채널에 들어가지도 못한다) — `module/` 좌석 배정의 몫이다.
>
> **한 문장:** 한 경로가 **두 장부에 동시에 예약**한다. 장부를 합치는 것이 아니라
> **한 손님이 두 가게에서 산다.**
>
> **옛 이름은 「교통관리관」이었고 뜻이 달랐다** — 두 장부를 *보는* 주체였다. 그 안은
> 조사로 기각됐다(두 장부는 `x` 로 서로소라 서로 볼 필요가 없다). 지금 필요한 것은
> **예약하는 주체**다.

## 착수 조건 (트리거) · 종류: **실측형** (뒤 조각은 해금형 → **실측형으로 바뀌었다**)

```
① 광선 기반 자격 통일   ✅ 완료 (2026-09-08, `78a5782` — 옛 `두점-잇기`)
② 직진 장부            ✅ 완료 (2026-09-10, `e9fd584`)
③ 계측기               ✅ 완료 (2026-09-11) — `flg.report()` 의 `반출배정` 줄
④ 표본을 만들 수단      ✅ 완료 (2026-09-11) — 커스텀 레시피
⑤ 그 줄의 수가 N 건 이상  ⬜ **대기 — 2026-09-11 실물 실측에서 둘 다 0**
     · **1홉** 끝 열에서 막힌 상자      → **못 쟀다.** manual 모드가 선행 결함으로 거절된다
     · **2홉** 중간 깊이에서 막힌 상자   → **0.** 위험군은 나오는데 전부
                                        단일 모듈 트리(= 중간 깊이 없음)다
```

> **막고 있는 것이 「표본 수단」이 아니라 「트리 모양」으로 바뀌었다**(아래 실측 §③).
> 커스텀 레시피는 **머신 모양**을 열었는데, 남은 벽은 *"그 모듈이 중간 깊이에 있으면서
> 동시에 그 상자가 반출 대상일 것"* 이라는 **트리 쪽 조건**이다.

**읽는 법 — 네 수가 각각 다른 것을 말한다:**

```
막힘     후보 0(배정 없음) + 강행(전부 강등됐는데 대안 없음)   ← **이 계획의 값**
강등     직진이 막힌 자리. 환승으로 내려갔으면 손해 0        ← 값이 아니다
위험군   모듈이 W·E 를 **둘 다** 막은 반출 포트 수           ← 2홉이 0인 이유를 가른다
다툰칸   같은 칸을 셋 이상이 다툰 수                       ← `셀장부` J-충돌차수 의 것
```

> **왜 `강등` 이 값이 아닌가.** 첫 실측(2026-09-10, advanced-circuit 동형 7판)에서 강등 6건은
> **전부 환승으로 내려갔다** — 오늘 체계가 이미 답을 갖고 있다는 뜻이다. 그리고 진짜
> 트리거인 **후보 0 은 강등 기록에 원리적으로 안 나온다**(`cands` 필터가 강등 루프 **앞**에
> 있다). 그래서 계측을 `ExitBlocked` 로 갈아 끼웠다.

## 두 조각의 게이트가 왜 다른가 — **막히는 조건이 다르다**

코드에서 나오는 필요조건: `W ∈ wayOuts ∨ E ∈ wayOuts` 면 후보가 **반드시 하나 이상** 선다
(중간 깊이는 `channelOpts` 가 둘, 끝 열은 가로 직진). 그래서:

| 조각 | 막히는 길 | 오늘 만들 수 있나 |
|---|---|---|
| **1홉**(끝 열) | 후보가 **전부 직진**인데 **둘 다 강등** → `강행`. 예: 끝 열 · `wayOuts = {N,E}` | **만들 수 있다** — 위험군이 필요 없다. 실물 트리에서 강등은 이미 6건 났다 |
| **2홉**(중간 깊이) | **후보 0** — 그러려면 `wayOuts ∩ {W,E} = ∅`(= 위험군) | **못 만든다** — 아래 스윕에서 0 |

## 재현 탐색 — **표본을 못 고르면 계측이 0을 두 뜻으로 읽는다** (2026-09-11)

검사기만으로는 게이트가 안 닫힌다. *"이 표본에 그 모양이 없다"* 와 *"어떤 표본에도 없다"* 가
같은 `0` 으로 나오기 때문이다. 그래서 **그 모양을 만드는 트리를 찾아봤다**(합성 픽스처 스윕):

```
흔든 축   깊이 D 1~3 · 형제 S 1~3 · 재료 K 2~6 · 머신 3×3/5×5 · 수요 rate 2/40 · 긴팔 유무
표본      216 트리 모양 · 반출 포트 4,710개
결과      **위험군 0 · 막힘 0 · 강등 0** — 한 건도 안 나왔다
추가      유체 입력(E)+유체 출력(W) **양 면**을 파이프가 먹는 모듈도 위험군 0
```

**관찰된 이유:** 반출 상자는 언제나 **자기 면의 가장 바깥**에 앉는다 — 그 방향으로 한 칸만
가면 `extent` 밖이라 `fillModuleWayOuts` 가 그 면을 언제나 열어 준다. 전체 포트로 넓히면
`side=W wayOuts=S`(W 가 막힌 상자) 가 196건 나오는데, **전부 납품으로 짝지어진 포트**였고
반출 대상에는 한 건도 없었다.

> **증명은 아니다** — *왜* 반출 상자만 늘 바깥인지는 안 밝혔다(모듈 생성기의 좌석 배정
> 규칙에 달렸다). 스윕이 넓은 반례 부재일 뿐이다.
>
> **그리고 스윕은 두 종류를 다르게 잘 본다.** *모양*의 부재(위험군)는 넓게 훑어 신뢰할 만하지만,
> *충돌*의 빈도(강등·강행)는 **실물이 더 세다** — 같은 스윕에서 강등이 0인데 실물 7판에서는
> 6건 났다. 합성 모듈의 포트가 실물보다 고르게 흩어져서다. **그래서 1홉은 실물로 재야 한다.**

**남은 후보 축은 하나다 — 같은 면에 유체 줄이 둘 이상**(`FluidLinePlan.rank ≥ 1`).
그러면 바깥 줄이 파이프에 먹히고 벨트 raw 상자가 **안쪽으로 밀릴** 수 있다
(`fluidJumpBlocker` 의 거절식 — 면 좌석에서 유체 행을 빼면 벨트 줄이 안 들어간다.
판정표는 [custom-recipe](../../docs/factorio/custom-recipe.md) §4 `seats-tight`).
그 모양은 머신 프로토타입의 `fluid_boxes` 에서 나온다.

> **표본을 못 만들던 제약이 풀렸다 (2026-09-11).** 커스텀 레시피가 들어오면서 그 모양을
> **콘솔에서 직접 만든다** — 실데이터에 있어야만 시험되던 축이 아니다.
> → [custom-recipe](../../docs/factorio/custom-recipe.md)

**재현 레시피** — 아래 그대로 넣으면 `E` 면에 `rank 0 · 1` 두 줄이 선다(2026-09-11 실측:
`water → E2 rank0` · `sulfuric-acid → E4 rank1`, 회전 180°):

```js
flg.custom.add({
  machines: [{
    name: 'twin-fluid-plant', size: 5, craftingSpeed: 1,
    craftingCategories: ['custom-twin'],
    fluidBoxes: [
      { role: 'input',  face: 'W', offset: 0 },   // 180° 에서 E4 · rank 1
      { role: 'input',  face: 'W', offset: 2 },   // 180° 에서 E2 · rank 0
      { role: 'output', face: 'E', offset: 4 },
    ],
  }],
  recipes: [{
    name: 'twin', category: 'custom-twin', energyRequired: 2,
    ingredients: [
      { name: 'water',         amount: 50, type: 'fluid' },
      { name: 'sulfuric-acid', amount: 20, type: 'fluid' },
      { name: 'iron-plate',    amount:  1, type: 'item'  },   // 벨트 재료 — raw 여야 한다
    ],
    products: [{ name: 'twin-thing', amount: 1, type: 'item' }],
  }],
})
flg.custom.map('twin-fluid-plant')   // 어느 면 어느 행에 앉았나
```

**아직 손으로 세워야 하는 것은 트리 쪽이다**: 그 모듈이 **중간 깊이**(maxDepth ≥ 2)에
오고 그 열에 형제가 위아래로 있어야(N/S 직진도 막힘) 2홉이 나온다.

## 실물 실측 — **위험군은 있다. 그런데 트리 모양이 막는다** (2026-09-11, 브라우저)

게임데이터(레시피 2,647)로 `flg.run()` → `반출배정` 을 여러 트리에서 읽었다.

```
트리                          모듈   반출배정
electronic-circuit  min·2/s    1     막힘 0 · 위험군 0
advanced-circuit    min        5     막힘 0 · 위험군 0
rocket-control-unit min        1     막힘 0 · 위험군 0
logistic-science    min        1     막힘 0 · 위험군 0
electric-furnace    min        1     막힘 0 · 위험군 0
low-density-str.    min        -     막힘 0 · 위험군 0
utility-science     min        -     막힘 0 · 위험군 0
plastic-bar         2/s        1     막힘 0 · **위험군 1** ← N/S 직진으로 나갔다
production-science  min        1     막힘 0 · **위험군 1** ← N/S 직진으로 나갔다
processing-unit     min        1     **막힘 1**(후보0) · 위험군 1 · 행채널로도 불가 1
```

**① 합성 스윕의 「위험군 0」은 틀렸다.** 실물에는 있다 — 216 트리 픽스처가 그 모양을
못 만들었을 뿐이다(면에 깊이가 둘 이상 서는 배치를 합성이 못 냈다). `processing-unit` 이
그 증거다: `E d2←advanced-circuit d2←kr-rare-metals **d3←sulfuric-acid**` — 같은 면에 세 줄,
바깥이 파이프. 계획서가 예상한 바로 그 모양이고, **커스텀 레시피 없이 실데이터에 있었다.**

**② 그런데 그 막힌 상자는 이 계획이 못 구한다.**

```
n0-processing-unit-input-advanced-circuit-0 [noOption] d0 행채널불가
  direct:N=모듈몸통(wayOuts)  direct:S=모듈몸통(wayOuts)
  direct:W=모듈몸통(wayOuts)  direct:E=모듈몸통(wayOuts)
  channel:W=모듈몸통(wayOuts)  channel:E=모듈몸통(wayOuts)
```

**`wayOuts = []`** — 네 방향이 전부 자기 모듈 몸통에 막혔다. 행 채널에 **들어가지도 못한다.**
`반출 relocated 3 / skipped 1` 로 상자가 실제로 안 나간다 — 사용자에게 보이는 결함이지만
**다른 결함**이다(상자가 자기 모듈에 갇혔다 → `module/` 의 좌석 배정 몫).

**③ 위험군이 N/S 로 빠져나간 둘(`plastic-bar` · `production-science`)은 전부 단일 모듈
트리였다.** `maxDepth 0` 이면 모든 열이 끝 열이라 **2홉이 구조적으로 불가능**하다.
그 모듈을 중간 깊이로 밀어 넣어 봤지만(`internal: [plastic-bar, …]` 로 4모듈 트리),
**그 순간 위험군이 0이 된다** — 중간 노드가 되면 그 상자가 납품으로 짝지어져 반출 대상에서
빠지기 때문이다.

> **그래서 2홉은 여전히 0이고, 이유가 처음으로 정확해졌다:**
> 위험군 상자는 **반출 대상일 때만** 세는데, 그 상자가 반출 대상인 트리는 **단일 모듈**이고
> 단일 모듈에는 중간 깊이가 없다. 둘을 동시에 만족시키는 트리를 아직 못 만들었다.

**④ 1홉(강등·강행)은 오늘 못 잰다.** `manual` 모드가 `unrouted-lines`(사다리 좌석막힘)로
거절된다 — advanced-circuit 을 1·2·5·10/s 로 전부 시도했고 전부 거절. `min` 모드는 도는데
거기선 강등이 0이다(상자가 적어 충돌이 안 난다). **선행 결함이 1홉 계측을 막고 있다.**

> **계측 방법 주의(2026-09-11 실측):** `await flg.run()` 뒤에 **곧바로** `flg.report()` 를
> 읽으면 **한 판 밀린 값**이 나올 수 있다(타이트한 async 루프에서 확인). 같은 트리를 세 번
> 돌려 확인하거나, 호출을 나눠서 읽는다.

**둘 다 0이면 영구 보류한다.** 2홉은 순서 변경(행 채널 두 조각)을 요구하므로 값이
확인되기 전에는 비싸다.

## 이 폴더의 어휘

```
홉(hop)   환승 횟수. 오늘 = 1. 이 계획 = 2
갈아타기   통로 A 를 타고 가다 통로 B 로 옮겨 타는 것. **코너에서 일어난다**
코너      두 통로가 만나는 칸. `(행 채널의 트랙 행, 열 채널의 트랙 열)`
동시 예약   한 경로가 **두 장부에 각각** 자리를 사는 것. 장부는 합쳐지지 않는다
위험군     모듈이 W·E 를 둘 다 막은 반출 포트 — **후보 0 의 필요조건**
```

## 착수 전 반드시 읽을 것

**줄 번호로 적지 않는다** — 이 문서가 한 번 낡았던 자리다(2026-09-11 에 전부 이동했다).
`modulePacking.ts` 는 단계 주석(`3c)` · `4a)` · `5c)` · `6b)`)이 안정된 이름이다.

| 무엇 | 왜 |
|---|---|
| `docs/auto-layout/common/exit-ray.md` | **선행이 남긴 모델.** 네 경우 중 **②(환승)만** 바꾸면 이 계획이 된다 |
| `planner/rowChannelPlanner.ts` — `planRowChannel` | 높이와 트랙 배정을 **같이** 낸다. Step 1 이 이걸 가른다 |
| `planner/modulePacking.ts` — `3c)` 행 채널 배정 → `4a)` `topY` → `5c)` 열 채널 | **두 장부의 시각이 어긋난 자리** |
| `planner/modulePacking.ts` — `6b)` (`b.top + t` → `seed.startY`) | 오늘 두 장부가 주고받는 **유일한 값**. 단방향이다 |
| `planner/perimeterExitPlanner.ts` — `ExitBlocked` · `enumerateOptions` | 트리거를 세는 자리. `directOpt` 의 거절 사유가 *왜 막혔나*를 낸다 |
| `tempPlanDocs/채널-양보-명세/judgements.md` J-교차 | ⓑ dogleg · ⓒ 지하 — 갈아타기와 **다른 문제**(같은 통로 안의 교차) |

## 하지 않는 것

- **장부를 합치지 않는다.** 두 장부는 `x` 로 서로소다 — 합치면 `capCol` 같은 각 장부의
  내부 관례가 서로 거짓 겹침을 만든다.
- **3홉 이상.** 근거가 없다.
- **격자 탐색.** 영역 목록만 훑는다.
- **1홉 자격 판정(`enumerateOptions`)을 다시 손대지 않는다.** 이미 섰다 — 여기는 그 위에 얹는다.
