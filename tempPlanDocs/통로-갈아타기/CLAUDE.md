# 통로-갈아타기 — 상태와 고유 컨텍스트

> 상태: **보류(트리거 대기)** (2026-09-11 갱신)
>
> **계획이 두 조각으로 갈렸고, 두 조각의 게이트가 다르다**(§2.4):
>
> ```
> 앞 조각 (끝 열 · 1홉)     트리거 = 실측  →  **오늘 판정할 수 있다**(실물 트리 `flg.report()`)
> 뒤 조각 (중간 깊이 · 2홉)  트리거 = 실측  →  **표본을 못 만든다** → `커스텀-레시피` 가 선행
> ```
>
> **한 문장:** 한 경로가 **두 장부에 동시에 예약**한다. 장부를 합치는 것이 아니라
> **한 손님이 두 가게에서 산다.**
>
> **옛 이름은 「교통관리관」이었고 뜻이 달랐다** — 두 장부를 *보는* 주체였다. 그 안은
> 조사로 기각됐다(두 장부는 `x` 로 서로소라 서로 볼 필요가 없다). 지금 필요한 것은
> **예약하는 주체**다.

## 착수 조건 (트리거) · 종류: **실측형** (뒤 조각은 **해금형 → 실측형**)

```
① 광선 기반 자격 통일   ✅ 완료 (2026-09-08, `78a5782` — 옛 `두점-잇기`)
② 직진 장부            ✅ 완료 (2026-09-10, `e9fd584`)
③ 계측기               ✅ 완료 (2026-09-11) — `flg.report()` 의 `반출배정` 줄
④ 그 줄의 수가 N 건 이상  ⬜ **대기**
     · **1홉** 끝 열에서 막힌 상자      → 앞 조각으로 구제. **선행 없음**
     · **2홉** 중간 깊이에서 막힌 상자   → 뒤 조각(Step 1~3 전부). **`커스텀-레시피` 선행**
```

**읽는 법 — 네 수가 각각 다른 것을 말한다:**

```
막힘     후보 0(배정 없음) + 강행(전부 강등됐는데 대안 없음)   ← **이 계획의 값**
강등     직진이 막힌 자리. 환승으로 내려갔으면 손해 0        ← 값이 아니다
위험군   모듈이 W·E 를 **둘 다** 막은 반출 포트 수           ← 2홉이 0인 이유를 가른다
다툰칸   같은 칸을 셋 이상이 다툰 수                       ← `셀장부` J-충돌차수 의 것
```

> **왜 `강등` 이 값이 아닌가.** 첫 실측(2026-09-10, advanced-circuit 동형 7판)에서 강등 6건은
> **전부 환승으로 내려갔다** — 오늘 체계가 이미 답을 갖고 있다는 뜻이다. 그리고 진짜
> 트리거인 **후보 0 은 강등 기록에 원리적으로 안 나온다**(`cands` 필터가 강등 루프 **앞**에
> 있다). 그래서 계측을 `ExitBlocked` 로 갈아 끼웠다.

## 두 조각의 게이트가 왜 다른가 — **막히는 조건이 다르다**

코드에서 나오는 필요조건: `W ∈ wayOuts ∨ E ∈ wayOuts` 면 후보가 **반드시 하나 이상** 선다
(중간 깊이는 `channelOpts` 가 둘, 끝 열은 가로 직진). 그래서:

| 조각 | 막히는 길 | 오늘 만들 수 있나 |
|---|---|---|
| **1홉**(끝 열) | 후보가 **전부 직진**인데 **둘 다 강등** → `강행`. 예: 끝 열 · `wayOuts = {N,E}` | **만들 수 있다** — 위험군이 필요 없다. 실물 트리에서 강등은 이미 6건 났다 |
| **2홉**(중간 깊이) | **후보 0** — 그러려면 `wayOuts ∩ {W,E} = ∅`(= 위험군) | **못 만든다** — 아래 스윕에서 0 |

## 재현 탐색 — **표본을 못 고르면 계측이 0을 두 뜻으로 읽는다** (2026-09-11)

검사기만으로는 게이트가 안 닫힌다. *"이 표본에 그 모양이 없다"* 와 *"어떤 표본에도 없다"* 가
같은 `0` 으로 나오기 때문이다. 그래서 **그 모양을 만드는 트리를 찾아봤다**(합성 픽스처 스윕):

```
흔든 축   깊이 D 1~3 · 형제 S 1~3 · 재료 K 2~6 · 머신 3×3/5×5 · 수요 rate 2/40 · 긴팔 유무
표본      216 트리 모양 · 반출 포트 4,710개
결과      **위험군 0 · 막힘 0 · 강등 0** — 한 건도 안 나왔다
추가      유체 입력(E)+유체 출력(W) **양 면**을 파이프가 먹는 모듈도 위험군 0
```

**관찰된 이유:** 반출 상자는 언제나 **자기 면의 가장 바깥**에 앉는다 — 그 방향으로 한 칸만
가면 `extent` 밖이라 `fillModuleWayOuts` 가 그 면을 언제나 열어 준다. 전체 포트로 넓히면
`side=W wayOuts=S`(W 가 막힌 상자) 가 196건 나오는데, **전부 납품으로 짝지어진 포트**였고
반출 대상에는 한 건도 없었다.

> **증명은 아니다** — *왜* 반출 상자만 늘 바깥인지는 안 밝혔다(모듈 생성기의 좌석 배정
> 규칙에 달렸다). 스윕이 넓은 반례 부재일 뿐이다.
>
> **그리고 스윕은 두 종류를 다르게 잘 본다.** *모양*의 부재(위험군)는 넓게 훑어 신뢰할 만하지만,
> *충돌*의 빈도(강등·강행)는 **실물이 더 세다** — 같은 스윕에서 강등이 0인데 실물 7판에서는
> 6건 났다. 합성 모듈의 포트가 실물보다 고르게 흩어져서다. **그래서 1홉은 실물로 재야 한다.**

**남은 후보 축은 하나다 — 같은 면에 유체 줄이 둘 이상**(`FluidLinePlan.rank ≥ 1`).
그러면 바깥 줄이 파이프에 먹히고 벨트 raw 상자가 **안쪽으로 밀릴** 수 있다
(`커스텀-레시피` §4.3 *"좌석 예산 — 유체 상자가 면을 다 먹으면 벨트가 못 앉는다"*).
그 모양은 머신 프로토타입의 `fluid_boxes` 에서 나오므로 **실데이터에 있어야만 시험된다** —
그래서 **뒤 조각의 게이트가 `커스텀-레시피` 뒤에 선다**(그 계획서 §3① 이 같은 말을 한다).

**예상되는 재현 레시피**(뒤 조각용, 아직 못 만든다):

```
머신    유체 상자를 **같은 면에 둘 이상** 노출 (정사각 5×5 이상)
레시피  입력 유체 **2종** → E 면에 rank 0·1 두 줄
        + 벨트 재료 ≥ 1, 그리고 그 재료가 **자식이 안 만드는 raw**
트리    그 모듈이 **중간 깊이**(maxDepth ≥ 2) + 그 열에 형제가 위아래로(N/S 직진도 막힘)
```

**둘 다 0이면 영구 보류한다.** 2홉은 순서 변경(행 채널 두 조각)을 요구하므로 값이
확인되기 전에는 비싸다.

## 이 폴더의 어휘

```
홉(hop)   환승 횟수. 오늘 = 1. 이 계획 = 2
갈아타기   통로 A 를 타고 가다 통로 B 로 옮겨 타는 것. **코너에서 일어난다**
코너      두 통로가 만나는 칸. `(행 채널의 트랙 행, 열 채널의 트랙 열)`
동시 예약   한 경로가 **두 장부에 각각** 자리를 사는 것. 장부는 합쳐지지 않는다
위험군     모듈이 W·E 를 둘 다 막은 반출 포트 — **후보 0 의 필요조건**
```

## 착수 전 반드시 읽을 것

**줄 번호로 적지 않는다** — 이 문서가 한 번 낡았던 자리다(2026-09-11 에 전부 이동했다).
`modulePacking.ts` 는 단계 주석(`3c)` · `4a)` · `5c)` · `6b)`)이 안정된 이름이다.

| 무엇 | 왜 |
|---|---|
| `docs/auto-layout/common/exit-ray.md` | **선행이 남긴 모델.** 네 경우 중 **②(환승)만** 바꾸면 이 계획이 된다 |
| `planner/rowChannelPlanner.ts` — `planRowChannel` | 높이와 트랙 배정을 **같이** 낸다. Step 1 이 이걸 가른다 |
| `planner/modulePacking.ts` — `3c)` 행 채널 배정 → `4a)` `topY` → `5c)` 열 채널 | **두 장부의 시각이 어긋난 자리** |
| `planner/modulePacking.ts` — `6b)` (`b.top + t` → `seed.startY`) | 오늘 두 장부가 주고받는 **유일한 값**. 단방향이다 |
| `planner/perimeterExitPlanner.ts` — `ExitBlocked` · `enumerateOptions` | 트리거를 세는 자리. `directOpt` 의 거절 사유가 *왜 막혔나*를 낸다 |
| `tempPlanDocs/채널-양보-명세/judgements.md` J-교차 | ⓑ dogleg · ⓒ 지하 — 갈아타기와 **다른 문제**(같은 통로 안의 교차) |

## 하지 않는 것

- **장부를 합치지 않는다.** 두 장부는 `x` 로 서로소다 — 합치면 `capCol` 같은 각 장부의
  내부 관례가 서로 거짓 겹침을 만든다.
- **3홉 이상.** 근거가 없다.
- **격자 탐색.** 영역 목록만 훑는다.
- **1홉 자격 판정(`enumerateOptions`)을 다시 손대지 않는다.** 이미 섰다 — 여기는 그 위에 얹는다.
