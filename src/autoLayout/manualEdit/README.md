# manualEdit/ — 수동 편집(드래그·라우팅 편집) **비활성 격리 구역**

> **호출자 0.** 이 폴더의 코드는 실행되지 않는다.
> **타입검사·테스트 제외.** `tsconfig.app.json` · `vitest.config.ts` 에서 빠져 있다.
> **되살릴 코드가 아니다** — 재구현 시 참고할 **증거**다.

---

## 왜 여기 있나

자동 배치 결과가 화면에 나온 뒤, 사용자가 마우스로 무한상자·조립기 그룹을 끌면
**벨트를 다시 깔아주던** 코드다. 배치 파이프라인이 아니라 **사후 편집** 경로다.

세 가지 이유로 격리했다:

1. **배치 코드와 같은 파일에 섞여 있어** 어느 쪽이 실제로 도는 코드인지 읽기 어려웠다.
2. 전부 **옛 Dijkstra 탐색** 전제 위에 있어, 예약 기반으로 바뀐 지금 구조와 맞지 않는다.
3. 재구현 시 **자료구조가 크게 달라질 예정**이라 유지 보수할 값어치가 없다.

## 어떻게 꺼져 있나

1단계(2026-08-02) — `AutoLayoutContainerPanel` 이 `setRoutingEditSession({...})` 을 부르지
않게 했다. 세션이 영구히 `null` 이라 드래그 재라우팅 분기가 한 번도 실행되지 않았다.

2단계(2026-08-05) — **`RoutingEditSession` 자료구조 자체를 삭제했다.** 그 껍데기가 나르던
`containerOriginOffset`(= 컨테이너 좌표 → 그리드 좌표 오프셋)이 살아 있는 코드에서
**항상 `(0,0)` 으로 읽히면서**, 콘솔 API 가 그리드 좌표를 레이아웃 좌표인 척 내보내고
있었기 때문이다. 함께 사라진 것: `routingEditMode` · `moveAssemblerGroup` ·
`liveArea` · 툴바의 "라우팅편집" 버튼 · 렌더러/매니저의 드래그 분기 전부.

**드래그 자체는 죽지 않았다** — 엔티티는 여전히 움직인다. **벨트가 따라오지 않을 뿐**이다.
(`moveEntityById` 의 단순 이동 경로는 `layoutStore` 에 살아 있다.)

> **재구현 시: `RoutingEditSession` 은 없다. 세션을 새로 설계한다.**
> 옛 세션은 표시용 정보(컨테이너·라우팅)와 편집용 정보(`machineChildren`·`routeOptions`·
> mutate 되는 `liveArea`)와 **좌표 오프셋**을 한 자루에 담고 있었다. 표시용은 이미
> `autoLayoutRunStore.appliedLayout` 이 맡고 있고, 좌표 오프셋은 **존재하지 않는다** —
> 배치가 그리드 좌표로 넘어온 뒤에는 더할 것이 없다(→ `docs/용어사전.md` §B 좌표 프레임).
> 새 세션이 날라야 하는 것은 **편집용 정보뿐**이다.

# 무엇을 하려던 기능이었나 — 의도 8가지

**이 절이 이 폴더의 진짜 산출물이다.** 코드는 낡아도 이 요구사항은 유효하다.

## 1. 상자 드래그 — 이동 + 영향받은 라우팅만 재시도

사용자가 무한상자를 끌면 새 자리로 옮기고, **그 상자에 연결된 라우팅만** 다시 깐다.
하나라도 실패하면 **전체를 되돌린다**(부분 성공 금지).

```
[상자]──벨트──[기계]
    ↓ 드래그
......[상자]              ← 벨트가 끊긴 중간 상태를 남기지 않는다
    ↓ 재라우팅 성공 시에만 반영
......[상자]─벨트─[기계]
```

**구현:** `dragArea.dragExternalContainer`

## 2. 간격 0 스냅 — 기계에 딱 붙이면 1칸 밀어낸다

상자를 기계에 **딱 붙이면 인서터가 앉을 칸이 없어** 벨트가 크게 우회한다.
그래서 요청한 열/행은 유지한 채 **바깥으로 1칸** 밀어 깔끔한 단일 인서터를 재형성한다.

```
[상자][기계]        ← 인서터 자리 없음 → 우회 강제
[상자]▢[기계]       ← 1칸 밀어 스냅 → 인서터 하나로 직결
```

**왜 여전히 유효한가:** 이건 **게임 규칙**이다. 인서터는 두 칸 사이에 있어야 한다.
자료구조가 바뀌어도 안 바뀐다.

**구현:** `dragArea.dragExternalContainer` 의 `lacksInserterGap` 분기

## 3. ring 가둠 — 벨트가 레이아웃 밖으로 새지 않게

재라우팅 벨트가 배치 바깥으로 나가면 청사진이 커지고 모양이 무너진다.
그래서 드래그 시 `routingBounds`(현재 레이아웃 직사각형)를 **자동 주입**한다.

**단일 외곽선 불변식** — 반출(perimeter export) 설계와 같은 원칙이다.

**구현:** `dragArea` 의 `layoutBounds` 계산 + `routeFallback.portInBounds`

## 4. 조립기 그룹 드래그 — 부모+후손을 함께

기계 하나를 끌면 그 **후손 기계까지 BFS 로 묶어** 평행이동한다.

- **그룹 내부** 라우팅 → 평행이동만 (다시 깔지 않음)
- **경계** 라우팅(한쪽 끝만 그룹) → 재시도
- **외부상자 위치는 고정** — 사용자 의도대로 perimeter 재배치를 하지 않는다

**구현:** `dragArea.dragAssemblerGroup`

## 5. 꺾임 penalty — 계단형 벨트를 줄인다

지상 벨트가 방향을 꺾을 때마다 비용을 더해 **곧은 벨트**를 선호하게 한다.
상자 같은 장애물은 *우회(2회 꺾임)* 대신 *직진 점프* 로 넘긴다.

`DRAG_BELT_TURN_PENALTY = 2` — 가독성 전용이라 드래그에서만 켰다.

> **재구현 시 버려도 된다** — "탐색으로 길을 찾는다"는 전제 위에 있다.

## 6. 포트 페어 폴백 — 그리디 실패 시 전수 시도

그리디 매칭이 실패하면 **모든 포트 조합**을 manhattan 거리 오름차순으로 시도한다.
`pickBest` 면 첫 성공이 아니라 **가장 적은 셀을 쓰는 경로**를 고른다.

**구현:** `routeFallback.routeWithFallback`

> **재구현 시 버려도 된다** — 예약 구조에는 "다른 조합을 찾는다"는 개념이 없다.

## 7. 유체 역할 보존 — 재료 칸과 결과물 칸은 다르다

폴백으로 포트를 바꿔 시도할 때도 **역할을 지켜야 한다.**
안 지키면 **재료 파이프가 출력 칸에 꽂힌다**(그림상 멀쩡하고 라우팅도 "성공"으로 보고된다).

**왜 여전히 유효한가:** 유체 상자의 입출력 구분은 **prototype 이 정한다**.

**구현:** `routeFallback` 의 `enumerateContainerPorts(…, 'producer'|'consumer')`

## 8. rollback 프로토콜 — 실패가 배치를 오염시키지 않게

호출자가 `Area` 를 **deep-clone** 해서 넘기면 함수가 그걸 직접 mutate 한다.
성공하면 commit, 실패하면 clone 을 버린다.

```
cloneArea(internal) ─┐
cloneArea(external) ─┼→ dragXxx(...) ─→ 성공? commit : 폐기
routings.map(clone) ─┘
```

**왜 여전히 유효한가:** 실패한 드래그가 배치를 망가뜨리면 안 된다 — **구현 무관 불변**이다.

**구현:** `dragArea.cloneArea` · `cloneRouting` + 각 함수의 `rollback()`

# ⚠️ 알려진 결함 — 재구현 시 반드시 고칠 것

## 유체 합류 가드가 없다

[known-limits](../../../docs/auto-layout/common/known-limits.md) **§9 Deprecated Dijkstra Guard**:

> 파이프는 **방향이 없다.** 닿기만 하면 남의 관망과 그냥 합쳐진다.
> - **오염** — 다른 유체 파이프가 옆을 스치면 두 관망이 하나가 된다.
> - **유실** — 남의 머신 **출력** 유체 상자를 스치면 생산물이 이쪽으로 빨려 나간다.
>
> 둘 다 그림상 멀쩡하고 라우팅도 "성공"으로 보고된다. **기계만 굶는다.**

배치 파이프라인에는 이 가드(`util/pipeFlow` 의 `collectPipeFlow`/`pipeFlowConflict`)가 걸려 있지만
**드래그 경로에는 없었다.** 이 폴더가 비활성이 되면서 그 결함의 영향 범위는 **0** 이 됐다.

**재구현 시 이 가드를 반드시 함께 넣을 것.**

# 재구현하려면

전제가 통째로 바뀌었다:

| 옛 코드 | 지금의 배치 파이프라인 |
|---|---|
| *"어디로든 길을 찾아라"* (Dijkstra 탐색) | *"예약된 자리 안에서 옮길 수 있나"* |
| 실패하면 다른 조합을 탐색 | 실패는 **예약 불변식이 깨졌다는 신호** |
| `Area` 를 직접 mutate | `ModulePortPlan` → 좌표 입히기 → 방출의 3계층 |

**가장 큰 미해결 질문:** 드래그는 **예약을 깨는 행위**다. 상자를 옮기면 그 상자에 배정됐던
lane·트랙이 무효가 된다. *"그 자리에서 길을 다시 찾는"* 게 아니라 **planner 를 부분
재실행(re-plan)** 하는 쪽이 답일 가능성이 높다 — 옛 코드에 없던 개념이다.

**설계·착수 조건은** `tempPlanDocs/수동편집-재구현-계획.md` **제2부** 참조.
