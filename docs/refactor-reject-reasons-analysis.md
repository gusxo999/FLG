# 신 경로(Module Pipeline) Reject 사유 분석

**날짜:** 2026-07-25  
**출처:** `planner/moduleWizard.ts` 의 `reject(...)` 호출 추적

## Reject 사유 카테고리

현재 신 경로에서 옛 경로로 폴백하는 이유들을 분류했습니다.

### 분류 기준

- **스코프 안**: v1 에서 처리 가능해야 하는 케이스. 신 경로가 처리 못하면 버그.
- **스코프 밖**: 새 알고리즘이 필요하거나 게임 제약으로 처리 불가. 옛 경로 유지 OK.

| 사유 | 종류 | 스코프 | 코드 위치 | 설명 |
|---|---|---|---|---|
| **1. 다-유체** | `kind: 'multi-fluid'` | **밖** | L130 | 입력+출력 유체 합 > 1 (정유·크래킹 등) |
| **2. 비정사각형 머신** | `kind: 'non-square'` | **밖** | L140 | 머신 회전 시 footprint 변경 → 배치 불안정 |
| **3. 파이프 프로토타입 없음** | `kind: 'no-pipe-entity'` | **안** | L141 | 플레이어가 파이프를 선택하지 않음 → buildSpec 실패 |
| **4. 엔티티 게임데이터 없음** | `kind: '?'` | **안** | L144 | 머신 prototype 누락 → 데이터 일관성 버그 |
| **5. 게임데이터가 낡았음** | `kind: 'stale-gamedata'` | **밖** | L156-159 | fluid_boxes 에 direction 필드 없음 (구 export) |
| **6. 어느 각도로도 유체 면 불일치** | `kind: 'no-rotation'` | **밖** | L161-164 | 머신 회전으로도 원하는 면에 유체 상자가 안 옴 |
| **7. 줄을 놓지 못함** | `kind: 'unrouted-lines'` | **안** | L329 | 과용량(미탭) 또는 라우팅 설계 실패 |
| **8. 파이프 합류 가드** | `kind: 'pipe-merge-conflict'` | **밖** | L394-397 | 다른 유체 관망과 접촉 → 오염 위험 |
| **9. 모듈 사이 납품 경로 실패** | `kind: 'hop-failures'` | **안** | L415 | 아이템 홉 라우팅 계산 실패 |

## 스코프 분석

### 스코프 안(v1 내에서 처리 가능)
- **3. 파이프 프로토타입**: buildSpec 설정 문제 → 사용자가 해결
- **4. 엔티티 게임데이터**: 데이터 일관성 → 버그 (신 경로가 처리해야 함)
- **7. 줄을 놓지 못함**: 아이템 라우팅 설계 실패 → 신 경로 버그
- **9. 홉 실패**: 아이템 홉 라우팅 실패 → 신 경로 버그

### 스코프 밖(새 알고리즘/게임 제약)
- **1. 다-유체**: 다-유체 라우팅 = v2 신기능 → 옛 경로 유지 OK
- **2. 비정사각형 머신**: 회전 시 footprint 변경 → 설계 한계
- **5. 게임데이터 낡음**: 구 export → 사용자가 재export 해야 함
- **6. 유체 면 불일치**: 프로토타입 제약 → 선택지 없음
- **8. 파이프 합류 가드**: 다-유체 때문에 복잡 → v2에서 해결

## Phase 1 검증 계획

### P1-0: v1 아이템 케이스 커버리지
- 신 경로가 아이템만 트리를 성공적으로 처리하는가?
- 스코프 안 **아이템 reject 사유**(7, 9)가 실제 발생하는가?
- **기대:** 스코프 안 아이템 사유 = 신 경로 버그, 0건 발생해야 함

### P1-1: v1 유체 케이스 커버리지
- 신 경로가 v1 스코프 유체(**외부 공급 입력 1개**) 트리를 성공적으로 처리하는가?
- 스코프 안 **유체 reject 사유**가 실제 발생하는가?
- **기대:** 스코프 안 유체 사유 = 신 경로 버그, 0건 발생해야 함

### P1-2: 스코프 밖 폴백 확인
- 다-유체(1, 8) 레시피가 옛 경로로 정직히 폴백하는가?
- 비정사각형·게임데이터 낡음 등 제약(2, 5, 6) 레시피 동작 확인

## 향후 계측

Phase 0-2 (이 문서)는 **정적 분석**. 실제 측정(P0-2 진행)은:
1. 대표 20+ 레시피를 목록화
2. 각 레시피를 신 경로로 실행
3. reject 사유별 카운트 기록
4. 표로 정리 (사유 × 레시피 × 발생 여부)
