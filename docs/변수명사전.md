# 변수명 사전 — 디버그 플래그와 진단 출력

[[용어사전]] 이 **도메인 개념**(ClusterBelt 가 무엇인가)을 정의한다면, 이 사전은 **코드에만 사는
스위치와 로그**를 정리한다. 두 사전을 나눈 이유는 성격이 달라서다 — 용어는 사람이 대화할 때 쓰고,
여기 있는 것들은 **켜고 끄거나 콘솔에서 읽는** 것들이다.

> **범위가 좁은 게 의도다.** 아래 "왜 이것만 담나" 참조.
> **문서와 코드가 어긋나면 코드가 현재 사실**이다(CLAUDE.md 규칙). 이 사전도 시점 기록이다.
> 진입점 지도는 [[README]] · 도메인 용어는 [[용어사전]].

---

## 왜 이것만 담나 (범위 규칙)

변수명 사전은 **stale 되기 쉬운 문서**다. 코드 심볼은 grep 이나 IDE 로 즉시·정확히 찾을 수 있는데,
사전은 손으로 갱신해야 한다. 어긋나는 순간 사전이 **거짓말**을 한다. 그래서 **IDE 가 대신 답할 수
있는 것은 안 담는다**:

- ❌ 타입·함수·지역 변수 이름 — `PlannedLine` 이 뭔지는 정의로 점프하면 된다.
- ❌ 개념 설명 — 그건 [[용어사전]] 의 일이다.
- ✅ **디버그 플래그** — 어디에 선언됐고, 켜면 **무엇이 어디에 나오는지**.
- ✅ **진단 출력** — 어떤 사유가 **콘솔 어느 문구로** 나오는지. 이건 grep 할 단어를 모르면 못 찾는다.
- ✅ **상태** — "정리대상", "옛 경로 전용" 같은, 코드만 봐선 모르는 것.

**실제 사례(2026-07-16):** 브라우저 실측 중 "새 모듈 경로가 왜 옛 경로로 폴백했나"를 알아야 했는데,
화면엔 "실패 0"만 떴다. 답은 이미 콘솔에 있었지만(아래 `모듈 경로 포기`), 그걸 모르고 화면 픽셀을
세며 **추론으로 이야기를 지어냈다**. 사전이 있었으면 "콘솔에서 이 문구를 찾아라"로 끝났을 일이다.
이 사전이 담아야 할 게 정확히 그것이다.

## A. 디버그 플래그

전부 `src/autoLayout/debugFlags.ts` 에 선언. 모듈 스코프 `let` 이라 세터로 런타임
토글이 된다(테스트에서 끄고 켜기 쉬우라고).

### AUTO_LAYOUT_COORD_DUMP
기본 **true**. 자동 배치의 좌표·배치 데이터를 콘솔에 JSON 으로 덤프한다. 목적은 *AI 가 사용자의
런타임 상황을 이해하도록* — 결과 좌표만이 아니라 **어떤 레시피·머신·벨트 제약에서 생성됐는지**까지
낸다.

- **토글**: UI 패널 상단 **"COORD DUMP" 버튼**, 또는 `setAutoLayoutCoordDump(true)`.
- **뱉는 곳**: `handleApplyCandidate`(컨테이너·라우팅·정규화 좌표 + `[autoLayout debug] 환경 정보`),
  `dragExternalContainer`, `dragAssemblerGroup`, `moveAssemblerGroup`.
- 새 경로 진단은 아래 [B](#b-진단-출력-콘솔) 가 담당하며, 그쪽은 **플래그와 무관하게 항상** 나온다.

### AUTO_LAYOUT_PERIMETER_PASS
기본 **true**. 모듈 합성 후 살아남은 외부상자를 전역 perimeter 로 재배치(`modulePerimeterPass`).
false 면 상자가 로컬 모듈 ring 에 남는다. 진단·회귀 격리용.

### AUTO_LAYOUT_CHANNEL_GEOMETRY
기본 **true**. 채널 예약을 폭이 아니라 **기하(트랙 배정)** 로 한다
(→ [[channel-geometry-reservation]]). false 면 옛 동작(폭만 예약 + dijkstra 탐색).

## B. 진단 출력 (콘솔)

**플래그 없이 항상 나온다.** 조용한 실패가 추적 불가를 만들었던 경험의 산물이라, 끌 수 없게 두었다.

### `[autoLayout] 모듈 경로 포기 [<kind>]: <detail>`
`moduleWizard.ts` 의 `reject()` 가 `console.info` 로 낸다. **배치가 왜 실패했는지의 단일
출처**이고, 같은 사유가 UI 실패 라벨로도 그대로 나간다(폴백 경로는 없다).
(2026-07-13 유체 트리 추적 불가 사건이 이 함수를 만든 이유.)

사유 문자열에 실제로 담기는 것들:

| 사유 형태 | 뜻 |
|---|---|
| `[fluid-underground-too-short] <레시피> <머신> <면>: ...` | 한 면의 유체 여러 줄을 바깥으로 넘길 **지하파이프 사거리가 모자란다**(또는 지하파이프를 안 골랐다). 유체가 한 줄이면 옛 스파인으로 물러나지만 두 줄이면 물러설 곳이 없다 → [[trunk-pipe]] §5 |
| `[fluid-face-seats-exhausted] <레시피> <머신> <면>: ...` | 그 면 좌석 행에서 유체 행을 빼면 **아이템 벨트가 안 들어간다**. 처방은 더 큰 머신 |
| `<노드> 의 줄을 못 놓음 [...] — <supply.reason>` | planner 가 줄 배정 실패. 뒤의 사유가 진짜 원인 |
| `complex: seats-exceed-capacity (<역할:품목>)` | ← 그 `supply.reason` 의 대표 형태. **팔을 앉힐 좌석 행이 W/E 두 면을 통틀어 모자란다**(2026-07-17~). 괄호 안은 **자리를 못 얻은 줄**이지 반드시 원흉은 아니다 — 앞 줄들이 먼저 앉아 남은 게 없을 수도 있다. 이게 뜨면 **머신당 수요 ÷ 인서터 처리량**을 세어 보라(그 합이 `머신 높이 × 2` 를 넘으면 **어떤 모드로도 배치가 없다** — 더 빠른 인서터가 답이다) |
| `seats: <면> N탭 > M행` | **옛 형태(2026-07-17 이전)**. 배분이 끝난 뒤 세던 사후 검사라 면을 넘나들 기회가 없었다. 지금은 안전망으로만 남아 있어 뜨면 **장부 버그**다 |
| `demand>beltCap (<품목>)` | 벨트 한 줄로 못 감당 (벨트 분할 미구현) |
| `[파이프 합류 가드] ... 이으면 안 될 것과 이어진다 (<hard\|soft>)` | → [[pipe-semantics]] |
| `게임데이터가 낡았다 — ... direction 이 없다` | `scripts/export-gamedata.lua` 재추출 필요 |
| `모듈 사이 납품 경로 실패 N건` | 납품 경로 라우팅 실패 |

**읽는 법(브라우저):** 콘솔에서 `모듈 경로 포기` 로 필터. 한 줄이면 **그 줄이 전부**다 —
화면을 뜯어보기 전에 이걸 먼저 본다.

### `[autoLayout debug] 환경 정보 (런타임 입력 — 레이아웃 검증용)`
`AutoLayoutContainerPanel.tsx`, **`AUTO_LAYOUT_COORD_DUMP` 가 켜져 있을 때만**. 타깃 레시피·
countMode·외부 공급 품목·선택된 머신/벨트/투입기의 핵심 스펙을 JSON 으로 낸다. "이 레이아웃이
어떤 제약에서 나왔나"를 재구성할 때 쓴다.

### `InsertingDecisionResult.reason`
로그 문구가 아니라 **필드**지만 여기 적는다 — 위 `줄을 못 놓음 — <사유>` 의 출처이기 때문이다.
`insertingPlanner` 가 탭 방식을 포기하고 **direct(1:1) 로 떨어진 사유**를 담는다.

> **비자명:** `insertingPlanner` 는 reject 해도 **모듈을 죽이지 않는다** — direct 로 폴백한다.
> 모듈이 포기되는 건 그 **direct 마저 줄을 못 놓았을 때**다. 두 단계를 하나로 착각하기 쉽다
> (2026-07-16 실제로 착각했다).
