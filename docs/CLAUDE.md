# docs/ — 설계 지식 베이스

코드만으로는 자명하지 않은 **"왜"** 를 적는 곳이다. 저장소 루트가 Obsidian vault 다.
지도는 [README.md](README.md), 골격은 [_template.md](_template.md).

## 새 지식이 생겼을 때 — 네 질문

| # | 질문 | 예 → 어디로 |
|---|---|---|
| **Q1** | 이 프로젝트 밖에서도 참인가? | 예 → **Factorio 문서** 확인이 먼저다. 우리가 적을 건 *"그래서 우리는 어떻게 하나"* 뿐 |
| **Q2** | **코드를 바꾸면 무효가 되나?** | 예 → `docs/` (코드와 같은 커밋에서 갱신된다) · 아니오 → 메모리(작업 습관·개인 취향) |
| **Q3** | 이미 그걸 다루는 문서가 있나? | 있다 → **그 문서에 넣는다.** 새로 만들지 않는다 |
| **Q4** | 같은 사실이 두 곳에 생기나? | 그렇다 → 한 곳만 서술하고 나머지는 **링크**한다 |

> **Q3 가 가장 자주 틀린다.** 절이 여러 개라서 문서를 나누지 않는다 — **주제가 다를 때만** 나눈다.
> 특히 **앵커 없는 지식**(요구사항·이력)은 떼면 아무도 안 여는 3줄 문서가 된다.
> 앵커 있는 지식(구현 설명)에 **업혀 있어야** 산다.

## 어느 폴더인가

[auto-layout/common/code-folders.md](auto-layout/common/code-folders.md) 의 **두 축**으로 판정한다.
문서가 코드 폴더에 대응하면 **그 거울**로 두고(`auto-layout/{common,module,link,channel,perimeter}/`),
대응이 없으면 주제로 둔다(`factorio/`·`blueprint/`). 사전·MOC 는 전역이라 최상위다.

**이 거울이 도달 경로다** — 코드 폴더의 `CLAUDE.md` 가 같은 이름의 문서 폴더를 가리키므로,
그 코드를 건드리면 해당 문서가 시야에 들어온다. 규칙이 아니라 구조다.

## 링크 — 문서끼리는 `[[위키링크]]`

| 형태 | 폴더 이동 | 이름 변경 |
|---|---|---|
| `[[문서이름]]` | **안 깨진다**(이름으로 찾는다) | 깨진다 |
| `](상대경로.md)` | 깨진다 | 깨진다 |

**문서 → 문서는 `[[위키링크]]`, 문서 → 코드는 상대경로**를 쓴다. 2026-08-02 이관에서
위키링크 115 · 상대경로 168군데를 고쳤는데, 전부 위키링크였다면 이름 바꾼 것만 고치면 됐다.

## 파일을 옮기거나 이름을 바꿀 때

옮기기 전에 **인용을 먼저 센다**:

```powershell
rg -F "옛이름" --glob '!node_modules'    # 위키링크 · 상대경로 · 본문 언급 전부
```

Obsidian 의 자동 갱신은 **Obsidian 이 직접 옮길 때만** 작동한다 — git·스크립트로 옮기면
아무것도 안 해 준다. 옮긴 뒤 링크가 실제 파일을 가리키는지 확인한다.

## 문서와 코드가 어긋나면

**코드가 현재 사실이다**(문서는 시점 기록). 어긋남을 발견하면 그 자리에서 문서를 고친다 —
"나중에" 는 오지 않고, 틀린 문서는 다음 세션을 **적극적으로 오도한다**(실제로 `code-folders`
의 옛 `planner/` 정의가 그랬다).
