> **관련 문서:** [[변수명사전]] — 콘솔에서 **읽는** 것(플래그·진단 출력). 이 문서는 **치는** 것이다.

# AI 콘솔 조작 — 화면을 텍스트로 누르고 읽는다

> **이 문서를 읽어야 하는 때**
> - `src/debug/**` 를 수정할 때
> - 콘솔 명령을 **추가**할 때 → **§2 세 방식 판정을 먼저**
> - "화면에서 확인해 주세요" 라고 쓰려는 순간 → **§1**
> - 명령이 화면과 다르게 동작한다고 느낄 때 → **§4 정직한 괴리**

## 0. 한 줄 요약

`window.flg` 가 조작·관측의 텍스트 채널이다. **무엇이 있는지는 `flg.help()` 가 답한다** —
이 문서는 카탈로그를 적지 않고, **규약과 괴리**만 적는다.

## 1. 왕복 규약 — 스크린샷을 쓰지 않는다

AI 는 화면을 못 본다. 그래서 확인은 **명령을 치고 로그를 읽는** 왕복이다.

```js
await flg.run()                  // 현재 위저드 설정 그대로 생성
copy(flg.report())               // 카운터·이슈·위반·명령이력을 한 덩어리로
flg.face('n0-concrete', 'W')     // 한 면의 단면표
flg.check()                      // 규칙 위반만
```

**한 덩어리로 요청한다.** 왕복 비용의 대부분은 사용자가 여러 곳을 복사하는 일이다.
`flg.report()` 하나가 화면 상태 · 납품/반출 카운터 · 이슈 · 규칙 위반 · 최근 명령 이력을
한 번에 낸다. *"콘솔 로그 좀 보여주세요"* 대신 *"`copy(flg.report())` 결과를 붙여주세요"* 라고
쓴다.

**픽셀을 세지 않는다.** 2026-08-17 실측에서 같은 결함을 스크린샷으로 두 턴 동안 못 봤고,
`flg.face()` 가 내는 단면표 한 장에서 두 개가 한 번에 나왔다. 메모리
`feedback_layout_check_by_dump` 가 이미 금지하던 방식이다.

## 2. 명령을 추가할 때 — 세 방식 판정

화면의 버튼은 **세 자리** 중 하나에 산다. 자리마다 "누른다" 의 정직한 구현이 다르다.

| | 방식 | 판정 | 예 |
|---|---|---|---|
| **A** | 스토어 액션 직접 | `onClick` 이 스토어 액션 **하나**다 | `flg.undo()` · `flg.wizard.go(step)` |
| **B** | 컴포넌트가 등록 (`registerCommands`) | 로직이 컴포넌트 안에 있다(로컬 state·파일·클립보드·복합 절차) | `flg.wizard.apply()` |
| **C** | 실제 이벤트 디스패치 | 리스너가 React 밖(`window`·`canvas`)에 붙어 있다 | 키보드 단축키 · 캔버스 클릭 |

**A 를 남용하면 명령이 거짓말을 한다.** 버튼이 스토어 액션 하나가 아닌 실제 사례:

- **"다음"** 은 `setStep` 이 아니다 — `nextStep()` 이 후보 1개짜리 단계를 건너뛴다.
- **"초기화"** 는 `wizardStore.reset()` 이 아니다 — 실행 결과(`autoLayoutRunStore.clear()`)도
  함께 버린다. 설정만 지우면 *"어떤 설정으로 만든 건지 알 수 없는 배치"* 가 화면에 남는다.
- **체크박스** 는 `selectedMachines` 가 아니다 — 화면이 쓰는 것은 후보 1개면 미선택도
  선택으로 치는 **effective** 집합이다. 읽을 때도 그쪽을 답해야 화면과 같다
  (`runLayout.effective`).
- **캔버스 좌클릭** 은 `placeEntity` 가 아니다 — `handlePointerDown` 의 **분기 6개**다
  (모듈 이름표 / 점유 셀 검사 / 배치 / 라우팅 선 / 벨트 흐름 / 사각 선택). 그래서
  `flg.grid.place()`(스토어 직행)와 진짜 클릭을 **다른 이름으로** 둔다.

**B 가 이 설계의 중심이다.** `useDebugCommands`/`registerCommands` 로 등록하면 버튼과 명령이
**같은 함수 객체**를 가리켜, "버튼은 고쳤는데 명령은 옛 동작" 이 원천적으로 안 생긴다.
스코프 단위로 붙였다 뗀다 — 옛 `registerAutoLayoutDebug(null)` 은 등록을 통째로 지웠다.

### 왜 `querySelector(...).click()` 이 아닌가

| 문제 | 실제 |
|---|---|
| 라벨이 i18n | 툴바·위저드 버튼 텍스트는 전부 `t(...)`. 언어를 바꾸면 셀렉터가 죽는다 |
| 결과값이 없다 | `.click()` 은 `void`. 무엇이 됐는지 로그를 따로 읽어야 한다 |
| 조건부 렌더 | 6단계 밖에서는 "레이아웃 생성" 버튼이 **DOM 에 없다.** 셀렉터는 "없음" 과 "비활성" 을 구분 못 한다 |

**C 는 예외다** — 거기서 디스패치하는 대상은 셀렉터로 찾은 버튼이 아니라 *리스너가 붙은
유일한 대상*(`window`·`canvas`)이고, 그 리스너가 곧 검증 대상이다.

## 3. 목록은 문서에 없다 — `flg.help()` 가 단일 출처

[[변수명사전]] 의 범위 규칙이 그대로 답이다: *"IDE 가 대신 답할 수 있는 것은 안 담는다"*.
명령 카탈로그는 **런타임이** 대신 답할 수 있다. 문서에 표를 적으면 그날부터 썩고, 썩은
표는 다음 세션을 적극적으로 오도한다.

`flg.help()` 는 그룹·인자·**지금 사용 가능한가**·거절 사유(=다음에 칠 명령)를 함께 찍는다.
`flg.help('wizard')` 로 그룹만 볼 수 있다.

## 4. 정직한 괴리 — 명령이 버튼과 다른 자리

**`flg.help()` 가 답할 수 없는 것이 이것뿐이라, 이 절이 이 문서의 핵심이다.**

| 자리 | 버튼 | 명령 | 왜 |
|---|---|---|---|
| **그리드 적용** | 결과가 자동으로 그리드에 올라간다 | `flg.run()` 은 **6단계 패널이 떠 있을 때만** 올라간다 | 적용은 패널의 React 이펙트가 한다. 진단 자료는 결과 leaf 에 다 있어 `flg.face`·`flg.check` 는 그리드를 안 본다 |
| **게임데이터·블루프린트 파일** | OS 파일 다이얼로그 | 문자열 인자 | 다이얼로그는 사람 손이 필요하다 |
| **클립보드 복사** | `navigator.clipboard` | 반환값 | 콘솔 호출은 사용자 제스처가 아니라 권한이 막힐 수 있다 |
| **내보내기** | 파일 다운로드 | 문자열 | 다운로드된 파일을 AI 는 못 읽는다 |
| **머신 대수** | 그런 입력이 없다 | `{ perTarget: n }` | 대수는 처리량에서 **유도**된다 — 직접 지정하는 UI 가 없으므로 명령에도 없다 |

**`flg.run()` 은 그리드를 먼저 비운다.** `autoLayoutRunStore.run` 이 `clearGrid()` 를 부르기
때문이다(손으로 만든 배치가 사라진다 — 되돌리기로 복구 가능). 화면으로도 보려면 6단계를
열어 둔다.

## 5. 진단 카운터는 어디서 오나

`planned` / `dijkstraFallback` / `reservationOverrun` / `relocated` / `skipped` 는 파이프라인
**안쪽에서 이미 계산되고 있었지만 밖으로 나오는 길이 문장뿐이었다** — `moduleWizard` 가
`LayoutIssue.detail` 문자열로 빚어 화면에 보낸다. 그래서 *"planned 가 몇이냐"* 를 물으면
콘솔 로그를 정규식으로 긁어야 했다(2026-08-17: `planned = 0` 을 그렇게 **우연히** 발견했다).

[runStats](../../src/debug/runStats.ts) 가 그 숫자를 받는 싱크다. 파이프라인은 **관측만
당한다** — 계산도 분기도 반환값도 그대로고, `moduleWizard` 에 기록 호출 3줄이 늘었을 뿐이다.
숫자를 `CandidateLeaf` 까지 실어 올리는 대안은 배치 모델에 진단 필드를 심는 일이라 기각했다.

## 6. 규칙 검사는 왜 넷뿐인가

[checkRules](../../src/debug/checkRules.ts) 의 R-겹침 · R-연속 · R-도달 · R-무우회는
**전부 실제로 위반을 낸 적이 있는 규칙**이다(넷 중 셋이 2026-08-17 결함 두 건을 잡았다).

지어낸 규칙을 늘리지 않는다 — 위반을 낸 적 없는 규칙은 통과해도 아무것도 증명하지 않으면서
*"검사했다"* 는 안심만 준다.
