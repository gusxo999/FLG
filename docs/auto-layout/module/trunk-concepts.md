# 무대와 낱말 — **트렁크가 정확히 무엇인가**

> **출처:** `tempPlanDocs/트렁크벨트-경로모델/` §1~§8 (2026-08-30 [[trunk-assignment]] 의
> **부록 A** 로 이관, 2026-09-02 독립 문서로 분리. 그 폴더는 삭제됐다).

> **이 문서를 읽어야 하는 때**
> - 트렁크·다이렉트라는 말이 처음일 때 — **한 번 읽고 안 돌아와도 되게 썼다**
> - *"직선 트렁크면 충분하지 않나"* 는 생각이 들 때 → **A5**
> - *"경로 말고 (깊이, 구간) 셋으로 표현하자"* 는 생각이 들 때 → **A6**
> - *"좌표를 먼저 정하고 배정하자"* 는 생각이 들 때 → **A7**

**절 번호 `A1`~`A8` 은 일부러 그대로 뒀다** — [[trunk-assignment]] 안에 있던 시절의
인용이 안 깨지게 하기 위해서다(§ 번호가 코드 주석에 박혀 있는 것과 같은 이유 —
[[trunk-assignment]] §0.1 이관 표).

**본문의 `§9.7`·`§14-2`·`§9-마` 같은 번호는 이 문서의 절이 아니라 옛 계획서의 절이다**
(위 출처). 분리 이전부터 그랬고, 옮기면서 손대지 않았다.

## A1. 무대 — 격자 위의 네 가지

| 것 | 차지 | 규칙 |
|---|---|---|
| **머신** | `W×H` | 자기 타일 밖으로 아무것도 안 한다. 아이템은 **인서터를 통해서만** 드나든다 |
| **인서터** | 타일 **1** | 한쪽에서 집어 반대쪽에 놓는다. `reach r` = `r` 칸 건너 |
| **벨트** | 타일 1 | **방향이 하나**. 아이템이 그 방향으로 흐른다 |
| **포트** | 타일 1 | 모듈 경계. 밖과 주고받는 유일한 창구 |

머신 면에서 바깥으로 센 거리 `d`:

```
d0   머신 자신의 가장자리
d1   머신에 붙은 첫 칸        ← 인서터 좌석
d2   reach 1 이 닿는 곳
d3   reach 2(긴팔)가 닿는 곳
```

**물리 하나:** 좌석 `d` 의 인서터는 `d + r` 을 집는다. 그래서 **벨트가 깊을수록 긴 팔이
필요**하고, 팔 종류가 유한하므로 **한 면에 겹쳐 놓을 수 있는 벨트 줄 수도 유한**하다.

## A2. 다이렉트 / 트렁크 — 정확히 무엇인가

### 다이렉트 — 머신 하나, 품목 하나

```
        ┌───────┐
   ▣ ←i │  M1   │    ▣ 포트  i 인서터(d1)  ║ 벨트(d2)
   ║    │       │
   ║ ←i │       │
        └───────┘
```

벨트가 **머신 하나만** 상대하므로 남의 행을 안 지난다 → **다른 품목이 같은 깊이를 행으로
나눠 쓸 수 있다.** 대가는 포트가 `머신 수 × 품목 수`.

### 트렁크 — 여러 머신의 인서터가 같은 벨트를 쓴다

```
        ┌───────┐
   ▣ ←i │  M1   │     인서터 넷이 벨트 하나를 공유
   ║ ←i │       │     → 포트 1개 (다이렉트였다면 3개)
   ║    └───────┘
   ║    ┌───────┐
   ║ ←i │  M2   │
   ║    └───────┘
   ║    ┌───────┐
   ╚ ←i │  M3   │
        └───────┘
```

> **"합친다"의 정확한 뜻:** 다이렉트 벨트 `N` 개(각자 포트 하나)를 **벨트 하나 + 포트 하나**로
> 바꾼다. **인서터 개수는 그대로다** — 머신이 필요로 하는 처리량은 안 변하니까.
> 병합은 처리량을 바꾸는 게 아니라 **배선을 바꾸는 것**이다.

## A3. 합치기가 성립할 조건 — 여섯

| # | 조건 | 어긋나면 |
|---|---|---|
| **①** | **같은 품목** | 두 품목이 한 벨트에 섞인다 |
| **②** | **같은 방향** — 전부 공급이거나 전부 수거 | 벨트 방향이 하나뿐이라 불가 |
| **③** | **부하 ≤ 벨트 용량** | 포화 → 뒤쪽 머신이 굶는다 |
| **④** | **도달가능** — 머신마다, 그 머신에 닿으면서 벨트에도 닿는 **좌석 타일**이 존재 | 그 머신은 이 트렁크에서 못 먹는다 |
| **⑤** | **연속** — 포트에서 모든 집는 지점까지 끊김 없이 | 구멍 너머는 아이템이 안 간다. **겹침도 미배치도 아니라 아무도 못 잡는다** |
| **⑥** | **비충돌** — 벨트·좌석·포트가 머신·남의 벨트·남의 좌석·파이프와 안 겹친다 | 배치 실패 |

**④가 기하의 전부다.** 형식으로:

> 머신 `M`, 벨트 `B` 에 대해 타일 `s` 가 존재해 — `s` 는 `M` 에 인접하고,
> `B` 의 어떤 타일 `b` 에 대해 `dist(s, b) = r` 인 인서터가 있다.

## A4. 맞바꿈 — **문제의 심장**

| | 다이렉트 | 트렁크 |
|---|---|---|
| **포트 수** | 머신 × 품목 | **품목당 1** ← 얻는 것 |
| 벨트가 지나는 타일 | 머신 하나 주변 | **여러 머신을 잇는 길 전체** ← 치르는 것 |
| 같은 깊이를 남과 나눠 쓰기 | **된다**(행 구간 서로소) | **안 된다**(길을 통째로 차지) |

> 트렁크는 포트를 줄이는 대신 **자리를 더 먹는다.** 그리고 **얼마나 더 먹느냐가 길의
> 모양에 달려 있다.** 이 한 줄이 A5~A7 전부의 근원이다.

## A5. 직선은 **특수해**다

지금 트렁크는 한 면을 따라 달리는 직선이다. **그 형태에서만** 나오는 제약이 셋:

```
직선이면 →  ① 머신들이 그 선 위에 나란히 있어야 한다      → 기둥 형태 강제
            ② 그 면의 그 깊이를 선 길이만큼 통째로 먹는다  → 다른 품목이 그 면을 못 씀
            ③ 겹쳐 놓으려면 더 깊이 → 더 긴 팔 → 팔 종류 수가 상한
```

**셋 다 "직선"에서 나온 것이지 "트렁크"에서 나온 것이 아니다.**

> **2026-08-13 실패의 정체가 이것이다** — 이 셋을 트렁크의 성질로 착각하고
> 새 코드에 그대로 옮겨 심었다(§10).

## A6. 그래서 모델의 핵심 객체는 **경로**다

```
   ┌────┐
   │ M1 │──┐          · 머신이 나란할 필요가 없다
   └────┘  │          · 지나가는 타일만 먹는다
   ┌────┐  ├──▶ ▣     · 두 트렁크가 안 만나면 깊이를 다툴 일이 없다
   │ M2 │──┤
   └────┘  │
      ┌────┴─┐
      │  M3  │
      └──────┘
```

> **기둥에서는 이 경로가 구간 하나로 퇴화한다** — 자유도가 (깊이, 구간 양끝) 셋뿐이다.
> 일반형이 필요해지는 것은 격자(J4)부터다. 무엇을 어떻게 고르는지는 **§9.7**.

> **트렁크 = (경로 `P`, 좌석 집합 `S`, 끝점)**
> `P` = 연결된 벨트 타일 열 · `S` = {(머신, 좌석)} 로 각 좌석이 자기 머신과 `P` 에 동시에 닿음
> **직선 트렁크는 `P` 가 직선인 특수해다.**

"면"과 "깊이"는 모델의 **축이 아니다.** 직선일 때 나오는 **좌표의 별명**일 뿐이다.

### 경로는 **두 종류의 조각**으로 갈린다

머신 하나가 팔 `k` 개를 쓰면 좌석도 `k` 개고, 좌석마다 닿는 벨트 타일이 있어야 한다.
**머신의 탭 자리는 점이 아니라 길이 `k` 의 지상 주행이다.**

```
▣ ──연결──▶ ═══ ──연결──▶ ═══ ──연결──▶ ═══
             M1탭          M2탭          M3탭
   ↑ 탐색한다   ↑ 구성한다(계산)
```

| 조각 | 누가 정하나 | 성질 |
|---|---|---|
| **탭 주행** | **구성**한다 — 좌석 수·면에서 바로 나온다 | **정의상 지상**. 여기가 일하는 자리다 |
| **연결 구간** | **열거**한다 — 후보가 손으로 셀 만큼이다(§14-2) | 여기서만 꺾이고, 여기서만 지하로 간다 |

> **이 갈래의 기하가 §14 에서 확정됐다**(2026-08-14): 탭 주행은 **세로만**,
> 연결은 **가로만**, 그리고 가로 행의 개수가 코너 후보의 개수다.

이 갈래가 하나를 공짜로 준다: **연결 구간이 지하로 가도 탭에 지장이 없다**
(지하 위에서는 인서터가 못 먹인다 — judgements J12).

## A7. 좌표 문제 — 고리를 어디서 끊나

```
경로를 짜려면   →  머신이 어디 있는지 알아야 한다
머신을 놓으려면 →  벨트·좌석이 자리를 얼마나 먹는지 알아야 한다
```

지금 코드는 **직선이라서** 고리를 끊는다 — 직선이 먹는 폭은 좌표 없이 계산된다
(`gap 폭 = 깊이 수`). **경로가 되면 그 계산이 불가능하다.**

**그래서 반대쪽에서 끊는다: 머신을 먼저 놓고, 그 위에서 경로를 예약한다.**

이것은 예약 철학에 **어긋나지 않는다.** 철학은 *"좌표를 모르라"* 가 아니라
*"큰 그림을 보는 **주체 하나**가 자리를 먼저 잡고, 방출은 탐색 없이 놓기만 한다"* 이다.
그리고 **이 저장소에 이미 그 패턴이 있다** — `channelGeometryPlanner`·`deliveryRoute` 는
모듈이 놓인 뒤 좌표 위에서 경로를 **예약**하고 `emitPath` 는 덧셈만 한다.

> **진짜 남는 문제는 하나:** 경로를 짜다 자리가 없으면 무엇을 되돌리나(§9-마).
> 지금은 gap 폭이 그 되먹임을 암묵적으로 한다. 경로 모델은 그걸 **명시해야** 한다.

## A8. 끝점은 두 종류다 — 포트 | 머신집합

| | 트렁크의 양 끝 |
|---|---|
| **외부 줄**(원료·완제품) | 한쪽 **머신들**, 다른 쪽 **포트**(모듈 경계) |
| **내부 링크**(자식→부모) | **양쪽 다 머신들** — 이상적으로 포트가 **없다**(자식이 벨트에 놓고 부모가 그 벨트에서 집는다) |

외부만 보고 설계하면 타입에 *"끝은 포트"* 가 박히고, 내부 링크를 넣을 때 **핵심 타입을
고쳐야 한다.** 그리고 내부 링크는 **모듈 둘이 합의**해야 해서 `module/`(형제를 모른다)의
경계를 넘는다.

> **결정:** 끝점을 처음부터 **`포트 | 머신집합`** 둘 다 받게 정의하되,
> **구현은 외부 줄부터.** 타입이 열려 있으면 확장이 안 깨진다.
