## 1. 지하 — 건너지는 쪽이 들어간다

`y=t` 행에서 얕은 줄 A 가 깊은 줄 B 를 건너려 할 때, **A 는 점프를 시작할 수 없다**:

```
shared/route.ts:351   if (di !== cur.arr) continue;   // entrance-straight
```

A 는 코너에 **남쪽으로** 도착하므로 남쪽으로만 점프할 수 있다. **B 가 잠수해야 한다:**

```
 y=t-1   ⊐   ║      ⊐ B 지하 입구 (남쪽 도착 → 남쪽 점프 ✓)
 y=t    ══╝  ·      ← A 가 지상으로 지나간다.  B 의 corridor 는 axis='v'
 y=t+1   ⊏   ║      ⊏ B 지하 출구
         B   A
```

**대가:** B 는 행 `t` 에서 탭을 못 한다(몸통이 땅속). 그 행에 B 의 좌석이 없어야 한다.
**언제 쓰나는 미결** — J3(모든 줄이 관통이면 구멍이 없다).

## 4. 지하는 **아끼는 자원이 아니다** (2026-08-14 정정)

§16 는 지하를 *"`(축, 티어)` 배타권이라는 한정 자원"* 이라 적었다. **모듈 안쪽에서는 그렇지 않다.**

```
containerRouting.isJumpAllowed
   같은 blockGroup ∧ 같은 axis ∧ 같은 line  →  range 가 strict disjoint 여야 한다
   line 이 다르면  →  **검사 자체를 건너뛴다**
```

깊이 하나(`axis='v'`, `line=x`)는 **그 트렁크가 이미 독점**하고 있다. 그러니 같은 line 위의
corridor 들은 서로만 안 겹치면 되고, 그건 자기 구간을 자기가 쪼개는 것이라 **다툴 상대가 없다.**

> **§16 의 "한정 자원"은 채널 층(모듈 사이)에서 여러 경로가 같은 line 을 다툴 때의 이야기다.**
> 모듈 안쪽 트렁크에는 적용되지 않는다.

**인접한 두 행을 건너야 하면 하나로 합친다.** 계단([[trunk-assignment]] §3 ③)에서 얕은 줄 둘이 `t`, `t+1` 에서
같은 깊은 줄을 건너야 할 때, corridor `[t−1, t+1]` 과 `[t, t+2]` 는 겹쳐 둘 다는 못 판다.
대신 **`[t−1, t+2]` 하나**로 판다 — 몸통이 `t`·`t+1` 둘이 되고 그 두 행의 탭만 잃는다.
필요 점프 길이 3 은 바닐라 `transport-belt`(`max_underground_distance = 4`) 안이다.

**(나) 끊기로 떨어지는 경우 — 규칙으로**

```
① 그 벨트에 지하 변종이 없다              maxJumpDistance = 0
② 필요한 점프 길이 > max_underground_distance   (합쳐야 할 인접 행이 너무 많다)
③ 잠수 구간의 몸통 칸이 그 트렁크의 탭 행이다   탭을 잃으면 그 머신이 굶는다
```

## 5. 좌석 예산이 넘치면 — **gap 을 열어 N/S 면을 쓴다** (TR8)

밀착 기둥(`gap = 0`)에서 머신 한 대가 가진 좌석은 **W면 `h` + E면 `h` = `2h`** 뿐이다.
N/S 면은 **옆 머신의 몸통**이라 못 쓴다.

```
 y=88   ███████  ┐
 y=89   ███████  │ ← 이 경계가 M0 의 S면인데 바로 M1 이라 좌석이 없다
 y=90   ███████  ┘
```

**gap 을 열면 그 경계가 살아난다.**

```
gap = 3   (좌석 / 벨트 / 좌석)
 y=88   ███ M0 ███
 y=89    ·  [i]  ·      ← M0 의 S면 좌석.  남쪽(y=90)에서 집어 M0 에 넣는다
 y=90   ══ ══ ══ ══     ← 가로 벨트 **하나가 위·아래 두 대를 먹인다**
 y=91    ·  [i]  ·      ← M1 의 N면 좌석.  북쪽(y=90)에서 집어 M1 에 넣는다
 y=92   ███ M1 ███
```

```
좌석 예산    2h  →  2h + 2w      (w = 머신 폭.  3×3 이면 6 → 12)
```

**gap 은 전부 열지 않는다 — 머신 2대마다 하나면 충분하다**(TR11). 가로 벨트 하나가 위·아래
두 대를 먹이기 때문이다.

```
M0 ┐
   ├ gap  ← 가로 벨트가 M0(S) 과 M1(N) 을 먹인다
M1 ┘
M2 ┐      ← M1·M2 는 **밀착**.  여기 gap 을 열면 아무도 안 쓴다
   ├ gap  ← M2(S) · M3(N)
M3 ┘

4대 · h=3 · gap=3    전부 열면 21행 · **2대마다 열면 18행** · 밀착이면 12행
N 대에 필요한 gap 수 = ⌈N/2⌉
```

`layoutCluster` 가 **이미 `rowGap: number | number[]` 를 받는다**(`module/shape/cluster.ts:51`) —
*"gap 은 자리마다 다를 수 있다. 그 gap 을 지나는 가로 벨트 수에서 유도되기 때문이다."*
**새 자료구조가 필요 없다.**

#### gap 폭은 가로 벨트 줄 수에서 유도된다 (2026-08-15 사용자 확인)

gap `g` 행: 맨 위가 위 머신의 S면 좌석, 맨 아래가 아래 머신의 N면 좌석, 가운데가 벨트.
좌석 `r` 은 `r + reach` 를, 좌석 `r+g−1` 은 `r+g−1−reach` 를 집는다. `ℛ = {1,2}` 로 세면:

```
g = 3   벨트 1줄  {r+1}                위 reach1 · 아래 reach1     → **양쪽 공유**
g = 4   벨트 2줄  {r+1, r+2}           위 reach1·2 · 아래 reach2·1 → **둘 다 양쪽 공유**
g = 5   벨트 3줄  {r+1, r+2, r+3}      가운데만 공유, 바깥 둘은 한쪽 전용
g = 6   벨트 4줄  {r+1..r+4}           **공유 0** — 가로 벨트의 이점(2대 동시)이 사라진다
```

> **`ℛ = {1,2}` 에서 "위·아래를 동시에 먹이는" 가로 깊이는 최대 2줄이고 그때 `g = 4` 다.**
> 이게 면당 `R` 의 가로판이다 — 세로는 면당 `R` 줄, 가로는 gap 당 `R` 줄.
> `g` 를 더 벌리면 줄은 늘지만 **한쪽 전용**이 되어 좌석 예산이 안 는다.

**몇 줄이 지나가야 하는가는 요구에서 나온다** — 그 gap 이 맡은 두 대에게 N/S 로 공급해야 할
품목 수. 세로 깊이 배정에서 밀려난 품목 수가 곧 그 수다.

> **이것이 *"한 자식 머신이 한 부모 머신에 여러 벨트로 전달하는 형태"* 의 실체다**(2026-08-15 사용자).
> 한 머신이 **W·E·N·S 네 방향**에서 벨트를 받는다.

**그리고 gap 행은 세로 트렁크가 공짜로 잠수하는 자리다.** 가로 벨트가 세로 깊이를 건너야
하는데, 그 행에는 **어차피 탭이 없다**(머신이 없으니까) — TR7 (가)의 대가가 0 이 된다.

**gap 은 두 가지 부족을 동시에 푼다:**

```
깊이가 모자라다 (품목 수 > R)      →  가로 깊이가 생긴다        (TR4)
좌석이 모자라다 (Σa > 2h)          →  N/S 좌석이 생긴다         (TR8)
```

#### 폐기 — *"fan-out = 같은 깊이를 행으로 나눠 쓴다"*

2026-08-14 에 내가 적었던 해석이고 **기하가 성립하지 않는다**:

```
깊이 x=159 에 구리(offset 0)와 나무(offset 2)를 올리면
   구리 M0 = 86,  나무 M0 = 88,  구리 M1 = 89
                              88 과 89 가 **붙어 있다** → 두 벨트가 이어져 아이템이 섞인다
offset 0/1 로 해도 86-87 이 붙는다
```

**밀착 기둥에서 `h = 3` 이면 한 깊이에 두 품목을 못 올린다.** 그러니 그 해석으로는 팔이 줄지
않는다. 실제 답은 위의 **gap** 이다.
