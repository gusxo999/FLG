# 광선 — **이 방향으로 나가면 무엇을 지나나**

**한 줄 요약:** 배치는 **이름 붙은 영역의 격자**다. 그 목록은 **좌표보다 먼저** 완성되므로,
*"이 방향으로 나가면 무엇을 지나나"* 는 **좌표 없이** 답할 수 있다.
코드는 [`shape/rays.ts`](../../../src/autoLayout/perimeter/shape/rays.ts).

## 1. 왜 필요했나

반출의 자격을 재는 코드가 축마다 다른 것을 뒤졌다 — 세로는 형제 모듈의 `top`/`bottom`,
가로는 *"끝 열인가"*. 그런데 **둘 다 같은 질문의 특수형**이었다:

```
세로  selfBlocked   "형제 모듈의 top 이 내 top 보다 작나"
가로  directWE      "끝 열인가"
 →    둘 다  "광선이 남의 모듈을 만나나 / 그대로 바깥에 닿나"
```

## 2. 배치는 이름 붙은 영역의 격자다

두 축 모두 **정해진 순서로 번갈아** 놓인다:

```
가로   [W 마진] [열 0] [열채널 1] [열 1] [열채널 2] … [열 D] [E 마진]
세로   [marginN] [모듈 #0] [사이 행채널] [모듈 #1] … [모듈 #k] [marginS]
```

| 목록 | 무엇이 만드나 | 언제 |
|---|---|---|
| 가로 | `maxDepth` 하나 | 트리를 읽자마자 |
| 세로 | `orderByDepth`(트리 DFS 순서) + `rowChannels` | **`topY` 보다 앞** |

> **좌표는 「얼마나 먼가」를 말하고, 순번은 「무엇을 지나나」를 말한다.**
> 자격 판정에 필요한 것은 뒤쪽뿐이다.

**세로 광선이 자기 열을 못 벗어난다는 보장:** `colWidth[d]` 가 그 열의 최대 모듈 폭이고,
배치가 모든 모듈 extent 의 왼쪽 변을 `colX[d]` 에 맞춘다(`shiftModule`). 그래서 **로컬 x
끼리의 비교가 절대 x 로 비교한 것과 답이 같다.**

## 3. 네 경우 — 이것이 규칙 전부다

```
그 방향의 광선이 지나는 영역을 차례로 훑는다

  ① 모듈 몸통    **그 모듈에게 묻는다** — "네 로컬 열 c 가 비었나". 비었으면 통과
  ② 통로 · 환승  통로를 따라 **꺾어** 나간다 → 그 축의 줄을 **산다** → 모자라면 통로가 넓어진다
  ③ 통로 · 관통  방향을 유지한다 → 파는 줄과 **직교** → **살 게 없다** → "비었나?" 만 묻는다
  ④ 마진        여백. 통과하고 seat 줄에 앉는다

하나라도 안 되면 그 방향은 후보가 아니다
```

**①은 블랙박스에게 묻는다.** 모듈이 있다고 무조건 막지 않는다 — `GeneratedModule.bodyColumns`
(몸통이 먹는 로컬 열)에 내 열이 없으면 지나간다. 그 요약은 `moduleWayOuts` 와 **같은
순간·같은 몸통**에서 나온다(`fillModuleWayOuts`). → [[module-way-outs]]

**통로는 자기 축의 줄을 판다** — 열 채널은 **세로줄**(트랙), 행 채널은 **가로줄**(트랙).
그리고 **환승하면 광선이 꺾이므로**, 사는 줄은 *"내가 지금 달리던 축"* 이 아니라
**"이 통로를 따라 계속 갈 축"** 이다.

| 통로 | 파는 줄 | 뻗는 방향 | 환승하면 닿는 곳 |
|---|---|---|---|
| 열 채널 | 세로줄 | 세로 | **바깥 N/S 마진** ✅ |
| 행 채널 | 가로줄 | 가로 | **옆 열 채널**(끝 열이면 바깥) ⚠️ |

## 4. 한계 — **1홉까지만 본다**

가로 광선은 **첫 통로(또는 바깥 마진)에서 멈춘다.** 그 너머는 남의 열이고, 남의 열을
가로지르려면 그 열의 행 채널로 **갈아타야** 하기 때문이다.

```
outerMargin 으로 끝난다   →  그대로 나갈 수 있다(끝 열)
columnChannel 로 끝난다   →  **거기서 환승해야** 나간다
```

세로 광선은 언제나 `outerMargin` 으로 끝난다 — 자기 열의 행 채널들을 지나면 바로 바깥이다.

**2×2 중 한 칸이 비어 있다:**

```
              직진(상자 좌표)      환승(트랙 배정)
세로 → N/S    있다                열 채널
가로 → W/E    있다                **없다** (행 채널)
```

**빈칸을 채우려면 — 두 조각이고, 무게가 다르다**(옛 계획 `통로-갈아타기`, 2026-09-12 옮김):

| 조각 | 홉 | 무엇이 필요한가 |
|---|---|---|
| **끝 열**의 행 채널 환승 | 1 | 행 채널 배정에 반출을 **신고자로** 넣는 것뿐이다 — 끝 열의 행 채널은 한쪽이 바깥 마진이라 열 채널이 끼지 않는다. 다만 **동쪽으로** 나가는 반출이 섞이면 *"서쪽 끝 공통"* 이 깨져 행 채널의 교차-없음 전순서가 사라진다(`rowChannelPlanner` 머리말) |
| **중간 깊이**의 행 채널 환승 | 2 | 행 채널은 옆 **열 채널**에 닿으므로 거기서 한 번 더 갈아탄다. 한 경로가 **두 장부에 동시에** 자리를 사야 하는데, 오늘은 행 채널 트랙 배정이 `topY` 앞에서 닫히고 열 채널은 그 뒤에 열린다. 행 채널을 *높이 산정*(겹침 수만 있으면 된다)과 *트랙 배정*으로 가르면 두 장부가 같은 시각에 선다. 코너는 `(행 트랙, 열 트랙)` **한 쌍을 한 번에** 신청하고 두 장부가 각자 거절권을 갖는다. 그때 이 광선은 재귀가 된다(홉 상한 2 · 같은 통로 두 번 금지) |

**오늘 이 빈칸이 실패를 내는 자리는 아니다**(2026-09-11 관측). 중간 깊이 상자가 후보 0 이
되려면 모듈이 W·E 를 **둘 다** 막아야 한다 — 하나만 열려도 열 채널 환승 후보가 선다
(`flg.report()` 의 `반출배정` 줄이 그 상자를 `위험군` 으로 센다). 위험군은 실물에 있었지만
전부 **단일 모듈 트리**였고(중간 깊이가 없다), 그 모듈을 중간 노드로 밀면 그 상자는 납품으로
짝지어져 반출 대상에서 빠졌다. 네 방향이 **전부** 막힌 상자는 행 채널로도 못 구한다 → [[known-limits]] §12.

## 5. **③(관통)은 통로에만 있는 게 아니다** — 직진 × 직진

> **직진 × 직진도 관통이다.** (2026-09-08 발견 · 2026-09-10 해소)

세로 직진과 가로 직진은 **직교**하고, 둘 다 **아무 자리도 안 산다.** 그래서 **서로를 볼
방법이 없었다.** 2026-09-08 까지 이 다툼이 안 난 이유는 단 하나 —

> **①이 보수적이라 세로 직진이 남의 모듈 extent 안으로 못 들어갔다.**
> 그 보수성이 **우연히 장부 노릇**을 하고 있었다 — 정확도를 깎는 대신 안전을 사는 거래인데,
> ①을 정확하게 만들어 보고서야 거래의 존재를 알았다.

실제로 넣어 봤더니 `oneToOneGuarantee ②`(모든 포트가 밖으로 나간다)가 **6건** 깨졌다 —
세로 직진이 남의 모듈의 빈 열을 뚫자, 그 칸을 비었다고 믿던 **가로 직진**이 방출에서
막혔다(`straight blocked to E`). 그래서 ①을 되돌렸다(`20b24fd`).

**정확도를 올리려면 직진이 먹는 「선 전체」가 장부에 있어야 한다** — seat 칸만이 아니라.
그 장부가 `DirectRay` 이고, 서고 나서 ①을 다시 열었다.
→ [[perimeter-export]] §3② **직진 장부**

> **광선은 그 장부가 아니다.** 광선은 *"무엇을 지나나"* 라는 **질문**이라 아무것도 안 먹고
> 순서와 무관하다. 직진이 **먹는 칸**을 말하는 것은 반직선(`DirectRay`)이고, 층이 다르다.

## 6. 이 모델이 지우는 것

| 옛 코드 | 광선 뒤 |
|---|---|
| `selfBlocked` · `ModuleSpan` · `spansByDepth` | **없다** — 순번 목록이 답한다 |
| `enumerateOptions` 의 N/S · W · E 세 갈래 | **네 방향에 규칙 하나** |
| 자격 판정이 `globalY`·`maxDepth`·`spansByDepth` 를 뒤짐 | **영역 목록 하나** |
| 자격 판정이 좌표를 씀 | **안 쓴다.** abs y 는 *"가까운 N/S 가 어느 쪽인가"* 라는 **선호 순서**에만 |

## 7. 함께 선 것 — 납품과 반출은 **같은 도형**이다

`channel/shape.routeShape` 가 옛 `staircaseShape`(납품)와 `elbowShape`(반출)를
합쳤다. 차이는 **끝점의 종류** 하나다:

```ts
type ChannelEndpoint =
  | { kind: "wall"; row; wall }   // 채널 벽의 한 점 — 그 행에 **가로 조각**이 붙는다
  | { kind: "edge"; edge }        // 바깥 N/S 변 — 세로가 그대로 나가서 가로 조각이 없다
```

```
납품 = [wall(startY,"E"), wall(endY,"W")]   → 가로 2 + 세로 1   (계단꼴)
반출 = [wall(entryY,진입벽), edge(진출변)]   → 가로 1 + 세로 1   (elbow)
```

**비대칭을 지우지 않고 담는다** — `edge` 끝점은 **행이 자유롭고** `wall` 끝점은 고정이다.
그게 해소 사다리 ①(진출 변 뒤집기)이 **반출에만** 있는 이유다. 납품엔 뒤집을 자유가 없다.

> **양 끝이 벽이고 행이 같으면 세로를 접는다** — 길이 0인 세로 조각을 남기면 `trackCount`
> 가 그 열을 세어 **안 쓰는 폭이 는다**(옛 `straightShape` 가 하던 일).
