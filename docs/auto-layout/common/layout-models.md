# 배치 모델 — 각자 무엇을 그릴 수 있나 (넷 + 빈자리 하나)

## 0. 왜 이 문서인가

자동 배치는 **모델 넷**이 이어 붙어 돈다(그리고 **빈자리가 하나** 있다 — §2⑤). 각 모델은 자기 좌표계에서 **정해진 도형만** 그린다 —
탐색이 아니라 배정이기 때문이다(예약 철학).

문제는 **그릴 수 없는 것**이 어디에도 안 적혀 있다는 것이다. 코드에는 그 경계가
*"판정"* 이나 *"조건"* 처럼 생긴 이름으로 들어 있어(`eligible`), **넓히면 되는 문턱**으로 보인다.
실제로는 **모델이 표현할 수 있는 범위**라서, 넓히면 못 그리는 그림이 나온다.

> **2026-08-18 실측:** `eligible` 을 넓혔더니 계단꼴이 모듈 몸통을 관통하는 경로를 그렸고,
> 계획된 납품 경로가 **0개**가 됐다. 게이트를 연 것이 아니라 **모델 밖을 그리게 한 것**이다.

이 문서는 모델마다 **좌표계 · 고정된 것 · 자유로운 것 · 그릴 수 있는 도형 · 경계**를 적는다.
경계를 알면 *"이건 이 모델의 일이 아니다"* 를 착수 전에 말할 수 있다.

---

## 1. 한눈에

```
① 모듈 모델      한 모듈 안쪽.  기둥 + 면 + 레인×행
② 트리 배치 모델  모듈들의 자리.  depth = 열 · tidy-tree = 행
③ 채널 모델      모듈 **사이 세로** 통로([[용어사전#채널 (channel)|채널]]).  트랙 + 계단꼴/한꺾임꼴
④ 반출 모델      갇힌 상자 → 배치 **밖** 테두리

⑤ **행 채널 모델 — 이름만 있고 없다**
   [[용어사전#행 채널 (row channel)|행 채널]] = 세로로 쌓인 두 모듈 **사이의 가로 띠**.
   채널을 90° 돌린 **직교 짝**으로 용어사전에 정의돼 있으나, **계획 모델이 없다.**
```

**셋(①③④)이 경로를 그리고, ②가 그 무대를 만든다.** 그리고 넷은 서로를 안 본다 —
사이를 잇는 것은 **자료형 하나**씩이다(§3).

> **⑤가 빈자리라는 것이 이 문서의 중요한 산출물이다.** 용어사전 `행 채널` 항목이
> *"모듈 간 납품 경로 벨트와 외부상자 exit 레인이 이 띠를 지난다 —
> 납품 경로가 이 띠를 가로막으면 상자가 perimeter 로 못 빠져나가는 **skip 의 무대**"*
> 라고 **역할과 사고까지 미리 적어 놨는데**, 그 띠를 계획하는 코드가 없다.
> 폭은 `STACK_GAP = 3` 으로 **우연히** 생기고(겹침 방지 여백), 아무도 예약하지 않는다.

## 2. 모델마다

### ① 모듈 모델 — 기둥 하나의 면

| | |
|---|---|
| **좌표계** | 모듈-로컬. 면(W/E/N/S) × 깊이 `d`(면에서 바깥으로) × 위치 `t`(면을 따라) |
| **고정** | 머신 대수·크기(기둥은 세로 한 줄), 유체 면(머신 `fluid_boxes` 가 정한다) |
| **자유** | 줄마다: 어느 면 · 어느 레인(깊이) · 어느 좌석 행 |
| **도형** | 레인 하나 = 세로 벨트 한 줄 + 그 좌석들. 포트는 벨트 끝 + 인서터 + 상자 |

**자원이 둘이다:** 좌석 행(머신마다 `h` 개)과 **레인 × 행**. 레인 수는 팔 종류(reach) 수에서
나온다 — reach `r` 인 팔은 `d(r+1)` 을 집는다.

```
관통(g = N)   벨트가 기둥 전체 → 레인을 통째로 먹는다 → 포트가 **기둥 끝**
구간(g < N)   벨트가 일부     → 행만 먹는다          → 포트가 **면 바깥**
```

**그릴 수 없는 것**

```
· 격자(2D) 클러스터 — 기둥은 세로 한 줄로 못 박혀 있다 (`clusterLayout`)
· 한 벨트가 비연속 구간 — 벨트는 연속이라야 흐른다
· 면에 관통이 레인 수보다 많은 것 — 그 이상은 다른 면이나 gap 으로 간다
```

### ② 트리 배치 모델 — 무대를 만든다

| | |
|---|---|
| **좌표계** | 절대. `colX[depth]` · `topY[node]` |
| **고정** | 트리 구조(`parentId` 는 **스칼라**), 각 모듈의 extent |
| **자유** | 같은 깊이 안에서의 세로 순서·간격 |
| **도형** | 열(깊이) + 세로 스택. 열 사이가 채널, 스택 사이가 `STACK_GAP` |

```
colX[d] = colX[d-1] + colWidth[d-1] + channelWidth(d)
colWidth[d] = max(그 깊이 모듈들의 extent.w)
```

**그릴 수 없는 것**

```
· DAG — 자식이 부모를 여럿 가질 수 없다.  `layoutY`(tidy-tree)가 트리를 전제한다
· **행 채널의 폭을 수요에서 유도하는 것** — `STACK_GAP = 3` 은 상수다.
  세로 채널은 `channelWidthFromTracks(trackCount, …)` 로 **폭 역전**(수요 → 폭)을 하는데,
  가로 띠는 그 대응이 없다(2026-08-18 확인 — 예약하는 코드가 0)
```

### ③ 채널 모델 — 모듈 사이 세로 통로

| | |
|---|---|
| **좌표계** | **반쪽 추상**. 열 = `-1`(W벽) · `0..cap-1`(트랙) · `capCol`(E벽) — **가상**<br>행 = **절대 y** — 실좌표 |
| **고정** | 납품의 출발 행·도착 행, 반출의 접점 행 (**포트가 정한다**) |
| **자유** | 트랙(세로 주행 열) 하나 |
| **도형** | 납품 = 계단꼴(직선 3) · 반출 = 한꺾임꼴(직선 2) · 열 갈아타기 · 지하 횡단 |

**핵심 도구는 절단선(cut)** — 반출이 채널을 두 쪽으로 가르고, 납품의 두 끝이 같은 쪽이라야
지상 경로가 존재한다. 벨트를 깔기 전에 **숫자 비교만으로** 판정된다.

**그릴 수 없는 것 — 그리고 그 경계의 이름이 `eligible` 이다**

```
전제   포트가 **채널 벽을 마주 본다**  (자식 출력 W변 · 부모 입력 E변 · 깊이 인접)
표현   modulePacking.ts  `eligible = out.meta.side === "W" && inp.meta.side === "E" && …`

그래야 "출발 행 · 도착 행" 이 뜻을 갖는다 — 벨트가 벽에서 **가로로** 나와 채널로 든다.
포트가 기둥 끝(N/S)이면 벨트가 **세로로** 나오므로 "출발 행" 이 아니라 "출발 열" 이고,
계단꼴은 그 모양을 표현할 수 없다.
```

```
· 열이 가상이라 **모듈 내부를 모른다** — 벽 안쪽은 좌표계 밖이다
· 여러 채널을 가로지르는 경로 — 좌표계가 채널 하나 안이다
· 기둥 끝 ↔ 기둥 끝 납품 — 채널이 아니라 가로 띠를 지나야 하는데 그 개념이 없다
```

### ④ 반출 모델 — 배치 밖으로

| | |
|---|---|
| **좌표계** | 절대 |
| **고정** | 상자 자리, 그 포트의 `moduleWayOuts`(모듈이 자기에 대해 답한다) |
| **자유** | 진출 변(N/S/W/E), 채널 host 면 트랙 |
| **도형** | 직진 · 한꺾임꼴(채널 경유) |

**탐색 폴백이 없다** — *"예약된 경로는 항상 방출 가능해야 한다"* 가 설계다. 못 놓으면
그 상자만 로컬 ring 에 남기고 **사유를 남긴다**(`skips`).

### ⑤ 행 채널 모델 — **빈자리**

| | |
|---|---|
| **좌표계** | (없음) |
| **고정** | 띠의 위치·폭이 `STACK_GAP` 상수로 우연히 정해진다 |
| **자유** | (없음 — 아무도 배정하지 않는다) |
| **도형** | (없음) |

> **⑤가 서면 "주체 둘" 문제가 따라온다**(2026-08-18). 세로 채널 장부와 행 채널 장부가
> 각자 예약하면 2026-08-17 의 사고(*"남의 계획을 밟는다"*)가 축만 바꿔 재현된다.
> 그래서 **통로망 모델**(세로 띠 + 가로 띠 + 교차로를 한 주체가 배정)이 후보로 있다 —
> 그러면 ③은 *"한 세로 통로 안의 배정"* 을 맡는 **부품**이 된다.
> → `tempPlanDocs/행채널-모델/judgements.md` `J-관리관`

**있어야 할 것은 ③의 전치(轉置)다.** `assignTracksLeftEdge`(구간 겹침 → 최소 트랙)는
**축과 무관한 순수 알고리즘**이라 그대로 쓸 수 있다. 그 위의 것(계단꼴·절단선·같은 쪽
판정)은 전부 세로 전용이라 다시 세워야 한다.

**왜 이 자리가 필요한가**

```
기둥 끝 포트끼리의 납품   상자가 기둥 위/아래에 있다 → 세로 채널이 아니라 **가로 띠**를 지난다
반출 exit 레인            갇힌 상자가 N/S 변으로 나가려면 이 띠를 지난다
사용자 요구               "블루프린트를 거의 관통하는 가로 벨트"
```

## 3. 모델 사이의 접점 — 각자 **자료형 하나**

```
①  →  ③④    ModulePort   { anchor(=상자=모듈 경계) · tapAnchor(=벨트 끝) · face · moduleWayOuts }
②  →  ③     DeliverySpec + 절대 포트 y
②  →  ④     LanePlan
③  →  방출  DeliveryGeometry (트랙 번호 → 호출자가 절대 x 로)
```

**접점이 얇은 것이 설계다.** 모듈은 자기 안을 안 보여 주고(불투명 블록), 채널은 모듈 안을
모른다. 그래서 한쪽을 바꿔도 다른 쪽이 안 깨진다 — **접점의 뜻이 그대로인 한**.

> **`ModulePort.anchor` 의 정의는 "모듈 경계"다**(`clusterModule.ts`). 실제로는
> *"자기 벨트 + 2"* 에 놓이므로, 그 둘이 같아지는 것은 **그 면에 이 그룹 혼자일 때**뿐이다.
> 면에 여러 줄이 앉으면 얕은 줄의 상자가 깊은 줄에 둘러싸여 **경계가 아니게 된다.**

## 4. 경계가 깨질 때 — 관측된 사례

**증상에서 모델로 역추적하는 표다.** 새 증상을 만나면 여기 추가한다.

| 증상 | 깨진 경계 | 왜 |
|---|---|---|
| `planned = 0` · `chain-blocked: 모듈 몸통` | ③ — 포트가 벽을 안 마주 본다 | 포트가 기둥 끝(N/S)인데 계단꼴이 면 진입을 그린다 (2026-08-18) |
| 포트 상자가 면 속에 갇힌다 | ①↔③ 접점 — `anchor` 가 경계가 아니다 | 같은 면의 깊은 레인이 얕은 상자를 감싼다 |
| `reservation not emittable` (반출) | ④ — 예약 불변식 파손 | 남이 그 칸을 먼저 밟았다. 대개 ③의 탐색 폴백 |
| `예약 무시 재시도 — 남의 계획을 밟는다` | ③↔④ — **예약 주체가 둘** | 납품과 반출이 서로의 장부를 모른다 |
| 벨트가 띄엄띄엄 | ① — 벨트 연속성 | 좌석 행 *목록*을 돌고 *범위*를 안 돌았다 (2026-08-17) |

## 5. 새 능력을 넣기 전에 던질 질문

```
1. 이건 **어느 모델의 일인가**  — 넷 중 하나에 안 들어가면 새 모델이다(비싸다)
   행 채널(⑤)의 일이면 **모델부터 세워야 한다** — 이름만 있고 계획이 없다
2. 그 모델이 **그릴 수 있는 도형인가** — 아니면 도형을 먼저 늘려야 한다
3. 접점의 뜻이 바뀌나 — `ModulePort.anchor` 같은 것.  바뀌면 **양쪽을 같이** 고친다
```

**2번을 건너뛰면 게이트를 여는 것으로 착각한다.** `eligible` 을 넓혔던 것이 그 예다 —
조건을 통과시켰지만 그릴 수 있는 도형은 안 늘어서, 못 그리는 그림이 나왔다.
