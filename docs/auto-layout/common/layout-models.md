# 배치 모델 — 각자 무엇을 그릴 수 있나 (넷 + 빈자리 하나)

## 0. 왜 이 문서인가

자동 배치는 **모델 넷**이 이어 붙어 돈다(그리고 **빈자리가 하나** 있다 — §2⑤). 각 모델은 자기 좌표계에서 **정해진 도형만** 그린다 —
탐색이 아니라 배정이기 때문이다(예약 철학).

문제는 **그릴 수 없는 것**이 어디에도 안 적혀 있다는 것이다. 코드에는 그 경계가
*"판정"* 이나 *"조건"* 처럼 생긴 이름으로 들어 있어(`eligible`), **넓히면 되는 문턱**으로 보인다.
실제로는 **모델이 표현할 수 있는 범위**라서, 넓히면 못 그리는 그림이 나온다.

> **2026-08-18 실측:** `eligible` 을 넓혔더니 계단꼴이 모듈 몸통을 관통하는 경로를 그렸고,
> 계획된 납품 경로가 **0개**가 됐다. 게이트를 연 것이 아니라 **모델 밖을 그리게 한 것**이다.

이 문서는 두 축을 적는다:

```
§2    모델마다 **좌표계 · 고정/자유 · 그릴 수 있는 도형 · 경계**   ← 무엇을 그릴 수 있나
§3.5  **두점 라우팅** — 경로 × 경로 규칙 하나 · 판정하는 자리 · 결함 · 구멍  ← 경로가 만나면 누가 갖나
```

**둘 다 있어야 증상을 읽는다.** 도형이 맞아도 자리가 없으면 못 그리고, 자리가 있어도
도형이 없으면 못 그린다 — §4 의 표가 증상을 그 둘로 가른다.

## 1. 한눈에

```
① 모듈 모델      한 모듈 안쪽.  기둥 + 면 + 깊이×행
② 트리 배치 모델  모듈들의 자리.  depth = 열 · tidy-tree = 행
③ 채널 모델      모듈 **사이 세로** 통로([[용어사전#채널 (channel)|채널]]).  트랙 + 계단꼴/한꺾임꼴
④ 반출 모델      갇힌 상자 → 배치 **밖** 테두리

⑤ **행 채널 모델 — 이름만 있고 없다**
   [[용어사전#행 채널 (row channel)|행 채널]] = 세로로 쌓인 두 모듈 **사이의 가로 통로**.
   채널을 90° 돌린 **직교 짝**으로 용어사전에 정의돼 있으나, **계획 모델이 없다.**
```

**셋(①③④)이 경로를 그리고, ②가 그 무대를 만든다.** 그리고 넷은 서로를 안 본다 —
사이를 잇는 것은 **자료형 하나**씩이다(§3).

> **⑤는 2026-09-06 에 빈자리를 벗어났다.** 용어사전 `행 채널` 항목이
> *"모듈 간 납품 경로 벨트와 외부상자 반출 트랙이 여기를 지난다 —
> 납품 경로가 여기를 가로막으면 상자가 perimeter 로 못 빠져나가는 **skip 의 무대**"*
> 라고 역할과 사고를 미리 적어 놨고, 이제 그것을 **계획하는 코드가 있다.**
> 높이는 통과 경로 수에서 유도되고(`planRowChannel`), 그 높이가 곧 **모듈 사이 간격**이다
> — 옛 `STACK_GAP = 3` 상수가 있던 자리다.

## 2. 모델마다

### ① 모듈 모델 — 기둥 하나의 면

| | |
|---|---|
| **좌표계** | 모듈-로컬. 면(W/E/N/S) × 깊이 `d`(면에서 바깥으로) × 위치 `t`(면을 따라). **면마다 `FaceTable` 한 장** — 칸 = `(행, 깊이)`([[module-planning]] §4.5) |
| **고정** | 머신 대수·크기(기둥은 세로 한 줄), 유체 면(머신 `fluid_boxes` 가 정한다) |
| **자유** | 줄마다: 어느 면 · 어느 깊이(깊이) · 어느 좌석 행 |
| **도형** | 깊이 하나 = 세로 벨트 한 줄 + 그 좌석들. 포트는 벨트 끝 + 인서터 + 상자 |

**자원이 둘이다:** 좌석 행(머신마다 `h` 개)과 **깊이 × 행**. 깊이 수는 팔 종류(reach) 수에서
나온다 — reach `r` 인 팔은 `d(r+1)` 을 집는다.

**둘은 한 표의 두 열이다**(2026-08-26). `d1` 열이 좌석, `d2..` 열이 깊이가고, **포트 인서터·
상자도 그 표의 칸**이다 — 예전엔 벨트 깊이만 장부에 실려서 포트가 남의 깊이에 서는 것을
아무도 몰랐다. 그리고 **깊이를 고르면 팔 종류가 정해지므로 팔 *개수*가 깊이마다 다르다**
(`armsAt`) — 좌석 예산은 깊이 후보마다 다시 재야 한다.

```
관통(g = N)   벨트가 기둥 전체 → 깊이를 통째로 먹는다 → 포트가 **기둥 끝**
구간(g < N)   벨트가 일부     → 행만 먹는다          → 포트가 **면 바깥**
```

**그릴 수 없는 것**

```
· 격자(2D) 클러스터 — 기둥은 세로 한 줄로 못 박혀 있다 (`clusterLayout`)
· 한 벨트가 비연속 구간 — 벨트는 연속이라야 흐른다
· 면에 관통이 깊이 수보다 많은 것 — 그 이상은 다른 면이나 gap 으로 간다
```

### ② 트리 배치 모델 — 무대를 만든다

| | |
|---|---|
| **좌표계** | 절대. `colX[depth]` · `topY[node]` |
| **고정** | 트리 구조(`parentId` 는 **스칼라**), 각 모듈의 extent |
| **자유** | 같은 깊이 안에서의 세로 순서·간격 |
| **도형** | 열(깊이) + 세로 스택. 열 사이가 채널, 스택 사이가 **행 채널** |

```
colX[d] = colX[d-1] + colWidth[d-1] + channelWidth(d)
colWidth[d] = max(그 깊이 모듈들의 extent.w)
```

**그릴 수 없는 것**

```
· DAG — 자식이 부모를 여럿 가질 수 없다.  중앙 정렬(`tree/shape.stackColumns`)이 트리를 전제한다
```

### ③ 채널 모델 — 모듈 사이 세로 통로

| | |
|---|---|
| **좌표계** | **반쪽 추상**. 열 = `-1`(W벽) · `0..cap-1`(트랙) · `capCol`(E벽) — **가상**<br>행 = **절대 y** — 실좌표 |
| **고정** | 납품의 출발 행·도착 행, 반출의 접점 행 (**포트가 정한다**) |
| **자유** | 트랙(세로 주행 열) 하나 |
| **도형** | 납품 = 계단꼴(직선 3) · 반출 = 한꺾임꼴(직선 2) · 열 갈아타기 · 지하 횡단 |

**핵심 도구는 완전 교차 판정** — 두 경로(납품이든 반출이든)의 끝이 채널 테두리에서 엇갈리면 지상
경로가 존재하지 않는다. 벨트를 깔기 전에 **행 · 벽 비교만으로** 판정되고, 엇갈린 쌍은 해소 사다리가
푼다([[channel-geometry-reservation]] §4).

**그릴 수 없는 것 — 그리고 그 경계의 이름이 `eligible` 이다**

```
전제   포트가 **채널 벽을 마주 본다**  (자식 출력 W변 · 부모 입력 E변 · 깊이 인접)
표현   link/arith/pair.ts pairDeliveries  `eligible = out.meta.side === "W" && inp.meta.side === "E" && …`

그래야 "출발 행 · 도착 행" 이 뜻을 갖는다 — 벨트가 벽에서 **가로로** 나와 채널로 든다.
포트가 기둥 끝(N/S)이면 벨트가 **세로로** 나오므로 "출발 행" 이 아니라 "출발 열" 이고,
계단꼴은 그 모양을 표현할 수 없다.
```

```
· 열이 가상이라 **모듈 내부를 모른다** — 벽 안쪽은 좌표계 밖이다
· 여러 채널을 가로지르는 경로 — 좌표계가 채널 하나 안이다
· 기둥 끝 ↔ 기둥 끝 납품 — 열 채널이 아니라 행 채널을 지나야 하는데 그 개념이 없다
```

### ④ 반출 모델 — 배치 밖으로

| | |
|---|---|
| **좌표계** | 절대 |
| **고정** | 상자 자리, 그 포트의 `moduleWayOuts`(모듈이 자기에 대해 답한다) |
| **자유** | 진출 변(N/S/W/E), 채널 host 면 트랙 |
| **도형** | 직진 · 한꺾임꼴(채널 경유) |

**탐색 폴백이 없어야 한다** — *"예약된 경로는 항상 방출 가능해야 한다"* 가 설계다. 못 놓으면
그 상자만 로컬 ring 에 남기고 **사유를 남긴다**(`skips`). **오늘은 하나가 있다** — 환승 반출의 예약 트랙이 막혔거나
트랙이 없으면(땅 위를 내준 반출) 방출이 진입 방향으로 트랙을 1~16칸 훑는다(`perimeter/shape/router`). 계획이 못 본
만남의 자국이고, 그 훑기는 다른 반출의 예약을 모른다.

### ⑤ 행 채널 모델 — ③의 **전치**

| | |
|---|---|
| **좌표계** | 행 채널 안의 **행 번호**(트랙 index). 절대 행은 `rowChannel.top + track` |
| **고정** | 행 채널의 **신원**(깊이 · 순번 · 이웃) — 트리 DFS 순서가 정한다 |
| **자유** | 어느 트랙에 앉나 |
| **도형** | 가로 직선. 포트에서 그 행까지 내려오는 **세로 진입**은 아직 배정 밖이다 |

**높이는 고르는 값이 아니라 배정의 결과다** — `channelWidthFromTracks(trackCount, 3)`,
세로 채널과 **같은 식**이다. 그리고 그 높이가 **모듈 사이 간격을 민다**(`tree/shape.stackColumns` 의 누적합 · 하한 복원)
— 그래서 행 채널이 트랙보다 좁을 수 없다.

> **⑤가 서면 "주체 둘" 문제가 따라온다**(2026-08-18). 세로 채널 장부와 행 채널 장부가
> 각자 예약하면 2026-08-17 의 사고(*"남의 계획을 밟는다"*)가 축만 바꿔 재현된다.
> 그래서 **통로망 모델**(채널 + 행 채널 + 교차로를 한 주체가 배정)이 후보로 있다 —
> 그러면 ③은 *"한 세로 통로 안의 배정"* 을 맡는 **부품**이 된다.
> → `tempPlanDocs/채널-양보-명세/judgements.md` `J-관리관`

**있어야 할 것은 ③의 전치(轉置)다.** `assignTracksLeftEdge`(구간 겹침 → 최소 트랙)는
**축과 무관한 순수 알고리즘**이라 그대로 쓸 수 있다. 그 위의 것(계단꼴 · 완전 교차 판정 ·
해소 사다리)은 전부 세로 전용이라 다시 세워야 한다.

**왜 이 자리가 필요한가**

```
기둥 끝 포트끼리의 납품   상자가 기둥 위/아래에 있다 → 열 채널이 아니라 **행 채널**을 지난다
반출 반출 트랙            갇힌 상자가 N/S 변으로 나가려면 이 행 채널을 지난다
사용자 요구               "블루프린트를 거의 관통하는 가로 벨트"
```

## 3. 모델 사이의 접점 — 각자 **자료형 하나**

```
①  →  ③④    ModulePort   { anchor(=상자=모듈 경계) · tapAnchor(=벨트 끝) · face · moduleWayOuts }
②  →  ③     DeliverySpec + 절대 포트 y
②  →  ④     PerimeterExitPlan
③  →  방출  DeliveryGeometry (트랙 번호 → 호출자가 절대 x 로)
```

**접점이 얇은 것이 설계다.** 모듈은 자기 안을 안 보여 주고(불투명 블록), 채널은 모듈 안을
모른다. 그래서 한쪽을 바꿔도 다른 쪽이 안 깨진다 — **접점의 뜻이 그대로인 한**.

> **`ModulePort.anchor` 의 정의는 "모듈 경계"다**(`module/build.ts`). 실제로는
> *"자기 벨트 + 2"* 에 놓이므로, 그 둘이 같아지는 것은 **그 면에 이 그룹 혼자일 때**뿐이다.
> 면에 여러 줄이 앉으면 얕은 줄의 상자가 깊은 줄에 둘러싸여 **경계가 아니게 된다.**

## 3.5 두점 라우팅 — **경로가 만나면 누가 갖나**

§2 가 *"각 모델이 무엇을 그릴 수 있나"*(도형)라면, 이 절은 **두 경로가 한 칸을 원할 때**다. 이름은
[[용어사전#두점 라우팅|두점 라우팅]] — 납품도 반출도 두 점을 잇는 경로이고, 만나면 규칙 하나로 푼다.

> **이 절은 *"무엇이어야 하나"* 다.** 오늘 코드가 다른 곳은 **⟨코드 다름⟩** 으로 적는다 — 고칠 결함이다(`docs/CLAUDE.md`
> *코드가 개념에 미달하면 결함으로 적는다*). 2026-10-01 계획 `두점-라우팅` 이 아홉 자리에 흩어져 있던 조각(이 절의 옛 판 ·
> [[priority-ordering]] · [[exit-ray]] · [[channel-geometry-reservation]] · [[pipeline-lifecycle]] · [[perimeter-export]] ·
> [[code-folders]] · 납품 사다리 · 유체 문서)을 여기 모았다. 옛 판(*경로 넷 · 장부 여섯 · 순서가 곧 우선권 · 진짜 축은 양보*)은 git.

### 읽는 법

1. **원칙을 한 번 읽는다.** 외울 것은 제4조다.
2. **목록은 찾아본다** — 1부(이 경로가 무엇을 할 수 있나) · 2부(만난 곳에서는 누가 판정하나) · 3부(계획이 못 해서 방출이
   대신 정하는 것 — 결함) · 4부(아직 모르는 곳).
3. **물음이 생기면 세 걸음** — 1부에서 두 경로의 값을 본다 → 2부에서 만난 자리를 찾는다 → 제4조에 넣는다. 2부에서 *없음* 이나
   4부가 나오면 그것이 답이다 — 아직 아무도 판정하지 않는 곳이다.

### 원칙

**제1조 경로.** 두 점을 잇는 선이다. 납품(모듈 → 모듈)도 반출(상자 → 바깥 변)도 경로다 — 반출은 *바깥으로 가는 납품* 이다
([[exit-ray]] §7 *같은 도형*). 두 끝(포트 · 바깥 변)은 경로보다 먼저 정해진 사실이고, 고르는 것은 그 사이의 길뿐이다
([[pipeline-lifecycle]] §8.2 물음 3 — 닭과 달걀이 아니다).

**제2조 경로의 값.** 경로마다 넷을 갖는다. 종류(납품 · 반출 · 유체)는 규칙에 나오지 않는다 — 종류가 바꾸는 것은 이 넷의 값이다(1부).

```
끝       양 끝이 고정인가, 한 끝이 자유인가(바깥 변)
후보     다른 길이 더 있나
층       땅속으로 갈 수 있나 — 매체(벨트 · 파이프)와 그 사거리
잃는 것  끝내 못 이으면 무엇을 잃나
```

**땅 위와 땅속은 매체마다 다르다**(사용자 2026-10-01).

```
파이프   땅속이 좋다. 직선으로 늘어선 지상 파이프는 사거리가 허락하는 가장 긴 지하파이프로 바꾼다
         — 모양이 낫고, 나중에 공간을 더 쓸 수 있다.  만나지 않아도 그렇다.
벨트     땅 위를 먼저 본다. 땅속은 만남을 풀 때 쓴다.
```

⟨코드 다름⟩ 파이프의 땅속 선호는 아직 없다 — 유체는 만남에서만 땅속으로 간다.

**제3조 범주 둘.**

```
경로 × 고정물(머신 · 모듈 몸통)   다툼이 아니다. 경로가 피한다 — 모듈 몸통이라도 빈 열은 지나간다
경로 × 경로                      아래 규칙 하나
```

모듈 안의 자리(좌석 · 깊이)는 이 절 밖이다 — [[module-planning]].

**제4조 경로 × 경로.**

```
① 만남   피할 수 있는 만남은 자리(트랙 · 행)를 달리 줘서 푼다. 아무도 지지 않는다.
         두 끝이 경계에서 엇갈리는 쌍(완전 교차)만 반드시 만난다 — 그때 한쪽이 진다.
         서로 다른 유체는 닿기만 해도 만난 것이다.

② 동등   만난 두 경로는 동등하다. 먼저 적은 쪽이 이기지 않는다 — 단계의 차례는 자리를 나누는 순서일 뿐,
         승자를 정하지 않는다. 차례가 승자를 정하고 있다면 그 자리는 두 경로를 함께 못 보는 것이다(4부).

③ 지하 횡단   반드시 만나면 한쪽이 지하 횡단한다 — 벨트는 지하벨트로, 파이프는 지하파이프로. 매체는 안 바뀐다.
         누가 들어가나는 만난 두 경로의 매체에 따라 셋으로 갈린다(아래).

④ 계획이 끝까지   자리가 모자라면 계획이 넓힌다(통로 폭은 배정의 결과다). 방출로 넘기지 않는다.
         방출에서는 도면 크기가 이미 굳어 넓힐 수 없다 — 방출이 길을 찾는 것은 계획이 그 만남을 못 본 결과다(3부).
```

**③ 을 매체마다 가르는 이유** — 벨트와 파이프는 땅속의 뜻도, 만나는 뜻도, 땅속에서 지켜야 할 것도 다르다.

| | 벨트 | 파이프 |
|---|---|---|
| 땅속의 뜻 | 만남을 풀 때만 | 원래 땅속이 좋다 |
| 만남 | 같은 칸을 쓰면 | 같은 칸을 쓰면 · **서로 다른 유체는 닿기만 해도** |
| 땅속의 짝 | 같은 종류(티어)의 지하벨트끼리만 끊는다 | 같은 줄 위의 지하파이프는 **종류와 무관하게** 서로 끊는다 |
| 입구 · 출구 | 방향이 있다 — 진행 방향으로 들어가 곧게 나와야 하고, 레인 옆으로 붙으면 안 된다 | 방향이 없다 — 대신 입구 · 출구 칸도 다른 유체에 닿으면 안 된다 |
| 끝내 못 이으면 | 부모 머신이 굶는다 | 트리 거절 — 유체엔 방출의 탐색이 없다 |

```
벨트 × 벨트       ⓐ 들어갈 수 있는 쪽(사거리 · 짝 · 입출구 방향)  ⓑ 상대가 많은 쪽  ⓒ id 뒤쪽      → 지하벨트로
파이프 × 파이프    ⓐ 들어갈 수 있는 쪽(사거리 · 짝 · 입출구가 다른 유체에 안 닿나)  ⓑ 상대가 많은 쪽  ⓒ id 뒤쪽  → 지하파이프로
벨트 × 파이프     ⓐ 들어갈 수 있는 쪽  ⓑ 상대가 많은 쪽  ⓒ 같으면 파이프가 지하파이프로(잠정)
```

- **상대** 는 그 경로와 반드시 만나는 경로다. 한 쌍이 여러 칸에서 겹쳐도 하나로 센다.
- **왜 상대가 많은 쪽인가** — 반드시 만나는 쌍마다 층 바꿈은 누가 들어가든 하나씩 든다. 선택이 바꾸는 것은 들어간 경로가
  *덤으로* 건너는 칸과, 붙은 여러 칸을 **지하 한 쌍으로 덮나** 다. 여럿과 엇갈린 경로 하나가 들어가면 둘 다 좋아진다(VLSI 의
  층 배정 · via 최소화와 같은 꼴). 다만 막힌 칸이 사거리 밖으로 흩어졌거나 사이에 인서터 행이 끼면 한 쌍으로 못 덮는다 — 상대
  수는 그때 값을 잘못 잰다.
- **섞인 만남의 *"같으면 파이프"* 는 잠정이다** — 지금은 무엇으로 들어가든 차이가 없다. 이 순서에 영향을 주는 문제가 나오면 바꾼다.
- 모듈 안에서도 같은 규칙이 선다 — 옆면은 상대가 포트 사슬이라 벨트만 들어갈 수 있고(ⓐ), gap 출구는 옆면 벨트 여럿을 건너는
  gap 벨트가 들어간다(ⓑ). → [[trunk-blocked]] §1 · §4.2

⟨코드 다름⟩
- **동등** — 행 채널 × 직진 반출은 *행 채널이 먼저 섰다* 는 이유로 반출이 진다. (열 채널에서는 2026-10-02 부터 반출도 땅속으로 간다.)
- **계획이 끝까지 — 남은 것** — 열 채널은 들어간 쪽이 못 건너면 **트랙 하나를 끼워** 그 새 열로 건넌다(2026-10-02 · 4부 *들어갈
  수도 없을 때*). 그래도 못 건너면 오늘처럼 진다 — 아이템은 방출의 탐색(3부 ①), 유체 · 반출은 땅 위로 돌아와 다시 배정하고
  아무도 못 들어가면 실패 비용(P10)이 진 쪽을 정한다.

**제5조 판정하는 자리.** 규칙은 영역의 장부에서 판정된다. 만난 두 경로를 **함께** 보는 장부라야 제4조 ② 가 선다.

> **경쟁은 좌표계가 만든다.** 로컬 좌표로 자기를 표현하는 주체는 *자기 안에서* 배정을 끝내고 절대 좌표로 나온다 — *"내 안의
> 자리는 내가 전부 안다"* 여야 공동 배정이 선다. 절대 좌표로 바로 쓰는 주체는 전역에서 만나 경쟁한다.
>
> | 주체 | 좌표계 | 절대화 지점 | 결과 |
> |---|---|---|---|
> | 모듈 안 | 모듈 로컬 | 배치(`moduleTransform`) | 나온 뒤엔 남이 읽기만 한다 — 고정물 |
> | 열 채널 | 채널 로컬(트랙 index) | `channelStartX(d)+1+track` | **로컬 안에서 납품 · 반출을 함께 배정** |
> | 행 채널 | 행 채널 로컬(`band.top+t`) | 세로 자리 | 납품끼리는 함께 · 반출은 가로선이 덮는 범위만 읽는다 |
> | 직진 반출 | 반직선(깊이 · 로컬 열 · 절대 행 · 방향) | — | 차례로 적는다(직진 장부) |
> | 방출 | 절대 칸 | — | 전역에서 먼저 깐 쪽 — 3부 |

**제6조 방출은 판정하지 않는다.** 정해진 것을 그린다. 방출이 무엇이든 정한다면 그것은 3부의 결함이다 — 줄이는 것이 아니라 없앨
것이다([[pipeline-lifecycle]] ⑥).

**제7조 진 쪽은 기록을 남긴다** — 누가 · 무엇을 내줬나([[용어사전#양보|양보]]) · 누구 때문에 · 어느 자리에서. 지금은 일부만 남는다(2부 *기록* 칸).

### 1부 경로의 값 — 종류는 여기에만 나온다

| 경로 | 끝 | 후보 | 층 | 끝내 못 이으면 |
|---|---|---|---|---|
| 아이템 납품 | 양 끝 고정(포트) | 없다 — 계획 하나 | 지하벨트 — **필수** | 부모 머신이 굶는다 — 트리 거절 |
| 유체 납품 | 양 끝 고정(포트) | 없다 | 지하파이프 — **필수** | 트리 거절 |
| 반출(벨트 · 파이프) | 한 끝이 바깥 변 | 출구 — **출구 선정은 아직 없는 기능**(오늘은 가까운 경계 · 구조 정리 뒤 착수) | 지하벨트 · 지하파이프 — 납품과 같다 | 상자가 안에 남는다 |

지하벨트 · 지하파이프는 위저드에서 **필수**다 — 지하파이프를 안 고르면 유체 레시피를 끄고, 지하벨트도 같은 정책이다(사용자 2026-10-01). 끝내 못 이었을 때의 피해 등급은
*머신이 굶는다 > 유체가 오염된다 > 납품이 안 이어진다 > 반출이 못 나간다 > 폭이 낭비된다* 다 — 앞의 셋은 치명, 반출은 물류가 이어지는
경고, 폭은 미관.

⟨코드 다름⟩
- **반출의 층 — 열 채널 밖** — 반출이 땅속으로 가는 곳은 열 채널뿐이다(2026-10-02 — 장부가 계획한 점프를 방출이 그대로 깐다).
  직진 반출 · 행 채널을 지나는 반출은 땅 위로만 간다 — 그 자리의 판정이 반출을 땅속으로 보낼 줄 모른다(2부 행 채널 · 직진 경로).
- **진 쪽을 정하는 잣대 — 아무도 못 들어갈 때** — 오늘 코드는 *"땅 위를 잃으면 어디로 가나"*([[priority-ordering]] P10 — 유체 >
  반출 > 아이템)로 진 쪽을 정한다. 아이템을 *"방출의 탐색이 회수한다"* 로 쳐서 가장 싸게 보는데, 그 탐색이 3부 ① 이다. 모델은
  그때 계획이 넓힌다(제4조 ④).

### 2부 판정하는 자리 — 닫힌 목록

| 자리 | 장부 | 함께 보나 | *반드시 만나나* 를 어떻게 보나 | 진 쪽 | 기록 |
|---|---|---|---|---|---|
| **열 채널** | 채널 기하 장부(`channel/ledger/geometry`) | 함께 — 납품 · 환승 반출 | 두 끝이 채널 경계에서 엇갈리나(완전 교차) · 서로 다른 유체는 닿나 — [[channel-geometry-reservation]] §4 · §10 | 제4조 ③ | 개수만 |
| **행 채널** | 행 채널 배정(`channel/ledger/row` · `assign`) | 납품끼리는 함께 — 순서 그래프(*내 세로 진입이 남의 가로선을 지나지 않게*) · **반출은 나중에 와서 이미 선 납품을 본다** ⟨코드 다름 — ②⟩ | 납품끼리: 같은 쪽에서 들어오는 두 끝이 방향이 반대이고 동쪽으로 가는 끝이 서쪽에 있나(완전 교차 — [[channel-geometry-reservation]] §10.3) · 반출: 직선이 가로선이 덮는 범위를 지나나(자식 쪽 `[0, x]` · 부모 쪽 `[x, 동쪽 변]` — [[exit-ray]] §3 ③) | 납품끼리: 한 끝이 행을 못 받고 사유를 남긴다 ⟨코드 다름 — ③ 지하 횡단이 없다. 모듈이 기둥 끝 포트를 세우는 방식상 실제 입력에선 아직 안 난다⟩ · 반출: 그 후보를 버린다 | 납품: 개수만(*행 채널 엇갈림*) · 반출: 후보가 0 일 때만 |
| **직진 경로** | 직진 장부(`perimeter/ledger` `DirectRay`) | 차례 — 후보가 적은 상자 먼저(P12) · *출구 선정의 오늘 동작* | 두 반직선이 한 칸에서 만나나 | 오늘은 뒤 상자가 다음 후보로(후보 강등) | 있다 |
| 모듈 옆 빈 자리 | **없음** | — | — | — | 4부 영역 목록 |
| 행 채널 진입 다리 · 마진 · 기둥 밖 | **없음** | — | — | — | 4부 영역 목록 |
| 두 영역을 이은 길 | **없음** | — | — | — | 4부 영역 경계 |

**경로 × 고정물** — 모듈 몸통: 반출은 그 방향 후보가 처음부터 안 생기고([[module-way-outs]]), 납품은 도형이 피한다(§2 ③ *그릴 수
없는 것*). 머신 · 모듈의 유체: 닿기만 해도 안 된다 — 납품은 계획 체인을 깔기 전에, 반출은 깔기 전에 본다.

**왜 이 차례로 서나** — 행 채널은 반출보다 먼저 선다(행 채널의 높이가 모듈의 세로 자리를 민다 — 뒤가 앞을 읽는 순서라 바꿀 수
없다). 차례는 그대로 두고 **판정**을 두 경로가 함께 보이는 자리로 옮겨야 제4조 ② 가 선다 — 4부 *영역 경계* 와 같은 물음이다.
반출의 출구는 열 채널 장부보다 먼저 정해진다 — 그래서 열 채널에서 반출에게 남은 자유는 진출 변 뒤집기뿐이다.

### 3부 계획이 못 해서 방출이 대신 정하는 것 — 결함 목록

방출에서는 도면 크기가 이미 굳어 **넓힐 수 없다.** 그래서 아래는 전부 *"계획이 그 만남을 못 봤다"* 의 자국이고, 원인은 대개 4부의 구멍이다.

| # | 무엇이 왔나 | 방출이 하는 일 | 왜 계획이 못 봤나 |
|---|---|---|---|
| ① | 계획 체인이 막힌 아이템 납품 · 계획이 없는 아이템 납품 | 굳은 도면 안에서 탐색 → 그래도 막히면 **반출의 예약을 무시하고 다시**(`link/policy/delivery.chooseRoute`) | 계획 체인이 지나는 칸에 계획이 모르는 것이 있었다 — 직진 반출의 예약 · 장부 없는 영역의 경로 · 모듈 몸통(도형). **계획에선 반출이 이겼는데 방출에선 납품이 이긴다**(전수표 #8 · #9). 계획이 아예 없는 것은 완전 교차에서 아무도 못 들어갔거나(열 채널) 행을 못 받은 끝이다(행 채널 — 지하 횡단이 없다) |
| ② | 땅 위를 잃은 반출 · 예약 트랙이 막힌 반출 | 진입 방향으로 트랙을 1~16칸 훑는다(`perimeter/shape/router`) — 땅 위로만 | 아무도 못 들어갈 때 실패 비용으로 진다(1부 ⟨코드 다름⟩) · 땅속 예약이 방출에서 막혔다(계획 밖의 탐색 납품이 입구 · 출구를 밟음) · 훑기는 다른 반출의 예약을 모른다 · 땅 위를 잃은 사유는 이 전에 버려진다 |
| ③ | 강행한 직진 반출 | 막히면 skip — 상자가 안에 남는다 | 출구 후보가 다 막혔다(출구 선정이 아직 없다) |
| ④ | 계획을 못 쓴 유체 납품 | 거절 | 인접(4부) · 행 채널의 완전 교차. *두 영역을 이은 길의 엇갈림* 으로 보이던 거절은 행 채널이 부모 쪽 가로선의 방향을 거꾸로 본 결함이었다(2026-10-02 고침) |
| ⑤ | 남의 유체에 닿는 반출 파이프 | skip | 열 채널 밖(진입 다리 · 직진 · 마진)의 인접은 장부가 없다 — 열 채널 장부는 2026-10-02 부터 반출 파이프의 둘레를 본다 |

방출 순서는 유체 납품 → 아이템 납품 → 반출이다(P11) — ① 이 유체를 밟지 못하게 하는 순서다. 결함이 없어지면 순서도 뜻을 잃는다.

### 고치기 전에 재는 법 — 자유도는 **한 배정 순간의 성질**이다

*"C 가 B 보다 자유롭다"* 는 측정할 수 없는 문장이다. 물을 수 있는 것은 하나뿐:

> **실제로 막은 그 셀을 만든 배정이, 그때 다른 선택지를 가지고 있었는가.**
> 단위 = `options.length`, 그리고 *그중 상대를 안 막는 것의 수*.

| 나오는 값 | 뜻 |
|---|---|
| `options.length == 1` | 자유가 없었다 — 자리를 **늘리는** 쪽(마진 · 행 채널 · 폭)이 답 |
| `> 1`, 대안이 전부 막음 | 쓸모없는 자유 |
| `> 1`, 안 막는 대안 있음 | 다른 후보로 갔으면 풀렸다 — 판정이 그 만남을 못 봤다 |

표를 물을 수 없다 — `reservedExportCells` 를 `Set<셀>` → `Map<셀, 배정id>` 로 바꾸는 것이 계측기다(제7조).

## 4. 경계가 깨질 때 — 관측된 사례

**증상에서 모델로 역추적하는 표다.** 새 증상을 만나면 여기 추가한다.

| 증상 | 깨진 경계 | 왜 |
|---|---|---|
| `planned = 0` · `chain-blocked: 모듈 몸통` | ③ — 포트가 벽을 안 마주 본다 | 포트가 기둥 끝(N/S)인데 계단꼴이 면 진입을 그린다 (2026-08-18) |
| 포트 상자가 면 속에 갇힌다 | ①↔③ 접점 — `anchor` 가 경계가 아니다 | 같은 면의 깊은 줄이 얕은 상자를 감싼다 |
| `reservation not emittable` (반출) | ④ — 예약 불변식 파손 | 남이 그 칸을 먼저 밟았다. 대개 ③의 탐색 폴백 |
| `예약 무시 재시도 — 남의 계획을 밟는다` | ③↔④ — **예약 주체가 둘** | 납품과 반출이 서로의 장부를 모른다 |
| 벨트가 띄엄띄엄 | ① — 벨트 연속성 | 좌석 행 *목록*을 돌고 *범위*를 안 돌았다 (2026-08-17) |
| `chain-blocked: 반출 예약` | §3.5 #8·#15 — C 가 협상 없이 박았다 | **직진** 반출은 ③의 공동 배정에 안 들어간다 |
| 다른 두 유체가 한 통이 된다 | §3.5 #7·#13 — **인접** 미검사 | `blocked`·`occ` 는 겹침만 본다. 파이프는 닿기만 해도 이어진다 |

## 5. 새 능력을 넣기 전에 던질 질문

```
1. 이건 **어느 모델의 일인가**  — 넷 중 하나에 안 들어가면 새 모델이다(비싸다)
   행 채널(⑤)의 일이면 **모델부터 세워야 한다** — 이름만 있고 계획이 없다
0. 그 앞에: **도형 문제인가 자리 문제인가** (§3.5 · §4). 자리 문제면 새 도형을 만들어도
   안 풀린다 — 2026-08-18 에 도형을 세 번 바꾸고서야 자리 문제인 걸 알았다
0b. 자리 문제면: **그 주체가 절대 좌표로 쓰나** (§3.5 전수표). 그렇다면 새 능력이 아니라
   **양보**나 **로컬 좌표**가 답이다 — ③이 경쟁을 푸는 이유가 그것이다
2. 그 모델이 **그릴 수 있는 도형인가** — 아니면 도형을 먼저 늘려야 한다
3. 접점의 뜻이 바뀌나 — `ModulePort.anchor` 같은 것.  바뀌면 **양쪽을 같이** 고친다
```

**2번을 건너뛰면 게이트를 여는 것으로 착각한다.** `eligible` 을 넓혔던 것이 그 예다 —
조건을 통과시켰지만 그릴 수 있는 도형은 안 늘어서, 못 그리는 그림이 나왔다.
